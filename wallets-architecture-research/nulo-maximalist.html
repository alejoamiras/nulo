Maximalist Nulo — 5/5 across the board

The year-long, three-engineer, no-shipping-pressure vision. What Nulo looks like when every dimension is at 5/5 and a few new dimensions are added that the comparative study never named. Synthesized from chat reasoning + an independent codex review.

SPINE PROGRESS Runtime-spine work has begun shipping: Phase 2 closed 2026-05-13; Phase 2+ Bundle 1 (production hardening) + Phase A (token imports through the journal, multi-in-flight card render fix) both shipped 2026-05-15 (v0.15.7 + v0.16.0). See the Phase 2+ page for what's shipped vs what's still aspirational on the spine; the maximalist tracks (Aztec depth, dApp ergonomics, supply-chain hardening, network privacy, cross-browser parity) remain future work.

The single biggest reframe

The 5/5 wallet is not bigger features on top of a fragile runtime. It's a runtime-reliability program (Phase 2+) at the spine, with everything else hanging off it — Aztec depth, dApp ergonomics, supply-chain hardening, network privacy, cross-browser parity. Maximalist Nulo is what the rest of the box looks like when you let the runtime spine do its job. Wallet stays browser-only; the design discipline is "make the extension impossible to kill, not bigger".

New dimensions worth adding consolidated

The 12-dimension star table missed these. Each is its own first-class concern for a privacy wallet, not a sub-bullet of an existing dimension.

Network-layer privacy

RPC routing discipline; metadata minimization; Tor/VPN-friendly endpoints; polling-rate ceilings to avoid origin linkability; sender-address rotation where Aztec supports it; private note discovery (range-proof subscriber when upstream ships). For a privacy wallet, metadata leakage is as architectural as encryption.

Supply chain & release integrity

Reproducible builds; provenance attestations; dependency allowlists; patch discipline; signed releases per platform; deterministic bundles. Not the full LavaMoat stack on day one — that comes once the architecture stops moving. SBOM in CI is cheap and useful immediately.

Observability + incident response

Privacy-preserving structured traces; local redaction-first logs; user-exportable encrypted debug bundles; opt-in aggregate metrics. You will not debug MV3/proving failures blind. The debug-bundle export pattern is the privacy-respecting way to ship observability without a backend.

Threat modeling + chaos discipline

Documented threat model maintained per release; regular red-team exercises; SW-kill chaos tests in CI; corrupted-storage drills; approval-spam drills; malicious-dApp suite. Not a one-time audit — an ongoing discipline.

Narrow formal methods

Model-check three things specifically — the job state machine, the permission wildcard matcher, and migration invariants. Use TLA+ or Alloy. Don't try to "formally verify the wallet" — that's how this kind of effort goes nowhere. The narrow scope is the whole point.

What's deliberately NOT in scope codex pushback

These are common asks for "professionalize the wallet" that codex pushed back hard on. The wins aren't worth the time given Nulo's actual constraints.
  • Dedicated progress window (a detached popout owning long-running prove UI) — adds a second long-running surface to design, maintain, and explain. The popup stays as Nulo's single user-visible surface; subscribe-by-jobId via the attach map already covers close-and-rejoin. Product decision.
  • Desktop proving companion (Tauri-style native daemon hosting PXE long-running) — introduces a parallel native distribution channel, install/update story, code signing, platform builds. The wallet stays browser-only. Product decision.
  • Mobile (RN / native) — Aztec proofs are long; mobile makes them longer. Mobile is Phase ∞, not Maximalist. Product decision.
  • Account abstraction features (social recovery, session keys, M-of-N) — product bets, not quality dimensions. Until upstream Aztec canonizes them, building custom account-contract complexity contradicts the "lean upstream" principle.
  • LavaMoat on day one — the supply-chain track lands after the architecture stabilizes. LavaMoat now would slow every iteration without proportional benefit.
  • Replace the typed Service<Methods,Events> boundary with @metamask/messenger / ObjectMultiplex / PatchStore. Nulo's typed boundary is already 5/5; only addition is Grego-style runtime schema validation.
  • Formally verify the wallet — the narrow formal-methods scope (job FSM + permission matcher + migration invariants) is the whole point. Broad formal verification of a Vue UI is a tar pit.

Where the comparative study undershoots consolidated

  • It implies durable jobs reaches 4/5 with the 8-item Phase 2. The 5/5 version needs fairness, idempotency, retry, tombstones, sweeper, attach/detach, and chaos discipline. The study underspecs this. codex
  • It underweights network privacy. For a privacy wallet, metadata leakage is as architectural as encryption. codex
  • It slightly overweights MetaMask-style framework mass. Nulo does not need @metamask/messenger / ObjectMultiplex / PatchStore to reach 5/5. codex
  • It treats AA features as plausible "quality" expansion. Until upstream canonizes them, they're distractions. codex
  • It doesn't surface the missing dimensions (supply chain, observability, network privacy, threat modeling, formal methods) as first-class star columns. They probably should be. chat
  • It implies sequential phases. The reality is mostly-parallel tracks with one front-loaded gating piece. chat
Note on two codex suggestions deliberately not included: codex argued for a separate approval/progress window and an optional desktop proving companion as part of the 5/5 vision. Both were ruled out as product decisions — see the "What's deliberately NOT in scope" section above. The runtime spine is what gets us to 5/5 on durable jobs within the existing browser-extension surface.
The maximalist take, condensed: Phase 2+ is the runtime-reliability program. Maximalist Nulo is what the rest of the box looks like when you let the runtime spine do its job — which is mostly not "add more features", it's "make Nulo impossible to kill, impossible to confuse, and much harder to deanonymize."
