MetaMask — the industrial-grade reference

Verdict: The most architecturally serious of the four. Approval state machine, LazyListener, persistence-manager with IDB backup, numbered migrations, ObjectMultiplex transport, Snaps sandbox, LavaMoat. Most of it is overkill for Nulo's current size, but specific primitives — especially M3, M4, M6, M7, M8 — are exactly the right next steps.

Runtime shape diagram

MetaMask's MV3 extension is built around a MetaMaskController that composes controllers from @metamask/* packages. Each controller exposes typed state, actions, and events via a central messenger. Persistence is mediated by a dedicated persistence-manager with explicit IDB fallback. The popup connects via long-lived chrome.runtime.Port and pipes traffic through ObjectMultiplex.

How durable jobs work here analysis

MetaMask is the only wallet of the four with a full approval state machine. It's the closest existing implementation to Nulo's Phase 2 JobRegistry.

  1. ApprovalController — every user-prompt request becomes an approval object with a stable id, origin, type, and requestData. The controller exposes methods to add, accept, reject, and resolve approvals. Resolution returns a promise the caller awaits. Each transition is reflected in state. M8 pattern
  2. LazyListener — events that fire before the controller is fully initialized are buffered in extension-lazy-listener and replayed when init completes. Nothing silently dropped on cold boot. M3 pattern
  3. await isInitialized gating on every port — the SW's port handler awaits init before forwarding traffic. dApp messages that arrive during cold-boot don't error; they queue. M4 pattern
  4. Numbered migrations — every schema change ships as a numbered migration script. Failed migrations are loggable, reversible, and tested. M6 pattern
  5. persistence-manager with IDB backup — writes to chrome.storage.local; if that fails or is corrupted, restores from an IndexedDB snapshot. M7 pattern
Pattern to internalize: approvals and migrations are not ad-hoc — they're first-class primitives with shared lifecycle. Every durable interaction goes through the same machinery, which makes new prompt types trivial to add and impossible to drop.

Strengths research

DimensionWhy it stands out
Approval state machineEvery prompt is durable, addressable by id, and replayable. The reference implementation for our JobRegistry.
LazyListener boot bufferingSolves the "event arrived before init" class of bug permanently.
Numbered migrationsSchema evolution is auditable and tested. Migrations have unit tests.
Persistence-manager + IDB backupSurvives storage corruption; not theoretical — it has saved users.
LavaMoat + SnapsDefense-in-depth for npm supply-chain attacks and 3rd-party extension code.
ObjectMultiplex transportMultiple typed streams over one port. Clean separation of concerns.

RiskWhy
Architectural massHundreds of controllers and packages. New contributors take weeks to ramp.
Tight upstream couplingForking pieces of @metamask/* for custom needs is hard; upstreaming changes is slow.
Heavy build pipelineLavaMoat + Snaps + V8 isolates add significant build complexity.
Redux at the popupTwo state systems (controller messenger + Redux) can drift if subscribed wrong.
Migrations are linear and irreversibleDowngrading is not supported; bad migrations can brick wallets.

What Nulo should steal phase 2

  • Approval state machine → directly maps to Phase 2 JobRegistry. Build this first; everything else snaps in.
  • LazyListener → solves Nulo's "event during SW cold-boot" loss class.
  • await isInitialized port gating → port handlers should await profile-boot before forwarding.
  • Numbered migrations framework → before we open to "real users", schema changes must be auditable.
  • IDB backup of critical state → ApprovalController-equivalent state + keystore wrapper must survive storage corruption.

What not to copy phase 2

  • @metamask/messenger bus — Nulo's Service<Methods, Events> is simpler and already production-quality. Don't replace it.
  • LavaMoat — defer until we ship for real users; right now it adds build pain without payoff.
  • Snaps — Aztec doesn't have a plugin ecosystem; sandboxing 3rd-party code is not Phase 2 scope.
  • ObjectMultiplex — Nulo's port traffic is single-purpose; don't add a transport layer we don't need.
  • Redux duplication of controller state — keep popup state derived directly from ServiceClient events.
