# Lessons — R3 (P16b dApp approval-window shell) · deep, UI orchestration

Three landings: characterization spec (`R3-characterization.md`, committed `fe5aca1`), **R3a frozen
oracle** (#238 @ `26401c7`), **R3b extraction** (#240 @ `c938603`, full gate green first-pass).

## Characterize FIRST paid for itself three times
The 440-line spec (produced by a subagent pass, spot-reviewed against source before trusting) found
divergences a naive "unify the shell" would have silently erased:
- **The two-layer reject + dismiss-routes-through-unload**: `closeWindow(true)` removes the
  `beforeunload` listener, `closeWindow()` (overlay `@dismiss`) deliberately KEEPS it — so clicking
  OK on an overlay delivers the rejection *via the unload event*, not a direct call. execute's
  wrong-profile rejection rides this indirect route (D13/D14).
- **capabilities' reject() lacks the `!requestId` guard** execute/discover have — with no requestId
  it still closes + detaches (B9). Pinned from BOTH sides so a shell can't normalize it silently.
- **execute's connect(3)/disconnect(4) asymmetry is not dead code** — `executionService` opens its
  transport lazily on first fee-estimation request; the unmount disconnect tears down a
  possibly-opened transport. An eager connect would CHANGE when that transport opens.

## Oracle-first mechanics (the R1.0/Q-15 discipline, applied to UI)
25 pins written against CURRENT code (capabilities 12 + execute 13; discover had 12) — green
first-run, proving the spec matched reality. The extraction was then graded by the SAME suite
passing byte-unchanged post-extraction (37/37), + 12 direct shell unit tests. codex xhigh
(`019f1f8f`): SAFE TO LAND, zero behavior-changing findings; it independently grep-verified no
leftover window-local `removeEventListener("beforeunload", reject)` and the thunk TDZ-safety
(`EventHandler.add` stores, never sync-invokes).

## Shell shape: hooks stay in the window
`useDappApprovalWindow` returns `start`/`dispose` that each window calls from its OWN
`onMounted`/`onUnmounted` (the composable convention — no hooks inside the composable). Divergences
are injected thunks (`connectServices`/`disconnectServices` with per-window ORDER, `init`, `reject`)
— lazy closures solve the script-setup TDZ (the options object is built before `init`/`reject`/the
service consts initialize; the thunks only dereference at runtime). One deliberate change: the
listener is a shell-owned stable wrapper `() => options.reject()` — add/remove/closeWindow all pair
on one identity; behaviorally invisible (the oracle can't tell, and codex confirmed).

## Test-harness lessons
- **vi.mock factory TDZ**: a factory that references a const DIRECTLY (`AccountServiceClient:
  ctorMock`) runs at hoisted-import time → `vi.hoisted()` for those two; factories that only CLOSE
  OVER consts (`() => ({...})`) are safe (discover's established pattern).
- **`biome check --write` would break the suite**: `useArrowFunction`'s "safe" fix rewrites the
  `vi.fn(function () {...})` constructor mocks into arrows (Vitest 4 `new`-mock requirement) —
  format with `biome format --write` ONLY, never `check --write`, on these files.
- Window listener spies must CALL THROUGH (real registration) so tests can deliver a synthetic
  `beforeunload` to the live handler; and every test must unmount (afterEach) or listeners leak
  across tests through the shared jsdom window.

## CI lessons folded in en route
The paths-filter `shallow file has changed` race went structural mid-phase (dev-quality ~100
commits from dev → merge-base beyond fetch depth on EVERY dispatch; 5/8 gate runs died pre-test).
Root-caused + fixed as its own PR (#239, `fetch-depth: 0` on the three changes jobs) — detection-
only, self-proven because `workflow_dispatch --ref` runs the branch's own workflow files. The
R3a canary red (`transfers` real-proving 300s timeout) was the known proving-load flake — single
RED-policy re-run cleared it; R3b's full gate then passed first-pass.
