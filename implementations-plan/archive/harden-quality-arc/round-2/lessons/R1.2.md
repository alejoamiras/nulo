# Lessons — R1.2 (contact adoption) + R1.3a (fpc adoption)

R1.2 merged `4f8468f` (PR #231, FULL gate green). R1.3a in flight (#232). Both behavior-preserving migrations onto the R1.1 helpers.

## The adoption pattern (now proven across contact + fpc)
- **Ownership guards** `const row = await storage.get(id); if (row?.profileId !== profile.id) throw "…"` → `const row = requireOwnedRow(await storage.get(id), profile.id, "…")`. Contact uses `"invalid id"`; fpc uses the default `"Invalid id"` (matches its existing throw exactly).
- **Always-fresh id** `do { id = getRandomHex(8) } while (contains(id))` → `nextRandomId(storage)`.
- **Restore** `for row { try { keep-id-else-random; set; push } catch { push {...row, restoreError} } }` → `restoreRows(rows, async (row) => { keep-id-else-random; set; return written })`. `getRandomHex` STAYS (restore keeps-id-else-random inline; only the always-fresh create-loops move to `nextRandomId`).

## fpc wrinkle: a per-row early-`continue` becomes a `throw`
fpc.restore had a legacy-DefaultFpc branch: `result.push({...fpc, restoreError: "Token FPC deprecated…"}); continue`. Under `restoreRows` there's no `continue` — but a **`throw new Error("Token FPC deprecated…")` inside `writeOne` produces the identical `{...fpc, restoreError: "Token FPC deprecated…"}` row** (restoreRows funnels the throw through `toRestoreError`). Behavior-identical. Generalizable: any "push a restoreError + skip this row" becomes a `throw <message>` in `writeOne`.

## Stacking friction (avoid next time)
R1.2 was BUILT stacked on the unmerged R1.1 branch (to not idle on R1.1's CI), which left it missing R1.0's isolation test. Resolved by **cherry-picking the single migration commit onto a fresh branch off the updated `dev-quality`** (which had helpers + isolation test) once R1.1 merged — then it verified against BOTH suites. Cleaner alternative: just wait for the dependency to merge, then branch. Stacking only pays off when the follow-on is truly independent (different files); R1.2 shares the isolation test with R1.0/R1.3+, so it wasn't.

## Isolation-test-editing phases SERIALIZE
R1.3a/R1.3b/R1.4/R1.5 all append to `cross-profile-isolation.test.ts`, so they **cannot** run in parallel branches (they'd conflict on that file). Each must branch off the previous phase's merge. (Service *code* is independent across phases; the shared isolation test is the serialization point.)

## fpc has no unit tests
`fpc/service.ts` had zero unit coverage — the migration is verified by typecheck + the new fpc isolation assertion (getFpc foreign-reject) + the full network e2e (fee flows exercise fpc). Worth a follow-on: fpc deserves a real unit suite.

## Recurring commit-hook friction (internalized)
Three commit bounces this cluster: body line >100 (×2) + `subject-case` (a subject starting `Q-13`/capital). **Default now: write commit messages to a file with every line ≤100 and a lowercase-first description**, verify with `awk 'length>100'` before committing.
