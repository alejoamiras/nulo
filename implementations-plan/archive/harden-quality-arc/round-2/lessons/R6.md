# Lessons — R6 (Q-02 arg guards + the authorized oracle edit) · mega-deep, dApp trust boundary

Merged `1492665` (#244), full gate green first-pass. The ONE authorized frozen-oracle edit of the
arc — the diff is permanently surfaced in #244's PR body for owner review.

## Predicates beat parsers on a trust boundary
The plan said "arg schemas"; both audits' HIGH findings were about what a SCHEMA can do wrong
(coerce before enforcement → scope checkers see different values → fail-OPEN; strictness →
fail-CLOSED regressions). A `(args: readonly unknown[]) => boolean` predicate makes the whole trap
class STRUCTURAL nonsense: it cannot return values, so nothing downstream can consume a transformed
result; `readonly` bans mutation at the type level; and wallet-bridge gains no zod dependency. When
an audit enumerates ways a mechanism can misbehave, prefer a mechanism that cannot express them.

## Honest omission beats vacuous coverage
8 of 19 methods carry NO guard — deliberately: sendTx/simulateTx/profileTx/executeUtility's payload
validation is OWNED by their scope checkers with PINNED error strings (a guard would change the
observable error = break the frozen suite); the no-arg trio has nothing to validate; disabled
registerContractClass must keep ITS error. The oracle freezes the guarded/unguarded SPLIT itself,
so a future method can't silently skip the decision. "Every method has a guard" would have LOOKED
more complete and been behaviorally wrong five ways.

## The ADD-only protocol, mechanized
"ADD-only" was proven three ways, none of them trust-me: (1) `git diff` of the oracle has ZERO
deletion lines (checked mechanically, surfaced in the PR); (2) the new strip-and-rederive test
removes `argSchema` from every row and asserts all six derived authz maps are IDENTICAL — the field
is invisible to enforcement derivation, so no widening can route through it; (3) the pre-existing
parity/identity/exhaustiveness tests ran unmodified. The order pin matters too: the guard runs
BEFORE capability enforcement (mandated), so a NEW observable exists — garbage args on an ungranted
method now fail on args, not capability. Pinned explicitly, with the mirror pin that UNGUARDED
methods still fail on capability (proving no guard sneaks in front of them).

## Divergence from plan, surfaced not buried
Plan point 4 ("type the `args[N] as X` casts via the schemas") conflicts with points 5b/6
(tolerance-exact, no over-tightening): a precise TS tuple type would claim what the runtime
deliberately does not enforce. Behavior-preservation is the arc's prime rule, so the casts stay and
the divergence is flagged in the PR + plan for an owner ruling — the same pattern as the R5 decoder
deferral. When two mandate points collide, the resolution goes to the owner in writing.
