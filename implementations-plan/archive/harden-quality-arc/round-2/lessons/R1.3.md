# Lessons — R1.3 (fpc + network adoption)

R1.3a (fpc) merged `82eabc0` (#232, full gate green). R1.3b (network) in flight (#233). Both behavior-preserving.

## Grouped `replace_all` for repetitive guards (network — the big win)
Network had **11** near-identical by-id guards (`const X = await this.storage.get(Y)` + `if (X?.profileId !== profile.id) throw new Error("Invalid id")`). Rather than 11 fragile context-disambiguated edits, they collapse to **5 `replace_all` edits by exact-string group**:
- 3-tab `network`/`networkId` (×4), 3-tab `network`/`id` (×3), 2-tab `peek`/`networkId` (×2) → `replace_all` each (byte-identical occurrences migrate identically → safe).
- 2-tab `network`/`id` (getNetwork, ×1) + 2-tab `network`/`networkId` (getNodeStatus, ×1) → single edits (unique by indent).
The indent (2-tab top-level vs 3-tab in-try) + var name (`network`/`peek`) + key (`id`/`networkId`) are what make each group's string distinct, so `replace_all` never crosses groups. **Lesson: for a service with many identical guards, group by exact string + `replace_all`; don't hand-edit N sites.**

## The return-null guard is NOT `requireOwnedRow` (network)
`getActiveNetwork` guards with `if (network?.profileId !== profile.id) return null` — it returns null for a foreign/missing id, it doesn't throw. `requireOwnedRow` THROWS, so it can't replace a return-null guard. **KEPT as-is.** (Only the throw-guards migrate.) Always check the guard's failure mode before swapping in `requireOwnedRow`.

## `restore` doesn't always fit `restoreRows`
Two restores were LEFT hand-rolled, each for a real reason:
- **account** (blueprint): whole-batch throw on duplicate-address (not per-row).
- **network** (R1.3b): takes untrusted `unknown[]` (not `T[]`), tracks cross-row `(profileId,chainId)` collisions in a growing `existing` array, and schema-validates each row (`NetworkSchema.safeParse`) + coerces the failure spread against non-objects. `restoreRows<TIn extends object>` assumes clean object rows + no cross-row state → forcing network in adds more complexity than it removes. Left it. **`restoreRows` is for the COMMON per-row try/catch; a restore with untrusted input, cross-row state, or whole-batch semantics stays hand-rolled.**

## `_freshStored8` vs `_fresh8` (network) — only the storage one migrates
`_freshStored8` = `do getRandomHex while storage.contains` = exactly `nextRandomId` → migrated. `_fresh8` = `do getRandomHex while seen.has(id)` (an in-memory Set for endpoint ids, NOT storage) → `nextRandomId` (storage-based) does NOT apply → left. Match the collision SOURCE, not just the loop shape.

## Unit-test coverage differs per service
`fpc` has **no** unit test file — its migration is covered by typecheck + a new isolation assertion + the full network e2e (fee flows). `network` has a 52-test suite that fully gates its migration behavior-preservingly. Add the isolation assertion regardless (it's the standing gate); lean on the service's own suite where it exists.
