# Q-17 — route profile/service.ts lock blocks through `runExclusive`

**Status:** ✓ DONE. Squashed to `dev-quality` @ `feac2de` (PR #190). Gate: full network `28466715227` + smoke + quality green; 204 profile tests (incl. C1/C2/C3 race + zeroization-invariant).

## What shipped
All 19 inline `try { await this.lock.enter() … } finally { this.lock.leave() }` facade blocks routed through the existing `runExclusive` helper, across 4 transform patterns.

## Key technical lessons
- **NOT a mechanical wrap** (the plan called it "light-but-not-mechanical"). The 19 sites fell into 4 shapes:
  - **A (simple)** → `return this.runExclusive(async () => {…})` (body unchanged indent — `try {` at 2 tabs → `runExclusive` at 2 tabs).
  - **B (block + zeroize-after-leave)** → `try { return await this.runExclusive(fn) } finally { zeroize() }`. The zeroize MUST stay in an OUTER finally so the order is leave()→zeroize() on BOTH return and throw paths (preserved verbatim).
  - **C (phased: unlock×2, confirmProfileOperation)** → each locked phase its OWN `runExclusive`; the ~1s PBKDF2 / WebAuthn prompt stays UNLOCKED between phases. Never widen the lock over crypto.
  - **whole-body with INNER zeroize (changeProfilePassword, deleteProfile, finalizeRestore)** → wrap the whole body; the inner zeroize STAYS inside the callback (don't reclassify as B — that changes timing).
- **2 codex-flagged specials:**
  - `restore(password)`: keep the `restoreError` `catch` INSIDE the runExclusive callback so `toRestoreError` runs before `leave()` (it calls `String(err)` → could invoke a custom `toString`; byte-exact preservation). Catch-outside was caught by codex post-impl as a Medium.
  - `restore(passkey)`: wrap ONLY the locked storage tail — the WebAuthn prefix + early throws (missing credentialData, credentialId mismatch) must NOT reach `lock.leave()`. This **fixed a latent leave-without-enter** (the old single try/finally called `leave()` even when `enter()` was never reached — `Lock.leave()` blindly sets `locked=false`, so an early throw could release another op's lock — codex confirmed it was real lock corruption, not benign).
- **Reentrancy confirmed safe** (codex): no locked body calls another lock-acquiring facade method (`backup()`→`getActiveProfile()` not while locked; `import*`→private helpers after unlocked prep). The `Lock` is non-reentrant, so any nesting would already deadlock today.
- **Closure capture**: a `let` captured in the callback loses TS narrowing — used `recovery.secret` (non-undefined) instead of the outer `recoverySecret` (`| undefined`) for the pending-map set.
