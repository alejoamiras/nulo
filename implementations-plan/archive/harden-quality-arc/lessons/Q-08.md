**Shipped:** `dev-quality` @ `726638b` (PR #204). tier: mid.

## What

Three BYTE-IDENTICAL `nulo-schema-patch.ts` copies (extension / faucet / playground) — side-effect modules mutating `@aztec/aztec.js`'s `WalletSchema` singleton with 3 Nulo-custom RPC entries + a signature-drift guard — collapsed into ONE private package:
- `src/apply.ts` → `applyNuloSchemaPatch(schema: object)` — the pure patch body (parameterized on the schema object; unit-testable in isolation, which the singleton-mutating side-effect never was).
- `src/register.ts` → side-effect entry `applyNuloSchemaPatch(WalletSchema)`.
- exports `./apply` + `./register`, NO root barrel. Deps: `@aztec/aztec.js` + `@aztec/stdlib` + `zod` (all already in the tree → bun.lock additive-only, no min-age gate hit).

The 3 apps swap their first import to `import "@nulo/wallet-sdk-schema-patch/register"` (side-effect-first ordering preserved). 3 copies deleted. 5 `apply.test.ts` cases (adds-all-three, per-method drift throws, shape-compatible no-op).

## The load-bearing learning: adding a workspace package breaks the CI dep-graph guard

`scripts/ci-cd/behavior-gating.test.ts` (run by `test:ci-gating` inside the Quality gate) DERIVES each PR paths-filter from the `@nulo/*` dependency graph and asserts the live filters cover every transitive dep's `src/**` + `package.json`. Adding `@nulo/wallet-sdk-schema-patch` as a dep of extension + faucet (+ playground) put it in their transitive closure → the guard FAILED (Quality red) until I added `packages/wallet-sdk-schema-patch/{src/**,package.json}` to:
- `pr-smoke-e2e.yml` `smoke-surface`, `pr-network-e2e.yml` `extension-network`, `pr-quick.yml` `core-foundation` (the extension union) + `faucet`.

**Takeaway for any future new-package finding (Q-01/Q-02/Q-03 seams, Q-12/Q-13 registries):** a NEW `@nulo/*` package is NOT done at "typecheck + units green" — you MUST gate it in the paths-filters or `test:ci-gating` reds the Quality job. Run `bun test scripts/ci-cd/` locally BEFORE pushing a new-package PR. This did NOT surface in local `typecheck:all`/`test` — only `test:all` (`--filter '@nulo/*' test`, which CI runs) + `test:ci-gating` do. **CI's unit step ≠ the extension vitest** — it runs EACH package's own `test` script standalone via `--filter`.

Also: the test files that import the new package by BARE specifier (`dispatcher.test.ts`, `method-descriptors.test.ts`) needed it declared as a wallet-bridge **devDependency** (was resolving only via bun hoisting — an undeclared-dep smell).

## Gotcha (mechanics)

The new package's bare `vitest run` (no config) transformed its TS fine (workspace resolution), and the bare-specifier import resolved standalone too — but the failure was `test:ci-gating`, several steps AFTER all the vitest output, so read the WHOLE job log, not just the vitest tail.
