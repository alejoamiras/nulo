## The load-bearing learnings

### 1. Core primitives CASCADE; leaves don't
Typing a LEAF primitive (MaterialIcon, Tooltip, Input, Banner) → `typecheck:all = 0`, no fan-out. Typing a CORE primitive (Icon, Text, Flex) that OTHER design components forward props into → the consumers' forwarding sites become type errors until they're typed too. So Icon had to be typed TOGETHER with its consumers (Button base + ToastManager) in ONE PR (c4); a standalone Icon attempt produced 9 cascade errors. **Rule: type a core primitive + every design component that forwards into it in the SAME cluster.** `typecheck:all` IS the cascade inventory — run it, it names every coupled site.

### 2. `TextColorName`/layout types go in HAND-source files, NOT generated `tokens.ts`
`tokens.ts` is GENERATED from `token-contract.ts` (`bun run gen:tokens`) and pinned by `tokens.drift.test.ts`. New derived types must live in separate hand-files: `color-names.ts` (`TextColorName`), `layout-names.ts` (`FlexAlign|FlexJustify|FlexWrap|FlexDirection|FlexGap|TextAlign`), `severity.ts` (`SeverityTone`), each re-exported from `index.ts`. `ColorToken` (from tokens.ts) is the WRONG type for `color` props — it's CSS-var VALUES; components pass utility NAMES (`keyof textColors`).

### 3. Numeric tokens need the stringified form
Static Vue attrs are strings: `size="13"` is `"13"`, not `13`. So a numeric-token prop types as `FontSize | \`${FontSize}\`` (both the number, for dynamic `:size="13"` binds, and its string form). Same for FlexGap. Omitting `\`${T}\`` → mass false-positive errors at every static call site.

### 4. THE BIG ONE — `typecheck:all = 0` does NOT prove the whole contract; JS SFCs / JS wrappers are invisible to vue-tsc
vue-tsc only template-checks SFCs with `<script setup lang="ts">`. It does NOT check:
- **JS SFCs** (no `lang="ts"`) — e.g. AmountCard.vue. c5's `typecheck:all=0` reported "exactly 4 over-contract sites" but MISSED AmountCard's `align="baseline"` (a JS SFC). codex post-impl caught it. **To get the TRUE over-contract inventory, grep ALL SFCs (`grep -rn 'align="baseline"'`), don't trust typecheck alone.**
- **JS wrappers** — the 3 host-coupled extension wrappers (Button→RouterLink, SubPageHeader→router, ToastManager→toast-root) are intentionally JS (CLAUDE.md L2). vue-tsc doesn't strict-check their forwarding, so a JS wrapper does NOT cascade when you type the base (c4 confirmed) AND the package union does NOT police the wrapper-mediated extension call sites (c5 codex HIGH).
- **Consequence + accepted scope boundary:** the typed unions enforce at the package/base + all TS SFCs + faucet/playground (TS). They're ADVISORY (compile-only, inert) at the extension's JS-wrapper/JS-SFC call sites. Converting those wrappers to `lang="ts"` would close the gap but is BEYOND the Q-10 finding (which scopes the `@nulo/design` primitives) — deliberately not done (scope discipline). This is the SAME gap as Q-16.

### 5. Over-contract handling: dead no-ops → REMOVE (behavior-preserving), off-contract test values → `@ts-expect-error`
The only real over-contract call sites across 1167 usages were 3 dead no-op attrs (`align="baseline"` ×3, `gap="0"` ×1) — CONFIRMED no-op by grepping the CSS (`no items-baseline`/`no gap--0` class; `.flex` only sets `display:flex`). Removing them is render-identical (codex independently verified). The Text PIN test that INTENTIONALLY passes an off-scale `size="large"` (pinning runtime passthrough) kept its value via `// @ts-expect-error`.
