# Q-20 — config store → zod schema (replace reflective typeof validation)

**Status:** ✓ DONE. Squashed to `dev-quality` @ `14d7ecb` (PR #194). Gate: full network `28470949243` + smoke + quality; config+store 13 tests.

## What shipped
`ConfigStore.apply()` validated persisted props by `typeof src[key] === typeof dst[key]`, so an out-of-domain literal-union value (e.g. `theme:"bogus"`) loaded as valid. Replaced with a zod `ConfigSchema` as the single source: `Config = z.infer`, `defaultConfig()` replaces the `Config` class at all 14 sites, per-key tolerant `apply()`, validating `set()`.

## Key lessons
- **`.default()` schemas + `safeParse(undefined)` = the trap** (codex High). A `ZodDefault.safeParse(undefined)` SUCCEEDS with the default — so a naive `set(key, undefined)`/`apply(undefined-prop)` would reset-to-default rather than reject/keep. Fix: explicit `undefined` guard (set throws; apply skips/keeps-current), matching the prior typeof behavior. (Alternative was raw no-default field schemas; the guard is simpler + version-safe.)
- **Per-key tolerant apply, NOT whole-object** (codex): `partial().safeParse(stored)` fails the whole object on one bad key — instead iterate keys + `ConfigSchema.shape[key].safeParse`, ignore missing/extra, emit on pass+differ.
- **A latent bug fixed:** the typeof check WRONGLY rejected a persisted `defaultExplorer: null` (`typeof null !== "string"` vs default `"aztecscan"`); zod `.nullable()` accepts it (valid domain). Pinned with a store test.
- **FROZEN security default preserved** — `strictSecurityMode: z.boolean().default(true)`; a corrupted stored string (`"false"`) is rejected (kept true); only a real boolean `false` (intentional Settings opt-out) flips it. Pinned both at schema + store level.
- **Single-source the enum** (codex Low) — `defaultExplorer` derives from a `BLOCK_EXPLORER_IDS` const (also the `BlockExplorerType` source) → no schema/type drift.
- **Class → schema is an API break** (no-backwards-compat OK): the `Config` class is gone; `new Config()` callers → `defaultConfig()` (settings files alias the import to keep their local `defaultConfig` name).
- **No coercion** — `sessionTtl: 0` must stay valid (no `.positive()/.int()/.min()`).
- **Store unit-testable** via a per-test in-memory `chrome.storage.local` (the shared vitest stub is non-functional `storage: {}`); install `.local` before `new ConfigStore()` (it captures the area at construction).
