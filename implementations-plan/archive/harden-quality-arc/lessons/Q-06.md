# Lessons — Q-06 (branded secret/wire types) · P14a

P14a = the branded-type layer (Passhash, MasterSecretBytes, + the WebAuthn ceremony trio Base64CredentialId/Base64SecretPrf/HexUserHandle). Base64Ciphertext defined-but-deferred; Base64MasterSecret + the restore split are P14b. Commits: `e330e29`, `e0a87ca`, `70f3c2a`, then codex-fix `f99af9a`, then regression-fix `5743d6e`.

## Critical — `biome check --write` silently breaks vitest constructable mocks
Running `biome check --write` to format touched files applied `lint/complexity/useArrowFunction` (a **warning**-level, "safe"-classified fix) and converted every `SomethingServiceClient: vi.fn(function () { return x })` mock in `useFullBackupImport.test.ts` to `vi.fn(() => x)`. Arrow functions are **not constructable**, so `new ProfileServiceClient()` throws `() => ... is not a constructor` — the exact failure the comment two lines above the mocks warns about. **13 tests regressed, and it passed my local checks** (see next lesson) so it only surfaced in CI Quality.
- **Rule: never `biome check --write` a file containing `vi.fn(function(){})` constructable mocks.** The repo's normal path is safe because the pre-commit hook is `biome check --staged` (NO `--write`) and CI `bun run lint` is `biome check` (no write) — neither auto-fixes, and `useArrowFunction` is warning-level so it never fails the gate. The hazard is *only* a manual `--write`.
- If you must format, run `biome check` (no write), eyeball the diff, and hand-apply formatting — or exclude the mock file.
- The `function` form is CI-safe: dev-quality ships it, biome check exits 0 with 11 warnings.

## Local validation must run the FULL package suite, not a hand-picked subset
I validated with `bunx vitest run <file1> <dir> <file2> ...` — a curated multi-file invocation — and got green (159/159), because cross-file module-mock state hid the per-file breakage. The same file **fails in isolation and in the full suite**. CI runs `test:all` = each package's whole suite standalone.
- **Rule: before pushing, run the touched package's whole `test` (`bun run --filter '@nulo/extension' test`), not a subset.** The subset is fine for the fast inner loop; the full suite is the pre-push gate. (Matches the user's "local validation gate before pushing" rule — apply it at package granularity.)

## codex post-impl caught the real gap: terminal sinks
codex (SHIP-WITH-FIXES) flagged that `MasterSecretBytes` protected the *producers* (unseal/derive/import) but not the terminal *sinks* — `SessionManager.open(secretBuffer)`, `SessionSecretUnsealer` return, `pendingRestoreSecrets` map, `importPasskeyProfile.secret` still took bare `Uint8Array<ArrayBuffer>`. Branding a producer without its sink leaves a future wrong-byte caller compiling. Closing the sinks added **zero** production mints (all 9 `open()` callers already pass unseal/derive/recovery results) — a clean signal the brand was well-placed. Lesson: **brand the sink too, or the guarantee has a hole at the most dangerous point.**

## Frozen-oracle-preserving design: widen the terminal param, not the oracle
Branding `PasskeyCredentialData` would have forced the frozen `key-vectors.test.ts` oracle (which calls `PasskeyCredential.create({id, prf})` with plain strings) to change — a hard-limit violation. Fix: make `create`'s param structurally **unbranded** (`{ id; prf; userHandle? }`) and mint onto the branded instance fields. The `id`↔`prf` swap is still caught upstream at the ceremony mint + the branded shuttle (every production path flows through `PasskeyCredentialData`); `create` is the terminal sink. **When branding would touch a frozen oracle, unbrand the terminal param rather than the oracle** — protection lives upstream.

## Scope: don't brand a value with no cross-boundary slot
`Salt` was in the finding's list but is a private local in both `EncryptionKey` and `PasskeyCredential` — it never crosses a function boundary, so a brand guards zero call sites. The finding's own cited "salt" instances were actually passhash/hex sites. **A brand only earns its keep where two same-typed values can be swapped across a boundary.** `Base64Ciphertext` deferred to P14b for the same reason: it only distinguishes from a *plain* secret once `Base64MasterSecret` exists.

# P14b — the restore-payload split (RestoreSecret union)

Merged `eda2607` (PR #210). codex post-impl: **SHIP** (clean; one LOW coverage note effectively already covered by `useFullBackupImport.test.ts`, which parses a real v2 backup → master-key → union → restore).

## Switch on the discriminant you narrowed, not its twin
`restore(profile, secret: RestoreSecret, …)`: the guard `if (secret.type !== profile.type) throw` proves they match at RUNTIME but does NOT narrow `secret` for TS. Switching on `profile.type` leaves `secret` un-narrowed (no `secret.masterKey`). **Switch on `secret.type`** (that narrows the union) and rely on the guard for the profile-match invariant. Each branch still hard-codes the `Profile.type` literal, so no wrong-type profile can be built.

## The new guard must fail CLOSED
The `secret.type !== profile.type` check runs BEFORE `runExclusive`/any decode and THROWS (not `{restoreError}`) — a cross-type secret writes no profile, opens no session. This is the one new protection the split adds over the old polymorphic slot; pin it with a `.rejects.toThrow` test. When you replace a permissive shape with a stricter one at a trust boundary, add the fail-closed test as the proof.

## Persisted-shape discipline held
`full.vue` still writes `"master-key"`, the session shape is untouched, the union is built at the import boundary from the existing field (codex confirmed `git diff -- full.vue` empty). A pre-change backup still restores. Rule: brand/type the TRANSIENT payload, never the persisted bytes (that's the Q-01 storage-codec phase).

## Infra / tooling (bit me this arc)
- **Don't background a codex call tangled with other commands.** `run-codex.sh … & ; git push ; wait` inside one `run_in_background:true` Bash meant codex never launched (0 output, no process). Fire codex STANDALONE in its own background Bash; push separately. Re-firing clean worked.
- **`gh pr merge --delete-branch` leaves local behind when SSH is down.** The GitHub squash succeeds, but the post-merge local checkout/prune uses the SSH remote and fails silently → local `dev-quality` stays pre-merge and the tree *looks* reverted (it's stale). Recover: `git pull --ff-only <https-url> dev-quality`. Verify the REMOTE merge commit has your content (`git show FETCH_HEAD:<file>`) before believing a local "revert".
- **`Explore`/`Plan` subagents can glitch** — one returned a system-prompt-shaped garbage blob, 0 tool_uses. Treat any subagent result that doesn't match the requested shape as a failure; redo inline or retry, never fold garbage into a plan.
