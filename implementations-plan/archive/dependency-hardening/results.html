Dependency hardening — what landed

Plain-English results of the dep-hardening + supply-chain work, including what shipped, what we couldn't safely bump, and the surprises we hit along the way.

PR #95 11 commits pushed 2 audit rounds (Opus 4.7 + Codex)

The 30-second result

We hardened the dependency surface in three real ways: added a 3-day supply-chain age gate (blocks recently-published npm versions, the axios/chalk attack pattern), pinned Bun and removed two curl|bash CI vectors, and brought 7 majors and a patch sweep current (TypeScript, jsdom, focus-trap, several plugins). We had to drop 5 planned bumps because each one revealed a real cost: vitest needs test rewrites, vite is coupled to vitest, zod 4 needs a schema rewrite, puppeteer 25 hit a Bun resolver quirk, and migrating the lockfile to text format hit a Bun bug.

The biggest surprise: we wanted a 14-day age gate but Bun 1.3.1's gate also blocks installs of versions already locked in your lockfile, so a 14-day window would have made CI fail for any patch newer than 14 days. Settled at 7 days — the widest setting that passes against the current lockfile (puppeteer 24.43.1 is ~6.6 days old and just squeaks through).

What we added (new things)

bunfig.toml — supply-chain age gate

New

minimumReleaseAge = 604800 (7 days). Bun refuses to install any npm version published less than 7 days ago.

Defends against the axios (March 2026) and chalk/debug (Sept 2025) attack pattern — both compromises were detected and pulled within hours, but anyone whose CI pulled during the window got breached. 7 days gives strong margin (we'd ideally use 14 — see "Bun surprise" section below for why we couldn't).

bun audit advisory CI step

New

Every PR runs bun audit and surfaces npm advisories in the GitHub step summary + uploads JSON as an artifact.

Free signal. Bun 1.3.x always exits 0 so we can't gate on findings yet — that promotion is a follow-up once we tune the severity threshold.

SECURITY.md "Dependency policy" section

New

CVE-on-Friday runbook (how to apply a fix that's newer than the gate window), Bun pin rationale, why the lockfile stays binary for now.

If a critical advisory drops, the on-call has a documented procedure instead of reinventing it.

CLAUDE.md "Dependency policy" subsection

New

Brief pointer to SECURITY.md with the Bun pin + age gate facts in the operator-rules file.

What we tried but couldn't ship

Migrate bun.lockb → bun.lock (text format)

Dropped

Real Bun 1.3.1 bug. The text-lockfile format works for bun install but breaks bun ci (frozen-lockfile install): vite ends up installed as 3 separate physical copies (peer-resolution duplication), and vue-tsc errors with "two unrelated Plugin types."

Re-evaluate after Bun 1.3.13 is in CI and the upstream issue is confirmed. We stay on the binary lockfile for now (review-unfriendly but functional).

vitest 3 → 4 (+ vite 7 → 8, coupled)

Dropped

Vitest 4 changed how vi.fn(() => mock) works — arrow functions are no longer usable as constructor mocks. Three test files need their mock pattern updated. Vite 8 is coupled because vitest 3 requires vite ≤7.

Not a clean version bump — needs real test-code changes. Better as a dedicated PR with focused review.

zod 3 → 4

Dropped

55 type errors across 7 schema files (PXE schemas, messaging helpers, content-script validators, RPC type guards). Zod 4 changed ZodType<X, Y, Z> signature, error-issue path types, and the internal type marker.

A real schema-layer rewrite. Wire-format mistakes here can silently corrupt dApp RPC. Deserves its own PR with extra review attention.

puppeteer 24 → 25

Dropped

Bun 1.3.1 has a resolver quirk on puppeteer's 25.x line: the newest (25.0.2) is within the 3-day gate window, and the older patches (25.0.0 / 25.0.1) hit a separate "No version matching... but package exists" error in Bun.

Wait for the older 25.x patches to be resolvable, or until 25.0.2 ages past the gate.

The Bun surprise (worth knowing)

You asked for a 14-day age gate. Bun's documentation says the gate "only affects new package resolution — existing packages in bun.lock remain unchanged." Reasonable.

Bun 1.3.1's actual behavior contradicts the docs. Setting the gate to 14 days and running bun install --frozen-lockfile against the unchanged manifest fails with:

error: No version matching "puppeteer" found for specifier "^24.43.0" (blocked by minimum-release-age: 1209600 seconds)

puppeteer 24.43.1 is already pinned in the lockfile. The gate gates frozen-lockfile installs of already-pinned versions. So a 14-day window would break CI for any patch newer than 14 days — and most of our deps have patches younger than that.

The widest setting that passes today is 7 days — puppeteer 24.43.1 (~6.6 days old) squeaks through; the rest of the lockfile is well-aged. We'll revisit and widen to 14 once Bun fixes the frozen-lockfile gate semantics or our lockfile naturally ages past 14d. The bunfig.toml comment cites both Bun's docs and the empirical repro so the next person reading it understands the conflict.

When Bun 1.3.13 lands in CI we'll re-test 14 days; if upstream fixed the bug we widen the window back.
