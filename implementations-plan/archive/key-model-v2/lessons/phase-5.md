# Phase 5 lessons — Export / Import Account

- **Layering worked out cleanly:** `NuloAccount.fromSigningKey` + the account-export ENVELOPE live in aztec-runtime (they need the frozen digests AND can import wallet-crypto's `EncryptionKey`); the imported-key BOX (HKDF(master)-per-row AES-GCM) lives in wallet-crypto; the service orchestrates. `GrumpkinScalar = Fq`, and `Fq.fromString` throws on `≥ modulus` — so canonical-scalar validation is free.
- **`self.crypto` → `globalThis.crypto` in `EncryptionKey`:** the encrypted-export KAT runs in aztec-runtime's NODE env, where `self` is undefined. `globalThis.crypto` works in SW, jsdom, and node alike (the same fix `mnemonic-master.ts` already used). One-line portability change, no behavior change (all key vectors still green).
- **Address confirmation needs a preview RPC:** the recompute needs bb (SW-only), so the import flow is `previewImportAccount(file, pw)` → SW returns the recomputed address → UI shows it → user confirms → `importAccount(file, confirmedAddress, pw)` re-validates `recomputed === confirmed`. The plaintext checksum authenticates nothing (owner A4 / final-codex High-4) — the user-confirmed address is the real gate.
- **Fail-closed = single-account quarantine (A4):** the Imported branch of `getAccountContract` throws `ImportedAccountUnusableError` (missing key / decrypt fail / non-canonical scalar / address mismatch) — NOT `raiseRuntimeMismatch`. External key material must not profile-wide-block the derived accounts; delete + re-import is the repair.
- **Imported-key ciphertext is `(master, chainId, address)`-bound, NOT profileId** (final-codex High-2): full-backup restore remaps profile ids, so a profileId-bound envelope would strand every imported key. The master travels with the backup, so the ciphertext stays valid across the remap — pinned by the "restore into a DIFFERENT profile id" unit test.
- **Backup slice = dedicated owner** (`imported-account-keys`, `optional: true`) with explicit restore ordering: account rows → key rows → **reconcile** (drop keyless type-1 zombies) → finalize/activation. The slice's client is a thin adapter over `AccountServiceClient` routing `.backup()` → `backupImportedKeys()`.
- **jsdom vs bb:** the service-orchestration test mocks `NuloAccount` (bb) but keeps the REAL envelope + imported-key box, pinning auth / address-confirm / dedupe / quarantine / purge / backup-round-trip. The envelope + fromSigningKey KATs run node-env in aztec-runtime.
