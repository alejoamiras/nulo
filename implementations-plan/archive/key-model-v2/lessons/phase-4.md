# Phase 4 lessons — product cuts + copy + e2e surgery

- **Service cuts already landed in P3** (they were structurally forced by required-entropy), so P4 was: (a) delete `export/key.vue` + the plain/encrypted UI branches + flow refs, (b) rename all user-facing "seed phrase"/"secret key" copy → "recovery phrase", (c) the e2e surgery.
- **Copy sweep:** `perl`-based rename across 8 SFCs; dropped "or secret key" everywhere (that export is gone). One component test (`AccountIntegrityBarrier.test.ts`) asserted the old copy — updated. Generic `SecretExportLayout`/`SecretRevealCard` tests use "Plain Key"/"Secret Key" as arbitrary label PROPS (the components stay generic) — left as-is.
- **E2E surgery (the bulk):**
  - `import-drivers.ts`: deleted `importPlainKey`/`importEncryptedKey`/`makeEncryptedKeyBlob`; added `makeRecoveryTriple()` (entropy→words→master) and `LOCAL_L1_CHAIN_ID`; `deriveNuloAccountAddress` → v2 (`deriveAccountSeed`, l1ChainId param); `buildSyntheticBackup` → epoch 4 + `entropy` field + `l1ChainId` on network+account rows (+ optional `l1ChainId` param for the custom-chain dead-rpc case).
  - `setupPreFundedAccount` (aztec.ts) rebuilt on the recovery-phrase path (returns `words`); the `feeJuiceImported` fixture (extension.ts) imports via the seed UI, not plain-key.
  - `revealSecretKey` helper deleted; the frozen-account canary now captures the recovery phrase and derives the master via `deriveMasterFromMnemonic`.
  - Per-test cuts: security-backup (2 secret-key tests), onboarding-import (plain+encrypted legs), import-paths (plain+encrypted legs + round-trips → one recovery-phrase round-trip), profile-reimport-matrix (importPlainKey→importSeed), passkey-backup (epoch 3→4 + l1ChainId), backup-migration + import-dead-rpc (→ makeRecoveryTriple), parity script formula → v2.
- **E2E is NOT typechecked** by any tsconfig (only esbuild-transformed at run time), so these edits are validated only by the actual smoke (`test:e2e`) + network (`e2e:agent`) gates — which need the browser + Aztec sandbox.
- **Gate GREEN (smoke + audit:vue):** `bun run audit:vue` exit 0. `bun run test:e2e` — 80 pass; the migration-fixture tests (backup-migration, 3/3) pass with the CI-matching armed build (`VITE_NULO_E2E_MIGRATION_FIXTURE=1` + `NULO_E2E_MIGRATION_FIXTURE=1`); the lone plain-run failure is the test's own anti-silent-skip guard for an UNarmed build, firing correctly.
- **Two real smoke regressions found + fixed (commit 9de0e34b):**
  1. `getMnemonic`/`getEntropy` (wallet-core/mnemonic.ts) + `getRandomHex` (random.ts) used `self.crypto`, undefined in the NODE e2e-driver context where the new `makeRecoveryTriple` helper calls them → `self is not defined`. Switched to `globalThis.crypto` (works in SW, jsdom, AND node — same fix already applied to EncryptionKey + used in mnemonic-master). Broke import-paths / backup-migration / import-dead-rpc (all makeRecoveryTriple callers).
  2. The passkey full-backup fixture hardcoded `kind: "local"` while the account lived on the default (non-local) network, so the epoch-4 Account↔Network l1ChainId cross-check (now validated against the seeded constant per kind) rejected it. Fix: read the account's REAL network row (kind + l1ChainId) from storage and stamp the synthetic backup with it.
- Lesson: the node e2e DRIVER context is a third runtime (after SW + jsdom) where `self` is undefined — any wallet code an e2e HELPER calls must use `globalThis.crypto`.
