## Collision / dedup risks

1. Network removal is asymmetric to FPC removal (mandatory stage vs optional loop) — the reseed is new control flow, budgeted as its own phase.
2. Old backups with `network`/`fpc` keys are rejected as "unknown backup slice" with no soft landing — acceptable pre-production; documented in the backup README and pinned by a test.
3. `full.test.ts` mocks (`:27-38,150-162`) hardcode `networkClient`/`fpcClient` — prune with the arrays.
4. `NetworkService.backup/restore` and `FpcService.backup/restore` (`network/service.ts:850-901`, `fpc/service.ts:487-535`) become unreachable from the UI but stay RPC surface — decision recorded in plan.md (codex ask).
5. RP ID is disjoint from the slice work — lands as its own phase/commit.
