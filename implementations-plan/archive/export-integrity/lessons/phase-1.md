# Phase 1 lessons — assembly extraction + page hardening

- **Vitest's auto-import surface is NARROWER than the build's.** `apps/extension/vitest.config.ts` wires `unplugin-auto-import` with `imports: ["vue", "vue-router"]` only — the dir-scanned symbols (composables/stores/`TOAST_DURATION`) are NOT injected under test. Pages were never component-tested before, so this had no victims until now. Resolution: explicit `import { TOAST_DURATION } from "@/composables/toast.js"` in `full.vue` (the module already re-exports it; build unaffected). Durable rule: any SFC that gains a component test must explicitly import every dir-scanned auto-import it uses.
- **The global chrome stub is minimal by design** (`tests/vitest.setup.ts` stubs `storage: {}`); mounting a page that instantiates the real app store needs `chrome.storage.local` + `chrome.storage.onChanged` fleshed out. Done in the test file's own `beforeEach` (runs after the setup file's) rather than widening the global stub for everyone.
- **One flushPromises does not drain a 12-await chain crossing real WebCrypto** — `subtle.digest` hops a macrotask, so assertions after assembly must `vi.waitFor` on UI state (the `protect-password-btn` appearance), not flush-and-hope. Same discipline the smoke spec already uses with its polls.
- **Shared constructor mocks conflate instances**: the import-level `AccountServiceClient` mock returns ONE object for the account slice AND the imported-keys adapter, so teardown assertions see 2 disconnects on it (production has distinct instances). Assert per-mock expected counts, don't assume 1.
- **Mid-flight UI re-find is itself an assertion**: after the synchronous status flip, `unlock-submit-btn` legitimately unrenders — "cannot re-click" IS the guard working; the test treats absence as pass and uses document-level Enter as the DOM-independent vector.
- Codex consults this phase: none beyond the plan-stage rounds (all implementation questions were pre-decided by the audited plan).
