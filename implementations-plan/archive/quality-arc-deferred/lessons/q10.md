## Reconciled decision (ledger)
- **Seam:** runtime-owned port injection (`browserApi.storage.local` to services; keep key literals in the owning module — keys stay byte-identical). NO factory wrapper.
- **PXE:** inject `PxeClientFactory = () => new PxeServiceClient(logger)` from runtime; each service calls it once in `init` where it currently does `new PxeServiceClient`. Thread through to `BalanceProjector` (token-balance) — the trickiest.
- **Fallback:** test-only → new migrations inject the port (no new fallback branches); delete the already-migrated dead branches OPPORTUNISTICALLY in-PR (codex), not a standalone phase.
- **Guardrail (codex):** per phase, a CI/local grep over touched paths forbidding `chrome.storage.local`/`chrome.storage.session`/`new PxeServiceClient(`; + a runtime-boot-with-FakeBrowserApi smoke; + assert raw persisted keys for ≥1 touched service.
- **Sequencing (storage-first, ~6 phases, ~2-3 services/PR, each network-gated):**
  - **P1:** account · dapp-session · transaction (simple single-store) + the runtime FakeBrowserApi smoke guardrail.
  - **P2:** auth-registry · token-balance(BalanceRepository) · incoming-transfer(repository) (hidden/multi-table seams).
  - **P3:** token · fpc · network (network ALSO has raw `chrome.storage.local` active-key get/set/remove at service.ts:~768 — must route those too, not just EntityStorage). Network = riskiest storage phase, isolate.
  - **P4 (PXE):** account-state · note · execution (PXE-only).
  - **P5 (PXE):** token · fpc · transaction · network.
  - **P6 (PXE):** token-balance (BalanceProjector threading) + ProfileService browserApi (runtime.ts:136 omission). Last (most exposed).
- **Scope verdict:** do the storage arc (P1-P3) — the high-value, data-at-rest slice — first; then the PXE arc (P4-P6) to complete the finding. Reassess PXE phase complexity at the P3→P4 boundary; if the BalanceProjector/Execution threading is hairier than expected, surface a scope note.
- **Biggest risk:** an "almost-complete" PR leaving one raw `chrome.storage.local` or nested `new PxeServiceClient` behind (NetworkService, BalanceRepository, IncomingTransferRepository are the traps). The per-phase grep gate is the backstop.
