## Key learnings (marathon-wide)
- **vitest AutoImport ≠ production AutoImport.** `vitest.config.ts` registers ONLY the `["vue","vue-router"]` presets (not the `src/composables`/`src/stores`/`src/components` dirs). So a component that uses a LOCAL composable must **explicitly import** it or it's `ReferenceError: X is not defined` at mount in unit tests (production auto-injects it; unplugin skips the explicit import as already-resolved). Auto-import works in tests only for vue/vue-router.
- **Don't commit generated-d.ts drift.** Building to regen `auto-imports.d.ts` also pulls in unrelated pre-existing drift (`toRestoreError`, components). Since the consumers explicitly import the composable, the d.ts global isn't needed → reverted the 3 generated `src/types/*` files to keep the commit pure (they regen at build).
