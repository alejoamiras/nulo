## I1, I2, I4 — what this environment could and could not check

- **I1 (Chrome closes an action popup on Escape unless the keydown is `preventDefault`ed) — not checked here.** This box has no Chrome with an action-popup context (no DevTools MCP, no display). `Popup.vue`'s `escapeDeactivates` hook does `preventDefault` and returns `false`, so the sheet closes on Escape and the event never reaches the browser; if Chrome closes the action popup regardless, the user sees today's behaviour (the popup closes), not a broken one. **Owner check on a real Chrome**: open the sheet in the action popup, press Escape; if the whole popup closes, A6's stated outcome applies (drop `closeOnEscape` from the sheet). Either outcome is safe to ship behind; neither changes phases 4–6.
- **I2 (a page-rendered `Popup` stacks and transitions like a registry one) and I4 (the 38px taller sticky footer leaves the form usable at 600px) — carried to phase 5**, where the smoke e2e drives the built popup and the both-theme screenshots are taken. Reaching the Send page in the built extension needs an onboarded profile, which is exactly the phase 5 fixture (`tests/e2e/fixtures/send-page.ts`); building it early to eyeball two assumptions would pull phase 5 forward for no gain. The stop conditions stand unchanged: an I2 failure means the registry-mounted sheet and a plan revision, an I4 failure goes to the owner as a measurement.
- **I5 confirmed**: `send.vue` mounts under jsdom with the real `FeeSettingsCard`, the real `FeeMethodSelector` and the real balances store. Stubbed: the card's read-only rows (`FeeMethodRow`, `FeeCostReadout`, `FeePriorityRow`) and the dropdown *menu chrome* (`DropdownRoot` — the real `DropdownItem`s render inline, so `send-fee-method-*` and their disabled semantics are the product's). Every service client is mocked at the class, the way `FeeSettingsCard.test.ts` does it; nothing on the card → settings → page seam is faked.

## Deviations from plan.md

- **`canSubmitNow()` split out of `submit()`**: the fiat gate's wall-clock re-evaluation and the allowed/sending checks are one predicate, so `submit()` reads as its three decisions (may it send, is the source the open one, does it need consent) and stays far under the line budget.
- **The strip reads "—" under the get-gas takeover** (`none`: every payer read, none can pay): the payer is null, so `you` is `unknown`, and the footer shows "Get private gas" instead of the button. Not a plan line either way — A5's "—" for an unfinished form is the nearest rule and this follows it. Flagged for the owner's screenshot review in phase 5, since hiding the strip under the takeover would be a UI decision.
- **T14's "fee pick intact" half lives in the integration test** (the stubbed-card page test cannot hold a pick): a hand-picked Fee Juice survives the sheet's close, with amount, recipient, sides and the gated action.
- **T12's degraded → recovery case drives the store's real retry** (`INIT_RETRY_BACKOFF_MS[0]` under fake timers), and the "network switch with a delayed response" case holds the second gas read open with a deferred, so the old scope's HIDDEN is shown to be withdrawn before the new scope commits — both are the paths production has (D18); no balance *event* is pretended to flip the payer.

## Harness notes

- **Stub the dropdown root by its file name.** `FeeMethodSelector` imports `Dropdown` from the barrel, but the SFC's `__name` is `DropdownRoot`; a `Dropdown:` stub key never matches. The stub renders both named slots inline so the items exist without opening anything.
- **One `EventHandler` pair for every `FpcServiceClient` instance** (`await vi.hoisted(async () => …)`): the balances store and the card each construct a client, so a test fires `fpcEvents.onFpcDeleted.invoke(row)` and whoever subscribed hears it, with no reaching into `mock.results` for the right instance.
- **`flushPromises()` keeps working under `vi.useFakeTimers()`** — test-utils captured the real `setImmediate` at import — so a page can be mounted with fake timers already installed and the store's backoff advanced by hand afterwards. The card suite's `advanceTimersByTimeAsync(0)` idiom is equivalent.
- **`ElementWrapper.element` is typed `Element`**: a native `.click()` (the same-tick double activation, which `trigger` cannot deliver) needs the `HTMLButtonElement` cast; `vue-tsc` fails it, vitest does not.
- **The `defineModel("payer", { default: null })` never emits for its default**: a card whose first resolution is `null` has no `update:payer` event at all — the parent's value is still `null`. Tests read "no event" as `null`, and assert an *explicit* `null` only after a non-null value (an identity switch).
