# Scoped bug hunt — findings + disposition

Dual-family adversarial bug hunt on the backup-import feature diff (~1,540 LOC): 3 fresh-context Claude agents with distinct lenses (trust-boundary / rollback-state / test-vs-reality) + a fresh codex session. No trust-boundary bypass found (checksum, version-gate, scratch-key injection, root misattribution, prototype pollution, secret-swap all held). Findings below; convergence noted where ≥2 reporters agreed.

## FIXED (in-scope — our code / our feature's guarantee) — commit `a4e312a`

## FLAGGED — pre-existing, out of feature scope, need an owner decision
These live in restore/remap logic the plan **deliberately kept byte-identical**, or in services our feature only calls. All pre-date this branch (present on `dev`). Recommend folding into the **Q-01 backup-seam follow-up** plan (the one #220 already owner-gated) rather than expanding this branch.

| # | Sev | Finding | Reporters | Why deferred |
|---|---|---|---|---|
| P1 | high | **Rollback `deleteProfile` wipes OTHER profiles' tx history.** `TransactionService.clearChainState` filters by `chainId` alone (tx rows carry no `profileId`; its own comment admits it). Any post-network rollback (e.g. re-importing your own backup → duplicate-address) purges every profile's txs on that chain. Trigger: P1 has tx history on chain X; import a backup with a network on X + an existing account → duplicate-address rollback → P1's tx history on X erased. | Lens B | Root cause in `TransactionService` (pre-#220). Real fix needs `profileId` on tx rows — **which itself requires a migration** (the thing this feature enables) — or removing `clearChainState` from the profile-deletion cascade. A genuine design decision. |
| P2 | high | **`remapIdInBackupData("networkId", …)` rewrites EVERY row's `networkId` to ONE new id**, ignoring the old value. On any network-id collision (a crafted plain backup with duplicate in-backup ids triggers it deterministically), account-state/FPC/auth rows for network N1 get grafted onto N2. | codex, Lens B (merge-review flagged it low; now high w/ trigger) | `full-backup-helpers.ts` + call site; plan kept remap byte-identical. Fix: remap old→new **pairs** (helper takes `oldId`). |
| P3 | high | **token-balance remap collapses same-contract tokens across networks.** `contractToNewId` is keyed by `contract` only, so balances for `{contract:"0xT", chainId:1}` and `{contract:"0xT", chainId:2}` both rewrite to the last-restored token id. | codex | Same byte-identical remap block. Fix: key by `(chainId, contract)`. |
| P4 | medium | **Rollback reported complete while the cascade is still running.** `deleteProfile` emits `onProfileDeleted` with **un-awaited** async listeners (floating promises), so `await deleteProfile` resolves before networks/accounts/PXE are purged; a retry reuses the same profile id (or the deterministic passkey userHandle) and races the still-running purge → "finished" import with silently missing rows. | Lens B | Root cause in `EventHandler.invoke` / `ProfileService` (pre-existing). |
| P5 | medium | **Popup death mid-import leaves a permanent half-imported profile.** All rollback bookkeeping (`createdProfileId`/`finalizeStarted`) lives in the ephemeral popup; closing it between `restore` and `finalizeRestore` (a window that includes slow PXE account-state registrations) orphans a never-finalized profile with no SW-side detection/cleanup. | Lens B | Architectural — restore orchestration has always lived in the popup. Needs an SW-side in-progress flag + boot-time sweep. |
| P6 | medium | **Unit fixtures diverge from the real service shapes** (old-shape network rows the real `NetworkService.restore` rejects with `BACKUP_TOO_OLD`; account/contact rows missing schema-required fields). The mocked happy paths are unreachable with that data in prod; some tests bless output the codec would hide. | Lens C | Test-quality; overlaps E. Fixture rows should be schema-sourced. Worth doing but not a shipping bug. |
| P7 | low | `completeImport` result never awaited (a rejected SW handshake hangs "Finishing import…" forever; a sync throw clobbers a successful import into "failed"); per-client `disconnect()` leaks on throw paths. | Lens B | Pre-existing, popup-lifetime-bounded. |

## Attacks that FAILED (coverage — the trust boundary held)
Checksum↔consumed-body match (rest-spread + key-order stable); `backup-schema-version` missing/fractional/`<1`/`>max` all reject; no scratch `nulo:schema:*` injection through registered slices; root-prefix misattribution impossible (all `${root}@` diverge before `@`); `numberAnchor` `String()` round-trips `-0`/`1e21`/`>2^53`; imperative + block-listed migrations blocked by preflight; accessor / array-@@species / `__proto__` / proxy / symbol / non-finite DSL smuggling all covered by the canonicalizer (valueMaps included); passkey↔password secret swap rejected by `ProfileService.restore`'s type-mismatch + 32-byte gates; `master-key` never enters migrator / scratch / errors / logs; migrate-before-restore atomicity (zero live writes on a failed/incompatible migration); the pre-finalize-delete vs finalize-keep rollback split is correct and can't double-fire.
