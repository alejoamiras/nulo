TL;DR

AMixed-payload fast path
Today: only pure public-static payloads skip the kernel sim. Goal: also fast-path the leading prefix of public-static calls in a mixed [public-static..., private/non-static...] payload, exactly like upstream BaseWallet.simulateTx does.
ELI5: if a dApp asks "what's my balance, then transfer 5 tokens", today we run BOTH through the slow PXE. After this, we run "what's my balance" fast against the node and "transfer 5 tokens" through the slow PXE — in parallel — and stitch the results back together.
BFee semantics unification
Today: standard path hardcodes maxFeesPerGas = 10^18; fast path defaults from the node's getCurrentMinFees().mul(1.5). Same dApp request can produce different gas behavior depending on which path runs. Goal: one shared completeFeeOptions translator, used by both, mirroring upstream byte-for-byte.
ELI5: the two paths disagree on what "default gas" means. We pick the upstream definition and make both paths use it. Also: discovered the planner silently drops maxPriorityFeesPerGas from dApp requests — fix that too.

Codex's concerns and their resolutions

codex round 2 (session 019e183f, response.md) "The planner only carries maxFeesPerGas through a custom FeeOptions shim, dropping priority fees entirely in operation-planner.ts:207. So 'mirrors upstream' is true, but 'matches pre-8c Nulo behavior' is not. That can matter if a dApp sets fee fields or skipFeeEnforcement: false."
Resolution: Added Phase 2c — full plumbing through schema + planner + builder.
codex round 2 "Upstream's scalar offset model cannot express 'go to nested[1], then descend again'. Instead, normalize the standard PXE result before merge."
Resolution: Codex's own v2 review agreed deferral is fine — first-tx-mixed is an edge case (dApp simulating non-pure payload before any tx has been sent). Tracked as follow-up.
codex round 3 (response-1.md, post-consolidation) "requiresMulticallInit() reaches through account.instance.initializationHash, but IAccountContract does not expose instance. As written, that plan does not type-check."
Resolution: Added IAccountContract.requiresInitialization(node) method. Clean interface boundary.
codex round 3 "Extending DefaultAccountEntrypointOptions with gasSettings is the wrong seam. Gas settings are not entrypoint options."
Resolution: Separate gasSettings parameter on buildTxExecutionRequest.
codex round 3 "Rehydrating a fully-private or non-optimizable payload just to throw it away is wasted work and recreates the double-parse you were trying to avoid."
Resolution: Renamed tryRehydrateCalls → rehydrateOptimizablePrefix with data-only boundary scan before rehydration.
