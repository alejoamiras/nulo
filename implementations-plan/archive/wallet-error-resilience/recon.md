## Error-string origins (verified)

| String seen in the log | Origin | Crosses the offscreen → SW port as |
|---|---|---|
| `Block hash 0x… not found when resolving query. If the node API has been queried with anchor block hash possibly a reorg has occurred.` | `@aztec/aztec-node` server (`node_world_state_queries.ts`), returned as a JSON-RPC error; surfaced inside an `AggregateError` ("2 of 6 concurrent operations failed: …") | plain `Error`, message only |
| `Trying to get block header with a not-yet-synchronized PXE - this should never happen` | `@aztec/pxe` `AnchorBlockStore.getBlockHeader` when the header singleton was never written (first sync job not done) | plain `Error`, message only |
| `Assertion failed: RewindableRegister write originates behind the current version` | aztec-nr `RewindableRegister` state variable, assertion compiled into the `HandshakeRegistry` artifact only (`@aztec/standard-contracts@5.2.0`, `@aztec/noir-contracts.js@5.2.0`); raised inside `executeUtility` (private-state sync cursor) when the PXE's anchor is OLDER than the register's stored version | plain `Error`, message only |
| `Contract artifact not found for class 0x…` | Nulo `contract-resolver.ts:155` (tx request building, before any broadcast) | plain `Error`, message only (today) |

Consequence for the design: the PXE already syncs before each op, so a failure means the node's answer moved between the sync and the query (a reorg, or a load-balanced endpoint whose nodes disagree on the tip — the "2 of 6 concurrent" shape fits the latter). A single resync + retry recovers the reorg case and gives the flapping-node case a second draw; beyond that the typed error is the honest answer.

## Collision / dedup risks

- Two predicates for the same "Client disconnected" check (`is-benign-sw-disconnect.ts` vs `isClientDisconnectRejection`) — consolidate while touching both handlers.
- Adding a generic retry utility would be the third bespoke-vs-shared fork in the repo; keep the offscreen helper narrow.
- `reconcile-pairs.ts`'s comment promises a queue-owned retry that does not exist — either the comment or the queue must change; the plan changes the queue and rewrites the comment.
- `useWalletConnection.test.ts:531` pins the registration call count; a re-registration path must not change the connect-time count.

## Corrections to the pre-plan diagnosis

- "[SYNC-DEBUG]" logging exists only on `main`, not on `dev`: no help from it.
- "The PXE never caught up" was wrong as stated: `autoSync` runs on every op. The recurrence an hour later says the node endpoint kept answering inconsistently, which the wallet cannot fix — it can only retry once and then say so clearly.
