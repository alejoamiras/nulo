## High

- **Successful handoff races its own eviction.** The plan requires cancel-on-unmount and defines cancellation as evicting completed reuse entries (`plan.md:43,76`). But Send fire-and-forgets `executeTransfer`, immediately navigates away, then cancels estimation during unmount (`apps/extension/src/popup/pages/send.vue:301-359,482-492`). Likewise, `approveInteraction` starts execution asynchronously and the popup immediately closes (`dapp-interaction/service.ts:94-110`; `popup/windows/execute/index.vue:374-378`). On a queued dApp execution, unmount cancellation will reliably beat `tryConsume` inside `runInSlot`, turning the promised reuse hit into a miss. Add an explicit ownership handoff: successful submit/approval must disarm unmount cancellation for transferred IDs, while reject/dismiss still evicts. Pin both Send and dApp race tests.

- **The Sponsored fast path is not behavior-preserving with custom gas limits.** Today `suggestGasLimits` constrains the app-only Pass 1; Pass 2 then replaces that envelope with measured app gas plus FPC allowance (`fee/fpc-strategy.ts:48-79`; `fee/fee-strategy.ts:120-142`). In the proposed payload-first path, the same custom limit constrains app plus SponsoredFPC and can now fail out-of-gas. That is not the “marginal fee-number drift” covered by Ask 3 (`plan.md:171,179`). Keep canonical Sponsored operations with `op.fee.gasLimits` on the two-pass path, or specify and prove an exactly equivalent treatment.

- **Reuse does not bind the resolved FPC identity.** `fingerprintFeeSettings` binds only `fpcId` (`transfer-estimate-reuse.ts:47-64`), while that row’s address can change in place (`fpc/service.ts:300-355`). Estimate against custom FPC A, update the same ID to B before approval, and reuse still sends the signed request calling A; a fresh build would call B. Snapshot and consume-time revalidate `{id,type,address,chainId/isProtocol}` for `fpc`.

- **The adopted fingerprint condition is still incomplete.** The pinned list omits `teardownGasLimits` and `maxPriorityFeesPerGas` (`plan.md:40`), despite both appearing in `FeeOptions` (`packages/wallet-bridge/src/operation.ts:59-71`) and the round-one finding explicitly naming them (`audit-codex-r1-response.md:13`). Teardown limits directly alter finalized request bytes (`fee/fee-strategy.ts:185-193`). Also specify payment-aware base-fee validation: explicit `maxFeesPerGas` should be compared to the normalized explicit value, not the inherited ladder’s predicted-fee product.

- **Cancellation still lacks the resource cap previously required.** Revision 2 adds profile ownership, duplicate rejection, and TTL, but no per-profile/global active limits (`plan.md:43`), contrary to the adopted A3 requirement (`audit-codex-r1-response.md:23`). Repeated refires can queue arbitrarily many non-preemptible simulations; sweeping controller-map entries does not remove those queued calls. Therefore the “bounded” claim at `plan.md:151` is false. Define caps and count underlying unsettled jobs until completion.

## Medium

- **Phase 5’s “pure extractor” contract is internally impossible as written.** A `TxSimulationResult → AddPrivateAuthwitAction[]` function cannot preserve `getNodeInfo`, live-chain assertion, and chain-bound message hashing (`authwit-discoverer.ts:101-123`). Fetching identity in the runner would also add a node call for the current zero-effects fast return. Either define a pure parser plus a separate chain-bound hasher with explicit `ChainInfo`, preserving lazy ordering, or defer this unused refactor with the fold. Removing Phase 5 from PR C would make the reuse PR materially easier to audit.

## Low

- The canonical Sponsored restriction itself is sound for default inputs: the address commits to the pinned artifact/salt, user-added addresses miss the branch, PrivateFPC remains untouched, and cold/reset decoration fails safely to two-pass. However, `FpcService` derives a network-independent artifact address (`fpc/service.ts:103-114`), not a “chain-derived” address as Inference 3 states (`plan.md:173`). Specify the discriminator as type + exact pinned address + matching row/network chain, and test cold cache plus purge/reset races.
