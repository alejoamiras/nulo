Runtime edges (batch 9 — the final batch)

Three small, sharp edges in the wallet's runtime, each fixed minimally per the adjudication:

1 · An honest error for a rare first-transaction race (N-15)

Your very first transaction from an account also "initializes" it on-chain. If two devices race, or a lagging node hasn't seen the initialization yet, the losing transaction fails with a completely generic error. Now: when the wallet KNOWS it attempted an initializing transaction and the network answers "that nullifier already exists", it says what actually happened — "another first transaction initialized this account; wait for network sync, then retry" — with its own typed error and journal category. Deliberately NOT added: a pre-flight double-check against the node (that exact pattern caused an offline-boot hang once before and is documented as rejected).

2 · A passkey window that outlives the ceremony (N-21)

Some authenticators need two rounds of "touch your key" (up to 3 minutes each), but the popup window enforced a hard 5-minute ceiling — it could slam shut under the user's finger at minute five of a legitimate 6-minute ceremony. The ceiling is now derived from the ceremony math (2 legs + 1 minute of slack = 7 minutes). This path has no production caller yet — the fix is future-proofing, per the audit's own re-weighting.

3 · A cleaner failure when the wallet's services boot (N-28)

Services start in dependency waves. If one failed, the wave aborted instantly: still-starting siblings ran on unobserved, and the error named only the first failure. Now the wave always finishes settling before failing, and the error names EVERY failed service. Deliberately unchanged: already-started services stay live (a full rollback mechanism would be a redesign; the existing boot-cutoff guard covers the worst symptom).
