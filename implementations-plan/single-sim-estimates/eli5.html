single-sim-estimates

The follow-up to the fee-estimation speedup you just merged. Three jobs in one arc: (1) make dApp fee estimates run on one local dry-run instead of two or three, wherever that's provably safe; (2) prove the safety with real measurements against the live Aztec testnet before anything changes how gas is sized — your rule: adopt automatically only if the measured difference is under 1%, otherwise stop and show you the numbers; (3) fix the local test that looked broken — it turned out to be a missing build flag, not a bug, and the real fix is making that mistake impossible to make silently again.

Why this tier was chosen

mid: one high-risk dimension (this touches the machinery that decides what the wallet auto-signs and how transactions are gas-sized), but no novel territory — the design was pre-negotiated in the previous arc's audits, and this arc's two auditors re-attacked the dangerous parts specifically. A deep run was arguable; you invoked mid and the audit rounds behaved exactly like a deep's would (one rejection, one conditional approval, everything folded in).

Human context

The trick everywhere is the same: the wallet already runs a "scout" dry-run with a lightweight stand-in account to discover which permissions a dApp transaction needs. That scout's gas numbers are currently thrown away. If measurements prove the stand-in burns the same gas as the real account (our one datum so far: exactly identical), the scout can do double duty and the second dry-run disappears. The audits added two hard guardrails: the cheaper path is forbidden for any fee contract that isn't the pinned canonical one (a malicious look-alike must always hit the strict path — both auditors attacked this pin and couldn't break it), and any transaction already carrying delegated permissions always takes the fully-checked path.

One honest trade you're being asked to accept (Ask 1 below): on the fastest new path, some kinds of problems that today surface while the spinner says "estimating fee" would instead surface a bit later, after proving. The blockchain still rejects anything invalid — nothing unsafe can land — but the user would wait longer to hear "no" in those rare cases.

Phases

C1 — Fix the "broken" test properly

The failing local test needed a special build flag nobody was told about; unarmed runs silently time out for 3 minutes. Fix: the test now aborts in seconds with the exact command to run instead, and the test runner warns you up front.

Proves itself by: the armed run passing, the unarmed run failing fast and loudly, all fast checks green.

A1 — Reshape without changing behavior

Move the scout machinery into its new home with everything switched off — provably identical behavior, verified by the test pins not moving.

Proves itself by: every existing behavior pin unchanged in value.

B1 — Measure for real, on testnet

A throwaway script runs six transaction shapes against the live testnet, stand-in vs real account, repeated to rule out noise, plus one real sponsored transaction sized from the stand-in's numbers to prove it lands on-chain. Your rule applied here: all differences under 1% → continue; anything at or over → full stop, you get the numbers.

Proves itself by: the complete measurement table in the plan's lessons, and nothing from the script committed.

A2 — The mainnet-contract fold (3→2)

Only unlocked by B1. The scout merges into the first of the private fee contract's two dry-runs; the second stays fully checked forever.

Proves itself by: updated count pins, the malicious-lookalike test fixture, and real end-to-end dApp transactions with real proofs.

B2 — The one-dry-run estimates (2→1) + safety clamp

Only unlocked by B1. Sponsor and own-fee-juice dApp estimates drop to one dry-run, and the wallet gains a safety clamp it never had: gas limits can no longer exceed what the network will actually accept.

Proves itself by: updated pins + the same end-to-end tests with real proofs.

B3 — Full validation

Proves itself by: the repo's full pre-PR gate, armed smoke suite, and the entire network test suite.
