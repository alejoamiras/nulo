Why a mid-sized plan

The work is one app, no wallet code, no contracts, no data migration. What earns it a real plan rather than a quick edit is the journal: the dock has to say "this bridge needs you" using the same logic the existing cards use, and that logic is buried in a 720-line component with watchers in it. Getting that extraction wrong is how a bridge silently stops showing its CLAIM button.

NoveltylowVue shell over composables that already exist.
Blast radiusmediumEverything the tools app shows, but nothing the wallet does.
IrreversibilitylowPure UI; revert is a git revert.
MigrationnoneTwo new browser preferences, both optional.
External couplingnoneNo new services or dependencies.
SecuritylowNo keys; the one real risk (a restore file carrying nasty text) is handled.

The five phases

Phase 1 · the logic, no visible change

One rulebook for "what can this bridge do"

Today the rules live inside the bridge card. They move into a small pure file the card and the new dock both read, so CLAIM, FINISH, RETRY and "switch account" mean the same thing in both places. The dock's grouping (Needs you / Running / Done) is a table with a test per row, and a parity test proves the dock only offers a button where the card would. The completion toast moves to the shell so it keeps firing even when the dock is hidden. Two tiny state modules: which section is open, and whether the dock is open.

Proves itself by: lint + typecheck + all tools unit tests + the tools smoke + the frozen-steps check, all green; the existing 42 card tests unchanged.
Phase 2 · the shell

Rail, header, three sections

The tab pill becomes the left rail (Send, Faucet, Activity with a plain count). Wallet chips move into a header and lose the chip-inside-a-chip look. Send and Faucet pages lose their big titles and wallet rows. Activity is a real page: your bridges as full cards, or on first visit the two action tiles. The "Activity" link on a backgrounded send opens that page instead of scrolling.

Proves itself by: the same gates plus a new shell smoke that mounts the whole app: switch sections, see the chips, dock hidden by default, a completion toast still appears while you are on Faucet with the dock hidden.
Phase 3 · the dock

Two-line rows, one badge

The right column lists bridges as amount over route · visibility · age, with CLAIM, the phase word, or "Bridged ✓" on the right. Hide it and a 44px strip remains with the badge, only while something needs you. It opens itself once per bridge when that bridge starts needing you, never for progress and never for a blocked one; hiding it again keeps it hidden for that bridge, even in another tab. Discard never appears in the dock. The bridge whose progress is on screen beside the dock is not listed until you background it.

Proves itself by: the same gates plus dock tests: hidden by default, hide moves focus to the strip, badge count equals the number of buttons on the Activity page, auto-open fires once, a double-click on Claim gas starts one claim.
Phase 4 · the wizard card and the quiet rules

Vertical step rail, calm stepper, glow budget

The step strip turns vertical with a hint under each step. The in-flight stepper becomes a timeline with one slow pulse. Accent is spent on three things per screen at most; mint marks only what is done. Below 1100px the dock becomes a slide-in panel; below 760px the rail becomes a top row.

Proves itself by: the same gates, with the frozen-steps check quoted explicitly.
Phase 5 · your walk

Preview, sign-off, docs

The branch preview builds. You walk one send to its first claim, one faucet drip, hide and reopen the dock, both themes, keyboard only, and the two narrow widths. Feedback is fixed in place; the README's file map is updated.

Proves itself by: bun run audit:vue and the testnet build green, and your sign-off written into the lessons file.

What the reviews changed

My first draft had two mistakes both reviewers caught. Hiding the dock would have unmounted the thing that shows completion toasts, so backgrounded sends would finish silently. And I planned to share the card's logic as a Vue composable created per row, which would have spawned watchers on every re-render. Both are fixed: the logic is a pure function, and the toast lives in the shell.

Follow the card exactlyI wanted the dock to show "running" for a deposit that is still crossing. The card already calls that one claimable. The dock now agrees with the card, always.
No Discard in the dockDiscard destroys a private bridge's only recovery secret. It stays on the full card behind its two-step confirm.
Blocked bridgesThey count in the badge (you owe a decision) but never pop the dock open, and the dock shows the word "Blocked", never the stored reason text.

Six choices that need your yes or no

These follow from your answers and the mock, but the reviewers were right that they are product calls, not defaults. Say "approve" to accept all six, or name the ones you want changed.

  • (a) Dock buttons: Claim, Finish, Retry, Switch account, Claim gas. Never Discard.
  • (b) Blocked bridges: count in the badge, never pop the dock open.
  • (c) Auto-open: once per bridge, remembered across reloads and tabs; it never overrides your explicit "hide".
  • (d) Networks without a bridge: no dock, no Activity list; the Activity page shows the same "being upgraded" note as Send.
  • (e) Breakpoints: 1100px (dock becomes a panel) and 760px (rail becomes a top row). The app had none before.
  • (f) The bridge on screen is not listed in the dock while its progress view is open beside it.
  • Follow-ups, not in this PR: the raw viem error when picking a token with no Ethereum wallet; sanitising stored text on the full card; merging the two near-identical wallet panels.
