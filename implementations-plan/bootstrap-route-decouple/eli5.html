Bootstrap Route Decouple

tier: mid fable: conditional approve — folded codex: 3× reject → conditional approve — all folded owner: APPROVED 2026-08-12 — asks 1–6 ratified

What this is

One of our automated wallet tests fails randomly a few times a month, and the investigation found it isn't the test's fault — it's a real product bug. When someone imports a wallet backup while the network connection to Aztec is bad, the import screen either freezes with no feedback, wrongly says the import failed when it actually worked, or gets stuck on an error screen. This plan fixes the product so an import always reaches a clear, honest outcome within about a minute, no matter how the network behaves — which also permanently fixes the flaky test.

Human context

Importing a backup does two kinds of work. First it copies all your data into the wallet — accounts, tokens, history. That part is local and fast and never needs the network. Second, it re-subscribes your wallet to the blockchain so it can spot your private incoming payments again. That part does need the network, and today it can hang for minutes or fail in confusing ways.

You decided (and this plan records): the import should simply require a working connection, try a few times with growing pauses if it's flaky, and — if the network really is unreachable — say so honestly on the existing "finished with errors" screen and let you continue into your wallet anyway. Your data is always safe; only the re-subscription is skipped, and the screen tells you.

An important correction surfaced during research: the earlier investigation blamed a different piece of code (the transaction sync). Reading the current code disproved that — the real network-dependent step is the re-subscription above. Because the evidence trail matters, the first phase does nothing but prove this empirically; if the proof fails, work stops and we reassess before touching anything.

Why tier "mid"

Prescribed in your directive; the rubric agrees: contained change, one high-risk dimension (it touches the heavily-audited backup-restore code), no novel surface, no migrations. Two independent reviewers audited the plan; a third fresh review is finishing now.

The six phases

01Prove the diagnosis (blocking)

Export a real backup the same way the test does, look inside it, and reproduce the freeze against a controlled fake network — including a control run (same backup with the suspect part removed must import cleanly). If the suspected step turns out not to be the culprit, everything stops for a rethink.

Proves itself by: a written evidence log with measured timings, plus clean lint + typecheck.

02The fix itself

A quick "can we reach the network?" check with growing pauses between retries (~6–21 s total), a hard time limit on the re-subscription step (~30 s), and honest "skipped — couldn't reach network" entries on the existing error screen. Also hardens the wallet against maliciously oversized backups, and adds tests that lock the wallet mid-import to prove nothing sneaks through. The flaky test gets one new branch: if the error screen appears, click Continue.

Proves itself by: unit tests + the full smoke test suite green on the first attempt, including three new dead-network import tests. The old 90-second test limit is untouched.

03Honest balance states

Today a failed balance refresh looks identical to one still running — nothing is saved and nothing shows. Failures get remembered and shown: a small pulsing dot while refreshing, a dimmed amount with "couldn't refresh" when it failed.

Proves itself by: unit + component tests green.

04Catch torn imports

If the browser kills the wallet mid-import, a half-imported profile can currently sit there looking normal — and unlocking it silently papers over the damage. A small durable marker now brands an unfinished import, and trying to unlock one shows "this import didn't finish — delete and re-import" instead of letting you in.

Proves itself by: unit + crash-boundary tests, the smoke suite, and the two backup-restore network test files, all green solo.

05Ship + certify

Full local test gates, then the pull request, then the same certification the previous arc used: three consecutive fully-green CI runs on frozen code, first attempt only, zero retries — any red resets the count.

Proves itself by: the recorded 3-run certification matrix and the merged PR.

06Close the books

Update the flake ledger (entry 1 → FIXED), file the deferred ideas as tracked follow-ups, and deliver the final report.

Proves itself by: reviewed ledger diff — nothing silently dropped.

Approval decision needed from you

  1. Test vehicle swap. You approved a build-time setting to point tests at a dead network. Research found a cleaner way: a crafted test backup controls the exact network address with zero product code. Both reviewers endorse the swap. Recommended: ratify.
  2. Two new stored fields. A per-token "last refresh failed" note and the unfinished-import marker. We're pre-launch, so no data migrations are needed. Recommended: confirm.
  3. Torn-import handling. Unlocking a half-imported profile is refused with an explanation and the existing delete + re-import path. (The earlier "block-screen" idea was dropped — review proved it could never actually appear.) Recommended: confirm.
  4. What "import didn't finish" covers. The marker protects the data-copying stage. The network re-subscription stage is time-limited and visible on screen, but if you close the popup during those ~50 seconds, only the on-screen note is lost — never data. Making that stage crash-proof would be the big machinery you already declined. Recommended: confirm.
  5. Deferred: true request cancellation. Abandoned network calls finish quietly in the background (bounded, a few at most). Properly cancelling them needs plumbing across three process boundaries — filed as a tracked follow-up instead. Recommended: confirm.
  6. Safety caps on backups. A hostile backup file could name hundreds of networks to probe. Proposed caps: 8 networks, 64 contacts + 64 contracts per network, error text trimmed to 200 characters. Recommended: confirm (or adjust numbers).
