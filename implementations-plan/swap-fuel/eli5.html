swap-fuel — arrive on Aztec with gas in your pocket

Today, bridging AZLO from Sepolia to Aztec leaves you with tokens you might not be able to claim — claiming costs gas (Fee Juice), and a fresh account has none. This arc adds a "fuel" toggle to the deposit form: a small slice of your deposit gets swapped into Fee Juice on the Ethereum side (through Uniswap), rides the same bridge transaction, and your one claim transaction on Aztec pays for itself from the fuel it claims. Private deposits get fuel too — the tokens stay private; only the gas part is public.

Why this tier was chosen

deep — two HIGH risk dimensions: security sensitivity (an atomic multi-step flow moving real value, a signed permission system, an owner-controlled swap contract, public pools anyone can trade against) and external coupling (Uniswap V4, Aztec's fee system, Permit2). Novelty is NOT high — the earlier mega-deep bridge arc already researched and fork-tested most of the machinery, so no research phase was needed. Three independent plans were drafted (me + codex + a fresh Claude planner), merged with a decision ledger, then attacked in three audit rounds. Two audits initially failed/rejected the plan — they found a real theft path and a flawed recovery design — both fixed before this gate.

Phases

P1 — Harden, then prove on a rehearsal copy

Before deploying anything, two safety checks go INTO the swap-router contract (one prevents a malicious swap component from under-delivering fuel; the other proves your slice was actually consumed, closing a theft loophole an audit found). A new deploy script targets the real, live AZLO token with correctly computed pool prices (the old script assumed a different token format). Everything runs against a "fork" — a perfect copy of Sepolia — before real money moves.

P2 — Deploy and seed for real

Deploy the two contracts to Sepolia, create the AZLO/WETH trading pool and fill it with liquidity (~0.07 ETH worth — fits the current budget, no top-up needed, because the second pool we'd otherwise pay for already exists). Guards against someone front-running our pool creation at a garbage price, and the script can resume safely if it fails halfway. Both contracts get source-verified on Etherscan automatically.

P3 — The plumbing (no UI yet)

Library helpers: build the swap route, ask Uniswap's quoter "how much fuel would N AZLO buy right now", and extend the bridge's journal/backup formats so fuel info survives reloads, backups, and restores — while every old record keeps working untouched.

P4 — Teach the wallet consent system about fuel

The Nulo wallet only allows what you've approved. The gas-claim call gets added to the app's permission manifest — and a real gap gets fixed: today, adding a NEW permission to an app you already approved never re-asks you, it just fails forever. The re-consent mechanism we built last arc for contract lists gets extended to permission lists, with the change shown prominently.

P5 — Prove it live, headlessly, before any UI

A script runs the full loop on the real testnet: mint, swap+bridge in one transaction, then claim on Aztec where the claim pays for itself. This also measures the real cost of claiming, which calibrates the minimum-fuel floor the UI will enforce (an audit caught that the UI would otherwise ship an uncalibrated guess).

P6 — The UI

A fuel toggle in the deposit form: pick a slice, see "≈ 9.9 FJ" quoted live, submit with one signature. The progress rail gains a FUEL step. A small pure function decides, from hard evidence only, whether the claim should pay-for-itself or fall back to the sponsored option — never guessing from ambiguous errors (the design two audits forced).

P7 — Manual checklist

You click through it on the live testnet: public + fuel, private + fuel, fuel-off regression, kill-the-tab recovery, backup/restore of a fueled bridge. Item 2 is historic: the first dApp ever to use the wallet's pay-by-claiming feature.

Human context

Three details shaped everything. (1) Your wallet already supports "pay this transaction by claiming bridged Fee Juice in the same transaction" — built last year, never used by any app; this arc is its first customer, which is why no wallet execution code changes. (2) The Fee Juice deposit is always public and always lands at the recipient's address — its claim secret only controls when the claim happens, not where the money goes, so it doesn't need the heavy seal machinery private token deposits use. (3) The pools are public infrastructure on a testnet: anyone can trade against them or grief them. The plan's stance is that user funds must never be stealable (fixed in-contract), while "fuel temporarily unavailable" is acceptable and honestly surfaced.

Open questions (the 3 Asks)

  • Budget: seed ~0.07 of the deployer's 0.168 ETH (recommended), or top up to 0.3–0.5 first so the pool can be re-seeded cheaply if someone griefs it?
  • Rate + preset: confirm 10,000 AZLO per WETH — chosen so 1 AZLO ≈ 1 Fee Juice, making the UI legible — and a prefilled editable fuel slice (~10 AZLO) as the default.
  • Owner model: the router's owner (your deploy key) can re-point the swap component (bounded by the new in-contract checks) and sweep dust. Keep the EOA on testnet (recommended), or introduce a multisig now?
