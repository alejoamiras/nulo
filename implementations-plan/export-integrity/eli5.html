Export Integrity

Your wallet's "Create Backup" screen has a dangerous flaw: if you press Enter twice, or click while it's still working, it can quietly produce a backup file that will refuse to restore — you'd only find out on the day you need it. It can also freeze forever on a spinner if anything goes wrong mid-way. Separately, picking the wrong file in the import screens (a huge file, or a compressed file that expands enormously) can crash the wallet popup. This plan fixes both.

What changes, in plain words

  • The backup screen becomes single-shot. Once you start creating a backup, extra clicks and key presses do nothing until it finishes or fails. The moment you start, the screen shows "Creating your backup" — including during the short pause that used to look like nothing was happening.
  • The backup file is sealed in one motion. The file's integrity stamp is now computed from one frozen snapshot, so a backup that downloads is a backup that will restore.
  • Failures say so. If anything breaks mid-backup, you get a clear message and can simply try again — no eternal spinner, and no blank screen for passkey profiles.
  • Leaving the screen cleans up. Navigating away stops the work and wipes the sensitive material from the page's memory.
  • File imports get a bouncer. Backup, account, and contact imports now refuse absurdly large files — including compressed files that would balloon after unpacking — with a clear "file is too large" message instead of a crash.

Why this level of ceremony (tier: mid)

One risk dimension is genuinely high — this touches the wallet's safety net (backups) and secret material. Everything else is contained: two findings, one page plus a few utility files, no new dependencies. That combination is exactly the "mid" tier: one plan, one competing alternative, two independent reviewers, and a final fresh-eyes review.

Phases

Phase 1 — Make backup creation single-shot and honest

Rebuild the backup screen's engine: a guard that blocks double-starts, the work moved into one clean assembly step that produces the file and its integrity stamp together, clear failure messages, and cleanup on leaving.

Proves itself by: automated checks that a second click does nothing, a mid-work failure recovers cleanly, leaving the page wipes secrets — plus the code style and type checks.

Phase 2 — Add the file-size bouncer

Teach the file-picking machinery a size limit, enforced before anything expensive happens — including inside the unpacking step, where a small compressed file could otherwise balloon into memory.

Proves itself by: automated checks that oversized and booby-trapped compressed files are rejected with the right message, and normal files still work.

Phase 3 — Prove it end to end

The existing full rehearsal — create a real backup in a real browser, download it, restore it in a fresh wallet — now also hammers Enter during creation to prove the old bug is dead.

Proves itself by: the project's full check battery plus the browser rehearsal suite, all green.
