Run each CI suite when its thing's behavior could change — derived from the dependency graph

The rules that decide "should this PR run smoke / network e2e / the chrome / firefox / faucet build" are hand-written lists of folders, and across the whole repo they've drifted from reality in two opposite directions: they fire on everything (even a doc-only PR, via a broken exclusion trick) and they miss real things — a change to wallet-core does not run network e2e today, and a change to bridge-core doesn't rebuild the faucet. The fix: stop hand-listing folders. Derive each rule from the dependency graph — run a suite/build whenever any package its target is built from changes — and add a test (that actually runs in CI) so the lists can never silently drift again. One honest caveat the audits insisted on: this errs toward running — e.g. editing only a unit test or a Storybook story will still run the heavy suites (see the decision below).

Why this tier light

It's a contained rewrite of two (maybe three) filter blocks plus one guard test. The one real danger — a behavior change silently skipping a required suite — is handled two ways: the rule is computed from the dependency graph instead of typed by hand, and a test fails CI if a package gets added without being gated. The footgun mechanics are already proven in the throwaway repo.

The idea

The extension is built from 7 packages: itself plus aztec-runtime, design, extension-messaging, wallet-bridge, wallet-core, wallet-crypto (that's the full chain of "things it imports"). So the rule becomes: run the suites if any of those 7 packages' source changed. We write it as one line per package — packages/<pkg>/src/** — with no backwards ! exclusion lines (those caused the original bug). One honesty note the audit insisted on: src/** excludes the common docs (each package's top-level README, the plan files), but a stray doc that happens to live inside a source folder will still trigger a run. That's on purpose — we'd rather occasionally run a suite we didn't strictly need than ever skip one we did. The rule errs toward running, never toward skipping. Then a tiny test reads the extension's dependencies and checks each one (plus the patches, the test harness, the playground) is gated — so the list can't silently rot again.

Phases

Phase 1 — Rewrite the rules from the graph

Replace the curated folder lists in the smoke + network (+ the build-skip) filters with one src/** line per graph package, plus the build inputs and each suite's own test/harness files. Zero ! exclusion lines left anywhere.

Proves itself by: actionlint green + a grep for '! in the workflows returns nothing.

Phase 2 — Add the anti-drift guard test

A small test reads the extension's dependency graph and asserts every package in it has a src/** rule in the smoke + network filters. If a future dependency isn't gated, this test fails — so the list can't silently rot like it just did.

Proves itself by: the test passes now, and deleting a package's line makes it fail.

Phase 3 — Prove it on real PRs

Throwaway PRs reading the "Detect changes" outputs: a doc/plan-only PR → both suites skip; a PR touching each of the 7 packages (especially the 3 that network was missing) → both fire; a package README.md PR → both skip (docs correctly excluded).

Proves itself by: skip on docs, fire on every behavior package, skip on a package README.

Phase 4 — Write down the principle

A note in CI.md: the e2e gates come from the dependency graph, src-scoped; never add a bare ! exclusion; the guard test enforces coverage.

Proves itself by: the brand/path guard is clean and the note is next to the filters.
