# C3 lessons — the build writes the file

## Proven on real builds

- Chrome and Firefox production builds emit byte-identical notices: 140 components (136 before,
  plus the four font entries), SHA-256 `d47e6b67…` on both. `check-minimum.ts both` names all 34
  expected components.
- **The font hashes reach the generator in a live build.** This was C2's open inference (Vite could
  have inlined a font, or handed the plugin no bytes). Probe: one digit of Inter's recorded hash
  changed, `build:chrome` run, and the build refused:
  `VENDORED entry for asset /^assets\/InterVariable-[\w-]+\.woff2$/ claims
  assets/InterVariable-DiVDrmQJ.woff2, whose bytes are not a reviewed font file`. Restored, the
  build passes with the previous hash.
- **The policy caught its own base branch.** Built on `dev` as it stands, the first C3 build
  refused all three Presto packages as `AGPL-3.0-only`. That is C1 (#639) not having merged, and it
  is the dependency between the arcs: this branch carries C1's two commits until it does.

## Codex loop

**Round 1 (GPT-6 Astra, `high`): reject, one finding, accepted.** Being last in `plugins` does not
make a hook run last: Vite sorts `enforce: "post"` plugins behind the list, and crx compiles and
emits content scripts from exactly such a plugin. Code emitted there shipped after the notices had
been written and the unclaimed-asset check had run.

Proven on a real build before touching the fix: a probe plugin with `enforce: "post"` emitting
`assets/late-probe.js` **built clean** and the file was in `dist/`. With the main hook declared
`generateBundle: { order: "post", handler }` the same build refuses
`assets/late-probe.js: emitted code or font asset with no VENDORED entry`.

**The fix found something the old ordering had been hiding:** `service-worker-loader.js`, which crx
writes late and which had therefore never been seen. It is one line
(`import './assets/<entry>.js';`) and is now claimed as generated output, proven by its whole text
like the content-script loader. Both targets rebuild to the same notices hash as before
(`d47e6b67…`), since a loader adds no component.

Not applied, with reason: adding `bin/**` and `expected-minimum.txt` to the smoke-e2e filter. S10
proves the file opens; the minimum list is checked by the production build job, which those paths
already trigger.

**Round 2: approve.** No blocking finding. Codex exercised the new loader claim in memory: the real
loader passes; extra executable code, several imports, a remote or traversing target and empty
content all refuse. The loop closed in two rounds of three.
