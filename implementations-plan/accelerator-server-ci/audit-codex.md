Attacker framing, explicitly: what could an attacker target, what are we trusting, and where are the weak spots?
- The repo-pinned SHA defends against release-origin tampering and cache poisoning; it does not defend against a malicious PR that changes both the download URL and the pinned hash. That remains branch protection + reviewer discipline.
- The thing you are still trusting too much is the unverified server log format. Right now both Layer 3 and measurement depend on it.
- The `setForceLocal` lint rule is bypassable by indirection, so it is not a security boundary.
- The workflow uses `pull_request`, not `pull_request_target` [pr-network-e2e.yml](/Users/alejoamiras/Projects/nulo/nulo-2/.github/workflows/pr-network-e2e.yml:5), so fork PRs do not receive repo secrets. That meaningfully limits exfiltration risk for this integration.
