Our fast "proverless" end-to-end test suite still fails on three tests. We tried to ship it as a required check, but it's flaky. Human context

Why "proverless" matters: real transactions do slow cryptographic proving (minutes). "Proverless" fakes that step so tests run fast — but the slow step was accidentally hiding timing bugs. Turning it on made hidden races visible as flaky failures.

What we're correcting: the previous round labeled these "resource starvation on the small CI runner" without ever measuring CPU/RAM. The audit confirmed that was an unproven guess — and one failure (F3) passing intermittently looks like a race, not a starved machine. This plan refuses to name a cause without a captured artifact.

The audit's biggest catch: the browser is launched fresh for every test, so "an earlier test left junk in the browser" is unlikely — any contamination would be via the shared sandbox or leaked OS processes. And "shard 1" is a different set of tests in CI than locally, so we must replay the exact list. Both reshaped the plan.
