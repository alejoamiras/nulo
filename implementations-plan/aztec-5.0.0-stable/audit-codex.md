### Findings (paths repo-relative; original response linked absolute worktree paths)

**Facts bucket**
1. **[High]** `currentContractClassId` inventory materially false: 28 reads across 11 production files, not 4 (authwit discovery, artifact/selector resolution, token/FPC handling, view simulation, tx construction). Fix: machine-generated inventory; centralize effective-class resolution; test immutable + upgraded instances. *(Overlaps fable F2 — folded in v2.)*
2. **[High]** "createSchnorrAccount signing-key-first signature" wrong — stable keeps `(secretKey, salt, signingKey)`; the e2e fixture calls it through `as any` (`apps/extension/tests/e2e/fixtures/aztec.ts:387`) so an argument-order error escapes typechecking. Fix: explicit two-step transformation; scripts use `Fq.random()` where ephemeral; remove the `as any`. *(Overlaps fable F6 + adds the `as any` — VERIFIED.)*
3. **[Critical]** The PrivateFPC loss gate is false-green and ordered after promotion: `check-fpc-version.ts:37` normalizes `5.0.0-rc.2 → 5.0.0` (major-only compare) so the rc.2 artifact passes against a stable node — VERIFIED; no artifact hash / class-id / live-class reconciliation; canonical JSON + npm package share ONE publisher trust root; **the extension derives PrivateFPC at salt ZERO in `fpc/service.ts:100-104` (VERIFIED) and salt-0 embeds exist across bridge tests/scripts/fixtures** — updating only the bridge pin leaves the wallet registering the WRONG FPC while local e2e stays self-consistently green; the plan promoted pins (step 8) BEFORE the private settle canary (step 9) — the exact unrecoverable-deposit window. Fix: one canonical descriptor (address, salt, deployer, aztecVersion, artifact digest, class id) consumed by every path; exact-version + digest reconciliation; live address+class query distinguishing RPC failure from absence; dust private claim BEFORE promotion.
4. **[Medium]** "Only Noir break" is an inference (grep), not a fact — only compiling the exact resolved dep set proves it. "No new trust boundary" false: new wallet KDF protocol, OPFS worker + deletion path, irreversible live deploys. Fix: reclassify; schedule a targeted hardening pass over KDF / OPFS ownership+deletion / live-deploy intent.

**Inferences bucket**
5. **[Critical]** OPFS model insufficiently understood for a multi-(profile,chain) offscreen architecture: upstream migration notes permit a custom `store` override (so "forced OPFS, no knob" was unsafe as a premise); SAH pool requires separate pool directories (exclusive lock); one-profile spike tests nothing that matters. Fix: `ProductionPxeFactory` explicitly constructs + injects per-(profileId, chainId) stores with Nulo-owned DB + pool names; ChainRuntime owns the handle, fail-closed close/delete; independently enumerable store registry for orphan cleanup; test 2×2 concurrent init/restart/targeted purge/profile purge/blocked handles/negative-control survival. *(Extends fable F3 — v2 had injection; adds registry + fail-closed + negative controls.)*
6. **[High]** `originalContractClassId` invalid as general replacement (names the deployment class; wrong after upgrade; readers select artifacts/ABI/selectors/authwit by class identity). Fix: resolve the effective class via the stable API, centralize; if upgrades unsupported, DETECT divergence and fail explicitly; upgraded-instance regression test. *(Consistent with v2's no-mass-migration rewrite; adds the explicit-divergence-failure requirement.)*
7. **[Critical]** Single-RPC trust: `deploy-bridge-testnet.ts:85` takes Registry/FeeJuice addresses from one node RPC — a compromised/stale RPC steers portal init, manifests, funding. "No third reset" checked once before a multi-hour arc. SponsoredFPC equality needs artifact/class + deployer + keys + salt, not "same rollup". Fix: reviewed deployment-intent manifest (node/L1 identity, rollupVersion, addresses, code/class hashes, signers, candidate digest); cross-check a second independent endpoint + Sepolia on-chain Registry/Rollup state; revalidate immediately before every irreversible step; SponsoredFPC mismatch = stop.

**Asks bucket**
8. **[Critical]** The signing-root decision hides an unresolved crypto-protocol spec: two incompatible candidate algorithms; "upstream primitives" doesn't define domain bytes, serialization, reduction, zero-handling, versioning; a regenerated vector can bless ANY implementation; fixture parity is tautological if both sides import the same helper. Fix: freeze a versioned seed→signing-root spec pre-implementation; one exported runtime helper; ≥2 independently computed known-answer vectors + 1 full address vector; record the reference computation; forbid fixture regeneration from the implementation under test.
9. **[High]** "Devs reinstall" ignores rc.2 FULL BACKUPS: `compat-epoch` (backup-migration-registry.ts — "account-contract generation. NON-migratable — the only hard version reject", currently 2 — field VERIFIED) is left unbumped while account restore writes the old address without re-deriving (`account/service.ts:248`) → broken accounts discovered only at load. Fix: bump the epoch; cleanly reject epoch-2 full backups; keep seed/import paths; test with a real rc.2 backup.
10. **[High]** Live authorization ≠ spend envelope: no signer allowlist, no max ETH/WETH/FJ exposure, `DeployFuelLive` defaults both seed flags TRUE with non-trivial default amounts (`DeployFuelLive.s.sol:95`); promotion not bound to the candidate bytes that passed smoke; `verify-l1.ts:89` treats "already verified" as success regardless of constructor args. Fix: explicit values for every live flag/amount, signer allowlist, hard maximums; promotion verifies candidate SHA-256 unchanged + canaries reference that digest; Etherscan = supplementary, never semantic proof.
11. **[High]** The plan does not restore the public faucet: it ends at a PR to dev; faucet deploys on a stable main publish (`release.yml:377`); all six phases can pass with `faucet.nulo.sh` still serving the dead-rollup build. Fix: add a production-delivery phase (authorized dev→main promote + release + live build-id reconciliation + a drip through the public site) or drop the restoration claim. *(Extends fable F11 from "name the follow-up" to "make it a phase".)*
12. **[Medium]** OPFS adoption, Firefox runtime exclusion, and /harden-skip are silently-defaulted subordinate choices, not user-locked decisions. Fix: surface exactly these three at the gate; do not reopen signing-root or coupled-redeploy.

**Plan-space bucket**
13. **[High]** Storage gates can green while storage is untested: `test:e2e` runs without a sandbox (no real PXE boot); the "scripted offscreen check" is not a committed command; a build doesn't prove the unhashed `sqlite3.wasm` URL/MIME/worker/CSP (the sibling found exactly that production-only failure); Phase 2 demands builds before Phase 3 adds the Vite plumbing; `verify:deployments` re-derives committed addresses, doesn't query the live network. Fix: committed commands for production-extension boot, WASM asset/MIME/CSP checks, persistent restart, multi-profile OPFS isolation + purge; live acceptance against the exact promoted candidate/build; clarify build ownership between Phases 2/3.
14. **[High]** Supply chain: exact pins + frozen lockfile prove reproducibility, not legitimacy; every relevant package is min-age-exempt precisely while newest; provenance checks were prose, not executable gates; Nargo tags are mutable. Fix: executable registry-integrity + attestation verification mapped to reviewed source commits; hash the PrivateFPC artifact against the canonical manifest; record resolved Nargo commit SHAs; machine-readable lock diff with explicit exceptions.
15. **[Medium]** Live-first rejection directionally correct, but "zero net time saved" not established; if outage duration justifies it, a separate exact-SHA faucet-only emergency lane with its own authorization could exist. Fix: keep the corrected main outline; the emergency lane is a distinct, separately-authorized option — not the current live-first ordering.

**Things codex called right in the plan:** Branch-B classification; candidate-first + journaling + reuse-on-partial; keeping upstream churn inside the seam; the Noir dependency-source correction; native-proving CI; dry-run-first; refusing to weaken gates.

## Final fresh-context pass — round 1

**Model:** gpt-5.6-sol · **Effort:** xhigh · **Sandbox:** read-only · **Date:** 2026-07-14 · **Input:** plan.md v3 + audit-fable.md + audit-codex.md (round 1). Fresh session (not a resume).

**Verdict:** `reject (with blocking findings: 1–7)`

### Findings (condensed; severities as issued)

1. **[Critical]** The independent-Aztec-node requirement wasn't folded: one Aztec RPC + L1 cannot validate L2 contract/receipt honesty; a malicious node can fake the FPC deploy + claim settlement. Fix: two independently operated Aztec nodes machine-checked, or an L1-verifiable settlement proof with the weaker posture surfaced. Re-validate before/after each irreversible operation, not just pre-flight.
2. **[High]** No semantic deployed-code gate replaces the demoted Etherscan check: the intent record was prose; candidate SHA-256 proves JSON identity, not that contracts are the reviewed code. Fix: schema-validated intent artifact (git-tree hash, artifact/class digests, constructor args, code hashes, predicted addresses) + a verifier run before signing and promotion.
3. **[High]** Spend limits unenforced: `DeployFuelLive` defaults `WETH_SEED=0.22 ether` etc.; a misspelled env silently selects defaults; env-derived signer allowlist is tautological; post-flight balance check detects loss after the fact. Fix: intent-enforcing wrapper (all params explicit, unknown/missing rejected, plan-pinned approved signer, per-asset + cumulative caps pre-checked, dry-run-bound broadcast, per-step reconciliation).
4. **[High]** The direct Fee-Juice faucet lane can ship broken while all gates pass: `fuel-testnet` exercises `l1.fuel`, not `l1.feeJuice`; the candidate type leaves `fuel` untyped and `bridge-deployments.ts` casts unvalidated; rc.2 already shipped a stale carried portal this way. Fix: strict shared candidate schema + pre-promotion public/private direct-FJ deposit→claim canaries + a Phase-7 public Fuel-surface canary.
5. **[High]** Supply chain incomplete: blanket in-range `^` acceptance; mutable Nargo tags (recording SHAs ≠ pinning); attestations prove origin, not reviewed-source correspondence; D10's "independent second trust root" is false (same publisher lineage). Fix: enumerate/disposition every unrelated change; commit-pin Noir deps; verify provenance subjects; reproducibly compare the FPC artifact to source; reword D10.
6. **[High]** The full-address reference gate was self-contradictory: an rc.2-captured seed→address CANNOT be a 5.0.0 known answer (stable `deriveKeys` changed) — "explain the shift" isn't a KAT. Fix: rc.2 vectors = continuity-only; capture stable references from the hash-pinned published 5.0.0 tarball via a committed reference script; strict equality, no exceptions.
7. **[High]** The IndexedDB fallback had no isolation/deletion gate (contradicts D8; the spike proves only the OPFS path). Fix: fail closed (don't ship the fallback) or force-test it; drop the "Firefox if trivially drivable" hedge.
8. **[Medium]** Missing semantic asserts: registerContract returned-address equality; upgraded-instance regression tests; registerAccount CompleteAddress equality; machine-dispositioned class-id inventory.
9. **[Medium]** Assumption attack: Fact 2 (excludes are the rc.2-known set); Fact 8 (gate is major-only compare, broader than prerelease-stripping); "independent FPC root" not a fact; I1 (fallback untested), I5 (tag mutability), I7 (one probe vs per-step promise), I8 (name the confirmed items); "encryption parity" unsafe (different plaintext surface). Asks bundled — split backend/Firefox/fallback, make hardening explicit, separate footer from encryption, surface signer addresses + numeric ceilings.
10. **[Medium]** Ledger consistency: D3 vs D8 tension; D11 rejected-things surviving operationally; D13 independence overclaim; D10 overstated; D9's plaintext acceptance should be its own explicit decision.

**Resolved properly (acknowledged):** the pre-promotion FPC settle + salt sweep + hardened gate; compat-epoch bump; OPFS injection + 2×2 spike; createSchnorrAccount semantics + `as any` removal; preimage/instance correction; digest binding + candidate-first + dry-run-first + Etherscan demotion; Phase 7.
