Home Refresh Blueprint

The implementation plan for the home-screen refresh you locked over five design rounds — the dot that only appears when the wallet is genuinely behind, the lock/globe private–public split, the tighter rows, the two-decimal fee juice, the "dRPC" endpoint name, the new header with one-click address copy, and the cursor fix. This page is the approval view; the full technical plan lives in the repo at implementations-plan/home-refresh/plan.md.

Blueprint tier: light · Worktree: home-refresh · 2026-08-13

Why the "light" tier

The sizing rubric scored zero high-risk dimensions: nothing novel (every piece reuses an existing pattern in the codebase), small blast radius (one screen plus one shared card layout), fully reversible, no data migrations, no third-party coupling, no security-sensitive surface. Light means one plan, one independent audit (a second AI model reviewed the plan critically), and a single pull request.

That audit earned its keep: the first draft was rejected with four real findings — the "how far behind" number was being measured from the wrong marker (a quiet token would have false-alarmed after any network hiccup, the exact thing you asked to avoid), the dot couldn't turn off mid-catch-up, the block-time guess was indefensible, and one test suite was missing from the checklists. All four fixes are in the revised plan; the auditor re-reviewed it and gave a conditional approve — its four conditions (a restart-proof progress marker, stricter input checking, keyboard access for the tooltip, proof the full address reaches the clipboard) are all folded in as extra tests and small design changes.

Phases

Phase 1 — The plumbing

First, measure how fast this network actually produces blocks (nobody has written it down), and set the "really behind" threshold from that measurement. Then teach the background scanner to report how far behind it truly is — measured from what it has covered, not from where it last saw a transfer, so quiet tokens can't false-alarm. Also: name the default endpoints "dRPC" in settings, retire the odd "+" copy cursor. No visible UI change yet.

Proves itself by: the full unit-test suite (extension AND design package), typecheck, and lint — including new tests for the quiet-token case, the threshold turning on and off mid-catch-up, and the seeded "dRPC" label.

Phase 2 — The token list

The visible refresh: the pulsing dot (with its tooltip) replaces the "Catching up…" text and only appears past the ~15-minutes-behind threshold; lock/globe icons replace the squares; unpriced tokens show their name instead of "PRIVATE / PUBLIC"; rows tighten.

Proves itself by: the rewritten TokenCard/TokensView/BalanceView component tests — threshold above/below cases, icon assertions, subtitle fallback — plus typecheck and lint.

Phase 3 — Density and decimals

Fee juice drops to two decimals, sections sit closer together, and activity cards get slightly tighter — everywhere they appear, so the whole app keeps one rhythm.

Proves itself by: new fee-juice tests with fractional amounts (the only signal for this change — today's tests all use whole numbers), plus the standard suite.

Phase 4 — The header

The account chip splits: avatar + name open the account switcher, the address copies itself with a toast, a copy icon appears on hover. Built from the avatar and copy components the app already has.

Proves itself by: typecheck, lint, and the unit suite staying green (the header's real proof is Phase 5's browser tests, per the repo's own convention).

Phase 5 — Browser tests, end to end

New browser-level coverage: clicking the address shows "Address is copied", the avatar and name open the switcher, the endpoint row reads "dRPC". Then the full gates: build, smoke suite, and the complete network suite (run alone, per house rule).

Proves itself by: audit:vue + smoke e2e + network e2e, all green.

Human context

One design decision made this plan simpler than it looks: the existing browser tests find the account switcher by an internal label (account-selector). Instead of updating every test, the new header keeps that label on the name button — so all existing switching tests pass untouched, and only genuinely new behavior (copying, the avatar) gets new tests. Your top priority — tests updated correctly — shaped the whole plan: every phase's checklist names the exact test files it rewrites or adds.

One quiet caveat: nobody has written down how long this network's blocks take, so "15 minutes behind" is set as a tunable constant with the reasoning documented next to it — easy to adjust if the network's pace changes.

Open questions

  • Avatar initials. The app's existing avatar component shows two letters ("PA" for Primary Account); the mock showed one ("P"). Reusing it unchanged is recommended (consistent, zero new code) — say "single letter" if you want the mock exactly.
  • Density everywhere. The tighter activity cards live in a shared layout, so the Activity page and token pages tighten too — recommended (one rhythm), but it's a wider ripple than "home screen" implies.
  • The threshold number. "15 minutes behind" is your policy; the block count that means will come from Phase 1's measurement of the live networks. Recommended: accept the measured number (documented, easily tuned later).

Small defaults decided for you (veto if wrong): a failed copy shows "Couldn't copy address"; the "dRPC" name stays editable like any endpoint label; the dot's tooltip also works from the keyboard.
