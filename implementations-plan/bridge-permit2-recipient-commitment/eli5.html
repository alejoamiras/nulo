Permit2 everywhere + private claims a relayer can't steal

Three linked upgrades to the Nulo bridge (the thing that moves tokens between Ethereum L1 and Aztec L2), plus a careful one-time swap of the L2 contracts. In plain terms: make every bridge deposit use a signature instead of an on-chain approval transaction (cheaper, one tap), and change how private deposits are "locked" so that someone else can finish the deposit for you on Aztec without being able to reroute the money to themselves.

Why this tier was chosen

Deep. Five of the six risk dials are HIGH: blast radius (touches L1 Solidity, L2 Noir, the shared TS library, and the faucet UI at once), irreversibility (a private-claim change forces a fresh set of L2 contracts that can never be un-deployed and that everyone must migrate to), migration cost (a full testnet redeploy + config cutover), external coupling (Uniswap V4, canonical Permit2, the Aztec sequencer), and security sensitivity (it's a token bridge — the whole point is not losing funds). Only novelty is moderate (the repo already has a working precedent for the crypto trick). Three independent plans were drafted, cross-checked for contradictions, then double-audited by an adversarial reviewer from a different model family and two fresh security auditors.

The three changes, plain

(a) Bridge a normal token with a signature. Today a plain token bridge makes you send an "approve" transaction first, then the deposit. There is already a signature-based path built into the on-chain router — it's just switched off in the app. We turn it on and delete the old approve path.

(b) Buy gas with a signature too. The "Fuel" tab (which tops up your Aztec gas) still uses the old approve flow. Surprising discovery from the research: we need zero new smart-contract code for this — the same router function from (a) already does exactly what the fuel deposit needs, because the two deposit calls are byte-for-byte identical. So (b) is mostly wiring, plus a one-time "approve Permit2" step the first time (the gas token, unlike the test token, doesn't pre-approve it).

(c) Lock private deposits to their recipient. Right now a private deposit is a "bearer" secret: whoever holds the secret can claim the money to any Aztec address. We change the lock so the secret is mathematically tied to the intended recipient. Then you can safely hand the claim details to a helper ("relayer") who submits the Aztec transaction for you — they can finish it, but the math only lets the money land at you. This is the real prize: it needs new (but small) Noir circuit code and, because Aztec's wiring is one-time-only, a brand-new set of L2 contracts.

What the review rounds actually caught (why the ceremony earned its keep): a validation gate that could never pass (it checked new contracts against the old config); a private-deposit path that would have silently stranded funds because one leg still used the old random secret; a rollback recipe that violated the plan's own safety rule; a "green" test gate that passes while the real test is skipped; and a "the relayer can't do anything bad" claim that was too strong (it can't steal, but it can stall your claim). All fixed in the plan before you see it.

Phases (each proves itself before the next)

1 — L1 tests first (no contract changes)

Add the project's first fuzz tests (throw thousands of random inputs at the router) + tests against the real deployed router and the real Permit2/Uniswap, including a hostile-portal test. Also a positive proof that the live router really has the function we're betting on.

Proves itself by: forge test green with fuzz + the named fork tests asserted PASSED (not just "didn't error").

2 — L2 recipient lock + cross-language pins

Rewrite the private-claim circuit to derive its secret from the recipient; pin the exact math in both Noir and TypeScript so they can never silently drift apart (a drift would strand deposits). A machine check confirms no old "bearer" path survives.

Proves itself by: both toolchains compute byte-identical secrets; the sole-consumer check passes; existing content-hash pins unchanged.

3 — Shared TS library + relayer script

Point the shared bridge library at the signature path, delete the old direct path, and ship a small relayer script (submits a claim from a different account — the proof the recipient-lock works).

Proves itself by: no old deposit path remains; all five claim call-sites pass the new salt; unit tests + type-check green.

4 — Full local dry-run (all three together)

On a local sandbox: public deposit, private deposit, private deposit claimed by a second account, and fuel-only — all end to end. First real proof the recipient-lock circuit actually consumes a real message, and that the recipient can find the money after a relayer submits it.

Proves itself by: every leg prints PASSED; the relayer leg's sender ≠ recipient and the recipient sees the balance.

5 — Faucet UI

One-signature deposits everywhere; the one-time gas-token approve; a runtime guard so new deposit code refuses to run against an old config (turns the safety rule into a technical lock).

Proves itself by: bun run audit:faucet green; no old deposit path in the UI.

6 — Deploy the new stack (candidate only)

Deploy the fresh L2 contracts + a fresh portal, reusing the existing L1 token and pools. Writes a candidate config file — the live app doesn't change yet.

Proves itself by: every on-chain read-back ✓; the live config file untouched.

7 — Prove on live testnet, then flip

Run five real-money-dust canaries against the candidate (including a wrong-recipient attempt that MUST fail, and a relayer claim that must succeed). Only then flip the live config and ship code + config as one release. (Approved WIPE: no drain window / old-state preservation — freeze the old faucet and cut over; no one cares about prior testnet state.)

Proves itself by: all canaries settle with balance checks; wrong-recipient fails without consuming.

8 — Durability + docs (shrunk by the WIPE)

A test proving real new-stack deposits are backup-recoverable, plus honest docs. The old legacy-claim + rollback machinery is dropped — there's no prior state to preserve.

Proves itself by: the backup-durability test passes.

9 — Focused security re-audit

A narrow red-team pass over only the new/changed surface, same shape as the June bridge audit.

Proves itself by: every finding fixed or explicitly accepted; full stack green.

Human context you need to judge this

  • "Bearer secret" = like cash: whoever holds it, spends it. Today's private claim is bearer. Change (c) makes it a locked cheque made out to you.
  • Why a whole new L2 stack? Aztec's contract wiring is one-time-only (a deliberate security fix). Changing the claim logic means the old bridge contract can't be re-wired, so a fresh token + minter + bridge + portal is unavoidable. The old ones stay live so nothing in flight is lost — it's the same shape as an Aztec network reset.
  • Relayer honesty: the recipient-lock guarantees a relayer can't steal. It does not stop a relayer from stalling (consuming your message then making you jump through a hoop to find the funds) or from learning that "address X deposited amount Y." Use a relayer you trust, or none. The plan says this plainly rather than overselling it.
  • This is testnet. The tokens are worthless, so a couple of accepted risks (a blind signature could drain the test token; a fresh L2 token means re-adding it in the wallet) are fine here — but the plan flags each as a hard blocker before this pattern ever touches a real-value token.
