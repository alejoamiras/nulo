## 2026-09-14 — blueprint codex round 2

## 2026-09-15 — post-implementation codex round 1 (GPT-6 Astra `high`, session `01a0a263-800c-7183-b7d6-fe7ac2a35c77`): `fix` — 2 blocking, 7 should-fix, all adopted
The admission gate had five concurrency holes codex reproduced in memory; all fixed in `verify-admission.ts` + `session-established.ts`:
1. **(blocking) one reservation could back two windows.** `markInFlight()` silently no-op'd unless unstarted, but `openVerifyWindow` always called `create()` — a second establishment callback on the same reservation opened a third window against two slots. Now `markInFlight()` returns a boolean and `openVerifyWindow` aborts before `create()` when it is false.
2. **(blocking) a cancelled adoption released capacity before the window closed.** `adopt()` called `finish()` immediately when cancelled, so a replacement could open while the doomed window still existed. Now `adopt()` returns `"live" | "abort"`; a cancelled attempt keeps its slot until `windowRemoved` fires for that id (or, if the removal already arrived, releases on adoption via a bounded removal buffer).
3. **(should-fix) dApp-controlled duplicate discovery ids leaked capacity.** A second admit of one id overwrote the first reservation, orphaning its counters. Now `admit` rejects a window-needing id already live (queued or reserved); a `liveWindowIds` set tracks them.
4. **(should-fix) removal before adoption leaked a slot.** `onRemoved` for a windowId the gate did not yet know (in-flight creation) is buffered; `adopt` consumes the buffer and releases immediately.
5. **(should-fix) an expired in-flight reservation spun the drain timer.** `serve`/`nextWake` now only timer-reclaim UNSTARTED reservations; in-flight/opened settle on their own creation/removal.
6. **(should-fix) `estimateId` and `previewId` could name different interactions.** A popup could pair A's reuse id with B's valid snapshot id (matching fingerprints pass both checks). `enforcePreview` now refuses when both are present and unequal (the producer guarantees `previewId = estimateId`), before either id is consumed — `PREVIEW_FOREIGN_MESSAGE`.
7. **(should-fix) `hideMsgSender` public transfers got "From: this account".** A 2-arg `transfer` with `hideMsgSender: true` executes with a null caller; the card now falls to the unverified raw-argument branch instead of naming the account.
8. **(should-fix) the flood e2e was timing-fragile** (counted UI work, raced the 20 s refill). Rewritten to assert the security invariant — at most two verify windows at any moment, none dropped, all four connect — and leave the exact refill ordering to the deterministic unit tests.
9. **(should-fix) coverage gaps** closed: a discovered-record unit test for the standalone discoverer (WASM mocked), duplicate-id / global-cap / removal-before-adopt / timer-loop / single-creation gate cases, a returning-approval-rollback case, the cross-interaction id executor case, the `hideMsgSender` card case.
10. **(nit) comments**: the `materialize.ts` header no longer describes the removed popup `assertExecutableOperation` flow; provenance tags trimmed from `operation-fingerprint.ts` and `discovery-aware-estimator.ts`.
Gate after fixes: extension typecheck, root lint (32 pre-existing warnings, complexity-baseline OK), the wallet-sdk + execution + execute-window + utils + dapp-interaction suites (118 files / 1460 tests).

## 2026-09-15 — post-implementation codex round 2 (GPT-6 Astra `high`, session `01a0a263-800c-7183-b7d6-fe7ac2a35c77`): `fix` — 0 blocking, 4 should-fix + 1 nit, all adopted (commit `7716a9ab`)
Round 1's fixes all held; round 2 found three residual holes and two coverage gaps:
1. **(should-fix) the estimate→preview equality check was skippable and ran too late.** In round 1 the guard lived only inside `enforcePreview` and fired AFTER `resolveStandardBuild` had already popped the reuse entry, and it checked equality only when BOTH ids were present — a popup that omitted `previewId` skipped it entirely. Refactored to a shared `assertEstimateBinding` called BEFORE the reuse cache is touched in `executeAztecSendTx`; an envelope that carries an `estimateId` MUST carry the equal `previewId` (the producer always mints `previewId = estimateId` for a bound standard estimate — verified: the service always passes a `PreviewContext`, and the popup sends `previewId = estimate.previewId`), else `PREVIEW_FOREIGN_MESSAGE` before a foreign id can pop an entry. The stricter form (throw on estimateId-without-previewId) is safe because no real popup path produces that pairing; the two stale reuse tests used a helper that omitted `previewId` and were corrected to the real contract.
2. **(should-fix) a removal event evicted from the bounded buffer before adoption leaked the slot.** The 64-entry `recentRemovals` ring can forget a removal still needed by a cancelled in-flight creation (its window's removal, then 65 unrelated removals). `adopt` then returns `"abort"` but the slot stays `opened` with no further `onRemoved` to free it. Added `releaseIfWindowGone()`: when `openVerifyWindow`'s `remove()` REJECTS (window already gone, no event coming) it releases the opened slot directly. New gate test reproduces the overflow + backstop.
3. **(should-fix) the flood e2e exited on connection, which precedes verification.** Closing captured windows could admit a late handshake whose verify window appears after the snapshot; all tabs report connected and the loop passes with fewer approvals than tabs. Now exits only once all four have connected AND all four verify-approvals have completed.
4. **(should-fix) coverage**: the fresh-approval rollback test expired before acquiring a reservation, so it could not detect missing fresh-path cleanup; rewritten to roll back AFTER acquisition and assert immediate capacity recovery (both later handshakes get a slot under the two-slot cap). The discoverer record assertion now pins the full decoded record (`selector`/`args`/`innerHash`) via mocked WASM.
5. **(nit) `serve()`** narration duplicated the invariant already documented at `expiredWhileUnstarted`; trimmed to one location.
Gate after fixes: extension typecheck (clean), root lint (32 pre-existing warnings, complexity-baseline OK), biome, the wallet-sdk + execution + execute-window + dapp-interaction suites (74 files / 832 unit tests + 131 execute/dapp-interaction). Round 3 next (hard stop at 3).

## 2026-09-15 — post-implementation codex round 3 (GPT-6 Astra `high`, session `01a0a263-800c-7183-b7d6-fe7ac2a35c77`): `fix` — HARD STOP at 3 rounds; cheap+correct fixes adopted, the rest surfaced as owner residue (commit `cb173ccf`)
The blueprint fix-loop stops at 3 rounds. Round 3 returned `fix` (5 should-fix + 1 nit), not `approve`. Triaged: adopt the fixes that are clearly correct and low-risk; surface the rest with impact analysis rather than spin a round 4.

**Adopted:**
1. **(should-fix #1+#2) reverted the round-2 `releaseIfWindowGone` backstop.** Codex correctly found my round-2 fix made things worse: releasing a reservation on ANY `windows.remove()` rejection is wrong — Chromium rejects removal for reasons other than absence (a non-editable tab strip), leaving the window open, so the release could put an origin one verify window OVER its cap (fail-OPEN). And it never covered the uncancelled-adoption overflow path anyway. `WindowPort` has no window-existence query, so "release on confirmed absence" is not achievable cheaply. Decisive realisation: `adopt()` runs synchronously right after `await create()` resolves, so the `recentRemovals` ring (64) only ever needs to hold removals that fired DURING a single in-flight `create()` — overflowing it needs 65 window-closes in a sub-millisecond window, impossible in practice. Reverting to `remove(id).catch(() => undefined)` restores fail-CLOSED behaviour (a theoretical lost removal tightens the cap and queues honest handshakes, never a breach). Fail-closed under an impossible scenario beats a fail-open regression under a rare-but-real one.
2. **(should-fix #4) the flood e2e now gates loop exit on four approvals**, not four connections. The SDK sends its key-exchange response before the async establishment callback, so a tab reports connected before its verify window appears; `countVerifyWindows === 0` was transiently true and the loop could exit early. Added `approvals >= tabs.length` to the exit condition.
3. **(nit #6) dropped the `serve()` narration comment.**

**Surfaced as owner residue (NOT fixed — recorded here and in the PR body):**
- **(should-fix #3) equal estimate/preview ids still don't establish snapshot OWNERSHIP.** A `take()` on a foreign `previewId` pops (consumes) another interaction's snapshot even on the "foreign"-reject path; a later approval with `estimateId = previewId` can then reuse a fingerprint-identical cached build while the snapshot is missing, and `assertWithinPreview(missing, [])` passes when nothing was discovered. Impact is bounded to (a) griefing — evicting a peer's snapshot forces it to rebuild, which is SAFE, and (b) reuse of a build whose identity fingerprint already matches the current operation, i.e. no substitution. The core F-02/F-16 property holds: a witness is NEVER signed without a matching snapshot, because a rebuild that discovers a witness with no snapshot throws `ESTIMATE_INCOMPLETE`. Codex's fix ("gate reuse on an owned snapshot; missing ⇒ rebuild") is a real reflow of `resolveStandardBuild` (the single-shot `take` would have to move ahead of `tryConsume` and thread its result to `enforcePreview`) — deferred as beyond the hard-stop's low-risk bar for a no-forgery griefing issue.
- **(should-fix #5a) NO_FROM preview RPC cancellation** is proven only via the executor's settled-attempt eviction test, not through `execution/service.ts`'s `previewOperationAuthwits` + `withEstimateAdmission` wrapper end to end. The eviction wiring IS covered; the RPC-level during-estimation cancellation is not.
- **(should-fix #5c) the discoverer's decoded-record test mocks WASM** and asserts the full record shape, but does not decode a real `@aztec` offchain-effect fixture (heavy real-crypto dependency).
- **the residual theoretical buffer-overflow leak** (the fail-closed one described above) — a lost removal under an impossible 65-closes-in-one-create scenario tightens an origin's cap by one slot until worker restart.
Gate after fixes: extension typecheck (clean), root lint (32 pre-existing warnings, complexity-baseline OK), biome, wallet-sdk + execution suites (59 files / 693 tests + 7 todo). Codex loop CLOSED at round 3.
