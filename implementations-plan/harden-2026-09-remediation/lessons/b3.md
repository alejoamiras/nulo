## Implementation — Phase 1 (F-06), 2026-09-14

Landed as one commit (`feat(crypto): mix the profile DEK into the PXE + dApp-session keys`).

- **The shared HKDF base-key helper** (`packages/wallet-crypto/src/dual-secret-hkdf.ts`, `importDualSecretHkdfKey(master, dek, usages)`) owns the 32+32 assert, the concat, the `importKey` and the IKM zeroize; `macKeyV3`, `derivePxeStoreKey` (now `(master, dek, profileId)`, label `v2`) and the new `deriveDappSessionMacKey(master, dek)` each keep their own salt/info + `deriveKey`/`deriveBits`. Envelope-MAC vectors stayed byte-identical (only the private key builder moved).
- **HMAC deriveKey OKM length gotcha**: an independent `hkdfSync(...)` reference for a `deriveKey({name:"HMAC",hash:"SHA-256"})` must extract **64 bytes** (the hash block size), not 32 — WebCrypto sizes an unspecified-length HMAC key to the block size. First `dual-secret-hkdf.test.ts` run failed on a 32-byte reference.
- **Recovery mode is a SW-side synchronous gate, not an async toggle.** `SessionManager.isRecoveryMode` reads `activeSession.dek === undefined`; the runtime registers it as `registerPxeRecoveryGuard`, and the app `PxeServiceClient.request` throws `RecoveryModeError` for any `NetworkInfo`-first (profile-bound) op before `super.request`. Cleanup calls (`clearChainState`/`clearProfileState`, bare-profileId-first) and `provisionChainStoreKey` are exempt so a recovery-mode profile is still purgeable. The base capture block needs a generation provider registered even in a unit test, or it throws "no current incarnation" before reaching the wire.
- **`viaPxe` must rethrow `RecoveryModeError` by type** (it otherwise flattens every throw to `Error("PXE request failed")`), so `AccountStateService.backup` can omit just that network. Extracted `backupNetworkState(n)` per-network so the try/catch fits and cognitive complexity stays under budget.
- **Codec strips unknown keys → MAC preimage drift.** A hand-planted `DappSession` row must carry ONLY schema fields: an extra `icon` in `dappMetadata` is dropped by `DappSessionSchema.parse` on read, so a MAC signed over the icon-bearing row fails `verifyOrDrop` and the row is dropped as tampered. `canonicalizeDappSession` sorts keys, so key ORDER is safe; unknown FIELDS are not.
- **Password change refuses (no mint).** `rekeyedDekForPasswordChangeHoldingLock` throws `DEK_UNRECOVERABLE_MESSAGE` when the slot won't unseal — the DEK now keys the store and every session tag, so a fresh mint would orphan them all. Exports carry a fresh DEK instead (`dekReplaced`), and that is the repair path; passkey profiles (no phrase) rely on `exportPasskeyBackupMaterial` sealing a fresh DEK under the ceremony wrap key.
- Gate green: wallet-crypto 120, aztec-runtime pxe 143, extension crypto/dapp-session/profile/pxe/account-state/export/general + `runtime.pxe-store-key.test.ts` 517. Lint + typecheck clean. (Local reinstall is a manual dev step, not run here.)

## 2026-09-14 — smoke run 1 red (14 tests), root cause: no `getManifest` in a Chrome offscreen document

Every red touched a SW→offscreen call (profile reset stuck on its tombstone because `clearProfileState` never answered; network delete; every backup export; the FPC/token popups behind a PXE read). A 30-second puppeteer probe (`apps/extension/.playwright-mcp/sender-probe.mjs`, ignored dir) recorded the real `sender` in both directions:

- SW → offscreen: `{ id, url: "chrome-extension://<id>/service-worker-loader.js" }` — exactly `getURL(manifest.background.service_worker)`, no `origin`, no `tab`.
- offscreen → SW: `{ id, url: "chrome-extension://<id>/src/offscreen/index.html", origin }`.
- **`chrome.runtime.getManifest` is `undefined` inside a Chrome offscreen document** (the offscreen target is even reported as `background_page` by the DevTools protocol), so `backgroundContextUrls()` was empty and `isBackgroundSender` refused every SW request. `fetch(chrome.runtime.getURL("manifest.json"))` works there. Fix: resolve the set once per context (getManifest where present, else fetch), admission awaits it.

Second probe (`pxe-probe.mjs`): a hand-built `getNoteSchemas` request from the SW is now answered (`from: "pxe"`, result present) with the offscreen document as the response sender. `MessageType` is numeric (`Request = 2`, `Response = 3`) — the first probe used string literals and timed out for that reason alone.

Lesson for the skill: when a sender predicate is added to either offscreen listener, probe the REAL `sender` shapes before the smoke run — the smoke suite reports the symptom (timeouts, stuck tombstones) three retries later, never the predicate.
