# B2 lessons

## 2026-09-14 — recon
One Sonnet sweep (`b2-backup-passkey/recon.md`). The seed's "drop the network slice" undersold the change: unlike the FPC slice (an optional post-token loop entry), network restore is a mandatory stage the pipeline depends on — `createdNetworks` feed the account-state chain-sync, the active pointer and the `networkId` remap across slices. Design chosen: a reseed stage (`NetworkService.seedDefaultsForProfile(profileId)` reusing the locked seed loop under a restore-style fence) plus a `chainId`-keyed remap, with `active-chain-id` replacing the raw `active-network-id`. Two of the seed's three open asks were answered by recon before codex: `IMPORT_BLOCKING_ACK` acknowledges migration versions only (registry edits suffice), and no `.well-known/webauthn` exists or is needed. `LESSONS_FILE=implementations-plan/harden-2026-09-remediation/lessons/b2.md`

## 2026-09-14 — blueprint round 1 (codex `high`)
Verdict `reject`, one blocking: the reseed reused `activateSeededLocked`, which writes `this.nodes` keyed by `chainId` — restoring profile B while A is active would replace A's cached node for that chain with B's seed endpoint (`network/service.ts:306`, `getNode` `:721` never checks ownership). Adopted: the reseed writes only B's persisted active pointer and never touches the node cache; a test pins A's custom endpoint surviving B's reseed. Five should-fix, all adopted: (2) a deletion epoch is not existence — `seedDefaultsForProfile` requires a live target profile, is idempotent on existing rows, re-asserts under the lock; (3) `content_scripts.matches: *://*/*` already covers the RP host — add `exclude_matches` for `passkey.nulo.sh` and its descendants, test effective matching, pin the literal `RP_ID`, document that `*.passkey.nulo.sh` stays content-free; (4) the synthetic backup builders (`tests/e2e/helpers/import-drivers.ts`, `passkey-backup.test.ts`) and the dead-RPC suite emit or rewrite a `network` slice — in scope for Phase 2/3; (5) the remap's claim narrowed ("imported data cannot define the destination network or endpoint"), strict numeric chain lookup incl. chain 0, malformed/unseeded account-state items dropped + reported, transaction rows assigned from their chain even without an old id; (6) the base class already supplies null `backup/restore` — delete the four overrides and their helpers (`validateRestoredNetwork`, `ERR_BACKUP_TOO_OLD` if unused). Asks: A keep chain remap + `active-chain-id` as an untrusted preference; B fail-closed; C remove now; D creation-only + assert management stays; E no `.well-known/webauthn`; F registry edits only.
