## Architecture & Implementation (compact)

- **F-01 chain identity.** `SelectedNetworkChainInfo` gains `l1ChainId: number`; `assertLiveChainIdentity` (a) asserts BOTH live values are canonical unsigned 32-bit integers (`assertCanonicalL1ChainId` from `@nulo/wallet-crypto` for `l1ChainId`; the same bound applied to `rollupVersion` — codex round 1 showed `rollupVersion` values differing above bit 32 alias under the `>>> 0` composite, e.g. `4248422647` vs `8543389943`, so exact-L1 alone does not pin the version), (b) requires `nodeInfo.l1ChainId === network.l1ChainId` for every row INCLUDING local (a seeded local row carries 31337; a custom devnet row carries whatever `_probeChainIdentity` stored at `network/service.ts:999`), (c) keeps the composite compare for non-local rows (`chainId === 0` skips only the composite). With both live values in u32 range, exact L1 + composite pins `rollupVersion` exactly. `FastPathDeps.network` widens to the same shape. `wallet/utils/fn.ts:85-95` takes `network` from its callers and asserts before `chainInfoFrom`. `buildNoFrom` hoists its `getNodeInfo` + assert above `account.ensureRegistered` and every resolver call (mirror `resolveBuildContext`).
- **F-08 fast path.** `FastPathDeps` gains `resolver: ContractResolver`; before `simulateViaNode`, for each optimizable call resolve the artifact, `findFunctionBySelector`, throw the same scope-violation error as `execution/service.ts:900-908` when `call.name !== fn.name`, and rebuild `type`/`isStatic` from ABI truth as `view-executor.ts:361-381` does. The bind runs BEFORE the infrastructure `try` (`fast-path.ts:188`), so a rejection propagates instead of being swallowed into the fallback. After rebuilding `type`/`isStatic` from ABI truth, eligibility is re-checked: if any rebuilt call is no longer public+static, `runFastPath` returns `null` and the whole operation takes the standard arm (which re-validates every call) — a forged `isStatic` flag can never split a dependent call off into node-side simulation. A name/selector mismatch throws.
- **F-03 picker.** `fee-helpers.ts:157` and `gas-balance-reader.ts:181` select `type === PrivateFpc && isProtocol === true` (mirror `fpc-strategy.ts:111-115`); `getFpcImpl` (`fpc/service.ts:426-432`) refuses a `PrivateFpc` row that is not protocol — and resolves protocol addresses with `await getOrComputeProtocolAddresses(chainId)` instead of the `protocolAddresses.get()` cache, which is empty after a service-worker restart and would make the genuine row look non-protocol (codex round 1). Custom sponsored FPCs (`addFpc` with `DefaultSponsoredFpc`) stay allowed. The restore-side rejection ships in B2 with the slice drop; `getFpcImpl`'s gate makes a poisoned row unusable for `pay_fee` even before B2.
- **F-10 logging.** `trim()`'s primitive-string branch runs `scrubUrls`; `network/service.ts:1003` and `pxe/service.ts` pass the `Error`; `log-payload-ban.test.ts` gains a denied pattern for `getErrorMessage(`/`errorMessageFromUnknown(` as a log argument (allowlist the sites that genuinely log a scrubbed message).
- **F-12 restore.** `ContactService.restore` applies `sanitizeString(name, 20)` (same call as `importContacts`); `TokenBalanceService.restore` writes `updatedAt: 0` AND drops `syncFailure` — `reconcile-pairs.ts:143` re-projects only when both are clear (codex round 1).
- **F-13 account reads.** `getAccount`, `getAccountContract`, `exportAccount` compare `row.address === requestedAddress` (plus profile/chain, as today); `loadImportedAccountContract` compares the rebuilt address to the *requested* address. Inline, mirroring `liveRows`; the `EntityStorage` primitive stays single-field.
- **F-15 pending restore.** `finalizePasskeyRestoreHoldingLock` consumes (deletes) the pending entry first, then rejects `now - pending.capturedAt >= PENDING_RESTORE_TTL_MS` with the existing missing-pending-secret error, zeroizing both buffers in a `finally` so no path retains restore authority; `lockActiveProfile` clears + zeroizes both maps under the facade lock BEFORE awaiting session closure, so a closure failure cannot leave them populated.
- **F-17 icon.** `background.ts:106` imports the logo as a `data:` URI (`?inline` Vite asset import) and the manifest drops `web_accessible_resources`. The SDK forwards the string verbatim (recon #8). Known limit (codex round 1): a dApp whose CSP `img-src` omits `data:` will not display the icon; narrowing `matches` instead would break icons on every unlisted dApp, so the data URI wins. Phase 6 verifies rendering against the playground dApp.
- **Hygiene.** `getPasshash`/`getHashHex` zeroize the encoded bytes in `finally` after the digest promise settles; the same treatment for the token/salt buffers in `session-secret-box.ts:93,120` and the export plaintext buffers in `account-export.ts:148,156`. `autocomplete="new-password"` on new-password fields, `"current-password"` on unlock/current fields, `"off"` on recovery-phrase inputs (`ImportSecretForm.vue`), via the existing `Input` prop. `logs-csv.ts` neutralizes on every final cell after splitting and before quoting: a cell starting with `= + - @ \t \r` gets a leading `'`. `pxe/service.ts` registerContract computes the address with `computeContractAddressFromInstance`, compares to the request, and only then performs both registrations (the upstream `registerContract` call itself writes — the old order left an instance write on rejection). `import.vue:227` renders the raw `previewAddress` in a wrapping monospace span (not `AddressDisplay`, which substitutes a contact/account name when one matches).
- **Alternatives not taken:** `AddressDisplay full` for the import preview (it hides the address behind a matched name); extending `EntityStorage.requireKeyIdentityMatch` to composite keys (larger primitive change for one root — inline compare wins); demoting a name/selector-mismatched fast-path call to the slow path (would silently execute; reject instead); a `.max(Date.now())` schema bound on `updatedAt` (time-dependent schema; write-side clamp is deterministic).

## Security & Adversarial Considerations
- Threat model for this batch: a lying RPC (F-01), a dApp with a narrow simulation grant (F-08), a doctored backup (F-03, F-12), a raw storage writer (F-13), a delayed internal continuation after lock (F-15), any web page probing extension resources (F-17), a log reader (F-10, CSV).
- Every change tightens a check; none adds a new input path, credential, or network call. The data-URI icon removes a world-readable resource; the manifest loses a permission surface.
- Crypto: no algorithm or vector changes; `zeroize` only. `key-vectors.test.ts` must stay byte-identical — its failure is a stop.
- Fail-closed everywhere: mismatches throw (chain identity, fast path, account address, pending-restore TTL); nothing silently demotes.
- Supply chain: no new dependencies.

## Assumptions
**Facts (verified in recon.md):** (1) every `assertLiveChainIdentity` caller passes a full `Network` carrying `l1ChainId` (`network/spec.ts:69`); (2) `assertCanonicalL1ChainId` exists in wallet-crypto with no external callers and aztec-runtime may import wallet-crypto (layer order); (3) the SDK types `walletIcon` as a plain string and never validates its scheme; (4) `Input.vue` already forwards `autocomplete`; (5) `consumeDekRewrapContext` (`profile/service.ts:221-225`) is the TTL idiom; (6) `liveRows` (`account/service.ts:88-106`) is the composite-key compare; (7) `updateFpcAddress` refuses `PrivateFpc` address edits (but see Inference d).
**Inferences:** (a) dApps render the discovery icon with `<img src>`, so a `data:` URI displays unless their CSP `img-src` omits `data:` — accepted; verified against the playground at Phase 6. (b) Some flatten-before-log sites beyond the two demonstrated may carry URLs — unverified, so the `trim()` backstop is mandatory and the ban test flags the idiom itself; the flagged sites get converted rather than allowlisted (the file-level `ALLOWLIST` at `log-payload-ban.test.ts:421` skips whole files and is not used for this). (c) Vite's `?inline` import works inside the SW bundle (crxjs) — verify at Phase 6; fallback is a build-time base64 constant. (d) Fact 7 was overclaimed: `addFpc` (`fpc/service.ts:276,315`) accepts a `PrivateFpc` at any address even though edits are refused; the `getFpcImpl` gate is what makes such a row unusable.
**Asks:** none open — all resolved by `../seed.md`. Open asks for codex (this audit): the local-network handling in F-01; F-17 data-URI acceptance; inline compare vs primitive extension for F-13.
