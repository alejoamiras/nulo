Blueprint · light · batch 1 of 4 · 2026-09-14

Harden B1 Mechanical Fixes

The first of four batches fixing the 2026-09-13 security audit. Every change here is a small, hours-scale fix that copies a pattern already in the wallet's code. No storage migration, no redesign.

What this batch fixes

  • F-01 The check that the RPC node is really on the selected chain compared a single mixed number. It now checks the L1 chain id exactly, bounds both values to 32 bits (Codex found a second way to alias the mixed number), and keeps the mixed compare as well. One helper, no caller churn.
  • F-08 The simulation fast path trusted the function name a dApp sent while executing the selector it sent. It now resolves the selector against the contract's ABI first, rejects a mismatch, and falls back to the slow, fully-validated path if a call turns out not to be public and static.
  • F-03 (half) The fee-payer picker chose the first "Private Fee Juice" row of that type; it now requires the protocol-derived one, and the execution path refuses any other. The backup slice that let a fake row in is dropped in batch 2.
  • F-10 RPC error strings that carried an endpoint URL (with an API key) reached the log; the logger now scrubs URLs in plain strings and the two demonstrated sites log the error object.
  • F-12 Restored contact names get the same sanitizer the import path uses; restored balances are marked stale so they refresh.
  • F-13 Account lookups by key now also require the row's address to equal the requested one, so a transplanted row cannot redirect signing.
  • F-15 A pending passkey-restore secret now expires as designed and is wiped on lock.
  • F-17 The wallet logo is no longer web-accessible to every site; the discovery response carries it inline.
  • Hygiene Zeroize password and token buffers after use; autocomplete on secret inputs (off for the recovery phrase); neutralize spreadsheet formulas in the log export; two write-before-check orderings fixed; the account-import preview shows the full address.

Known limit

An inline (data URI) icon will not render on a dApp whose Content-Security-Policy forbids data: images. Narrowing the manifest instead would break icons on every dApp not listed, so inline wins. Verified against the playground before the PR opens.

Why light

Zero high-risk dimensions: no novelty (every fix mirrors an existing pattern), bounded blast radius, reversible, no migration, no external coupling. Security-sensitive by subject but not by mechanism. The owner set the tier in the seed.
