Harden B2 Backup and Passkey

The second of four batches fixing the 2026-09-13 security audit. Three surfaces get smaller: a backup file can no longer carry fee-payer or network rows, adding a custom network becomes a Developer-Mode action, and the passkey's Relying Party moves to a subdomain that serves nothing.

What this batch fixes

  • F-03, second half. A doctored backup could plant a fake "Private Fee Juice" payer. The fee-payer rows leave the backup entirely; the wallet re-derives the protocol payers on its own, and a user-added sponsored payer is re-added by hand.
  • F-04. A doctored backup could bind the restored profile's "mainnet" to an attacker's RPC. Network rows leave the backup too. On import the wallet re-creates its built-in networks (mainnet, testnet, local) for the new profile from constants compiled into the extension, then re-attaches the imported account state and history to those rows by chain id. A backup can still choose among the built-in networks; it can no longer define one.
  • F-04, the gate. "Add network" shows only with Developer Mode on. Editing endpoints on the built-in networks stays available to everyone, and a profile that already has custom networks keeps managing them.
  • F-05. Any page on nulo.sh or its application subdomains could run the passkey ceremony and reproduce the wallet's master secret. The Relying Party ID becomes passkey.nulo.sh, the wallet's own content script is kept off that host, and the build gate that pins the value keeps working unchanged.

Owner action

Provision passkey.nulo.sh as a static page with a strict Content-Security-Policy and no scripts, and keep every *.passkey.nulo.sh descendant content-free (subdomains stay eligible for the passkey). The code change is safe to land first; it must land before any real passkey wallet exists, because changing the Relying Party later bricks them.

What codex changed

Round 1 rejected the first reseed design: the seeding routine also refreshes a per-chain node cache, so restoring profile B while profile A is active would have pointed A at B's default endpoint. The reseed now writes only the new profile's rows and its active pointer, and a test pins that A's endpoint survives. Round 2 rejected the dead-RPC test fixture binding the built-in local port (another agent's run may own it); the test now reroutes requests through the browser's own interception instead. Round 3 approved.
