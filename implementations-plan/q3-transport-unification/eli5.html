Q3 — Unify the forked background/offscreen RPC transports

The wallet talks to itself over two internal "phone lines": one between the popup and the background service worker, and one between the background worker and the offscreen page (which runs the heavy Aztec proving). Both lines were built twice, almost identically — ~973 lines of near-duplicate request/timeout/error plumbing across four files. Every fix to one line has to be paid again on the other, and the two lines disagree on one important thing: when something fails, the background line hands back a proper typed error, but the offscreen line hands back a bare string. This plan merges the two lines into one shared core, and fixes that error mismatch — so a failure looks the same whichever line it came down.

Why this tier was chosen

deep (3 of 6 rubric dimensions HIGH): blast radius (the wallet's entire RPC boundary — 21 background service clients + the PXE offscreen path + the dApp error envelope), irreversibility (moderate — touches every RPC), security sensitivity (the trust boundary + a changing error contract). Three independent plans (me + codex + a planning subagent) were drafted, consolidated, then double-audited — both auditors initially rejected, and their findings reshaped the plan (see below). That's the deep tier earning its keep.

Phases

Phase 0: Get the transports under test, where they live

Move the existing transport contract tests into the package that owns the code, and add the missing service-side + timer-cleanup tests. Pin today's behavior (including the to-be-changed string errors) so every later step is provably safe.

Proves itself by: the new unit suites pass and reproduce today's behavior; no production code touched.

Phase 1: Extract the shared pure helpers + fix the bugs they expose

Pull the genuinely-identical pieces (decode, timeout bookkeeping, error-response builder) into one place and wire the background side to them. Fix three real bugs the tests surface — including the offscreen side silently hanging when a result can't be serialized.

Proves itself by: unit + consumer tests green; new tests show a malformed message returns a clean error instead of hanging; network e2e (liveness).

Phase 2: One shared "request correlator" for both clients (riskiest)

Both clients track in-flight requests, ids, and timeouts. Merge that bookkeeping into one base class, with the transport-specific bits (reconnect, keepalive, telemetry) staying as plug-in hooks. This is the riskiest step — a sloppy merge could silently double-answer or leak a timer.

Proves itself by: unit tests for every race (timeout-then-late-reply, send-fail-then-disconnect) — exactly-once is unit-proven, not e2e-hoped — PLUS a real-Chrome e2e leg that proves the lifecycle things a fake browser can't (service-worker death → reconnect → request still resolves). Mock proves logic; real Chrome proves lifecycle.

Phase 3: One shared service core (+ lock the callable surface)

Merge the server-side request handling into one base. While here, fix a latent security weakness: today a message can name any method on the service object (even inherited ones) — restrict it to the intended RPC surface. The offscreen side starts emitting the structured error payload here (harmless — the offscreen client ignores it until Phase 4).

Proves itself by: a unit test proving a non-registered method name is rejected; a unit test proving the keepalive ping fires on schedule, AND a real-Chrome e2e proving a >30s proving job actually completes without the worker dying (only a real browser can prove that); smoke + network.

Phase 4: Make the offscreen line return typed errors (and keep the dApp's view stable)

The offscreen client stops returning bare strings and returns proper typed errors like the background line. Critically — these errors do reach connected dApps via the response envelope, so we add explicit handling there so the dApp-visible error message stays intentional and stable. Migrate the handful of tests that asserted the old string shape.

Proves itself by: offscreen unit tests assert typed errors; a dApp-error-contract check (a prove/simulate timeout yields the intended response.error); smoke + network.

Phase 5: Security hardening sweep

A thin /harden security pass over the now-shared seam: reject malformed/hostile cross-context messages, duplicate ids, replayed responses.

Proves itself by: hostile-message tests show bad input is dropped safely (listener never crashes); network.

Human context

"Background" and "offscreen" are two Chrome-extension execution contexts. Aztec proving is heavy and can't run in the service worker, so it lives in the offscreen page; the worker talks to it over Chrome messaging. The two transports drifted because they were written at different times for different Chrome APIs (long-lived Port vs one-shot sendMessage). The error mismatch is a real latent bug: a PXE failure today reaches a connected dApp as a slightly different string than an equivalent background failure, and some internal "is this just a benign disconnect?" checks don't even recognize the offscreen string form.
