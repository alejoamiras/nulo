# M4.1 — codex (xhigh) audit

Date: 2026-04-26

- BLOCKING: [`implementations-plan/M4/1/plan.md:52-58`](<(project root)/implementations-plan/M4/1/plan.md:52>) assumes Design 2 can start from a “user-initiated dApp connect” after removing static `content_scripts`, but today first contact only exists because the always-on content script forwards discovery into `onPendingDiscovery` ([`packages/extension/src/wallet/services/wallet-sdk/background.ts:106`](<(project root)/packages/extension/src/wallet/services/wallet-sdk/background.ts:106>), [`:252`](<(project root)/packages/extension/src/wallet/services/wallet-sdk/background.ts:252>)). Without a new bootstrap path, new dApps cannot be discovered at all. Change the memo to specify the bootstrap mechanism up front: extension action “Connect this site”, context-menu flow, or a tiny discovery-only static injector. This also means the recommendation heuristic at [`plan.md:73-80`](<(project root)/implementations-plan/M4/1/plan.md:73>) should hinge on willingness to add that UX, not on ecosystem size.
- BLOCKING: Design 1’s guard/test plan is assigned to the wrong seam. [`plan.md:37-39`](<(project root)/implementations-plan/M4/1/plan.md:37>) and [`:97-109`](<(project root)/implementations-plan/M4/1/plan.md:97>) propose `event.source` / origin filtering in `content.ts`, but the live file only hands transport callbacks to `ContentScriptConnectionHandler` and never sees raw page `MessageEvent`s ([`packages/extension/src/content-script/content.ts:11-19`](<(project root)/packages/extension/src/content-script/content.ts:11>)). Make the SDK audit currently listed as “prework” at [`plan.md:84-85`](<(project root)/implementations-plan/M4/1/plan.md:84>) a hard pre-M4.1 gate, then choose one of two real options: vendor/wrap the SDK locally so Nulo owns page-message filtering, or drop hostile-frame rejection as a Design 1 invariant and focus only on scope reduction.
- BLOCKING: Design 2’s migration/revocation state model is underspecified. The memo says “persist registered hosts via M4.7 migrator” and “re-authorize on first boot” ([`plan.md:115-119`](<(project root)/implementations-plan/M4/1/plan.md:115>)), but today the durable state is `nulo:core:dappSessions` ([`packages/extension/src/wallet/services/dapp-session/service.ts:29`](<(project root)/packages/extension/src/wallet/services/dapp-session/service.ts:29>), [`:78-90`](<(project root)/packages/extension/src/wallet/services/dapp-session/service.ts:78>)), and “Disconnect session” only deletes that row ([`dapp-session/service.ts:263-277`](<(project root)/packages/extension/src/wallet/services/dapp-session/service.ts:263>), [`connected-apps/index.vue:84-103`](<(project root)/packages/extension/src/popup/pages/settings/connected-apps/index.vue:84>)). Change the memo to define the source of truth and reconciliation rules: boot behavior when session exists but host permission does not, and disconnect behavior for permission/script cleanup. Prefer boot-time reconciliation against permissions + sessions over coupling M4.1 to M4.7.
- SHOULD-FIX: Design 2’s tests at [`plan.md:121-124`](<(project root)/implementations-plan/M4/1/plan.md:121>) miss the risky transitions. Add tests for “existing session but no site permission” and “disconnect session cleans up or intentionally preserves site access,” otherwise the migration path is not actually covered.
- NIT: [`plan.md:108`](<(project root)/implementations-plan/M4/1/plan.md:108>) should not say “Malformed JSON rejected.” `chrome.runtime.onMessage` delivers structured values, and the current content script does not parse JSON ([`content.ts:12-18`](<(project root)/packages/extension/src/content-script/content.ts:12>)). Replace it with “invalid envelope / unexpected sender shape rejected.”
