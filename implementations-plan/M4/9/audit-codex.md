# M4.9 — codex (xhigh) audit

Date: 2026-04-26

- BLOCKING — `implementations-plan/M4/9/plan.md:47-49` only rewires `rpId`, but the creation flow also hardcodes the RP ID in `packages/extension/src/popup/windows/passkey/index.vue:35-40`, alongside the get-flow literal at `:85-89`. The `rpId:` drift scan proposed in `plan.md:60,113` would miss the create path entirely. Change Step 1 so `RP_ID` replaces both `rp.id` and `rpId`, and make the drift check fail if either WebAuthn options object contains a string literal. A targeted check on `src/popup/windows/passkey/index.vue` (AST or narrow regex after comment stripping) is better than a repo-wide `rpId:` grep.
- BLOCKING — `implementations-plan/M4/9/plan.md:55-65` says `check-rp-id.ts` runs before build but reads built Chrome + Firefox manifests. That is internally inconsistent with the actual build topology: `packages/extension/package.json:9-12` builds Chrome and Firefox separately, `packages/extension/vite.chrome.config.mts:4-18` and `vite.firefox.config.mts:4-18` emit to different outDirs, and the repo currently only has a stale Chrome artifact (`packages/extension/dist/chrome/manifest.json:1-9` still says `0.13.0`, while `packages/extension/package.json:6` is `0.13.1`). As written, `bun run build` on a clean tree cannot reliably pre-check both browsers. Keep the pre-build script if you want the simpler/testable approach, but have it import and validate the source manifest modules (`manifest.config.ts` and the two browser wrappers) directly. If you really want to validate emitted `manifest.json`, move that check post-build or into a Vite hook.
- SHOULD-FIX — `implementations-plan/M4/9/plan.md:86,98-100` claims CI coverage that the repo does not currently provide. A test at `packages/extension/scripts/check-rp-id.test.ts` will not run under the current Vitest include set (`packages/extension/vitest.config.ts:47-55` only picks up `src/**/*.test.ts` and other packages’ `src` tests), and `bun run typecheck` will not typecheck `scripts/**/*.ts` (`packages/extension/tsconfig.json:21`; `packages/extension/tsconfig.node.json:18-24`). Either move the checker/tests under `src/` or expand Vitest + TS config. The three manifest mismatch cases are the right baseline once wired, but if the source-drift scan remains, add one test for `rp.id` and one false-positive comment case.
- NIT — `implementations-plan/M4/9/plan.md:70-75` says to add a new `SECURITY.md` subsection, but the RP ID is already documented as a crypto-bound invariant at `SECURITY.md:7-29`. Update that existing entry to reference `RP_ID` and `check-rp-id.ts` instead of creating a second statement of the same contract in another section.
