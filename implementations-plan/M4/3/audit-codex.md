# M4.3 — codex (xhigh) audit

Date: 2026-04-26

- `BLOCKING` [plan.md](<(project root)/implementations-plan/M4/3/plan.md:15>) and [plan.md](<(project root)/implementations-plan/M4/3/plan.md:78>) say the trust check moves into `ArtifactRegistry`, but the registry-source validation is still specified inside `HttpRegistryFetcher.fetchArtifact`. `RegistryFetcher` is the abstraction seam in [artifact-registry.ts](<(project root)/packages/aztec-runtime/src/pxe/artifact-registry.ts:55>), and `ArtifactRegistry.resolve` currently trusts whatever the fetcher returns at [artifact-registry.ts](<(project root)/packages/aztec-runtime/src/pxe/artifact-registry.ts:203>). Change Step 2 so `ArtifactRegistry.resolve(...)` runs `verifyArtifactClassId(...)` on every returned artifact before returning, including `"registry"`. Keep `HttpRegistryFetcher` responsible for fetch + schema parse only. That matches the stated invariant and makes test #1 in [plan.md](<(project root)/implementations-plan/M4/3/plan.md:103>) honest for stub fetchers too.
- `BLOCKING` The Step 1 code sketch has the wrong imports. [plan.md](<(project root)/implementations-plan/M4/3/plan.md:37>) imports both `ContractArtifact` and `getContractClassFromArtifact` from `@aztec/stdlib/contract`, but this repo consistently gets `ContractArtifact` from `@aztec/stdlib/abi` and the helper from `@aztec/stdlib/contract` in [artifact-registry.ts](<(project root)/packages/aztec-runtime/src/pxe/artifact-registry.ts:2>) and [execution/service.ts](<(project root)/packages/extension/src/wallet/services/execution/service.ts:24>). Update the snippet and execution notes accordingly. Also, the note at [plan.md](<(project root)/implementations-plan/M4/3/plan.md:72>) names `ContractClassPublic`; the installed type is `ContractClassWithId & ContractClassIdPreimage`, not that alias.
- `SHOULD-FIX` Step 3 is internally inconsistent. [plan.md](<(project root)/implementations-plan/M4/3/plan.md:89>) and [plan.md](<(project root)/implementations-plan/M4/3/plan.md:126>) talk like M4.3 includes build-time define/gate work, but [plan.md](<(project root)/implementations-plan/M4/3/plan.md:93>) and [plan.md](<(project root)/implementations-plan/M4/3/plan.md:95>) say first cut is just an inline array and env-aware substitution is out of scope. In this repo, build-time defines live in the extension bundler/test runner at [vite.config.ts](<(project root)/packages/extension/vite.config.ts:201>) and [vitest.config.ts](<(project root)/packages/extension/vitest.config.ts:33>), and the current chainId switch already fail-closes to fixed `https` URLs at [artifact-registry.ts](<(project root)/packages/aztec-runtime/src/pxe/artifact-registry.ts:93>). Pick one story. My recommendation: M4.3 ships the inline `REGISTRY_ALLOWLIST` only; env-aware substitution can be follow-up.
