# M4.4 — codex (xhigh) audit

Date: 2026-04-26

- **BLOCKING** — The “durable + reapable” design is not durable and cannot recover across SW restart. [implementations-plan/M4/4/plan.md:87](<(project root)/implementations-plan/M4/4/plan.md:87>) makes `pendingMeta` in-memory only, then [plan.md:94](<(project root)/implementations-plan/M4/4/plan.md:94>) explicitly says restart reconstructs nothing. That makes the claimed boot-time orphan reap in [plan.md:96](<(project root)/implementations-plan/M4/4/plan.md:96>), the unit test in [plan.md:136](<(project root)/implementations-plan/M4/4/plan.md:136>), and the manual QA in [plan.md:162](<(project root)/implementations-plan/M4/4/plan.md:162>) impossible as written. It also misses the milestone target of “durable request ids” in [architecture/plan/03-final-plan-v3.md:225](<(project root)/architecture/plan/03-final-plan-v3.md:225>). Change: either persist pending request metadata in storage and rehydrate/reap it at boot, or explicitly descoped restart recoverability from M4.4 and rename the work to observability-only.
- **BLOCKING** — The 5-minute reap path is unreachable while the 90-second request timeout stays unchanged. [plan.md:33](<(project root)/implementations-plan/M4/4/plan.md:33>) preserves the 90s timeout; [plan.md:118](<(project root)/implementations-plan/M4/4/plan.md:118>) sets reap at 5 minutes. In a live SW, every pending request dies at 90s first; after restart, the maps are empty. So the alarm in [plan.md:120](<(project root)/implementations-plan/M4/4/plan.md:120>) and adversarial 6-minute test in [plan.md:165](<(project root)/implementations-plan/M4/4/plan.md:165>) do not exercise a real state. Change: if you want `orphaned`, persist only metadata and fence it on boot; otherwise drop `orphaned`/alarm scope entirely.
- **BLOCKING** — The plan still misses the immediate `chrome.runtime.sendMessage` failure window, which is the closest match to the incident. Current code stores pending state before `await chrome.runtime.sendMessage(request)` and does no cleanup if that await rejects: [packages/extension-messaging/src/offscreen/client.ts:141](<(project root)/packages/extension-messaging/src/offscreen/client.ts:141>) and [client.ts:153](<(project root)/packages/extension-messaging/src/offscreen/client.ts:153>). But the terminal enum in [plan.md:47](<(project root)/implementations-plan/M4/4/plan.md:47>) and the tests in [plan.md:128](<(project root)/implementations-plan/M4/4/plan.md:128>) omit any `send_failed` path. Change: add a transport-send-failure terminal, wrap `sendMessage` in `try/catch`, clear request/timer/meta synchronously, and add a contract test that mocks `sendMessage` rejection.
- **BLOCKING** — The plan says “the popup will retry naturally” in [plan.md:94](<(project root)/implementations-plan/M4/4/plan.md:94>) and tests “retry after recreate” in [plan.md:135](<(project root)/implementations-plan/M4/4/plan.md:135>), but it never does the architecture-required idempotency catalog from [architecture/plan/02-final-plan.md:242](<(project root)/architecture/plan/02-final-plan.md:242>). The PXE client mixes read calls with mutators like `registerAccount` and `registerContractClass`: [packages/aztec-runtime/src/pxe/client.ts:59](<(project root)/packages/aztec-runtime/src/pxe/client.ts:59>), [client.ts:83](<(project root)/packages/aztec-runtime/src/pxe/client.ts:83>). Change: add a method table classifying each PXE RPC as safe-to-retry, unsafe-to-retry, or requires caller compensation, then scope recoverability claims/tests to the safe subset.
- **SHOULD-FIX** — The telemetry seam is fine as an optional ctor dependency; full DI is unnecessary here. But the sketch in [plan.md:73](<(project root)/implementations-plan/M4/4/plan.md:73>) should use existing `ILogger`/`LogLevel`, not a duck-typed logger plus `2 /* Info */` in [plan.md:76](<(project root)/implementations-plan/M4/4/plan.md:76>) which is actually `Warn` in [packages/wallet-core/src/logger/interfaces.ts:14](<(project root)/packages/wallet-core/src/logger/interfaces.ts:14>). Also, [plan.md:126](<(project root)/implementations-plan/M4/4/plan.md:126>) names the wrong harness: offscreen tests should mirror background invariants, but use the existing `sendMessage` harness, not the port harness ([packages/extension/tests/vitest.setup.ts:33](<(project root)/packages/extension/tests/vitest.setup.ts:33>), [background/client.test.ts:21](<(project root)/packages/extension/src/wallet/base/background/client.test.ts:21>)).
