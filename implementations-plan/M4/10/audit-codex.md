# M4.10 — codex (xhigh) audit

Date: 2026-04-26

- BLOCKING — The proposed `migration-registry` hook does not fit the M4.7 contract. `CollectionMigrator` is explicitly single-root `MinimalStorageArea` and “MUST NOT touch any other root”, but the M4.10 PXE step enumerates IndexedDB and reads `nulo:core:networks` from another root ([implementations-plan/M4/10/plan.md:129-167]((project root)/implementations-plan/M4/10/plan.md:129), [implementations-plan/M4/7/plan.md:83-126]((project root)/implementations-plan/M4/7/plan.md:83)). This also cannot stay an “execution-time decision” because ordering against `nulo:core:networks` is a correctness requirement, not a nice-to-have ([implementations-plan/M4/10/plan.md:229]((project root)/implementations-plan/M4/10/plan.md:229), [implementations-plan/M4/10/plan.md:239]((project root)/implementations-plan/M4/10/plan.md:239)). Change: either extend M4.7 with a separate boot-migration type that can read both storage and IndexedDB plus explicit `after: ["nulo:core:networks"]`, or keep the PXE rename outside the per-root runner and invoke it only after the networks root has migrated.
- BLOCKING — The orphan-cleanup design would delete recoverable pre-M4.10 DBs and also misses inactive-profile networks. The sample preserves only hashed names ([implementations-plan/M4/10/plan.md:104-118]((project root)/implementations-plan/M4/10/plan.md:104)), but the same plan later says an old-shape DB with a matching current network must be preserved for the migrator ([implementations-plan/M4/10/plan.md:184-185]((project root)/implementations-plan/M4/10/plan.md:184)). On top of that, `NetworkService.getNetworks()` only returns the active profile’s networks, not all profiles’ networks ([packages/extension/src/wallet/services/network/service.ts:100-109]((project root)/packages/extension/src/wallet/services/network/service.ts:100)). Change: preserve both `pxe/{profile}/{chain}` and `pxe/{profile}/{chain}/{hash}` for any known network until migration has succeeded, and add an all-profiles network reader plus the necessary offscreen wiring ([packages/aztec-runtime/src/offscreen/entry.ts:20-33]((project root)/packages/aztec-runtime/src/offscreen/entry.ts:20), [packages/extension/src/offscreen/index.ts:41-45]((project root)/packages/extension/src/offscreen/index.ts:41)).
- BLOCKING — `renameIndexedDb` is not specified tightly enough to satisfy the plan’s own idempotence requirement. The text says “copy then delete” and “re-attempts” ([implementations-plan/M4/10/plan.md:163-165]((project root)/implementations-plan/M4/10/plan.md:163), [implementations-plan/M4/10/plan.md:224-225]((project root)/implementations-plan/M4/10/plan.md:224)), but it never defines behavior for `newName` already existing, both DBs existing, or crash-after-old-delete-before-sidecar-bump. The tests at [implementations-plan/M4/10/plan.md:190-192]((project root)/implementations-plan/M4/10/plan.md:190) assume a contract that is not written. Change: codify re-entry rules in the helper: `old missing + new present => already migrated`, `both present => either verify-and-delete old or delete/recreate target from old`, and only bump the migration version after every DB reaches a settled state.
- SHOULD-FIX — The plan says `ChainRuntime` is unchanged ([implementations-plan/M4/10/plan.md:31]((project root)/implementations-plan/M4/10/plan.md:31)) but then changes its exported constructor shape ([implementations-plan/M4/10/plan.md:83-95]((project root)/implementations-plan/M4/10/plan.md:83)). That breaks existing direct callers/tests such as [packages/extension/src/wallet/services/pxe/chain-runtime.test.ts:30-31]((project root)/packages/extension/src/wallet/services/pxe/chain-runtime.test.ts:30). Change: either keep backward compatibility with optional trailing params/static factory, or drop `rpcUrlHash`/`dataDir` from the class; the cleanup flow described here does not require storing them on the runtime object.
- SHOULD-FIX — The test/verification section does not match the repo. The plan says all tests live in `packages/aztec-runtime/src/pxe/` and recommends `bun run --filter '@nulo/aztec-runtime' test` ([implementations-plan/M4/10/plan.md:171-213]((project root)/implementations-plan/M4/10/plan.md:171)), but `@nulo/aztec-runtime` currently has no `test` script ([packages/aztec-runtime/package.json:15-17]((project root)/packages/aztec-runtime/package.json:15)) and the existing chain-runtime suite is under extension ([packages/extension/src/wallet/services/pxe/chain-runtime.test.ts:1]((project root)/packages/extension/src/wallet/services/pxe/chain-runtime.test.ts:1)). Change: either add an aztec-runtime test harness explicitly or point the plan at the extension Vitest surface and real commands.
