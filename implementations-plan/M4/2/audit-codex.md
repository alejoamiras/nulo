# M4.2 — codex (xhigh) audit

Date: 2026-04-26

**Codex audit BLOCKING**: M4.2 must not be written as a normal implementation plan with default `(a)`. The current `SECURITY.md:73` security contract explicitly requires the replacement to be "a session token that cannot itself decrypt the secret." If we default to design `(a)` (device-local session key wrap) **and** the wrap-key is co-located with the wrapped secret in `chrome.storage.session`, design `(a)` is just "passhash with different packaging" — the threat model doesn't shift.
**Plan agent audit BLOCKING**: same conclusion via different reasoning — wrap-key extraction makes design `(a)` no better than today.
**Codex audit BLOCKING**: M4.8 depends on more than M4.2. Passkey pending requests are memory-only at `packages/extension/src/wallet/services/passkey/service.ts:26` (`private pending: Map<string, PendingPasskey> = new Map()`). On SW restart, every in-flight passkey request is dropped. The pre-existing audit (`architecture/codex-notes/08-passkey-flow.md:198`) already flagged this.
**Codex audit BLOCKING**: do NOT introduce a per-record `version` field. `EntityStorage` already has **collection-level** `getVersion()` / `setVersion()` (`packages/wallet-core/src/storage/entity_storage.ts:33-40`). M4.7 should:
**Plan agent audit BLOCKING**: write fence — per-collection mutex during migration. Re-use existing `Lock` primitive at `packages/wallet-core/src/utils/lock.ts`.
- **M4.7 must precede M4.10** (codex BLOCKING). M4.10's `${profileId}/${chainId}/${sha256(rpcUrl)}` PXE data-dir scheme requires a one-time IndexedDB rename, which M4.7's per-collection migrator handles cleanly. Without M4.7 first, M4.10 ships its own one-shot wipe — strictly worse.
- `audit-diff.md` — what changed in the plan after audit feedback (BLOCKING fixes applied, SHOULD-FIX inline-noted, NITs dropped)
- `BLOCKING` `implementations-plan/M4/2/plan.md:42` and `:65` contradict each other on the non-extractable `CryptoKey` alternative. The memo first says cached non-extractable key material is “the same problem at a different layer,” then later says a per-installation non-extractable key is the mandatory Design A fallback. Rewrite this section to distinguish:
- `SHOULD-FIX` `implementations-plan/M4/2/plan.md:67-83` overclaims that all five prework items are “safe to do now, regardless of decision.” The `SessionToken` abstraction at `:73` and its M2.6 vector at `:83` are not design-agnostic; Design B does not need a token or new session crypto at all. The `SECURITY.md` update at `:82` also should not pre-announce an unapproved path in a source-of-truth security doc. Keep the safe prework to inventory/TODO/test scaffolding; defer `SessionToken` and security-contract edits until the decision is final.
- `SHOULD-FIX` `implementations-plan/M4/2/plan.md:71-72` underscopes the passhash inventory. It lists service-layer `getPasshash` callsites but misses live UI uses in `packages/extension/src/popup/pages/import.vue:265` and `packages/extension/src/popup/pages/settings/security/export/full.vue:139`. Change this from a hand-curated list to a repo-wide grep baseline for both `getPasshash` and `fromPasshash`, otherwise the “centralize passhash handling” prework is incomplete.
- `SHOULD-FIX` `implementations-plan/M4/2/plan.md:89-107` is too loose on legacy cleanup and too unit-centric in tests. `:92` punts old `session.passhash` cleanup to M4.7, while `:106` treats “lock screen presented” like a `SessionManager` assertion. Either state that M4.2 execution depends on M4.7 having landed, or specify M4.2’s own boot-time scrub/ignore behavior for legacy `{ passhash }` session records. Then add one popup-boot integration test through the real auth fallback in `packages/extension/src/popup/app.vue:178` and `packages/extension/src/popup/index.ts:76`, not just SessionManager tests.
- `NIT` `implementations-plan/M4/2/plan.md:102` proposes SECURITY wording that is too broad. `chrome.storage.session` will not contain “only encrypted profile + opaque session record”; the repo also stores session-scoped journal/log data there (`packages/extension/src/wallet/services/operation-journal/service.ts:43`, `packages/extension/src/wallet/logger/store.ts:67`). Reword the row to the narrower claim: reading `nulo:core:session` no longer compromises the master secret; other session-storage metadata may still leak.
