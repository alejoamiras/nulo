Correction to round 1 I wrote that off-list signature requests "still prompt". They are refused. The real rules (checkCreateAuthWit, handleCreateAuthWit): a request for a call on the app's list is signed with no popup; a call off the list is refused; a request that names only a contract and a hash opens a confirmation popup, and only if the app's list covers every function of that contract; a bare hash is always refused. An app with no transaction or simulation list at all gets a popup for every call.

What an app sends

  • Per permission, a list of contract address + function name pairs, or "*" for any. Nothing else: no token names, no descriptions, no purpose.
  • The tools app's real request on testnet (buildCombinedManifest, four bridge tokens) lists 12 contracts and 57 contract-function pairs, and asks for signatures.
  • Function names are the app's words. When a call comes in, Nulo checks it against the list by name, and the name must match the function actually called (matchesScope plus the name-to-selector check). So a name can't lie about which function runs, but nothing says what that function does.

What Nulo can check

  • Today it recognizes nothing: the window prints raw addresses, with your own contact name in brackets (ScopeAddress.vue).
  • What it could vouch for is short: the tokens it ships (two on mainnet, one on testnet, each pinned to its contract class in default-tokens.ts) and the contracts it uses itself: Fee Juice, the sponsor, the private fee payer and the auth registry.
  • A token an app registered, or a contact you named, doesn't count. The address-first rule exists because a label can be planted, so those stay addresses.
  • Aside, not part of this item: testnet's shipped "Test USDC" (0x1c81…e9ae) is no longer in the tools bridge's list, whose USDC is 0x0024…6502. So today even the tools app's own token would show as unknown.

My pick: Off = ask

An Off that quietly breaks the app is a trap: people who switch it off meet a failure later, with no link back to this screen. "Ask me each time" is what someone switching it off actually wants, and the confirmation window it needs already exists. It also lets Nulo default to Off whenever the list is "any contract". Separately, I'd stop letting every card be unticked: unticking simulation, contracts or transactions just breaks the app, so switches stay only where Off leaves a working app (signatures, the address book, unknown permissions). Naming the four known contracts relaxes the address-first rule for that list only; if you'd rather not, the lines keep only the counts.

Confidence: high that the check becomes a real switch with its consequence on screen; moderate on "ask" as the meaning of Off.
