Some rows look clickable, some are clickable, rarely both

HistoryHome recent activitySettings rows
Your noteThe hover is weird: some transactions have pointers, some don't. Incoming might not have a pointer but you can click on them, etc. Try to improve the consistency. It's confusing.

What the code does

  • Four row types share TransactionCardLayout.vue, which sets no cursor and no hover. Each wrapper adds its own, or doesn't:
  • Settled sends (TransactionCard.vue): pointer and hover. Received (TransactionIncomingCard.vue) and cancelled or failed (TransactionTerminalCard.vue): clickable, with neither. In-flight (TransactionAwaitingCard.vue): pointer only while it waits for approval, no hover.
  • None of them works from the keyboard: they're divs with click handlers. Same story on capability cards, the auth-witness revoke icon and focusable settings rows that Enter doesn't activate.

What the research says

  • Weak signifiers cost time: in NN/g's eyetracking, people spent 22% longer on pages with flat, ambiguous clickables (NN/g).
  • Platforms disagree on whether buttons get the hand cursor (Tailwind v4 dropped it to match browsers). In a dense popup, consistency matters more than which convention you pick.
  • MetaMask, Phantom and Rainbow open a detail view from every activity row; none of the wallets surveyed mixes clickable and inert rows in one list.

What changes

  • The shared layout becomes the interactive element when a row opens something: pointer, full-row hover tint, and a keyboard focus ring that matches the hover. Wrappers stop adding their own.
  • Real elements: a link when it navigates, a button when it opens a window. Enter and Space work.

The rules, for every list in the wallet

  1. If a row opens something, the whole row is the target: pointer, hover, and a matching focus ring.
  2. Rows that do nothing get no hover and no pointer.
  3. Buttons inside a row (copy, cancel) are their own targets, at least 24×24, and don't trigger the row.
  4. A pending row that can be opened looks exactly like a settled one.
  5. The same row behaves the same on Home and in History.

Effort: small to medium. The layout, four wrappers, and the stragglers listed above.

My pick: A

Every activity row opens something, so the fix is to make them all say so, the same way, from one place, and to make them work from the keyboard. The rules also cover the other lists with the same bug. B's chevron is a reasonable extra if you want a signal at rest, but in a list where every row opens, it repeats the same information on every line.

Confidence: high on A; low-moderate on whether a chevron helps here.
