05

Naming a profile before anyone knows what one is

Onboarding · step 02 Setup
Your noteThe requirement of setting a Profile Name on the onboarding "was too much". Feels like we can make it optional, or hidden under a toggle under "Advanced" or something with a default name. So the user just feels that it's setting up either passkeys or password, and doesn't have to stop and think why the F there are profiles.

What the code does

  • The first field on onboarding/pages/create.vue is a required "Profile name" (OnboardingProfileNameField.vue, placeholder "My Profile", max 32). It's checked on submit: empty shakes the field. Nothing on the page says what a profile is.
  • A profile is one recovery phrase with its own password or passkey and its own accounts. Most people will only ever have one.
  • The popup's "new profile" page shares the same flow (useProfileCreateFlow), so the name rule can differ per shell: optional at first run, asked when you add a second.

What others do

  • No product surveyed names the container at creation. Chrome starts at "Person 1", 1Password's default vault is "Personal", Bitwarden's is "My Vault", and Phantom never shows the recovery-phrase level until you import a second one (Phantom).
  • Pre-fill the most common value when you can know it in advance — NN/g on defaults. Field count, not step count, drives form cost (Baymard).
  • First-run concepts are expensive: only 43% of wallet users in a CHI '25 study could pick out a seed phrase (Of Secrets and Seedphrases).

What changes

  • The name field leaves the first-run page. The profile is named Main and can be renamed in Settings → Profiles.
  • Hero "Create / Profile" → "Create / Wallet"; the method label becomes "How you'll unlock Nulo"; CTA "Create wallet" / "Create with passkey".
  • Adding a second profile later (popup) keeps the name field, prefilled "Profile 2" — by then the word has been met.

Clicks

One fewer field; focus starts on the password (or the passkey button).

Effort: small. useProfileCreateFlow takes a default name when the shell hides the field.

My pick: A, default name "Main"

Every precedent defers the container until you create a second one, and that's exactly the complaint. "Main" rather than "Profile 1" because it doesn't re-teach the word people stumbled on, and it still implies there could be others. B is fine if you want power users to see the name up front, but it keeps a concept on the page that 99% of first runs don't need.

Confidence: high on removing the field; moderate on "Main".
