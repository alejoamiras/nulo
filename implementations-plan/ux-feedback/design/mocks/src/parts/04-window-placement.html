Nulo's windows land on top of the app's emoji check

Window placementConnect flow
Your noteThe request capabilities pop-up opened in the center of the window for my friend, and it was blocking the "encryption check" from the app. Maybe we can pop it up somewhere on the right?

What the code does

  • Connecting takes up to three Nulo windows in a row: Allow (discover), the emoji check (verify), then permissions (capabilities).
  • Allow, permissions and every transaction approval open centered on the browser window (centerOn in window-manager.ts). That's where dApps put their own modals, including the tools app's "Verify the grid".
  • The emoji window sets no position at all (session-established.ts calls windows.create with only a size). Chrome then offsets it from the browser window, so it also lands over the page.
  • Every window is 400×800. On a 1440×900 laptop that's nearly the full height; on a 768px screen it doesn't fit.
  • We can't tell from the report which window covered the check. Any of them could have.

What others do

  • Nearly every wallet anchors its window to the top-right of the last-focused browser window: MetaMask, Rabby, Phantom, Keplr, Argent X, Talisman, SubWallet, Backpack (MetaMask, Rabby, Argent X). None centers. They're 360–400 wide and 600–660 tall, and Rabby shrinks the height to fit short screens. Enkrypt sets no position — the same as Nulo's emoji window today.
  • Aztec: the dApp should "let the user confirm it matches what's shown in their wallet" before connecting. The docs give no placement advice, and the reference wallet shows the emojis inside its approval window (Aztec docs).
  • A side panel can't answer a dApp's request: Chrome and Firefox only open one "in response to a user action" (Chrome, MDN), so I dropped that idea.

What changes

  • A second placement next to centerOn: right edge and top of the last-focused browser window. The emoji window goes through the window manager too, so it gets the same spot.
  • Height becomes min(800, browser window height), so it never runs off a short screen.
  • Nothing inside the windows changes. It appears near the toolbar icon people click to open Nulo, so it reads as the same wallet.

Clicks

The app's Connect button → Nulo appears top-right → Allow → the emoji check replaces it in the same spot, with the app's grid still visible → permissions, same spot.

Limits: in a browser window narrower than about 1,100px, no corner clears a centered modal. The window can still be dragged. On macOS, a window opened from a full-screen browser can land in another Space; Coinbase opens a tab in that case. If Chrome rejects the position (it refuses windows less than half on-screen), retry with size only.

What changes

  • After Allow, the window stays open and switches to the emoji check once the secure channel is up (usually under a second), instead of closing so a second window can open.
  • Permissions stay a separate window: the app asks for them on its own schedule, and possibly never.

Clicks

Allow → the same window shows the emojis → OK closes it.

Effort: moderate, and it touches the security-critical verify path (slot reservation, fail-closed termination). Worth doing only after A.

What changes

  • Nulo saves the last position you drag its window to and reuses it next time, falling back to A.
  • A saved position is checked against the current screen before it's used, so unplugging a monitor can't strand the window off-screen.
  • Firefox has no "window moved" event; it would save on close instead.

Effort: small on top of A. It only helps from the second time.

My pick: A now, B later

A is what almost every wallet does, clears the app's center on common screen sizes, and gives all four windows one predictable home. The height cap fixes a separate bug on short screens. B is the better experience, but it reworks the verify path; I'd ship A, watch the next round of testers, then decide.

Confidence: high for A; moderate that B is worth its risk.
