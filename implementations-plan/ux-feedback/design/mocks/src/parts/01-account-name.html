"Account" reads like a label, not a name

Popup headerAccount switcherdApp account picker
Your noteThe default account should be named "Account 1" — the problem of it being "Account" is that when reading it, it looks like we are talking about SOME account. But if we put "Account 1" it's clearly a name.

What the code does

  • DEFAULT_ACCOUNT_NAME = "Account" in apps/extension/src/wallet/services/account/spec.ts:6 seeds the first account on every network.
  • The header uppercases the name right above the address (Header.vue), so it renders as ACCOUNT / 0x1dd7...d930 — exactly the shape of a field label. The avatar initials become AC.
  • Numbering is already inconsistent: the New Account popup suggests the lowest free Account N starting at 1 (NewAccountPopup.vue:101-105), so your second account is called "Account 1".

What others do

  • MetaMask: "You'll see that as your Account 1 (default account)" — support doc. Accounts are hidden, never deleted, so numbers don't get reused.
  • None of the wallets surveyed asks you to name the first account; all rename in place later.

What changes

  • The constant becomes "Account 1". The New Account popup's numbering already continues from there.
  • Avatar initials read A1, A2 — distinguishable at a glance.
  • Pre-production, so no migration: existing dev installs keep "Account" until reinstalled.

Clicks

None change.

Effort: one constant + test expectations.

My pick: A

One option is enough here. I considered your alternative — no default name, address as identity until named — and dropped it: the name is load-bearing in about ten places (header, identity strip on every dApp window, the dApp account picker and its aliases, tx detail, contacts), each of which would need an address fallback.

Confidence: high.
