Blueprint · light · Nulo extension

Escape closes the popup you are looking at

Today, pressing Esc inside most wallet popups quietly unlocks the keyboard while the popup stays on screen, so Tab starts moving things you cannot see. After this change, Esc does exactly what tapping the dark area outside the card already does: it closes that one popup and puts focus back where you came from.

Before · press Esc
Send page
Switch account
New account ⌨ keyboard is loose, popup still shown

Nothing visibly happens. Tab now walks controls hidden under the card.

After · press Esc
Send page
Switch account ⌨ focus is back on “New account”
New account (closed)

Only the top popup closes. The one beneath stays. A second Esc closes that one too. A menu open inside a popup closes first, the popup second.

What you decided

  • All popups, no exceptions. Pickers, forms, confirmations, the incoming-token prompt, read-only sheets: every one already closes on its X and on the outside tap, so Esc adds no new way out. Fullscreen is a global setting, not a per-popup trait, so “fullscreen popups behave differently” could not be expressed anyway.
  • One switch, not 28 edits. The Esc handler already exists in the shared popup shell, gated off by default. The default flips; a future popup that must be answered can still opt out, and opting out now keeps the keyboard inside instead of quietly releasing it.
  • Focus really goes back. Some forms move the cursor into their first field the instant they open, which used to fool the shell about where “back” is. The shell now remembers the opener itself, so closing lands you on the row or button you pressed.
  • Merging is your call. The PR gets opened and watched to green. It is not merged unless you say so.
You said: “Let's do it with no exclusions and maybe we don't merge it.” The plan treats the first half as the scope and the second half as a standing instruction not to merge.

Why light

Six risk dimensions were scored. Novelty: low, the mechanism exists and the Send sheet already uses it. Blast radius: moderate, every popup, but one behaviour that mirrors an exit they all have. Irreversibility: low, a one-line default. Migration cost: none. External coupling: none. Security sensitivity: low, a keypress in the wallet's own window, and nothing is ever approved by Esc. Zero highs, one package: light, with a single Codex audit.

Codex plan audit (two rounds): conditional approve, conditions folded in — it caught that two popups host a fee menu (so Esc closes the menu first, the popup second), that opting out must keep the keyboard inside, and that some forms grab the cursor before the shell records the opener; all three are in the plan and its tests.

Phases

  1. Flip the default and prove it in unit tests

    The popup shell's Esc option becomes on by default; opting out holds the keyboard; the shell records the opener before any form grabs the cursor. The Send review sheet drops its now-redundant opt-in. The unit tests cover all three.

    Proves itself by: lint, typecheck, and the popup + send unit tests, all green.

  2. Prove it in real browsers: a stacked pair, and a menu inside a popup

    The existing browser test that opens “Switch account” and then “New account” gets a twin: press Esc, only “New account” closes and focus lands back on the “New account” row; press Esc again, “Switch account” closes and focus lands on the avatar button that opened it. A second, small test on the local network opens the authwits registry popup, opens its fee-method menu, and shows Esc closes the menu first while the popup still holds the keyboard, and the popup second.

    Proves itself by: a fresh build, the smoke browser test on Chrome, the new local-network test, the static checks on test conventions, and the PR's Firefox smoke job (no Firefox driver on this machine).

  3. Write it down, close the old follow-up

    One rule line in the repo's keyboard guidance, one line in the testing skill (after Esc, wait for focus to land), the previous plan's records updated: the focus-ring restyle is dropped, this one is taken.

    Proves itself by: a repo-wide lint pass and a grep showing the dropped follow-up survives only where the drop is recorded.

Then a Codex review of the finished diff, fixes folded in until it comes back clean, the full pre-PR gate (bun run audit:vue), and the PR into dev. No merge.

Human context

Each popup sits in a keyboard “trap”: Tab cycles inside it and never reaches the page behind. The trap library's stock reaction to Esc is to switch itself off, which is fine for a dialog that then closes, and wrong for one that stays open. The Send review sheet was given the right reaction last week; every other popup still had the stock one. The fix is to make the right reaction the default for the shared shell that every popup is built on.

Nothing is ever decided by Esc. A confirmation cancels, an incoming-token prompt stays pending and asks again later, a form is discarded the way the X discards it, the review sheet closes without sending.
