Shell Identity Fences

Batch 6 — four "who am I acting for?" fixes in the popup UI, plus the owner-approved deletion of a dead (and dangerous) legacy path. Plan of record: plan.md (rev 4, approved through a 3-round dual audit).

The wrong-passenger problem (N-05)

When you switch networks, the popup fetches your accounts for the new network. If you switch again mid-fetch, the OLD fetch could still land its results — showing accounts from a chain you already left. Now every fetch carries a ticket for the run it belongs to and throws its results away if a newer switch superseded it. The logic moved into its own tested module instead of living untestably in the app shell.

The frozen-spinner problem (N-08)

After typing your password, the popup waited in a loop for "unlocked!" — forever, if anything in the unlock pipeline failed. The spinner froze and the button stayed dead until you closed the popup. Now the wait is bounded (30 s, matched to real-world timing), a failure anywhere in the pipeline releases it IMMEDIATELY with an honest error message, and a continuation that lost an identity race writes nothing.

The wrong-receipt problem (N-23)

The home screen's activity list reset itself only when your ADDRESS changed. Two profiles restored from the same phrase share an address — so switching between them kept the other profile's in-flight transfer card on screen. The reset now keys on profile + network + address together, in-flight loads carry run tickets, and transfer tasks remember which network they belong to.

The silent-failure problem (N-22)

Renaming a profile could fail without telling you — the one dialog in its family with a silent error path. It now shows the same "Something went wrong" toast as its siblings.

The dead trapdoor (N-09 — removal, owner-approved)

A legacy "network was reset" modal — which has never been shown to any user — carried a button that would have deleted whichever profile happened to be active. The audit rated its remedy "affirmatively wrong". The whole path (modal template, its trigger, the version stamp it read, the build flag feeding it) is deleted. The notification system itself stays: real failure notices still work.

How we know it works

Every fence has a test that parks it mid-operation, forces the race, and proves the stale run writes nothing — chosen so quietly reverting any mechanism turns a test red. The removal is verified by a scoped search that must come back empty.
