# Plan — Nulo × Aztec Faucet (author: orchestrator)

## 1. Summary

A new `packages/faucet/` workspace in this monorepo. Static Vue 3 + Vite
SPA that dispenses test **USDC** (decimals=6) and **ETH** (decimals=18)
on **Aztec alpha-testnet** via Wonderland's permissionless `Dripper`
contract (`@defi-wonderland/aztec-standards@4.2.0-aztecnr-rc.2`).
Visitors connect any Aztec wallet through `@aztec/wallet-sdk` (Nulo is
the only one in practice today), pick a public or private destination,
and self-mint 1,000 USDC or 1 ETH per click. No backend, no custodial
wallet, no rate limit — the on-chain Dripper is permissionless and the
audience is the Aztec Foundation team.

Success is one-screen: land → connect → drip → see balance change →
done. Anything more is scope creep.

```
              │  ├─ TokenCard × 2                       │

              │  - useDripper     (drip + tx tracking)  │
              │  - useToast       (queue + auto-dismiss)│
              └─────────────────────────────────────────┘
```

**State principles** —
- No Pinia. One screen, one root component owns the wallet, child
  components receive state via props + emit events. Pinia is overkill.
- Contract addresses live in `src/contracts/deployments.json`,
  synchronously imported at build time. The file is regenerated by
  `scripts/deploy.ts`.
- Each `TokenCard` owns a `useTokenBalance(tokenAddress)` instance
  with its own 15-second polling timer; the parent provides the
  connected wallet via prop.
- Drip state is owned by `useDripper(dripperAddress, wallet)` and
  surfaced to the four `DripButton`s through a small `(token, target) →
  state` map.
- Fees are paid via the alpha-testnet SponsoredFPC, registered on
  connect — the user never needs a fee asset to drip.

## 4. Phase plan

`bun run --cwd packages/faucet typecheck && test && build` from repo
root, unless noted.

- Risk: bb.js wasm wiring. Mitigation: lift the proven extension config.

- `composables/useWallet.ts` (+ test): port of
  `packages/playground/src/lib/wallet.ts` adapted to Vue refs. Exposes
  `status`, `accounts`, `selectedAccount`, `wallet`, `connect()`,
  `disconnect()`, `error`.
- `components/EmojiVerifyModal.vue` (+ test): renders 9 emojis from

- `App.vue`: BrandHeader + ConnectPanel; modal portaled to body.
- Validation: typecheck + test + build. Manual: dev server + Nulo
  extension → end-to-end discovery + emoji + confirm.
- Risk: `chainInfo` matcher mismatch with alpha-testnet. Mitigation:
  use `Fr.ZERO/Fr.ZERO` like the playground (Nulo doesn't reject
  discovery on chainInfo mismatch).

### Phase D — Token reads (½ day)
- `lib/contracts.ts` (loads `deployments.json` — placeholder addresses
  for now so typecheck passes; real addresses arrive in Phase F)
- `lib/format.ts` (+ test); `lib/explorer.ts`
- `composables/useTokenBalance.ts` (+ test): `wallet.simulateUtility()`
  on `balance_of_public` and `balance_of_private`; polls every 15s;
  exposes `publicBalance`, `privateBalance`, `loading`, `error`,
  `refresh()`, `dispose()`. Wallet-sdk balance calls run as utility
  calls (no fee, no popup).
- `components/{BalanceRow,AddressDisplay}.vue` (+ tests)
- `components/TokenCard.vue` skeleton — symbol header + balance row,
  no drip buttons yet.
- `App.vue` renders 2 `TokenCard`s when connected; passes Wallet down.
- Validation: typecheck + test + build. Manual: with placeholder
  deployments.json the UI shouldn't crash on contract-not-found —
  surfaces "—" or "0".
- Risk: simulating against missing contracts. Mitigation:
  `useTokenBalance` catches and surfaces a `loading=false, error=…`
  shape; the UI renders a polite zero.

### Phase E — Drip flow (1 day)
- `lib/fees.ts`: `getSponsoredFee(wallet)` builds the SponsoredFPC
  instance, registers it (idempotently), returns `InteractionFeeOptions`
  with a `SponsoredFeePaymentMethod`. Same pattern as
  `aztec-standards/scripts/deploy.ts:createSponsoredFeeOptions`.
- `composables/useDripper.ts` (+ test): for each `(token, target)` it
  exposes a `state` ref (`idle | dripping | success | error`) and a
  `last` ref ({ txHash | error }). Methods: `dripToPublic(token, amount)`,
  `dripToPrivate(token, amount)`. Each builds the `Dripper` contract
  wrapper via `Contract.at(addr, DripperContractArtifact, wallet)`,
  calls the relevant method, sends with sponsored fee, returns the
  receipt txHash, and triggers a `balance.refresh()` callback the
  parent supplied.
- `components/DripButton.vue` (+ test): single action button with
  bound state. Renders `Drip 1,000 USDC to public` / `Sending tx…` /
  `Sent` (transient 200ms) / `Failed — retry`.
- `components/TokenCard.vue` full: wires two DripButtons + balance refresh.
- `components/ActivityFeed.vue` (+ test): subscribes to all drip
  emissions, keeps last 5 in-memory, renders rows with status icon +
  explorer link.
- Validation: typecheck + test + build. Manual end-to-end requires Phase F.
- Risk: account-not-deployed error. Mitigation: on connect, do a one-shot
  `node.getContract(selectedAccount)` check; if missing, show a one-line
  banner: "Your wallet account isn't deployed yet — send any tx from
  your wallet to initialize it first."

### Phase F — Contract deployment (½ day)
- `scripts/deploy.ts`: thin wrapper that vendors the deployment logic
  from `aztec-standards/scripts/deploy.ts` (~150 lines) but uses our
  own token list (USDC d=6, ETH d=18) and writes to
  `packages/faucet/src/contracts/deployments.json`. Two reasons to
  vendor rather than import:
    1. The aztec-standards npm package's `scripts/` directory is NOT
       in the published export — only `dist/artifacts/*` is.
    2. We want our own token names/decimals, not their WETH/DAI/USDC defaults.
  The artifacts themselves (`@defi-wonderland/aztec-standards/artifacts/Token.js`,
  `…/Dripper.js`) ARE published — we just import those.
- Run once: `cd packages/faucet && DEPLOYER_SECRET="…" bun run deploy:testnet`
- Commit the resulting `deployments.json`.
- Validation: smoke: dev server + Nulo → drip USDC public → tx confirms
  on alpha-testnet → balance updates → explorer link works. Repeat for
  private + ETH × both targets.
- Risk: alpha-testnet SponsoredFPC unavailability. Mitigation: the
  error toast tells the user; we can't fix from our side.
- Risk: `salt=1337` is the Wonderland default — if they're already
  using that salt on alpha-testnet for their Dripper, we'll get the
  SAME address (deterministic). That's actually fine — we'll just
  reuse their Dripper. Our tokens get their own salts (`4242`, `4243`)
  so we don't collide there.

### Phase G — Smoke e2e + polish (½ day)
- `tests/e2e/helpers/mockWalletProvider.ts`: minimal fake provider that
  intercepts `aztec-wallet-discovery` postMessage and responds with
  canned WalletInfo + a MessagePort. Implements just the 5 RPCs we
  use: discovery handshake, `establishSecureChannel` (returns a
  deterministic verification hash → predictable emojis), `confirm`,
  `requestCapabilities` (returns granted accounts), `simulateUtility`
  (returns balance), and `sendTx` (returns a fake txHash).
- `tests/e2e/faucet-smoke.test.ts`: 5 cases
    1. Empty state — no wallet detected (mock disabled)
    2. Connect → emoji modal → confirm → connected state
    3. Renders 2 TokenCards with balance 0
    4. Click drip USDC public → loading → success toast with tx link
    5. Disconnect → resets to empty state
- README: dev, deploy, host. Footer microcopy finalized.
- Validation: `bun run --cwd packages/faucet test:e2e` green.

Total estimate: ~4 working days for a solo author, with each phase
ending green.

## 5. Wallet-SDK integration details

**Discovery** is identical to `packages/playground/src/lib/wallet.ts`:

```ts
const manager = WalletManager.configure({ extensions: { enabled: true } })
const discovery = manager.getAvailableWallets({
  chainInfo: { chainId: Fr.ZERO, version: Fr.ZERO },
  appId: "nulo-faucet",
  timeout: 60_000,
})
```

`Fr.ZERO/Fr.ZERO` is the permissive matcher — Nulo doesn't reject on
chainInfo mismatch. For test drivers we read `?chainId=N&version=M`
overrides from the URL (same as the playground).

**Emoji verify**: `pending.verificationHash` → `hashToEmoji(hash)` →
split into chunks → 3×3 grid in `EmojiVerifyModal`. Match → `await
pending.confirm()` returns the `Wallet`. Cancel → `pending.cancel()`
and the SDK rejects.

**Capability manifest** — declared once, upfront:

```ts
const manifest: AppCapabilities = {
  version: "1.0",
  metadata: {
    name: "Aztec Faucet",
    version: "1.0.0",
    description: "Test USDC + ETH on Aztec alpha-testnet — Nulo",
    url: window.location.origin,
  },
  capabilities: [
    { type: "accounts", canGet: true, canCreateAuthWit: false },
    {
      type: "contracts",
      contracts: [dripperAddr, usdcAddr, ethAddr],
      canRegister: true,
      canGetMetadata: true,
    },
    {
      type: "simulation",
      utilities: {
        scope: [
          { contract: usdcAddr, function: "balance_of_private" },
          { contract: usdcAddr, function: "balance_of_public" },
          { contract: ethAddr,  function: "balance_of_private" },
          { contract: ethAddr,  function: "balance_of_public" },
        ],
      },
    },
    {
      type: "transaction",
      scope: [
        { contract: dripperAddr, function: "drip_to_public" },
        { contract: dripperAddr, function: "drip_to_private" },
      ],
    },
  ],
}
```

Per the wallet-sdk skill: `accounts` capability returns
`granted.accounts: Aliased<AztecAddress>[]` after user approval. We
use the first granted account as `selectedAccount`. (No account
switcher in v1 — single-account UX matches Nulo's default account
model and matches the audience expectation.)

**Contract registration**, immediately after capability grant:

```ts
await wallet.registerContract(dripperInstance, DripperContractArtifact)
await wallet.registerContract(usdcInstance,    TokenContractArtifact)
await wallet.registerContract(ethInstance,     TokenContractArtifact)
```

**Fee payment** — sponsored FPC on alpha-testnet, same code shape as
`aztec-standards/scripts/deploy.ts`:

```ts
const fpc = await getContractInstanceFromInstantiationParams(
  SponsoredFPCContract.artifact,
  { salt: new Fr(SPONSORED_FPC_SALT) },
)
await wallet.registerContract(fpc, SponsoredFPCContract.artifact)  // idempotent
const feeOpts = { paymentMethod: new SponsoredFeePaymentMethod(fpc.address) }
// every drip uses feeOpts; user needs zero fee asset
```

**Disconnect**: subscribe to `provider.onDisconnect()` → reset
`useWallet` state to idle. Manual disconnect calls
`provider.disconnect()`. Browser refresh forgets everything (no
auto-reconnect by design — keep v1 simple).

### Network e2e — DEFERRED
A network e2e against alpha-testnet would: (a) require a funded
deployer key in CI, (b) consume drips on every run, (c) flake whenever
the testnet stutters or the SponsoredFPC has a hiccup. ROI is negative
for a 1-screen app with a clean smoke. We rely on smoke + manual
verification for v1. If a regression suite becomes necessary later, run
against the local sandbox with a sandbox-mode flag.

Total: ~75 unit/component cases + 5 smoke cases. Sub-30-second `bun
run test`. Sub-2-minute smoke.

```bash
cd packages/faucet
export DEPLOYER_SECRET="some-strong-secret"   # any utf-8 string, hashed before use
bun run deploy:testnet
```

`scripts/deploy.ts` does the following, vendoring from
`aztec-standards/scripts/deploy.ts`:
1. `createAztecNodeClient(VITE_AZTEC_NODE_URL || alpha-testnet default)`
2. `EmbeddedWallet.create(nodeUrl, { pxeConfig: { proverEnabled: true, dataDirectory: ".faucet-deploy-store/" } })`
3. Schnorr deployer account derived from `poseidon2Hash([Fr.fromBufferReduce(Buffer.from(DEPLOYER_SECRET))])`
4. Ensure deployer account contract is deployed (sponsored fee)
5. Compute deterministic addresses for Dripper + USDC + ETH from salts (1337, 4242, 4243)
6. For each, check `node.getContract(addr)`; if absent, deploy via sponsored FPC
7. Write `packages/faucet/src/contracts/deployments.json` (overwriting in place)

**Idempotency**: re-running is a no-op when all three contracts already
exist at the deterministic addresses; the script logs `[EXISTING]`.

**Salts** (pinned):
- Dripper: `1337` (matches Wonderland's default — if their Dripper is
  already deployed at this salt on alpha-testnet, ours is the same
  address by construction; we reuse).
- USDC: `4242`
- ETH: `4243`

The faucet imports `deployments.json` at module load (`lib/contracts.ts`).
A deploy → commit → push cycle is enough to update production.

## 9. Build & hosting

- **Build**: `bun run --cwd packages/faucet build` → `packages/faucet/dist/`.
  Static output, ~3-5 MB gzipped (most is bb wasm).
- **Headers**: bb.js needs `Cross-Origin-Opener-Policy: same-origin`
  and `Cross-Origin-Embedder-Policy: require-corp` for threaded wasm.
  Add a `public/_headers` file:
  ```
  /*
    Cross-Origin-Opener-Policy: same-origin
    Cross-Origin-Embedder-Policy: require-corp
  ```
  Cloudflare Pages respects `_headers` natively. Vite dev server gets
  the same headers via `vite.config.ts:server.headers`.
- **CSP**: keep loose for v1 — wallet-sdk content scripts use
  `postMessage`, no inline scripts beyond the node-globals shim.
- **Hosting recommendation**: **Cloudflare Pages**. Reasons:
  - Free tier handles bb wasm bundle size without spend-cap risk
  - Native `_headers` support (no edge function needed for COOP/COEP)
  - GitHub integration: push to branch → preview deploy
  - Set custom domain later (`faucet.nulo.app`?); fine on `<project>.pages.dev` for v1
  - Build command: `bun run --cwd packages/faucet build`; output: `packages/faucet/dist`
- Alternatives considered: Vercel (similar quality, but Cloudflare's free
  tier is more generous on bandwidth); GitHub Pages (no `_headers` support
  → CORS/COEP requires a workaround).

## 10. CI gates

- Faucet is auto-included in:
  - `bun run lint` (root biome scans `packages/`)
  - `bun run typecheck:all` (root filter `'@nulo/*'`)
  - `bun run test:all` (same filter)
- `bun run audit:vue` is extension-focused; we deliberately do NOT
  expand it to also build the faucet — separate concerns.
- New root script: `audit:faucet` = `typecheck:all && bun run --cwd
  packages/faucet test && lint && bun run --cwd packages/faucet build`.
  Optional, matches the audit:vue pattern.
- GitHub Actions: `.github/workflows/_lint-and-typecheck.yml` already
  triggers on `packages/**` — faucet is covered. No new workflow
  required for v1.
- Smoke e2e: a new `Faucet smoke / Status` workflow that runs on PRs
  touching `packages/faucet/**`. Advisory at first; required after one
  green week.
- Network e2e: not in v1.

## 11. Risks & open questions

1. **`aztec-standards/scripts/deploy.ts` is NOT in the published npm
   package** — only the built artifacts are. We must vendor ~150 lines
   of deploy orchestration in `packages/faucet/scripts/deploy.ts`.
   Mitigation: vendor, cite the source file + version. Risk: low — the
   logic is stable.
2. **alpha-testnet SponsoredFPC reliability** is external. If the FPC
   is down, every drip fails. Mitigation: clear error copy + link to a
   github issue we can update.
3. **Account-not-deployed UX gotcha**. Newcomers will hit a cryptic
   "nullifier" error. Mitigation: pre-flight `node.getContract(account)`
   check on connect; show banner if missing; suggest "send any tx from
   your wallet first to initialize".
4. **bb.js wasm bundle size**. ~3-5 MB gzipped. v1 ships it; lazy-load
   in a follow-up if perf complaints arrive.
5. **No persistent state on refresh**. Browser refresh re-discovers.
   For an internal tool this is fine; defer auto-reconnect.
6. **Test token symbol confusion**. "USDC" + "ETH" matches mainnet
   brands. The `Test token · no real value` chip mitigates but the
   risk persists. Re-evaluate after first round of Foundation feedback.
7. **Wonderland's published artifact path** (`@defi-wonderland/aztec-standards/artifacts/Dripper.js`)
   — verify it's actually in the published tarball before merging.
   If not, we may need to ship the artifact JSON ourselves (or pin a
   git ref). Mitigation: confirm in Phase A.
8. **chainInfo matcher**. We use `Fr.ZERO/Fr.ZERO` like the playground.
   If Nulo tightens its chainInfo enforcement, we may need real chainId/version
   for alpha-testnet. Mitigation: parameterize via env + URL override.

## 12. Non-goals (explicit)

- Multiple networks (only alpha-testnet)
- Network switcher UI
- Multiple drip amounts (fixed at 1,000 USDC / 1 ETH)
- User-configurable amounts or chips
- Rate limiting (none — trust the audience)
- Backend / server
- Custom wallet UI (use SDK as-is)
- i18n (English only)
- Mobile-first layout (responsive-default suffices)
- Activity history beyond session (no localStorage / no backend)
- Storybook for faucet components
- Visual regression testing
- Lighthouse a11y CI gate (manual check only)
- Custom dripper contract (use Wonderland's)
- Refactoring the extension to extract `@nulo/ui`
- React port
- More than 2 tokens
- Account switcher (use first granted account)
- Wallet picker UI (auto-pick first — there will be one in practice)

## 13. The one question I'd ask

**Where will this be hosted publicly, and do we need a custom domain
(e.g. `faucet.nulo.app`) or is `<project>.pages.dev` fine for v1?**

It affects the COOP/COEP header config (more flexible on a domain we
own), the link in the footer, and the manifest `metadata.url` we send
to the wallet during `requestCapabilities`. Everything else is decoupled.
