Faucet multi-account: choose a main account, switch anytime

Your wallet can share several accounts with the faucet, but the app currently grabs the first one and hides the rest — there's no way to see them or pick a different one. This plan fixes that: when your wallet shares more than one account, the faucet asks which one to use; it remembers your answer per wallet; and a small account menu on the connected chip lets you switch whenever you want, on every tab (Faucet, Bridge, Fuel).

CODEX FINAL VERDICT: conditional approve — all conditions folded into the plan

The decision trail

You picked Proposal D from the four UX mockups: a "choose main account" step on connect (skipped entirely when only one account is shared) plus a quiet dropdown on the account chip for changing later. You also chose: the selection drives all tabs, and it's remembered per wallet across visits.

Why the light tier

Scored zero "high" risk dimensions: this is a known pattern (the wallet SDK documents it, a sibling app half-implements it), it touches one app, nothing is irreversible, no data migrations, no new outside services, and the money involved is testnet-only. Light means one plan, one auditor (Codex) — but you asked for an iteration loop, so Codex reviewed three rounds instead of one: reject → reject → conditional approve, with every finding either adopted or explicitly rejected with evidence (31 ledger entries in plan.md).

What the audit loop actually caught

Worth knowing before you approve — these were real:

  • The big one: the token cards bind to your account when they first appear. Without a fix, switching accounts would update the label at the top while drips kept going to the old account. The plan now rebuilds the cards on switch and includes a test that proves the next drip uses the new account.
  • "Remember per wallet" originally remembered only the last wallet — connecting wallet B forgot wallet A's choice. Now it's a small per-wallet memory (last 8 wallets).
  • Switching is blocked while an operation is running (a drip, a bridge transfer) — enforced in the state layer itself, not just greyed-out buttons — so nothing can ever run under an account other than the one it started with.
  • Data from the wallet is treated as untrusted: account names get sanitized (no invisible-character tricks), addresses validated, duplicates dropped, oversized lists capped with a visible notice instead of silent hiding.
  • Codex also made one wrong claim (said a test file doesn't exist — it does); it was pushed back with evidence and conceded. The loop worked in both directions.

Phases

Phase 1 — The brain: selection state & memory

Teach the wallet-session logic about multiple accounts: the pause-and-ask step on connect, the per-wallet memory, safe handling of weird wallet data, and the switch function itself.

Proves itself by: types check + code style + all unit tests green, including ~14 new tests covering every edge (double-clicks, disconnect mid-choice, hostile data, retries).

Phase 2 — Nothing acts on the wrong account

Make every consumer of "the current account" switch-safe: token cards rebuild, the bridge form resets cleanly, and every running operation blocks switching until it finishes.

Proves itself by: same checks + an integration test showing a post-switch drip provably uses the new account.

Phase 3 — The "choose main account" dialog

The connect-time picker (only appears when >1 account is shared and nothing is remembered), keyboard-friendly and screen-reader-labeled.

Proves itself by: same checks + dialog component tests (selection, cancel, never shown for single-account wallets).

Phase 4 — The account menu on the chip

The connected chip becomes a button that opens a small menu: all shared accounts, a check on the active one, copy-address, and Disconnect. Switching shows a confirmation toast. Present on both Faucet and Bridge panels.

Proves itself by: same checks + menu component tests (open/close, switch + toast fires exactly once, disabled while busy, keyboard navigation).

Phase 5 — Polish and the full gate

Copy review, stale-comment cleanup, docs, plan index update.

Proves itself by: the repo's full faucet audit command — all typechecks, all tests, lint, deployment verification, and a production build, end to end.
