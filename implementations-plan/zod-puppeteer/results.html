The Zod 4 story — why we couldn't ship

What we tried (Option B from the consolidated plan)

Force a single Zod 4 across the whole tree via package.json#overrides. The idea: Aztec's transitive zod ^3.23.8 would resolve to our ^4.4.3 via the override, giving us one runtime instance everyone shares. The type-bridge helper az<T>(s): ZodType<T> becomes a pure type cast (no runtime risk because both sides are the same v4 instance).

At the type level, it worked beautifully:

  • Override resolved bun pm why zod to a single zod@4.4.3
  • node_modules/.bun/ had exactly one zod copy
  • Type-bridge fixed all 75 typecheck errors → 0
  • Build passed

Where it broke

The moment unit tests ran, 34 of 141 test suites failed to load. The error was deterministic and informative:

SyntaxError: The requested module 'zod' does not provide an export named 'OK'
❯ src/wallet/utils/auth-registry.ts:1

Tracing the import chain reached this in Aztec's bundle:

// node_modules/.bun/@aztec+foundation@4.2.0/node_modules/@aztec/foundation/dest/schemas/utils.js
import { OK, ZodFirstPartyTypeKind, ZodOptional, ZodParsedType, z } from 'zod';

All of OK, ZodFirstPartyTypeKind, and ZodParsedType are Zod 3 internal exports. Zod 4's package ships them on the zod/v3 subpath but NOT on the main zod entry. Without per-package zod aliasing (which Bun doesn't expose today), there's no way to give Aztec a Zod-3-compatible main entry while we use Zod 4.

Why we can't work around it today

  • Per-package alias — Bun's overrides are tree-wide. We can't say "Aztec gets v3, we get v4."
  • Patch the package — re-exporting v3 globals from Zod 4's main entry would require shimming v4's bundle, which is fragile.
  • Restructure to never compose Aztec schemas into our combinators — the proper "mixed-major" pattern from Zod's library-authors guide. Doable but ~20 sites need restructuring through parseAsync(unknown) plumbing. Substantial PR by itself.

What we're waiting for

Either Aztec ships Zod 4-typed schemas upstream (no public roadmap we've seen), or we accept the restructuring cost as a dedicated PR. The deferral is recorded in the plan archive for whichever path comes first.
