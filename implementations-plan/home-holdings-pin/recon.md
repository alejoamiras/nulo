## Facts the plan leans on

- **Entities.** `TokenInfo` (`services/token/spec.ts:57-82`): `id, chainId, contract, name, symbol, decimals, hasPublic*/hasPrivate*` flags; `TokenDeleted = TokenInfo & {profileId}`. `TokenBalanceInfo` (`services/token-balance/spec.ts:66-74`): `id, token, account, publicBalance?, privateBalance?, updatedAt, syncFailure?` — NO `isUpdating`/`isMinting`; TokensView splices those on from `TaskService` rows (L183-187, L309-313). `getTokenBalances(tokenId?, accountAddress?)`.
- **Config service.** `ConfigStore.set` validates with the zod schema and only persists/emits on change (`wallet/config/store.ts:46-68`); `ConfigServiceClient` re-emits `onUpdate: EventHandler<ConfigProp>`.
- **Prices.** `usePrices(client)` owns freshness (30s ticker, `QUOTE_TTL_MS = 15 min`), parent owns the client; `getPriceMapEntry` maps only USDC-pegged contracts + Fee Juice, everything else is unpriced. `showFiatValues` config gates every fiat render (`BalanceView.vue:82-90`).
- **Nav.** `app.vue:45-51` sets `data-has-nav` from `route.meta.showBottomNav` (drives `--nav-clearance`); `app.vue:429` renders `Navigation`. Route name for Home stays `general`.
- **E2E contract.** Selectors by `data-testid` only (`tests/e2e/fixtures/helpers.ts:1-19`, CLAUDE.md). Helpers that touch these surfaces: `clickNavTab(page, "activity" | "general" | "settings")` (`helpers.ts:306`, one caller of `"general"`, `navigateToSettings` uses `"settings"`), `importToken` (`helpers.ts:715-756`: Home `tokens-menu-trigger` → `tokens-menu-import` → NewTokenPopup), `refreshBalances` (`tokens-menu-refresh`), `navigateToTokenDetail` (`helpers.ts:793-803`: first `tokens-card` on Home → `balance-amount`), `getTokenDetailBalances` (`private-balance-value`/`public-balance-value`). Direct `tokens-card`/`token-symbol` selectors in network tests: `tokens.test.ts:16-31`, `default-token-seeding.test.ts:39`, `fiat-send.test.ts:47`, `send-amount-clamp.test.ts:31`, `receive-unregistered.test.ts:62,103`. None select more than the sandbox's handful of tokens, so a cap of 3 does not strand them, but the Home rows MUST keep `tokens-card` + `token-symbol[data-symbol]` and the Home menu MUST keep every `tokens-menu-*` item.
- **CI.** `pr-smoke-e2e.yml` and `pr-network-e2e.yml` filters are whole-package `apps/extension/**` — this feature trips both gates on every PR; no filter edits. Network suite shards 5-way in CI; locally `bun run e2e:agent` passes `--shard=N/M` and test-file args straight to vitest (`scripts/e2e/agent.sh:212`), classifies infra boot failures as exit 86.
- **Unpriced sort order is undefined today.** Existing code only SUMS unpriced as $0 (`isAggregatePartial`); nothing sorts by price. The plan must state the rule.

## Collision / dedup risks (each is a plan decision)

1. Three token lists today (TokensView `TokenCard` rows, SelectTokenPopup `SettingItem` rows, the new Holdings page) — the plan extracts ONE `TokenList` used by Holdings and the Send picker; Home keeps `TokensView` (its service wiring is the expensive part) but shares the comparator and the cap helper.
2. Two `nulo:ui:*` persistence idioms already coexist (`useSyncedRef` flat vs BalanceView's per-profile map). Pins must not add a third ad hoc copy: one `usePinnedTokens` composable owns the key.
3. `isUpdating`/`isMinting` are spliced in two places already; Holdings must not add a third. The plan hands Holdings the same decorated rows by lifting the decoration out of TokensView into a helper both use, or Holdings renders without the section refresh dot (decision recorded in plan.md).
4. Retiring `displayOption` is a `BalanceView.test.ts` rewrite (S-A matrix L247-330, deletion ordering L166-187) plus the store shape pin (`app.store.shape.pins.test.ts:40,84`), not a file deletion.
5. Renaming the Home ROUTE would touch the manifest, two redirect pages, the header fallback and 65 e2e hash assertions. Only the label changes.
6. `Dropdown` items compose their icon+label by hand at every call site; the new item follows the local pattern rather than introducing a helper.
