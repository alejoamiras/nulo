VERDICT: **reject (blocking: ABA-blind fencing, a residual release→send race, unsound snapshot watermarks, deletion/recovery contradictions, and an unrecoverable submitting state).**

## Blocking

- **The execution fence is ABA-blind.** P1 captures; user locks/switches P1→P2→P1 during proof; no checkpoint observes P2. Profile ID, deletion epoch, and activity incarnation are again identical, so the CAS broadcasts despite D1. `capturedAt` has nothing monotonic to compare against (plan §9.1–9.4; [profile/service.ts:216](/home/homelab/Projects/nulo/.claude/worktrees/account-switch-isolation/apps/extension/src/wallet/services/profile/service.ts:216)). Add an active-session generation incremented on every open/close/switch and test P1→P2→P1 plus lock→unlock-P1.

- **The CAS still has a switch-before-broadcast window.** Section 9.4 releases the facade lock, then invokes `node.sendTx`; a queued switch can acquire between those continuations. The async marker write also has no latency bound, and the lock force-releases after five minutes ([lock.ts:3](/home/homelab/Projects/nulo/.claude/worktrees/account-switch-isolation/packages/wallet-core/src/utils/lock.ts:3)). Hold facade→activity locks until `sendTx` is synchronously invoked, capture its Promise, release, then await outside. Do not return that Promise through `runExclusive`, whose `return await fn()` would accidentally hold the lock across the network ([profile/service.ts:160](/home/homelab/Projects/nulo/.claude/worktrees/account-switch-isolation/apps/extension/src/wallet/services/profile/service.ts:160)).

- **Counter-first writes make the lock-free watermark false.** A@4 exists; writer persists counter 5 and pauses; snapshot reads `W=5` plus A@4; writer commits/emits A@5; §5.2 drops it because `5 ≤ coverage`. A single storage scan can observe that durable intermediate state ([entity_storage.ts:106](/home/homelab/Projects/nulo/.claude/worktrees/account-switch-isolation/packages/wallet-core/src/storage/entity_storage.ts:106)). Use a committed-through checkpoint/seqlock or copy a source view under its write lock. Add live pause-after-counter snapshots; crash-after-counter does not model this trace.

- **“Unconditional” recording has no valid destination after retirement.** CAS releases; profile deletion retires and purges I1, then send succeeds and recreates tx/journal after privacy erasure—or purge runs second and destroys the required on-chain record ([profile/service.ts:843](/home/homelab/Projects/nulo/.claude/worktrees/account-switch-isolation/apps/extension/src/wallet/services/profile/service.ts:843)). An old-incarnation row also cannot enter the current slice safely. Keep deletion reserved until armed submissions reconcile and perform a final purge, or use a dedicated non-rendering orphan ledger. The bypass must require a one-shot capability bound to marker/scope/incarnation/hash; normal APIs must never accept “omit fence”.

- **Restart reconciliation is not implementable as specified.** `{scope,txHash,fence}` lacks journal ID, endpoint, complete `Tx` draft, and public-authwit tail required by current send callbacks ([transaction/service.ts:115](/home/homelab/Projects/nulo/.claude/worktrees/account-switch-isolation/apps/extension/src/wallet/services/transaction/service.ts:115)). Worse, boot immediately reaps every `submitting` journal to terminal `failed` ([reaper.ts:121](/home/homelab/Projects/nulo/.claude/worktrees/account-switch-isolation/apps/extension/src/wallet/services/operation-journal/reaper.ts:121)); failed→succeeded is illegal. Introduce a versioned, runtime-validated submission bundle and `submission_unknown` state; reconcile before reaping, pin the original endpoint, make every step idempotent, and delete the marker last. A transport timeout is ambiguous—not proof the node rejected the tx.

## Serious

- **Cold slices can accept stale snapshots, not just stale events.** Snapshot I1 starts; scope retires/reactivates as I2; old snapshot arrives and establishes I1; fresh I2 is rejected as “different.” Accepting differences permits rollback. `pxeGeneration` is random hex, not the monotonic decimal generation the reducer requires ([profile/spec.ts:27](/home/homelab/Projects/nulo/.claude/worktrees/account-switch-isolation/apps/extension/src/wallet/services/profile/spec.ts:27)). Add durable per-scope lineage and property-test delayed old snapshots and disconnected-cache reconnects.

- **The cache policy contradicts the actual switch UX.** Existing profile switching is lock→profile selector→unlock ([Header.vue:22](/home/homelab/Projects/nulo/.claude/worktrees/account-switch-isolation/apps/extension/src/components/Header.vue:22)). Therefore “clearAll on hard lock” destroys profile switch-back caching; retaining slices crosses the lock boundary. Late refreshes can also recreate cleared/evicted slices and defeat the 32-slice cap. Add a distinct authenticated switch lifecycle plus cache/request epochs, deletion tombstones, and cap enforcement on every completion.

- **Shared-path behavior is unresolved.** Section 9.3 makes builders/fee strategies fence-consuming, but `estimateOperationFee` uses the same builder without a session fence ([dapp-send-executor.ts:208](/home/homelab/Projects/nulo/.claude/worktrees/account-switch-isolation/apps/extension/src/wallet/services/execution/dapp-send-executor.ts:208)). Required breaks estimates; optional is fail-open. Also the recovery hook is dApp-only, so an accepted UI transfer can still be dropped ([transfer-executor.ts:199](/home/homelab/Projects/nulo/.claude/worktrees/account-switch-isolation/apps/extension/src/wallet/services/execution/transfer-executor.ts:199)). Split preview versus authorized builders; couple principal with origin; use submission recovery for every send, with drift abort dApp-only.

- **The property model misses cross-source crash graduation.** Tx Added callbacks are unawaited; SW death before incoming-note removal leaves both forever because restart emits no Added and the existing-record scan returns before outgoing suppression ([incoming service.ts:650](/home/homelab/Projects/nulo/.claude/worktrees/account-switch-isolation/apps/extension/src/wallet/services/incoming-transfer/service.ts:650)). Add startup exact-scope reconciliation and this trace to P1–P11.
