## PREP FINDINGS that change the design (verified while dual-model ran)

**1. Helper MUST be a free function, not a ProfileService method.** The 48 sweep sites call getActiveProfile
through 5 distinct receivers:
- `this.profileService.getActiveProfile()` — most services (network, fpc, dapp-session, tx-request-builder,
  execution/service, account, auth-registry, contact, transaction, token-balance)
- `this.deps.getActiveProfile()` — `transfer-executor:{172,281}` (deps adapter exposes getActiveProfile
  DIRECTLY — there is no `.profileService` to hang a method on)
- `this.deps.profileService.getActiveProfile()` — `view-executor:{84,245,337}`
- `this.profiles.getActiveProfile()` — `token:{470,528}`
- `services.profiles.getActiveProfile()` — `get-view-simulation-deps:32`

A method on ProfileService cannot be invoked on `this.deps` (transfer-executor) without ALSO widening the
deps adapter interface. ∴ the clean universal shape is a **free function**:
```ts
// profile/require-active-profile.ts  (new file, L-low; or co-located util)
export async function requireActiveProfile(
  source: { getActiveProfile(): Promise<ProfileInfo | undefined> },
  lockedMessage = "Profile locked",
): Promise<ProfileInfo> {
  const profile = await source.getActiveProfile()
  if (!profile) throw new Error(lockedMessage)
  return profile
}
```
Every site → `const profile = await requireActiveProfile(<receiver>[, "<msg>"])`. Works for all 5 receivers,
leaves ProfileService's surface (and the RPC spec) untouched. (Open: variant (b) `requireProfile(profile,
msg)` taking the already-fetched value is even more universal but saves less per site — dual-model to weigh.)

**2. The silent non-thrower class is BROADER than the audit's "return undefined".** Beyond the 4 `return
undefined` sites, `incoming-transfer:{408,446,480,535}` do `if (!profile) return` (void early-return on a
locked wallet — deliberate). `execution-lane:149` is `if (!profile || record.profileId !== profile.id)
return` (absence OR identity → silent). All correctly OUTSIDE the throw-sweep (message-exact buckets), but
the negative-test pins should cover a representative void-return non-thrower too, not just the throwers.
