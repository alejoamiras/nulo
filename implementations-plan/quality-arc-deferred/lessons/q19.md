## The 3 EXCLUSION classes (NEVER sweep — verified)
1. `operation-planner.ts:97-100` — `if (!profile) throw new Error("Unauthorized")`. Distinct authz message,
   documented at lines 8-10, dApp contract. Absorbing it would change the dApp-observable error.
2. `dapp-interaction/service.ts:149-151` — `if (active?.id !== payload.session.profileId) throw new
   Error("Active profile changed since approval; ...")`. This is an IDENTITY check (wrong/changed profile),
   NOT an absence check. Different semantics — uses optional chaining, not `!profile`.
3. Three silent `return undefined` non-throwers, incl. `dapp-session/service.ts:104-107`
   (`tryGetDappSessionByOriginAndChain` — a locked wallet must SILENTLY decline auto-approve, not throw).
   Plus `profile/{service,client,spec}.ts` internal/raw uses (can't wrap their own getActiveProfile) and any
   raw use not of the exact `if(!profile) throw` shape (dapp-interaction, transfer-estimate-reuse, etc.).

## DECISIVE: error strings are LOAD-BEARING → PRESERVE VERBATIM (unify is OFF the table)
- `"Profile locked"` asserted in `profile/session-manager.test.ts`, `profile/service.integration.test.ts`
  (`rejects.toThrow(/Profile locked/)`), and `useFullBackupImport.test.ts` (UI fillError arg).
- **`"Wallet locked"` is pinned by a NETWORK E2E**: `tests/e2e/network/wallet-locked-mid-session.test.ts:37`
  — "silent path errors with 'Wallet locked'" — it's the dApp-observable silent-path error string.
- ∴ Unifying the 3 messages is a real BEHAVIOR CHANGE that breaks existing unit + e2e tests and the dApp
  contract. The dedup must be STRUCTURAL only, zero behavior change. (This is the opposite of the Q5/PXE
  false-DRY rejections: here the duplication is mechanical and the centralization is authz-positive.)

## Proposed design (pending dual-model)
1. Add non-RPC method `ProfileService.requireActiveProfile(lockedMessage = "Profile locked"):
   Promise<ProfileInfo>` → `const p = await this.getActiveProfile(); if (!p) throw new Error(lockedMessage);
   return p`.
2. Sweep the 48 absent-throw sites: 34 → `requireActiveProfile()`; 12 → `requireActiveProfile("Wallet
   locked")`; 2 → `requireActiveProfile("Wallet is locked")`. Each preserves its exact message.
3. Leave all 3 exclusion classes + raw/non-guard uses untouched.
4. Negative-test pins (DETERMINISTIC): requireActiveProfile unit (present→returns profile / absent→throws
   passed message / default message); pin each exclusion still behaves (operation-planner→"Unauthorized";
   dapp-session silent path→undefined; dapp-interaction→"profile changed" on identity mismatch); pin ≥1
   representative site per message variant still throws its exact string.
5. Gate = units + smoke + FULL network e2e (the "Wallet locked" e2e proves the silent-path string preserved).
