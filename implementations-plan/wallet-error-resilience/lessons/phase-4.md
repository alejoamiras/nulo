3. **`[object Object]`.** `formatArg` shares one `WeakSet` across the array recursion and the object branch (a self-referential array recursed forever), renders a revisited object or array as `"[circular]"`, stringifies `bigint` via a replacer, and names the constructor when stringify still throws. `formatLogData` now passes one argument to `formatArg` — `.map(formatArg)` used to hand the array index in as the `seen` set.

Grep across `apps/extension/src` and `packages/*/src`: nothing reads `getPublicKeyAlgorithm()` or `pubKeyCredParams` other than the ceremony builder — key material is the PRF output, so the authenticator's choice is invisible to the wallet.

## The network canary — what it took and what it proves
`tests/e2e/network/stale-anchor-recovery.test.ts`, run alone (ten iterations to get here; the last: `1 passed | 1 skipped`, exit 0, step line `attempt 1: L2 block 6 pruned, 8/8 views ok, 0 retry line(s)`).

- **Hard assertion (holds):** eight views issued while the node pruned the tip after an `anvil_reorg` all succeeded. The PXE logged `Reorg detected. Pruning blocks from 6 to 6` and `Pruning data after block 5 due to reorg` mid-burst and every view came back ok.
- **Soft assertion (not landed):** no `stale anchor on first attempt — resynced, retrying once` line. With `autoSync` on, every op syncs first, so the failure needs the prune to land between that sync and the op's anchor-bound query; one reorg's worth of burst did not hit it. The spec skips with that reason (`1 passed | 1 skipped`, exit 0) rather than passing; the delivery report carries the extension-level reproduction as **unmet**. The real-PXE integration test (Phase 2) remains the recovery evidence.
- **Dead ends, in order.** (1) `pg-btn-executeUtility-balance` fails on every chain: the playground hands the Token's PUBLIC `balance_of_public` to `executeUtility`, and the wallet's `findFunctionBySelector` only sees private/utility functions plus `public_dispatch` (`loadContractArtifact` parks other public functions in `nonDispatchPublicFunctions`). `sim-methods.test.ts` case #25 tolerates "ok or error", which is why this never surfaced — a playground bug, reported as a follow-up, not fixed here. (2) The e2e token was not registered in the wallet's PXE (`getContractInstance` is the only lookup; no node fallback) — the dApp registers it first, with its own artifact via the phase section. (3) Reorging the sandbox's tip pruned the block that DEPLOYED the token: the view then failed `Assertion failed: Not initialized` — a legitimate failure on a chain where the contract no longer exists, not a stale anchor. A disposable mint now lands before the reorg so the pruned block is its own. (4) A second attempt's mint timed out awaiting its block: after a prune the local network does not reliably mine again, so one reorg per run.
- **It reproduced inside the pooled run — and poisoned it.** The first full-suite attempt had the canary in the pool (it lives under `tests/e2e/network/`). There, with the sandbox at L2 block 46 and busier, the soft assertion landed: `attempt 1: L2 block 46 pruned, 8/8 views ok, 1 retry line(s)` → `reproduced: the offscreen resynced and retried once, and every view still succeeded` — the extension-level proof the plan asked for, observed once. The same prune then left the local network unable to mine again (the same fact that capped the canary at one reorg), and every later spec that lands a transaction died at the token-ready fixture's 5-minute hook (`account-balance-orphans`, `authwit-lifecycle`, `fee-methods`, `imported-account-execution`, `transfers`, `backup-migration-roundtrip`, all ≈309 s; tx-free specs kept passing). Two false leads on the way: the arc's balance-queue diff (it never touches row creation) and the Phase 2 store-key recovery keying on `instanceof` across the offscreen boundary (it does round-trip: `error-response.ts` projects any `WalletError` to `errorPayload`, `walletErrorFromPayload` rebuilds the class, and every profile's first PXE op depends on it — the passing specs prove it). Fix: the canary skips unless `NULO_E2E_REORG=1`; the plan's gate command carries the flag; the e2e skill records the rule. A CI shard would have been poisoned the same way.
- **Diagnostics that made this tractable.** The dApp only ever sees the constant "The wallet could not process the request." (by design); the spec turns Developer + Debug mode on and, on any failure, dumps the service worker's retained trail filtered worker-side (`readSwLogTrail(page, { match })`) — reading the raw tail was useless under debug mode (a burst of views logs hundreds of oracle lines and pushed the failure out of the window).
- **Observed on the read path.** Right after the PXE's prune, the wallet's `getSyncedBlockHeader` READ failed twice with the "not-yet-synchronized PXE" wording (logged at error by the offscreen client's op-failure line). `getBlockHeaderAnchor` catches it and falls back to the node's latest header, so nothing broke; the retry helper covers the four write ops only, as planned. Worth knowing for a future noise pass: that error-level line is a handled fallback.

- **Smoke recipe lesson.** The first smoke run went red on one spec, `backup-migration.test.ts`'s arming contract: it ran against the plain build `audit:vue` leaves behind, which carries no migration fixture. The gate is the CI recipe — build with `VITE_NULO_E2E_MIGRATION_FIXTURE=1 VITE_NULO_E2E_DEFAULT_NET=testnet VITE_NULO_E2E_TOKEN_SEEDS=1 VITE_NULO_E2E_TOKEN_SEEDS_CONFIRM=1`, assert both seed markers in the dist, run with `NULO_E2E_MIGRATION_FIXTURE=1` — and on that build the whole suite passed (the passkey specs passed on both runs). The e2e skill already says this; the miss was mine.
- **Network recipe.** Two specs carry `@requires-proverless`, so a bare `bun run e2e:agent` refuses to start; the full local run is `NULO_E2E_PROVERLESS=1 bun run e2e:agent`, which is exactly CI's shard pool build.
