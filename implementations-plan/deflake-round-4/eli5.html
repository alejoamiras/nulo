Crash-Truth Fixes

Two real bugs were proven by the round-4 crash experiments. This plan fixes both and turns the tests that found them into permanent guards — delivered as four small, stacked pull requests.

The two bugs, in plain words

1. Deleting and re-importing a wallet freezes its balances

When you delete a profile and re-import the same backup, an internal safety lock (built to stop deleted data from coming back to life) mistakes the fresh copy for the deleted one and blocks it from ever syncing again — until you restart the browser. No crash needed: the app's own "forgot password → delete → re-import" instructions trigger it.

2. The crash cleanup can never actually run

If the extension's background process dies mid-import, the app is designed to undo the half-finished import automatically. But the cleanup message is sent while the background process is still rebooting, fails instantly, and the automatic undo never happens — the user gets the manual recovery screen instead.

Why the heavyweight process

This got the deep treatment (three independent plans, cross-checks, two audit rounds, a final fresh review) because both fixes touch safety-critical machinery: the anti-resurrection lock protects deleted wallet data, and the messaging layer carries every feature. Rubric: blast radius HIGH, security sensitivity HIGH.

The four pull requests

PR 1The tests land first

The crash-test suite merges with the two bug-revealing tests switched off, each labeled with why and where the evidence lives. The healthy test (crash after the save-point) stays on — it has passed five times in a row.

Proves itself by: lint + types + unit tests + one solo run (healthy test green, two skips visible), CI green.

PR 2Fix the freeze

The safety lock learns to tell "the deleted copy trying to come back" (still blocked, forever) apart from "a fresh re-import that needs its key installed" (now allowed to ask for one — and the key handout itself was hardened against a subtle timing attack the audit found). The delete + re-import test turns back on and must pass.

Proves itself by: new unit tests for every lock state + the re-import test green, plus one run with real proving on.

PR 3Fix the cleanup

The undo now waits for the background process's own "I'm fully back" heartbeat before sending the delete — once, cleanly, no blind retries. The crash-mid-import test turns back on and must pass end to end: crash → automatic undo → fresh retry → money visible on chain.

Proves itself by: unit tests for the wait-and-retry logic + the full crash test green.

PR 4Close the books

The flake ledger gets its entries closed with evidence, the testing skill gets the lessons, and the whole stack is certified: three consecutive clean runs, zero retries, plus one proving-on run.

Proves itself by: 3× consecutive green certification + docs checks.

Decisions already made (and argued hard)

Small, causal fixes won over a big rework. One reviewer proposed rebuilding the messaging layer's handshake — architecturally nice, but it touches everything to protect one victim. It's recorded as future work; the chosen fixes are surgical. The same reviewer then tried to break the chosen design and conceded.

The audits made the fixes better. The review chain caught a real timing hole in the key-handout path (now closed and pinned by a test), an edge where a double-crash leaves a profile that refuses deletion until browser restart (documented, fails safe), and a test-file split needed so the proving-on check is even possible.

Nothing user-visible changes. Both fixes restore behavior the product already promises. The manual recovery screen stays as the last-resort backstop.
