# tools-extraction — split the bridge/tools product out of nulo

Nulo becomes wallet-only (extension, playground, landing, their packages). `apps/tools`, `packages/bridge-core`, `contracts/bridge`, their CI, runbooks and plans move to `alejoamiras/unleashed` with history. Both repos leave Cloudflare Pages for Workers static assets deployed by Workers Builds.

**Rule of the whole plan (removal-first, decision 23): decouple → delete from nulo → rebuild unleashed from the freeze SHA → rehearse → prove → cut over → delete from Cloudflare.** Stage 1 (A1 → A5a → A5b) makes nulo wallet-only as fast as its own gates allow; nothing in it waits on unleashed, npm or Cloudflare credentials. Git history keeps every deleted file, so Stage 2 extracts unleashed from the **freeze SHA** — the last `dev` commit that still carries the tools tree — at whatever pace the owner likes. `dev` is green at every commit. Steps without a rollback come last, each behind a named precondition and an explicit owner go.

**What removal-first buys, and what it does not.** It removes ~870 files / ~10 MB (≈16 % of `dev`'s tracked files, 15 % of its bytes), the tools/bridge share of `bun.lock` and `node_modules`, and two CI pipelines (the 6-shard tools e2e, the bridge contracts). It does **not** shrink the clone: `.git` (≈40 MiB packed) keeps every past blob, and shrinking it means rewriting `dev` and `main`, which branch protection blocks and this plan never does. Costs, accepted by the owner: (a) the tools sites keep serving their last Pages deployment, frozen, until unleashed's Workers take over at C1; (b) bridge contract and tools e2e coverage pause between A5a and unleashed's B2 — the code is frozen in history and no longer editable in nulo, so nothing can regress in that window, and F0 records a baseline run of both suites at the freeze candidate; (c) an Aztec network reset inside the window is handled from unleashed once B2 is green (the frozen site points at dead contracts until then); (d) if nulo bumps its `@aztec/*` line after the freeze, the extracted tree must move to the same line before the published packages resolve — R's preparation does it, B1 replays it, and the pin-equality test enforces it.

**UI impact (nulo extension): none.** No popup, onboarding or window surface changes. The wallet's `https://tools.nulo.sh` link and the landing's two `testnet.tools.nulo.sh` links are unchanged (a redirect serves them).
**UI impact (unleashed):** colour values and the logo glyph become a neutral placeholder on every tools screen; layout, copy, rows, fonts, component API and every `data-testid` are unchanged. Owner signs off on screenshots in the B1 PR.

### 2. Published packages — three, staged, narrow

| `@nulo/resolve-asset` | `.` | — |

- **Workspace manifests do not change** (`private: true`, raw-`.ts` exports): the extension, playground and every vite/vitest config keep consuming source, and `npm publish` from a workspace dir is refused by `private`.
- `scripts/publish/stage.ts <pkg>` writes `dist-publish/<pkg>/`: JS from `bun build --format=esm --target=browser` (`resolve-asset`, a Node-only build helper: `--target=node`) `--external '@aztec/*' --external zod` per entry (sources use extensionless relative imports, so plain `tsc` emit would not run under Node ESM); types from `tsc -p tsconfig.publish.json` — a small per-package config (the packages' own tsconfig sets `noEmit` and includes every test) with `declaration` + `emitDeclarationOnly`, rooted at the public entries only; a generated `package.json` (not private, `exports` → `dist`, `files`, repository metadata, `sideEffects` naming the **emitted** path `./dist/register.js`, `zod` kept as a declared dependency, **`@aztec/*` as exact `peerDependencies`** where the package has any — `resolve-asset` has none), README, LICENSE.
- **Peer deps are necessary, not sufficient**: under Bun's isolated linker identical version strings do not prove a single instance. unleashed keeps its own explicit `@aztec/*` dependencies, and R + B1 assert real identity with the helper that already exists for this — `assertPackageIdentity(…, { lockstepVia })` (`packages/resolve-asset/src/index.ts:128`) — plus a check that the `/register` import mutated the `WalletSchema` object the app's wallet-sdk client actually uses (asserted on a production Vite bundle, not just under Node). A deliberately mismatched fixture must fail.
- `scripts/publish/stage.test.ts`, wired by changing root `test:release` to `bun test scripts/release/ scripts/publish/` (today it covers `scripts/release/` only): staged dist has no `@nulo/wallet-core` specifier in JS or d.ts; staged `wallet-crypto` reproduces the existing key-derivation vectors byte-for-byte; `EncryptionKey` **cross-compatibility** — sealed by source / opened by bundle and the reverse, plus AAD-mismatch and tamper rejection (two changed implementations can round-trip with each other and still reject existing recovery ciphertext); `npm pack --dry-run` file list equals an allowlist; every `@aztec/…` (deep subpaths included) and `zod` specifier survives as a **bare import** in the staged JS, under a size ceiling — if the bundler inlined Aztec code the vectors would still pass while unleashed silently got duplicate `Fr` classes, which `assertPackageIdentity` cannot see inside a bundle; the staged JS of `wallet-crypto` and `wallet-sdk-schema-patch` contains no `node:` import (`register` and `EncryptionKey` run in the browser, so those entries build with `--target=browser`; `resolve-asset` is Node/Bun-only by contract and legitimately imports `node:fs`, `node:module`, `node:path`, `node:url`); an out-of-workspace fixture installs the three tarballs, imports every export under Bun and Node 24 ESM, and **type-checks** under both `NodeNext` and `Bundler` resolution (runtime imports cannot validate declarations). *As built*: the fixture is **offline** — it unpacks the tarballs and links the peers from the installed tree, because `test:release` gates every PR, nightly and release and a registry blip must not red them; R's `file:` install into the extracted tree is the real-registry consumer. Declarations are emitted with `removeComments` (the sources' doc headers describe wallet internals), so comment-only edits leave the staged bytes unchanged; the Azguard notice is re-added to the bundle and to the declaration derived from `encryption-key.ts`. `stage.ts` refuses any cwd but the repo root: the bundler labels modules by cwd-relative path, and a run from elsewhere embedded this host's home path. The fixture's type-check runs with `skipLibCheck` (`@aztec`'s own declarations fail a lib check), which masks TS2834, so a separate assertion requires every relative declaration import to carry `.js`.
- **The first publication is bound to the rehearsed bytes** (the digest file is a `0.1.0` bootstrap control; later versions rely on the staged tests + environment approval + verified provenance, so an `@aztec` bump does not need a rehearsal commit first). R records the SHA-256 of each packed tarball in `scripts/publish/approved-digests.json` (committed through A2's PR or a follow-up). `.github/workflows/publish-packages.yml` (`workflow_dispatch` only; inputs: version, `dry_run` default true; ref restricted to `dev`/`main`; actions pinned by SHA) has two jobs: an unprivileged **build** (`contents: read`: frozen install → `test:release` → stage → `npm pack` → compare digests to the approved file, **fail before anything is published** → upload the `.tgz` artifacts) and a **publish** job (`id-token: write`, environment `npm-publish`, owner as required reviewer, environment restricted to `dev`/`main`) that downloads those artifacts, re-checks the digests and runs `npm publish <tgz> --provenance --access public` with a pinned npm CLI ≥ 11.5.1. The approval screen shows the source commit and the three digests. One lockstep version. No token exists anywhere. (*Inference*: `bun build` + `npm pack` are byte-reproducible across this host and the runner. If they are not, the approved digest becomes a hash over the **complete unpacked package** — every shipped path and its bytes, `package.json` included, since its `exports`, dependencies and lifecycle scripts are part of what a consumer executes — never over `dist` alone; and the publish job additionally records the final archive digest before publishing. Build and publish jobs enforce the same definition.)
- **Names**: the staged manifests are named `@alejoamiras/nulo-<name>` (decision 12); the workspace packages keep their private `@nulo/*` names, which never reach a registry.
- **Bootstrap, from this host with the owner's npm CLI** (decision 13). The owner runs `npm login` once in the session (web flow — prints a URL, works headless); the agent then drives everything, pausing for the owner's 2FA at each write: (1) publish a code-free `0.0.0-bootstrap.0` per package under a `bootstrap` dist-tag — the pattern `@alejoamiras/presto` already used; (2) `npm trust github <pkg> --file publish-packages.yml --repo alejoamiras/nulo --env npm-publish --allow-publish` ×3 with the host's nvm npm 11.19.0 (Node 24.21.0), which has `trust`; `/usr/bin` npm 11.6.2 does not, and npm 12 is inside the 7-day window and excludes Node 24.12 (`--allow-publish`, not `--allow-stage-publish`, because the workflow publishes directly); the placeholder publish needs `--tag bootstrap --access public`; (3) `npm trust list <pkg>` to confirm; (4) owner sets "require 2FA and disallow tokens" per package (web UI if the CLI cannot); (5) `npm deprecate` the placeholders; (6) **`npm logout`** — the login token does not stay in `~/.npmrc` past the bootstrap. `0.1.0` then ships through OIDC, so no code is ever published without provenance.

### 3. Extraction recipe (versioned, replayable)

The recipe lives in `implementations-plan/tools-extraction/tools/` (the repo's convention for arc-scoped tooling): `paths.txt`, `extract.sh` (clone → `--analyze` → filter → callbacks → audit), `bootstrap/` (the fresh root-config commit as a patch set), `codemod.ts`. The rehearsal and the real run execute the **same files at the same freeze SHA**; the real run differs only in the push.

The reset adds a reflog entry, which filter-repo's fresh-clone check rejects, so `extract.sh` passes `--force` — only inside the clone it just created, and only after asserting `HEAD` equals the freeze SHA. **Everything the recipe copies rather than filters** (the bootstrap root files, `.gitignore`'s bridge rules, the scripts named by root `package.json`, the bridge block of `layout-identity.test.ts`, the bridge sections of `UPDATE.md`, `CLAUDE.md` and the `aztec-update` skill that B4 turns into unleashed's runbook) is read with `git show <freeze SHA>:<path>`, never from nulo's working tree, where Stage 1 has already deleted or rewritten it. `git filter-repo --paths-from-file`, ancestors listed explicitly — filter-repo does not follow renames; ancestry verified from `git log --diff-filter=R`: `packages/faucet → apps/faucet → apps/tools`; `packages/bridge-evm`, `packages/bridge-aztec → contracts/bridge`; plus `packages/bridge-app`:

`--message-callback` rewrites `(#N)` → `(alejoamiras/nulo#N)` so GitHub does not autolink to unleashed's own PR numbers. `--replace-text` normalises home-directory / mount-point absolute paths (a sample of 7 plan dirs holds 45 such lines). filter-repo's `commit-map` is committed in unleashed: historical deploy intents record nulo SHAs (`live-intent.ts` `assertNoSourceDrift`), which stop resolving after the rewrite — the map is the evidence trail and the drift check is never disabled. Concretely (`live-intent.ts:361` diffs the literal recorded SHA and verification calls it at `:562`): any deployment in flight is **finished from nulo before the freeze**; historical intents are immutable evidence; the first live operation from unleashed requires a **newly authorised intent** recorded against an unleashed commit — no operation runs against an old intent.

Exactly one ref is pushed (`main`), named explicitly — never `--mirror`, no tags. The filtered paths were already public in nulo; the bootstrap commit is new content and gets the same scan. A real credential finding is rotated, not merely filtered. Rewritten commits lose signatures: push first, enable `required_signatures` + rulesets after; README records source SHA + the recipe.
**Freeze**: the freeze SHA is the first parent of A5a's squash commit on `dev`, recorded in `lessons/` the moment A5a merges. From the moment A5a merges, bridge work happens in unleashed only (sole developer): a tools or bridge change still in flight either lands on `dev` before A5a or is re-applied in unleashed after B1. Any deployment in flight is finished from nulo before A5a merges.

## Security & Adversarial Considerations

- **Threat model**: a public repo + a bridge UI + a wallet that links to it. Attackers: npm scope squatters / publish takeover, a compromised PR trying to publish or deploy, subdomain takeover on `nulo.sh`, a hostile preview deployment posing as the bridge, history scrapers.
- **npm**: scope ownership verified before any name appears in a public manifest. Placeholder-then-OIDC bootstrap → no code without provenance; "disallow tokens" per package; trusted publisher pinned to repo + workflow file + environment; the environment's required reviewer means a merged malicious PR still cannot publish; `id-token: write` is job-local. Published surface is three functions and one class, not the wallet's crypto toolbox. Provenance proves origin, not safety — the vector + seal/open tests on the staged bundle are the correctness gate, and R proves them against the real consumer.
- **Supply chain (unleashed)**: 7-day min-age kept; excludes name three packages, never a wildcard; `npm audit signatures`; frozen lockfile; exact pins.
- **Cloudflare token**: Account → Workers Scripts:Edit, Cloudflare Pages:Edit, Workers Builds Configuration:Edit; Zone `nulo.sh` → DNS:Edit, Workers Routes:Edit. TTL ≤ 14 days, shell env only, never on disk, in a repo or in CI; revoked in C2. Residual: Workers Scripts:Edit is account-wide.
- **Dangling DNS**: domain detach and re-attach in one sitting; Pages projects deleted only when no record points at `*.pages.dev`.
- **Redirect**: exact-host map, hardcoded targets, nothing user-controlled reaches `Location`, 302 + `no-store`, unknown host 404, tested against open-redirect inputs. A `workers.dev` name is only as safe as the Cloudflare account — the real domain should replace it soon.
- **Host allowlist / previews**: exact-match and fail-closed; alias computed by us; per-version URLs rejected; testnet only; mainnet `preview_urls: false`. CSP / COOP / COEP asserted against the deployed Workers in GATE-U.
- **CI (unleashed)**: `contents: read`, `pull_request` only, no secrets; exact-state aggregators (an empty filter output fails, fixing the inherited gap); halmos cannot pass vacuously (`--ast --force` + proof names carried).
- **Custody**: KDF labels, salts, manifests, addresses, amounts move byte-for-byte; deploy intents are already-public data; historical intent SHAs are explained by the committed commit-map; before any live operation from unleashed, `verify:deployments` and the L1 verification script are re-run from the new repo. The audit confirms no `.env` or keystore ever entered history.
- **Smart contracts**: no source changes. Removal-first means nulo's copy is deleted **before** unleashed runs the four proof/test layers (R, then B2), so coverage pauses in between. Accepted because nothing can change in that window: the code exists only in history, the deployed contracts are unaffected by where their tests run, and F0 records green `bridge-contracts` and tools-e2e runs at the freeze candidate for R to reproduce. No bridge deployment or generation runs until B2 is green in unleashed.
- **Input validation**: the only new parser is branch → alias (bounded charset + length, tested against hostile names).
