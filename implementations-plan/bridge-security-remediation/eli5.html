Bridge Security Remediation

The security audit found 8 issues in the bridge contracts — one critical and live (anyone can re-point the deployed L1 portal and drain it). This plan fixes all 8 across two PRs: a quick no-redeploy PR (CI gate + a JS guard + docs), then a heavier PR that ships new, hardened contracts and migrates the live testnet bridge onto them. The chosen fixes were locked one-by-one with you earlier; this plan is purely how to implement + migrate safely.

Why this tier was chosen (deep)

HIGH on blast radius (real bridge funds), irreversibility (a one-way live cutover), migration cost (full L2-stack redeploy), and security sensitivity (it IS the security fix) — 4+ HIGH ⇒ deep. The process earned it: three independent plans → a contradiction-check → a double audit that rejected a keystone (a CREATE2 factory would have shipped stub bytecode to production) — caught and corrected before you ever saw a gate.

Phases

PR A · A1 — JS guard (F-005)

Make the shared bridge helper refuse a private-fuel bridge that's missing its secret/recipient, instead of silently stranding the gas.

Proves itself by: bridge-core unit tests (the bad inputs throw before signing), green.

PR A · A2 — docs (F-007)

Verify the bearer-secret is never logged/stored in plaintext and document that contract for integrators.

Proves itself by: bridge-core tests + lint, green.

PR A · (F-003 — NOT done, your call)

Contract tests are NOT wired into CI. They run locally only (via the PR-B phase gates). F-003 stays an open, documented finding — a future Aztec bump could silently strand deposits, caught only by local discipline.

PR B · B1 — forked, init-locked portal (F-001)

A copy of the portal with a one-line "already set up? stop" guard, compiled with the real Aztec interfaces so the deployed code can't subtly diverge. (A throwaway stub copy exists only to run the regression test.)

Proves itself by: the guard reverts a second init (unit test); the content-hash test still matches (no drift).

PR B · B2 — sign the swap target + slippage floor (F-004/F-006) + regression test

Bind which swap contract runs into the user's signature; require a non-zero minimum. Move the critical PoC in as a permanent regression test.

Proves itself by: a signature for one swap target reverts after the target changes; witness hashes match L1↔JS.

PR B · B3 — lock the minter (F-002)

Rebuild the L2 minter so the bridge is the only minter, fixed at setup with no owner backdoor. (Forces a fresh L2 token too — the old token's minter can't be changed.) Also updates the sandbox/deposit wiring so its own test passes.

Proves itself by: Noir compile + sandbox end-to-end (mint-on-claim, burn-on-exit) on the new wiring.

PR B · B4 — deploy-script rework

Deploy-then-init the portal; per-attempt fresh salts + a resume rule (so a failed attempt can't half-brick a generation); write the new addresses to a private temp file (never the live config directly); add an "existing-deployment" smoke script.

Proves itself by: the candidate-manifest writer/readers round-trip; faucet unit tests green.

PR B · B5 — pre-live logic gate

Prove the new contracts on a Sepolia fork (L1) + a local sandbox (L2) before any real transaction.

Proves itself by: fork tests + sandbox deposit/withdraw + the staged portal compiling, all green. Hard gate.

PR B · B-canary — throwaway testnet rehearsal

Deploy a disposable generation to the real testnet and run a full deposit→claim against it — the first real-network proof — without touching the app.

Proves itself by: canary deposit→claim + fueled bridge round-trip on testnet; canary portal refuses re-init.

PR B · B6 — the real cutover (irreversible)

Deploy the real generation, read everything back on-chain (abort on any mismatch), then atomically point the app at it; rollback = don't re-point. The old contracts are abandoned.

Proves itself by: on-chain read-backs match; portal re-init reverts on-chain; faucet build+test green; a live deposit→claim works.

PR B · B7 — re-audit

Run /harden security over the new contracts to confirm the 8 findings are closed and nothing new opened.

Proves itself by: a clean harden report; the regression pins stay green.

Human context

The portal is the L1 "vault + mailbox" to Aztec; the minter proxy controls who can create the L2 token. The critical fix can't be patched in place (the live portal is fixed bytecode), so we deploy fresh, hardened contracts and move the app onto them. Because the L2 token's minter is permanently fixed at creation, a new minter means a new token — so old testnet balances are left behind (your call: fresh start).
