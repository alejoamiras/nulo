## Round 0 — independent planning contribution

**Architectural stance:** the headline is the **resolver cutover, not a markup rewrite**. The honest reuse ceiling is bounded by the consume-only constraint:

- The faucet already consumes 10 package components via explicit imports in exactly 10 SFCs. Converting those to bare resolver-backed tags is **pixel-identical by construction** (same components, only the import mechanism changes) — the safe bulk + the literal ask.
- The brutalist controls (mode cards, fuel `<button>`+`.knob` toggle, boxed numeric `.amount` inputs, dashed add-to-wallet button, letter-spaced mono labels) **do not map** to existing primitives without modifying the package (forbidden) or accepting drift (forbidden). Verified mismatches: `@nulo/design`'s `Input` is an underline (`border-bottom`) emitting parsed numbers vs the faucet's full-border box bound as a string; `Toggle` hardcodes `data-testid="toggle-switch"`, `role="switch"`/`aria-checked`, 32×20 vs the faucet's `aria-pressed` `<button>` 40×22 wired to `TESTIDS.bridgeFuelToggle`. **Stay local by design.**
- `Flex`/`Text` adoption is real but **modest**: `Flex` cannot express CSS grid (`.cards`/`.panels`/`.modes`) or two-axis gaps (`.wallets` `gap:12px 16px`); `Text` renders inline `<span>` and **cannot express `letter-spacing`** (which nearly every faucet mono label uses). So swaps are limited to pure single-axis layout wrappers + non-letter-spaced labels.

**Order:** by **risk ascending / test-coverage descending** — zero-visual-risk import cutover first (two reviewable waves), then optional individually-gated `Flex`/`Text` swaps last before the human gate. Resist any swap whose only effect is to prepend a `<Flex>` to a wrapper that still needs its bespoke `.panel` class (churn, ~0 reuse, net-negative reviewability).

**The load-bearing finding — vitest must get the resolver too.** The extension's `vitest.config.ts` deliberately does NOT register `unplugin-vue-components`; its tests hand-stub design tags. The faucet's tests do the **opposite** — they `mount` with the *real* design components (reachable today via explicit imports) and assert on forwarded `data-testid`s + `.trigger("click")` on the real `<Button>` (verified: `WalletPanel.test.ts` `fa-btn-connect`; `MintFuelAsset.test.ts` `fuelMintBtn`/`fuelMintCard`; `VerificationModal.test.ts` `btnVerifyConfirm`/`btnVerifyCancel`). If the explicit imports are deleted and only `vite.config.ts` has the resolver, bare `<Button>`/`<Card>` are **unresolved** under the current `plugins:[vue()]`-only vitest config → Vue renders a fallback element, `:loading`/`:disabled`/slot semantics diverge, green tests break or pass-for-the-wrong-reason. Wiring `useComponents({ resolvers:[nuloDesignResolver()] })` into both vitest configs makes vitest resolve bare tags to the **same** SFCs the build uses; the injected `import { Button } from "@nulo/design"` is byte-identical to today's, and `@nulo/design` already resolves in faucet vitest (tests pass now), so **no `server.deps.inline` change needed**.

**Phasing:** (0) resolver setup, infra only, zero call-site changes (explicit imports stay → observably inert) → (1) import cutover wave A (leaf+wallet: AppToastRegion, MintTestUsdc, MintFuelAsset, L1/Bridge/WalletPanel, VerificationModal) → (2) import cutover wave B (forms: BridgeForm, FuelForm, TokenCard) → **CHECKPOINT: DECISION #4 satisfied; if "cutover only," stop** → (3) conservative `Flex`/`Text` swaps, optional, per-swap gated → (4) human visual gate.

**Verified Facts of note:** `base.css` `@import "./utilities.css"` (line 9) → the `.flex`/`.gap--N`/`.color--*` utilities `Flex`/`Text` emit ARE loaded by the faucet · `biome.json` `files.includes` (line 6) excludes `!**/packages/extension/src/types` but NOT the faucet's → add `!**/packages/faucet/src/types` · the resolver discipline (root `CLAUDE.md` line 65) is add-on-delete; the faucet uses the router-free `Button` base directly so it has NO host-coupled wrappers → every consumed name may enter the map immediately · gap utilities are discrete (no `gap--5`) · `data-testid`s flow through `packages/faucet/src/lib/testids.ts`.

**Asks (A1–A4):** confirm resolver-only `dirs:[]` · confirm Phase-3 swap scope ("pure layout + non-letter-spaced labels only" vs "import cutover only, drop Phase 3") · OK to git-track the generated `components.d.ts` + add the biome exclude · pin `unplugin-vue-components@^32.0.0` + `--frozen-lockfile`.

**Inferences (I1–I4):** `dirs:[]` valid + minimal blast radius (fallback `dirs:["src/components"]`, verified collision-free) · `bun run build` regenerates the dts deterministically · vitest-resolver fully mitigates the unresolved-fallback risk, no test edits · pure swaps visually equivalent (sub-pixel `lh--100` or sibling-selector reliance could drift → human gate).

**Security:** XSS unchanged if no `v-html` introduced; external links keep `rel="noopener noreferrer"` verbatim · resolver can't shadow a local component with `dirs:[]` (no collision verified across 18 local SFCs); `VerificationModal`/`EmojiGrid` testids are e2e security selectors — cutover must not alter them · `unplugin-vue-components` is already a monorepo build dep (no new package); devDependency only, no version bump · light-theme regression = the round-1 canonical failure (byte-identical tokens, missing element-global rule) → parity test + human gate both mandatory.

**Single biggest risk:** removing explicit imports **without** the resolver in the vitest config(s) — turning real, asserted-upon components into unresolved fallbacks and quietly breaking (or passing-for-the-wrong-reason) the existing tests.

**Consolidation outcome:** fable's plan was adopted as the **structural spine** (change-type phasing, honest reuse ceiling, the vitest-resolver load-bearing fix, the biome exclude, `dts:false` on vitest configs, the Input/Toggle non-fits, all verified Facts). Its A2 (run conservative swaps vs cutover-only) is the one open item surfaced at the gate.

## Round 1 — fresh hostile audit (new fable subagent, no prior context)

**Verdict: `conditional approve`** — conditions block **Phase 4 (swaps) only**, NOT the import cutover, which it verified as sound ("the safe bulk and I could not break it"). All findings adopted.

**H1 (Critical, adopted) — the `.links` swap is a machine-invisible regression.** `BridgeReceipt.vue` `.links a` children carry no class; they're styled solely by the descendant selector `.links a`/`.links a:hover` (color/mono/underline/hover). Swapping `<div class="links">`→`<Flex gap=12>` + deleting `.links` orphans the anchors. No test catches it (`BridgeReceipt.test.ts` asserts only link *count*; no faucet test except `BridgeAddToken` asserts style); jsdom computes no layout. → **Remove `.links` from Phase 4** (it's the forbidden half-swap; the wrapper class is still needed *by its children*). Generalizes to a new rubric criterion: a swap is forbidden if any descendant selector depends on the wrapper's class.

**H2 (High, adopted) — reuse ceiling rests on a FALSE fact + an un-done audit.** (a) "Text has no letter-spacing utility — verified" is **false**: `base.css:385-390` ships `.tracking-wide`(0.05em)/`.tracking-widest`(0.1em); Text forwards `$attrs`. The real Text limits: **no `font-family`/headline prop** (so `--font-headline` labels can't be Text) + off-scale tracking values (0.04/0.06/0.08/0.12em) have no utility. (b) The plan never evaluated `Badge`/`Banner`/`LoadingState`/`SectionLabel`/`Tooltip`; smoking gun: `BridgeJournal.vue:179` comments its empty-state as "the extension's pattern," which now ships as `LoadingState`. → **Corrected the fact + did the inventory** (recorded in plan v3): LoadingState/Banner/Tooltip/SectionLabel are genuine non-fits for *documented* reasons (forced spinner+no action slot+hardcoded testid; too-heavy rich box vs plain hint; unmet `#tooltip` host contract; standalone-title vs label+count); **Badge is a partial fit** — 1–2 real candidates (`BridgePhaseRail` SKIPPED, `BridgeJournalCard` PRIVATE/PUBLIC) pending visual-match. This is the finding most aligned with the user's "reuse a bit more."

**M1 (adopted) — "mirror the extension" is inaccurate; vitest path is novel + unproven.** The extension uses `dirs:["src/components",...]` (not `[]`) and its `vitest.config.ts` wires `useAutoImport` but **NOT** `useComponents` — so resolver-in-vitest is novel, not a mirror, and Phase 1 (explicit imports intact) never fires it. → Stop calling it a mirror; add an explicit early bare-tag render smoke in vitest before mass work. (Converges with codex Round-1 High #2.) Fable verified `dirs:[]` IS valid against the installed unplugin source (default overridden by `Object.assign`; `toArray([])→[]→globs=[]→no scan`) — I1 confirmed.

**M2 (adopted) — `--frozen-lockfile` will fail.** unplugin is in `bun.lock` for *other* workspaces, but `packages/faucet/package.json` doesn't declare the edge; adding the devDep + frozen errors. → One normal `bun install` to record the workspace edge (no download, no version bump), then frozen.

**M3 (adopted) — `.head`/`.foot` swaps silently change `<header>`/`<footer>`→`<div>`.** Flex defaults `tag="div"`. → Pass `tag="header"`/`tag="footer"`; drop `.foot` (single-child `justify-flex-start` = layout no-op = churn).

**L1/L2/L3 (adopted):** candidate list wasn't from a complete per-file scan (BridgeJournal `.cards` is flex not grid; `.head-row`/`.opt-row` missed) → frame candidates as examples, implementing phase derives the complete list per rubric · Phase-1 dts is *empty* (not "resolver entries") with explicit imports intact → reword · human checklist must name the exact machine-invisible nodes from the Phase-4 diff (orphan-risk, header/footer, untested FuelForm), not a generic page walk.

**Fable confirms fine:** the import cutover is import-equivalent for the current snapshot (all 10 importers bare-named, no aliases; all named exports; zero dynamic/`:is`/render usage; no double-inject) — attack failed honestly; `dirs:[]` correct; no-shadow guard sound; amount-row swaps clean (`gap--8` exists); testid-relocation a non-issue (swap-target containers carry no testid); Flex grid/baseline/off-scale limits all real; supply-chain framing + the `biome.json:6` faucet-types-exclusion gap real.
