## BLOCKING

- **PR 1 still does not fully tighten the `aztec_registerContract` wire path, and plan-v2 leaves the real SDK/versioning question open.** `plan-v2.md:87-110,220` correctly moves toward "artifact required", which addresses the core round-1 blocker from `implementations-plan/registry-stealth-notes/audit-codex.md:8-12` and `implementations-plan/registry-stealth-notes/audit-plan-agent.md:10-29`. But the dApp-facing surface in this repo is not `@nulo/wallet-bridge`; that package is private (`packages/wallet-bridge/package.json:2-8`). In-tree callers compile against upstream `@aztec/wallet-sdk` (`packages/wallet-bridge/package.json:13-19`, `packages/playground/package.json:12-20`), and that SDK still exposes `registerContract(instance, artifact?)` plus a PXE fallback (`node_modules/.bun/@aztec+wallet-sdk@4.2.0-nightly.20260413/node_modules/@aztec/wallet-sdk/src/base-wallet/base_wallet.ts:267-295`). There is also an in-tree caller that omits the artifact today (`packages/playground/src/sections/contracts.ts:83-92`), with e2e coverage on the silent path (`packages/extension/tests/e2e/network/contracts-register.test.ts:10-65`). Most importantly, the wallet execution path still parses `op.artifact` as optional and falls back to `pxeService.getContractArtifact(...)` (`packages/extension/src/wallet/services/execution/service.ts:1495-1513`), but `plan-v2.md:70-92` does not list that file at all. Change shape: PR 1 needs to explicitly edit `execution/service.ts`, update `playground` and its e2e, and treat the upstream `@aztec/wallet-sdk` sync as a separate breaking-change track rather than an unresolved open question.

- **The pinned note-schema details in PR 3.B/3.C are wrong for the actual bundled artifacts, so the planned parser/tests would be incorrect as written.** `plan-v2.md:135-183,216` fixes the round-1 "pick a concrete decode strategy" blocker from `implementations-plan/registry-stealth-notes/audit-codex.md:12` and `implementations-plan/registry-stealth-notes/audit-plan-agent.md:30-47`, but two of the concrete mappings are wrong and one phrasing is misleading. Aztec Token stores `balances` at slot `0x...03` and uses `UintNote`, not `TokenNote` (`node_modules/.bun/@aztec+noir-contracts.js@4.2.0-nightly.20260413/node_modules/@aztec/noir-contracts.js/artifacts/token_contract-Token.json:28835-28844,30911-30918`). Wonderland Token stores `private_balances` at slot `0x...07`, not `balances`, and also uses `UintNote` (`node_modules/.bun/@defi-wonderland+aztec-standards@4.2.0-aztecnr-rc.2/node_modules/@defi-wonderland/aztec-standards/artifacts/target/token_contract-Token.json:49,19743-19751`). PrivateFPC stores `balances` at slot `0x...01` via `BalanceSet<Context>` (`node_modules/.bun/@wonderland+aztec-fee-payment@4.2.0-aztecnr-rc.2/node_modules/@wonderland/aztec-fee-payment/target/private_contract-PrivateFPC.json:377,8444-8452`). Aztec NFT and Wonderland NFT both use `private_nfts` shared-set slots, not "per-NFT slots" (`node_modules/.bun/@aztec+noir-contracts.js@4.2.0-nightly.20260413/node_modules/@aztec/noir-contracts.js/artifacts/nft_contract-NFT.json:14748-14756`, `node_modules/.bun/@defi-wonderland+aztec-standards@4.2.0-aztecnr-rc.2/node_modules/@defi-wonderland/aztec-standards/artifacts/target/nft_contract-NFT.json:17514-17522`). `decodeFromAbi` only decodes the packed note fields (`node_modules/.bun/@aztec+stdlib@4.2.0-nightly.20260413/node_modules/@aztec/stdlib/src/abi/decoder.ts:45-91,144-145`), while `owner` and `randomness` live separately on `NoteDao` (`node_modules/.bun/@aztec+stdlib@4.2.0-nightly.20260413/node_modules/@aztec/stdlib/dest/note/note_dao.d.ts:12-26`). The notes page currently only special-cases keys like `value`, `amount`, and `token_id` anyway (`packages/extension/src/popup/pages/settings/advanced/account-state/notes/index.vue:148-155`). So the test plan at `plan-v2.md:179-180` expecting `TokenNote` plus `{amount, owner, randomness}` cannot pass from ABI decode alone. Change shape: rewrite the schema/comments/tests around the real note shapes: `UintNote -> { value }`, `NFTNote -> { token_id }`; if `owner` / `randomness` are wanted for debug UX, append them from `NoteDao`, not from `decodeFromAbi`.

## SHOULD-FIX

- **The PR 1 fail-loud table still misstates current error semantics, and plan-v2 should either normalize them or stop promising a shared string.** `plan-v2.md:93-110` says token parsing and manual FPC add will throw `"Contract artifact not found for class ${classId}"`, but today token flows throw bare lowercase `"contract artifact not found"` (`packages/extension/src/wallet/services/token/service.ts:245-248,330-333`), manual FPC add throws capitalized `"Contract artifact not found"` (`packages/extension/src/wallet/services/fpc/service.ts:196-199`), `ContractResolver` throws the formatted class-id string (`packages/extension/src/wallet/services/execution/contract-resolver.ts:98-105`), account-state backup silently skips (`packages/extension/src/wallet/services/account-state/service.ts:156-169`), and notes fall back to raw rendering (`packages/extension/src/wallet/services/note/service.ts:104-110`). Recommendation: PR 1 does not need a cross-package `ContractArtifactUnavailableError` class, but it should at least use a shared formatter/helper inside the extension if the UX is supposed to be consistent.

- **The slot-map invariant test should also assert `schema.location` matches the artifact field name, not just that the slot exists.** `plan-v2.md:183` is directionally right. But `loadContractArtifact()` materializes storage as `field-name -> slot` (`node_modules/.bun/@aztec+stdlib@4.2.0-nightly.20260413/node_modules/@aztec/stdlib/src/abi/contract_artifact.ts:247-275`), so the stronger invariant is: for each schema entry, the artifact has that slot *and* the field name owning that slot equals `schema.location`. That catches slot renumbering and copy/paste/name drift.

- **The artifact-registry test rewrite should drop the fake config seam, but keep verifier injection and fake loaders.** The current file's `makeConfig()` and `onUpdate` coverage exist only for the registry/config coupling (`packages/extension/src/wallet/services/pxe/artifact-registry.test.ts:50-69,141-160`). Once PR 2 deletes `contractRegistry` and PR 1 removes the subscription, that seam is dead. The verifier DI helpers are still useful for class-id verification with fake artifacts (`packages/extension/src/wallet/services/pxe/artifact-registry.test.ts:13-42`), and the contract-resolver miss case already has a good home in `packages/extension/src/wallet/services/execution/contract-resolver.test.ts:140-155`.

- **PR 1 should explicitly remove the now-dead PXE config plumbing.** After PR 2 deletes `contractRegistry`, `PxeService` no longer needs `IPxeConfig`, the optimistic allow-registry bootstrapping, or the init-time reconciliation (`packages/aztec-runtime/src/pxe/service.ts:54-86,125-135`). The offscreen bootstrap and extension shell still thread `ConfigServiceClient` through that seam (`packages/aztec-runtime/src/offscreen/entry.ts:1-33`, `packages/extension/src/offscreen/index.ts:1-45`). Plan-v2 mentions dropping the registry instantiation/reconciliation but not this leftover dependency chain.
