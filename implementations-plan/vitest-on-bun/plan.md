## Goal

Run every workspace Vitest suite on the **Bun runtime** — `bun --bun vitest run` — with proof, from retry-0 repeated-run baselines taken at the same commit on both runtimes after a frozen clean install, that Bun is no flakier than Node, and land it as one reviewable PR that leaves CI YAML untouched. The Puppeteer e2e layer (extension smoke/network) stays on Node in this arc.

**Done** = the eleven workspace `test` scripts (ten packages + the extension aggregate) plus extension `test:components` and the faucet jsdom smoke (`test:e2e`) run under Bun; every phase gate passed as written; the unit-layer soak tool exists and its own failure modes are proven on both engines by `test:ci-gating` on every CI run; a `workflow_dispatch` of `pr-quick.yml` bound to the matrix commit is green on the real runner; docs state the runtime; the vitest/Bun interop stopgap carries its retirement trigger; PR open with all three named required checks green at its HEAD, codex loop converged. If a genuine Bun defect forces a package to stay on Node, that is an explicit STOP for the owner (abort vs reduced-scope replanning) — not a silent scope cut.

## Why this tier (Phase 0.5 rubric)

Novelty MED (first Bun-runtime test execution here, de-risked by the dossier + pre-plan probes), blast radius MED (`quality-status` depends on `test:all`; a bad flip reds every PR — reversible per package by one script line), irreversibility LOW, migration cost LOW, external coupling MED (a real vitest×Bun interop defect — fixed upstream in vitest 5 beta, stopgapped here), security LOW. One MED-HIGH dimension → `mid` (dossier tier confirmed).

## Recon → design (see [recon.md](recon.md); probes in [lessons/pre-plan-probes.md](lessons/pre-plan-probes.md))

- No unit workflow invokes vitest directly; `test:all` fans out to each package's `test` script (packages run concurrently) → the flip is script strings, no workflow change.
- Every Bun failure in the repo is ONE vitest interop rule (`interopModule` tests `"__esModule" in mod.default`; Bun answers `true` for ES-module namespaces; zod@4's namespace default loses `z`). Upstream fixed it in vitest PR #10363 (issue #10359, shipped in 5.0.0-beta.3) — not in our locked 4.1.10. `test.deps.interopDefault: false` is the stopgap: it fixes Bun and is test-set-identical on Node (extension aggregate 372 files / 4,635 tests on both runtimes).
- The probes de-risked the package order: after the stopgap, every suite is green on Bun on a single run. So the effort goes into ONE strong gate (fail-closed soak matrix at one clean commit after a frozen install, inventory-exact comparison, the CI-shaped concurrent fan-out repeated, and a real-runner dispatch) rather than six sequential rollouts.
- No soak harness, coverage, or consumed reporters exist → the gate tooling is a small new script; coverage parity is out of scope by evidence.

## Architecture & Implementation

**Proposed architecture.** Three small pieces, no new package, no dependency changes.

1. **`vitest.base.ts`** (repo root) — one plain object, no imports (resolvable identically under the hoisted and the isolated linker):
   ```ts
   /** Shared `test` options every workspace vitest config spreads in. */
   export const sharedTest = {
   	// STOPGAP until the installed vitest contains vitest-dev/vitest#10363 (≥ 5.0.0-beta.3):
   	// Bun's ES-module namespace objects answer `"__esModule" in ns` (Node: false), so vitest 4's
   	// default interop replaces an externalized module by its `default` — zod@4's default IS a
   	// namespace and `z` vanishes. Off, named exports of CJS deps follow each runtime's own loader
   	// (no vitest fallback); the Node soak baselines prove nothing here depends on that fallback.
   	// Retire: delete this key and re-run the Bun soak matrix.
   	deps: { interopDefault: false },
   } as const
   ```
   Every workspace `vitest.config.ts` spreads it: `test: { ...sharedTest, globals: true, environment: "jsdom", … }`. The four config-less workspaces (`aztec-runtime`, `wallet-bridge`, `wallet-sdk-schema-patch`, `landing`) get a minimal config with `...sharedTest` and an explicit `environment: "node"` — and nothing else (no `globals: true`; their current defaults are preserved). `experimental.viteModuleRunner` stays at its default (`true`): `false` would route through `module.registerHooks`, which Bun lacks — a documented never-flip. `biome.json` `files.includes` gains `vitest.base.ts` and `scripts/ci-cd/test-soak/**` so the new code is linted/formatted (`scripts/**` is otherwise excluded).

2. **`scripts/ci-cd/test-soak/`** — the fail-closed unit-layer soak driver.
   - Files: `cli.ts` (guarded by `import.meta.main`), `lib.ts` (pure: parse vitest JSON → inventory; canonicalize paths; merge runs; compare; metadata checks; the run loop takes an explicit launcher argv), `lib.test.ts` (`bun:test`), `runtime-reporter.ts` (a vitest reporter passed by absolute path; records identity only), `resolve-esm.mjs` (ESM resolution probe, run OUTSIDE the test process), `fixtures/<name>/{vitest.config.ts, *.fixture.ts}` (`passing`, `crash`, `hang`, `unhandled-rejection`, `no-json`, `sourcemap`), `cli.test.ts` (`bun:test`).
   - **Fixture discovery safety.** `bun test scripts/ci-cd/` recurses; a crash or hang fixture discovered by `bun:test` would crash or hang CI itself. Fixture test files are therefore named `*.fixture.ts` (never `*.test.*`/`*.spec.*`), each fixture's `vitest.config.ts` sets `include: ["*.fixture.ts"]`, and `cli.test.ts` asserts that no file under `fixtures/` matches `bun test`'s discovery pattern.
   - **Fixture execution.** Through a workspace that DECLARES vitest, on BOTH engines: `bun --no-install run [--bun] --cwd apps/landing vitest run --root <abs fixture dir>` (probed pre-plan) — never from the root, which declares no vitest (under the isolated linker a root-anchored launch would not resolve it). `cli.test.ts` runs each fixture with a short timeout under Node and under `--bun` and asserts: `passing` → `failedRuns: 0`; `crash`/`unhandled-rejection`/`no-json` → `failedRuns > 0` with the right flag; `hang` → `timedOut: true`; `sourcemap` → the run FAILS and its failure message names `sourcemap.fixture.ts:<the exact line>` — the source-map sentinel is machine-checked on every CI run, on both engines.
   - Invocation: `bun scripts/ci-cd/test-soak/cli.ts soak --cwd <workspace> --script <name=test> --runtime script|node --runs N --out <full.json> [--timeout <min>] [-- <vitest filters>]` (writes the FULL summary), `… compare <a-full.json> <b-full.json>` (consumes full summaries; no allowlist option exists on the CLI), and `… compact <full.json> --out <compact.json>` (drops the `inventory` map, keeps everything else — the committed form).
   - `--runtime script` (the default, and the ONLY mode for Bun evidence) runs the REAL script: `bun --no-install run --cwd <ws> <script> -- <filters> <enforced flags>` — so `pretest`, `--passWithNoTests` and the flipped `bun --bun vitest run` string are exactly what is soaked. `--runtime node` is the same-commit Node reference with the same lifecycle: it reads the script's value, requires it to match the strict grammar `bun --bun vitest run( <token>)*` (tokens without shell metacharacters; anything else → refuse), runs `pre<script>` first if declared (`bun --no-install run --cwd <ws> pre<script>`; a non-zero exit = a failed run, as `bun run` would fail the script), then `bun --no-install run --cwd <ws> vitest run <tokens> -- <filters> <enforced flags>` (Node by shebang), then `post<script>` if declared — the pre-flip CI string at the same commit, with no environment injection of any kind. The tool refuses to label a summary Node when any run's reporter reports `versions.bun`, and vice versa.
   - Enforced flags are appended LAST (`--retry=0 --reporter=default --reporter=json --outputFile=<tmpDir>/results.json --reporter=<abs runtime-reporter.ts>`); forwarded filters may not contain reserved flags (`--retry`, `--reporter`, `--outputFile`, `--root`, `--config`, `--pool*`, `--watch`) — rejected up front.
   - Each run: `node:child_process.spawn` (argv array, no shell, `detached: true` = its own process group, stdio captured), a timer that on expiry kills the GROUP (`process.kill(-pid, "SIGKILL")`) and marks the run `timedOut`; SIGINT/SIGTERM handlers forward the same group kill and exit non-zero; `mkdtemp` output dir removed after parsing. `failedRun := exitCode ≠ 0 ∨ !json.success ∨ JSON missing/unparseable ∨ timedOut ∨ runtime record missing`.
   - `runtime-reporter.ts` (`onInit(ctx)`) writes `{ execPath, versions }` to `runtime.json` next to vitest's own configured JSON output (`dirname(ctx.config.outputFile)` — the per-run temp dir the tool already passes as `--outputFile`), so the reporter needs NO environment variable — one record PER RUN, kept on the run row; the summary is rejected unless all N records exist and agree. Neither runtime mode injects any environment. (The launcher spawns its workers with its own `execPath` — verified: workers report `versions.bun` under both pools when the launcher is Bun — so the launcher record is the runtime record.)
   - `resolve-esm.mjs` runs ONCE per summary, outside any test process, anchored at the workspace: on Bun `bun scripts/ci-cd/test-soak/resolve-esm.mjs <wsDir> <specs…>` using `Bun.resolveSync(spec, wsDir)`; on Node `node --experimental-import-meta-resolve scripts/ci-cd/test-soak/resolve-esm.mjs <wsDir> <specs…>` using `import.meta.resolve(spec, pathToFileURL(wsDir + "/"))`. Specs: `zod`, `@aztec/foundation/curves/bn254`, `@aztec/stdlib/abi`, `@aztec/aztec.js/wallet`, `@aztec/bb.js`, `vue`, `jsdom`, `isows`, `msgpackr`, `@logtape/logtape`, `axios`; an unresolvable spec is `{ error: <canonical message> }` (expected where the workspace does not depend on it). The tool picks the runtime for this probe from the summary's runtime mode and REFUSES to emit a summary whose probe engine disagrees with its run records.
   - **Canonical paths.** Before anything is compared or written: `file:` URLs → paths; paths under the repo root → `<repo>/…`; paths under the temp dir → `<tmp>/…`; `execPath` → `<bun>` or `<node>`; the reporter path → `<repo>/scripts/…`; resolver error messages have paths canonicalized the same way. A committed or compared artefact never contains a home directory (the pre-commit brand/path guard is the backstop).
   - Summary JSON: `{ meta: { tool: "test-soak@1", argv (canonical), cwd (repo-relative), script, runtimeMode, gitSha, gitDirty (computed with `implementations-plan/vitest-on-bun/lessons/baselines/**` excluded), lockfileSha256 (of `bun.lock`), vitestVersion, pool, maxWorkers, runs, timeoutMin, resolves }, runs: [{ exitCode, wallMs, timedOut, missingJson, runtime: {execPath, versions}, collected, passed, failed, skipped, todo, failing: string[], inventoryDigest }], inventory: Record<testId, { statuses: Record<status, number>, observations: number, failures: number }>, inventoryDigest, failedRuns }`, `testId = <workspace-relative file> :: <full test name>`.
   - `compare a b` exits **non-zero** unless ALL hold: `a.meta.gitDirty === false` and `b.meta.gitDirty === false`; same `gitSha`, `lockfileSha256`, `vitestVersion`, `cwd`, `script`, filters and `runs`; every run row in `a` has a runtime record without `versions.bun` and every run row in `b` has one WITH it, all rows consistent within each side; identical inventories (same ids, same status set) with `observations === runs` for every id on BOTH sides; `a.failedRuns === 0` AND `b.failedRuns === 0`; no id with `b.failures > a.failures`; and every `resolves` entry that differs between `a` and `b` is in the PINNED allowlist — a constant in `lib.ts`, exactly the four packages that declare a `"bun"` export condition (`isows`, `msgpackr`, `@logtape/logtape`, `axios`), with no CLI or config way to widen it (widening is a code change, which the matrix commit rule re-gates); a differing spec outside it FAILS the compare. The comparator prints the effective allowlist, the per-id delta, wall-clock min/median/p95 for both, and every differing resolution (allowed or not).
   - Evidence flow: `soak` writes FULL summaries to `lessons/baselines/full/{node,bun}/<name>.json` (gitignored); `compare` consumes those full files; `compact` produces the committed copies under `lessons/baselines/{node,bun}/<name>.json` (the summary without the `inventory` map — `meta`, run rows, `inventoryDigest`, failing ids with counts, `resolves`). Committed copies are review evidence, not tamper-evident: the comparator's stdout for all 12 pairs (including the effective allowlist) and every inventory digest are preserved verbatim in `lessons/phase-1.md` and quoted in the PR body. Process spawning stays on `node:child_process` (Arc D owns `Bun.spawn`).

3. **Script flips** — every workspace `test` (`vitest run` → `bun --bun vitest run`; extension-messaging keeps `--passWithNoTests`; landing keeps its `pretest`), extension `test:components`, faucet `test:e2e` (the jsdom in-process smoke run by `_build-faucet.yml:44`) — **one commit per workspace**, so `git revert` is per package. `test:watch` (faucet, bridge-core, design) flips in the same commit as its package ONLY if that package's watch smoke passes (start → edit a test → observe the rerun → Ctrl-C → no `bun` worker survives, `pgrep`); otherwise it stays on Node with a one-line comment. **Untouched**: extension `test:e2e`/`test:e2e:all`, root `test:e2e:*`, `agent.sh`, `observability.test.ts` (Puppeteer/Node layer).

**Key interfaces / types.** `sharedTest` is a `const` object typed by inference (no `vitest` import → no runtime resolution from the root). The soak summary schema above is internal to the tool and its tests.

**Data & control flow (critical path).** `bun run test:all` → `bun run --filter '@nulo/*' --if-present test` (concurrent) → per package `bun --bun vitest run` → Bun executes `node_modules/vitest/vitest.mjs` and spawns `forks` workers with `process.execPath = bun` → vite transforms; the module runner imports externalized deps with `interopDefault: false` → results. `--bun` also puts a `node` symlink to Bun on the PATH of that process tree — the blast-radius boundary; no unit test spawns a process (Fact F12), so nothing else moves.

**Algorithms / non-obvious mechanics.** (i) The interop rule and why the stopgap is a class fix (any externalized ESM package whose `default` is an object Bun answers `"__esModule" in` for is collapsed; inlining zod hides one instance). (ii) Both matrices are taken at the SAME clean commit after `bun install --frozen-lockfile` (HEAD after the flip commits): Bun via the real scripts, Node via the same-commit reference mode — the comparator's provenance checks (SHA, lockfile hash, clean tree, per-run runtime records) are exact. (iii) The comparator compares complete inventories with per-run observation counts and per-id failure counts, so fewer collected tests, a test missing from some runs, changed skip/todo, or a deterministic Bun failure hiding behind a rare Node flake all fail closed. (iv) Statistical power, stated honestly: N=30 retry-0 detects a ≥10 % per-run flake with 96 % confidence and a 5 % one with 78 %; it is the agreed sampling budget, not proof of zero flakiness — which is why the concurrent `test:all` fan-out is ALSO repeated ×5 and a real-runner dispatch is required. (v) The extension aggregate is soaked N=30 FULL on both runtimes (≈1 h each, unattended) — no hand-picked shard.

**Trade-offs & alternatives not taken.**
- *`bunfig.toml` `[run] bun = true`* (outline B) — rejected: flips vite (incl. `cross-env NODE_OPTIONS=… vite build`), storybook, puppeteer and every Node-shebang tool at once, crossing the owner's e2e boundary; per-script `--bun` is explicit and revertable per line.
- *`server.deps.inline: ["zod"]`* — rejected as the primary fix: per-config, transforms ~240 zod modules per worker, hides the class. Kept as the documented fallback.
- *Wait for vitest 5 / bump to the beta* — rejected for this arc: a prerelease bump across 11 workspaces is its own review under the 7-day gate; the stopgap has a retirement trigger.
- *A `@nulo/vitest-config` workspace package* — rejected: dependency edges in 11 manifests + lockfile churn for one object; a root plain object is layout-proof at zero cost.
- *Six per-package phases each with its own gate* (plan v1) — rejected after audit: the probes de-risked the order; sequential phases add ceremony without isolation. One flip phase (per-package commits) gated by the full matrix at one commit.
- *Two stacked PRs (foundation → flips)* — rejected: the foundation is NOT inert (it changes Node interop semantics) and must ship with its evidence.
- *Node baselines BEFORE the flip commit* (plan v2) — rejected: two SHAs make provenance incomparable; the same-commit reference mode replaces it.
- *A pre-run `--root` sentinel for runtime identity* (plan v2) — rejected: relative roots and root-anchored resolution do not work from workspace cwds or under the isolated linker; a per-run reporter record + an out-of-process resolver replace it.
- *ESM resolution captured from inside the test process with an injected `NODE_OPTIONS`* (plan v4) — rejected: it made the Node reference environment differ from the real one; the resolver now runs outside the test process.
- *A hand-picked race/timer shard* (plans v1–v2) — rejected: it covered 7 of 37 fake-timer files; N=30 full is affordable unattended.
- *Per-package `test:bun` scripts alongside `test`* — rejected: two runtimes per package is the split-result confusion recon warned about.

Any change after it to anything executable or configuration — a test, a source file, a `vitest.config.ts`, `vitest.base.ts`, a `package.json`, the soak tool, `biome.json`, `bun.lock` — invalidates the matrix: re-run the frozen install, the full matrix (both runtimes, all 12 suites), the `test:all` ×5 loop and the dispatch at the new commit. This includes fixes from the post-implementation code-review/codex loop. The final PR HEAD may differ from the matrix commit ONLY by the documentation allowlist: `**/*.md` and `implementations-plan/vitest-on-bun/lessons/baselines/**/*.json` — nothing else (no `.ts`, `.mjs`, `.json` manifests, configs or workflow files; `implementations-plan/**` code of any kind is NOT allowed). Layers: unit/component (all) · build · smoke e2e · lint/typecheck · bun:test · real CI runner.

## Security & Adversarial Considerations

- **Threat model.** Test infrastructure only: which JavaScript engine executes the existing test code. No new network surface, no secrets, no build-output change (`vite build` scripts untouched — production bundles stay Node-driven and the product runs in the browser).
- **Supply chain.** Zero dependency changes; `bun.lock` untouched; the 7-day min-age and `--frozen-lockfile` CI unaffected. The matrix is preceded by a recorded `bun install --frozen-lockfile` and every summary carries the `bun.lock` hash, so the soaked `node_modules` is attested against the lockfile — `bun --no-install` alone only prevents auto-install. `bun --bun` executes the already-installed `vitest` bin — the bytes CI installs.
- **What we trust that we should name.** (a) Bun's resolver may select `"bun"` conditional exports — four externalized packages declare one (`isows`, `msgpackr`, `@logtape/logtape`, `axios`); their ESM entry files may differ under Bun, recorded by the out-of-process resolver and allowlisted in the compare; any other difference fails the compare. (b) `--bun` symlinks `node` to Bun for the process tree; no unit test spawns a process (F12). (c) `interopDefault: false` removes vitest's named-export fallback for CJS deps; each runtime's own loader then decides — the same-commit Node references on every suite are the proof nothing depends on the fallback.
- **Evidence integrity.** Summaries are review evidence, not tamper-evident: every summary carries provenance (canonical argv, repo-relative cwd, script, runtime mode, git SHA + clean flag, lockfile hash, per-run runtime records, vitest version, pool/workers, per-run exit codes and inventory digests) and the comparator refuses dirty trees, SHA/lockfile/version/runtime-identity/argument drift and non-allowlisted resolution differences; both matrices come from one clean commit; the comparator's stdout and the digests are preserved in the lessons and the PR body; no absolute or home paths in any committed or compared artefact (canonicalization + the pre-commit brand/path guard).
- **Least privilege.** No workflow permission changes (no YAML changes at all). No new CI variables. The `workflow_dispatch` uses the existing `pr-quick.yml` with its existing permissions.
- **Gate integrity.** The three required checks keep being produced by the same jobs; nothing becomes advisory. The soak tool is a local/plan gate, not a CI gate — it never weakens or replaces `quality-status`; its own ability to fail (crash, hang, unhandled rejection, missing output, wrong source map) is asserted on both engines by `test:ci-gating` on every CI run, with fixture names `bun:test` cannot discover. Runtime-conditional skips are forbidden.
- **Crypto tests under a second engine.** wallet-crypto's KATs mix `node:crypto` (`hkdfSync`, `createHash`) with WebCrypto; a KAT mismatch is a wrong answer, never a flake — a hard stop (failure procedure (b)).
- **Run isolation.** Soaks run one at a time in the owning worktree; each child is its own process group, killed as a group on timeout/signal; temp dirs are per run under the OS temp dir and removed; nothing under a shared fixed path; no port or service is involved.
