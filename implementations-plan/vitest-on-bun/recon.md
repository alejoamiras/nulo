## Findings that shape the design

1. **The migration is entirely script-level.** `bun run test:all` → each package's `test` script → `vitest run`. Editing 11 script strings to `bun --bun vitest run` flips them one by one; `pr-quick.yml`'s `changes` filters already cover every `package.json` (`behavior-gating.test.ts` derives them from the `@nulo/*` graph — a script edit touches no filter pattern, so no CI change is required; adding a NEW workspace would). Root `test:e2e:network`/`test:e2e:all` and `apps/extension/scripts/e2e/agent.sh:193` name vitest directly — they belong to the e2e layer and stay on Node (dossier: e2e stays this arc; `observability.test.ts` spawns a Node child by shebang regardless of parent — also e2e, untouched).
2. **One interop defect explains every Bun failure in the repo** (probes § 3): vitest's `interopModule` tests `"__esModule" in mod.default`; Bun answers `true` for ES-module namespace objects (Node: `false`), so an externalized ESM package whose `default` export is a namespace (zod@4) loses its other named exports. Reached through `@nulo/wallet-sdk-schema-patch/src/apply.ts` (`z.function`) into extension (124 files), wallet-bridge (2), schema-patch (1), faucet unit (6) and faucet jsdom smoke (3). `test.deps.interopDefault: false` fixes it on Bun and is byte-identical on Node (aggregate 372/4635 both). Everything else — aztec-runtime incl. the bb.js-WASM node-only files, bridge-core's Aztec/WASM graph, wallet-core, wallet-crypto, extension-messaging, design (Vue SFC), landing — is identical between runtimes on a single run.
3. **Six packages run twice per CI pass**: standalone (own config or defaults, node env for the config-less ones) AND inside the extension aggregate (`apps/extension/vitest.config.ts:32-44`, jsdom, `tests/vitest.setup.ts`, 7 bb.js-WASM files excluded, `server.deps.inline: [/^@nulo\//]`). Flipping "package X" means its standalone script; the aggregate copy flips with the extension in the last phase. The plan must say so explicitly.
4. **No soak harness exists for the unit layer; no unit-layer flake catalogue exists either** — all flake documentation (`e2e-deflake/flake-ledger.md`, `network-test-triage`, …) is e2e. Unit configs carry no `retry`; 46 files use `vi.useFakeTimers`, 108 files / 426 `vi.mock` sites, 30 `vi.hoisted`, 27 `vi.waitFor`, 0 `test.concurrent`, 0 workers/SAB/MessageChannel, 0 direct WASM or `node:inspector`/`worker_threads`/`vm` imports (jsdom and the `forks` pool use `vm`/`child_process` inside vitest itself). Densest race/timer suites: `profile/service.integration.test.ts` (2644 lines), `incoming-transfer/service.scenarios.test.ts` (3933 lines), `wallet/utils/offscreen.test.ts`, `aztec-runtime/src/pxe/opfs-store-open.test.ts` (30 s fake-timer windows), `wallet-core/src/utils/lock.test.ts`.
5. **Vue transform surface is inert under a runtime change**: test-time plugin sets are `vue()` (+ `unplugin-auto-import` with `dts:false` in extension, + `nuloComponentsPlugin({dts:false})` in faucet); no file-writing or process-spawning plugin is reachable from any `vitest.config.ts` (the `.wasm` emitters and faucet's `buildMetaPlugin`/`execSync` are `apply: "build"` in the never-imported `vite.config.ts`); `sass` is dead on the test path; storybook is a separate Vite server not wired to vitest. `apps/faucet/src/test/setup.ts:6-14` fakes `process` behind `typeof globalThis.process === "undefined"` — under Bun+jsdom the real `process` is present (same as Node+jsdom via vitest's env — the shim guards a case vitest does not produce; recorded as an Inference to verify, not a change).
6. **`apps/faucet` is missing from the dossier's order** — it has a jsdom unit suite (53 files / 542 tests) and a jsdom in-process "e2e" smoke (`vitest.e2e.config.ts`, 3 files / 15 tests, run by `_build-faucet.yml:44` inside the faucet BUILD job) — both behave like unit-tier suites and are in scope; `apps/playground` has no tests; `apps/landing` is a plain-TS node control (1 file).
7. **Worker pools**: unit configs set no pool (vitest 4 default `forks`, `coverage.*.js:180`); e2e configs pin `forks` + `fileParallelism: false`. Probed: workers are Bun under both `threads` and `forks` with `--bun`. Nothing in the repo reads `os.cpus()`/`availableParallelism()`; vitest sizes its pool itself — a runtime-behaviour item for the baseline, not a code change.
8. **Dossier drift to correct while here**: `adoption-map.md:16` still lists the removed `pr-quick.yml` inline Bun pin; `:17` overstates `Bun.$` usage; the Arc C order omits faucet; `CI.md:29` (landing) as above.

## Conventions to match

- Config shape: thin `defineConfig` from `vitest/config`, `globals: true` universal, `resolve.alias["@"] → src`, colocated `*.test.ts`; unit/e2e split is by separate config FILES, never `--project`/workspace.
- Scripts: `test` = `vitest run` (never bare `vitest`); `test:watch` only in faucet/bridge-core/design (local-only, never in CI).
- Bun-native tooling lives in `scripts/**` with a colocated `bun:test` file and is run by `bun test scripts/<dir>/` (`test:ci-gating`), which `_unit-tests.yml` already executes — a new `scripts/ci-cd/*.test.ts` is CI-covered for free. Arc-scoped throwaway tools go to `implementations-plan/<plan>/tools/` and are run with `bun <path>`.
- Comments: dated, evidence-cited rationale next to a non-obvious setting (`bunfig.toml` style; `vitest.e2e.config.ts:29-33`).
- Required checks `quality-status` / `smoke-e2e-status` / `network-e2e-status` are produced by the existing jobs and must keep being fed by them — no parallel/replacement job, nothing advisory.

## Collision / dedup risks

- Two `design-resolver.ts` files (extension, faucet) with different component sets — never edited together. Two `vitest.e2e.config.ts` files with opposite semantics (extension: Node + Puppeteer; faucet: jsdom in-process).
- The extension aggregate re-runs six packages: a package "flipped" standalone still runs under Node inside the aggregate until Phase 4 (and vice versa) — split results are expected mid-arc, not a regression.
- `audit:vue` (local gate) runs only the extension suite; the other workspaces are exercised only by CI's `test:all` — the plan's gates call `test:all` explicitly.
- An out-of-workspace `audit/bugs/2026-08-22-production-ready/proofs/vitest.config.ts` and the archived `adversarial-key-model-review/harness/*.audit.test.ts` are not wired to any script — not part of the surface.
- Untracked probe artefacts (`apps/extension/vitest.config.probe-*.ts`, `apps/faucet/vitest.config.probe-interop.ts`) must be deleted before the first commit; the reproducer lives in scratch and is reproduced verbatim in the lessons.
