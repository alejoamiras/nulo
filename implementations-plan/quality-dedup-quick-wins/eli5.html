Quality dedup quick-wins (batch)

A batch of small, independent "remove duplicate code" cleanups from the quality audit — each its own PR, merged one at a time, validated by CI before the next starts. The goal: less copy-pasted code that has to be kept in sync by hand, with zero behavior change.

Why this tier was chosen

Mid. Each cleanup is low-novelty, low-risk, and per-PR revertible — but they span 4 packages and each carries one small "don't break this" rule, so the dual audit (two independent reviewers) is worth it. That audit paid for itself immediately: it caught that the week-old audit list was stale and two of the original seven weren't actually quick (details below).

Scope changed after the audit: 7 → 5

  • Q21 (scope-enforcement dedup) — dropped. A PR that merged after the audit (#91) already did this dedup; the code the audit described has moved and is mostly cleaned up.
  • Q19 (active-profile guards) — demoted to its own plan. It's 90 call sites, ~37 of which deliberately don't error — telling those apart is careful auth work, not a "quick win". Doing it mechanically could silently weaken a lock check. It deserves its own focused plan.

Phases (each = one PR, merged before the next)

Phase 1 — Q16: delete dead code

Remove exports/files nothing imports anymore (a couple of helper subpaths, a few unused functions, one unused dependency).

Proves itself by: each deletion gated by a search proving nothing uses it + the package's unit tests stay green. (No network e2e — it's dead-code removal.)

Phase 2 — Q22: share the serializer helper

Two helpers turn BigInts/Errors into JSON in overlapping ways. Share only the truly-common part — keeping each one's deliberately different output exactly as-is (one feeds the wire protocol; the other a job log). First we add tests pinning both outputs, then refactor.

Proves itself by: the wire-shape tests + the new job-error tests stay green; network e2e confirms the RPC wire format is unchanged.

Phase 3 — Q20: one home for the CAIP helpers

Two copies of the same chain/address-string functions. Make the bridge package the single owner; the extension re-exports. (The shared types are already centralized — only the functions are duplicated.)

Proves itself by: a parity test (both sides produce identical output) + unit tests green.

Phase 4 — Q7: de-duplicate the test/build configs

Several Vite/Vitest configs copy the same settings under "keep in sync" comments — and the sync already broke (the "all" e2e config lost some settings). Extract a shared helper and fix the drift.

Proves itself by: build + unit green, resolved-config diff shows no unintended change, and network e2e confirms the e2e configs still work on CI. (This is the only cleanup with an already-shipped bug.)

Phase 5 — Q14: share the restore-result loop

14 services hand-roll the same "collect each restored item + its error" loop. Extract one helper; each service keeps its own validation/locking. Preserve every existing quirk exactly (including one service's odd error shape — pinned by a test, fixed in a later follow-up).

Proves itself by: each service's restore test + a helper test green, and the smoke backup-import test exercises the restore path end-to-end.

Human context

"Dedup" = the same code copy-pasted in N places, which rots when someone updates one copy and forgets the others. Each phase replaces N copies with one shared piece. The risk in dedup is accidentally changing behavior while consolidating — so every phase preserves the existing quirks verbatim (pinning surprising ones with a test) and re-verifies the code against the latest dev before touching it (the lesson from the stale audit list). Two cleanups touch sensitive surfaces — the wire format (Q22) and chain-address strings crossing the dapp boundary (Q20) — so those keep their output byte-identical.

R2 — How much testing per cleanup? (default: selective)

Your original ask was "run the full network e2e suite on every cleanup." The reviewers pushed back: that suite is slow, is currently being de-flaked by another agent, and most of these cleanups don't touch anything it actually exercises. Decision: selective testing (default) vs your original network-e2e-every-cycle.
