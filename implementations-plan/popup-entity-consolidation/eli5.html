Popup Entity Consolidation

One mechanism owns the popup Enter-key lifecycle — and cleans up after itself.

What & why

Eight popups share one Enter-to-submit helper; four more still hand-copy the same ~15-line boilerplate, and none of it removes its keyboard listener when a component dies. That never hurts users (popups never die in the running wallet) — but it has now tripped our own tests three times, and five copies of the same code drift apart (last arc proved two already had). This arc: the shared helper cleans up after itself automatically, the four copies are deleted by moving onto it, and the test suites drop their hand-rolled workarounds.

What the review round changed (its reject was right)

  • The subtle one: the four popups only accept Enter after their data finishes loading. The naive migration would have made Enter live during loading — and the safety nets from last arc stop double-submits, not a too-early first submit (which could, e.g., add a duplicate FPC because the duplicate list hadn't loaded). The helper now gets an opt-in "wait for loading" switch so each popup keeps its exact current timing.
  • Async loading errors would have been silently dropped — the helper is now promise-aware and re-surfaces them.
  • Test cleanup becomes guaranteed (runs even when an assertion fails) instead of a per-test convention, plus one canary test proving the leak can never quietly return.
  • NewToken is named as a deliberate exception (it has specialized teardown and the family's biggest test suite — migrating it is risk for no gain).
One decision for you: the repo's rulebook says composables must not own their teardown (parents call dispose()). The self-cleanup here technically bends that — for a keyboard listener, not a service.

(a) Recommended: add a one-sentence carve-out to CLAUDE.md ("scope-tied cleanup of non-service resources is allowed; service clients stay parent-disposed") — this matches what parts of the codebase already do.
(b) Alternative: the helper returns a dispose() all twelve popups must remember to call — stricter on paper, but it reinstates the exact forget-one-callsite failure mode this whole effort exists to kill.

Risk posture

Zero intended behavior change; every timing preserved per popup and pinned. The two never-tested popups get their pins before migration; the two well-tested ones use their existing suites as the regression oracle. Frozen-oracle suites untouched, byte-identical.
