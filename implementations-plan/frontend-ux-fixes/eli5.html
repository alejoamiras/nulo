Frontend UX fixes — batch 1

Six small things you reported in the wallet popup were annoying or subtly unsafe. This plan fixes them: a confusing settings label, a doubled border on the contact form, the ugly "vault" icon on accounts, the Send recipient display, a long address that scrolls out of view in input boxes, and keyboard Tab order that skips fields. It's all front-end polish — no network, no money-movement logic, no secrets touched.

Why this plan looks different from a first draft: it was rejected three times before it was right. Two independent reviewers (codex + a top-tier Claude critic standing in for the offline Fable model) both rejected the first draft (factual mistakes + a security gap); a final fresh-context pass then rejected the revision too, catching real bugs it had introduced (a keyboard-focus regression, an incomplete fix). All folded. The full story is in the decision ledger and the audit transcripts (codex, opus).

Why "mid" tier

Rubric: ~1 higher-risk + 2 medium dimensions. Security-sensitivity — fix #3 changes how you verify who you're sending money to. Blast radius — fix #5 changes a shared toggle/dropdown's keyboard behavior, which touches many screens; fix #2 adds an address-input behavior. Everything else is contained and reversible. That's a textbook mid: dual audit, competing outline, final fresh-context pass — which is exactly the ceremony that caught the first draft's mistakes.

The two decisions you made

  • Account indicator → initials avatar (a little colored disc with the account's initials, color derived from its address). The "emoji identicon" idea was dropped: a single emoji is only 256 possibilities (trivially faked), and the emoji tool can't even read a raw address. Initials are legible at tiny sizes and carry no security weight — they just sit next to the real name + address.
  • Send recipient → masked card with on-screen reveal: name + 0x first-8 *** last-8, and a tap to reveal the full address + copy, right there before you hit Send.

Phases

P1 — Copy + border quick fixes (#1, #6)

Settings: the row under "Identity" shows your profile name (confusing) → make it say "Profile". Contacts: a doubled line where the address box meets the "Register as a sender" row → remove the extra border. Tiny, safe.

Proves itself by: typecheck + lint + the contact/settings component tests + build, all green.

P2 — Replace the "vault" icon with an initials avatar (#4, non-Send)

You hate the vault SVG. It's also the same icon for every account (no distinction at all). Replace it on the account rows with a small initials avatar whose color is derived from the address — so accounts finally look different from each other. One reusable avatar component, shared with the Send card.

Proves itself by: avatar component tests + a check that no "vault" usage remains + build.

P3 — Send recipient card (#3) + remove the Send vault icon (#4)

When you pick a recipient, show a card: avatar + name + the masked address, with a one-tap reveal of the full address (selectable, copyable) for when you want 100% certainty. The reviewers pushed for a forced reveal (the Send screen submits and leaves with no later confirmation, so the card is the only check). You decided the reveal stays optional — you'll tap it when you want to verify. That's a deliberate call you own; the build just makes the reveal obvious and one tap away, and applies the same card to addresses you paste in directly (so nothing skips it).

Proves itself by: RecipientField tests (rewritten — they used to assert the vault icon) + the send smoke test + build.

P4 — Address inputs that don't scroll out of view (#2)

Typing a long 0x… address in a narrow box makes the start scroll off-screen and "jump" on focus. Fix: when you're not editing, show a clean truncated address; when you click in, show the real editable input. Done with a thin extension-side wrapper that never rewrites the value — so paste, selection, and screen readers keep working (the reviewers flagged that risk explicitly).

Proves itself by: wrapper tests (blur/focus, value stays intact) + a paste smoke test + build.

P5a — Fix the keyboard Tab order at the root (#5)

The real cause (the first draft got this wrong): two shared widgets force a bogus tabindex="1", which corrupts Tab order for the whole page; and the show/hide-password button sits between the password and confirm fields, so Tab lands on it instead of the next field. Fix both, write down the convention (no forced tabindex; secondary buttons sit out of the Tab path), and pin it with a test that Tab really goes name → password → confirm.

Proves itself by: the create-account Tab test going green + the toggle's own tests still passing + build.

P5b — Sweep the remaining screens (#5) — needs your hands on the keyboard

With the root cause fixed, walk every remaining screen and confirm Tab order reads top-to-bottom. This one ends with you tabbing through onboarding, send, contacts, settings, and the edit popups to sign off.

Proves itself by: full audit:vue + smoke + your keyboard sign-off.

Human context

"Masking" an address means hiding the middle (0x3333…7a9c) so it fits and reads cleanly. That's fine for showing an address you already trust, but dangerous as the only thing you see before sending money — attackers can grind a fake address that matches the visible ends. That's why P3 keeps a full-address reveal. "Tab order" is the sequence the keyboard moves through fields when you press Tab; a stray setting can scramble it for the entire page, which is what was happening.
