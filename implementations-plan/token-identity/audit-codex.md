# Codex audit transcript - token-identity

## Round 1 - dual audit (new session, xhigh, both outlines)

Verdict: **reject** - blockers folded same-round (T6 contracts-capability enforcement, T7 silent route, the explicit 18-dec sweep incl. parse + L1 mint, the deploy symmetry assert). Outline: redeploy.

- The privacy model is not real in the current flow. `dispatch()` only does type-gating plus whatever checker exists in `METHOD_SCOPE_CHECKER`; there is no token-address scope checker today, and `registerToken` itself is explicitly routed through the popup path, not the silent/query path ([dispatcher.ts](/Users/alejoamiras/Projects/nulo/nulo-4/packages/wallet-bridge/src/dispatcher.ts:233), [dispatcher.ts](/Users/alejoamiras/Projects/nulo/nulo-4/packages/wallet-bridge/src/dispatcher.ts:483), [scope-enforcement.ts](/Users/alejoamiras/Projects/nulo/nulo-4/packages/wallet-bridge/src/scope-enforcement.ts:348)). A non-prompting `isTokenRegistered` can fit, but only as a new direct/silent handler or new execution op; it does not “mirror registerToken”.

- The proposed per-token grant on `accounts` is the blocker. `accounts` re-consent only diffs `canGet`/`canCreateAuthWit` ([dispatcher.ts](/Users/alejoamiras/Projects/nulo/nulo-4/packages/wallet-bridge/src/dispatcher.ts:140), [dispatcher.ts](/Users/alejoamiras/Projects/nulo/nulo-4/packages/wallet-bridge/src/dispatcher.ts:556)), so adding `queryableAddresses` would neither re-prompt nor backfill existing sessions. The popup also hides `accounts` from the capability-card list and only renders the account picker ([build-items.ts](/Users/alejoamiras/Projects/nulo/nulo-4/packages/extension/src/popup/windows/capabilities/build-items.ts:32), [index.vue](/Users/alejoamiras/Projects/nulo/nulo-4/packages/extension/src/popup/windows/capabilities/index.vue:108)); the visible copy is only coarse “Account access / Register tokens” with no token-address scope ([capability-meta.ts](/Users/alejoamiras/Projects/nulo/nulo-4/packages/extension/src/wallet/services/dapp-session/capability-meta.ts:34), [CapabilityDetailPanel.vue](/Users/alejoamiras/Projects/nulo/nulo-4/packages/extension/src/components/composite/capabilities/CapabilityDetailPanel.vue:44)). That silent ask must be resolved first: new capability type, or field-diff + UI work.

- The 3-copy schema-patch risk is understated. The pinned reachability test imports only the extension copy ([dispatcher.test.ts](/Users/alejoamiras/Projects/nulo/nulo-4/packages/wallet-bridge/src/dispatcher.test.ts:676)); faucet/playground copies can drift unnoticed. Inference attack: registry-readable is directionally true (`findToken` exists), but the dispatcher is not wired to any token reader today; playground has its own schema patch, but not a faucet-style manifest that automatically needs token-address grants.

- The 18-dec sweep is broader than the plan’s proof points. Execution/validation still use `Number(...) * 1e6` in [BridgeForm.vue](/Users/alejoamiras/Projects/nulo/nulo-4/packages/faucet/src/components/BridgeForm.vue:83), and display/toasts still use `Number(...)/1e6` in [BridgeForm.vue](/Users/alejoamiras/Projects/nulo/nulo-4/packages/faucet/src/components/BridgeForm.vue:219), [BridgeReceipt.vue](/Users/alejoamiras/Projects/nulo/nulo-4/packages/faucet/src/components/BridgeReceipt.vue:32), [BridgeStepper.vue](/Users/alejoamiras/Projects/nulo/nulo-4/packages/faucet/src/components/BridgeStepper.vue:48), [BridgeJournal.vue](/Users/alejoamiras/Projects/nulo/nulo-4/packages/faucet/src/components/BridgeJournal.vue:32), [BridgeJournalCard.vue](/Users/alejoamiras/Projects/nulo/nulo-4/packages/faucet/src/components/BridgeJournalCard.vue:130). L1 mintability is real, but `MINT_AMOUNT = 100_000_000n` plus “MINT 100 USDC” would mint dust on 18 decimals ([useL1Usdc.ts](/Users/alejoamiras/Projects/nulo/nulo-4/packages/faucet/src/composables/useL1Usdc.ts:51), [MintTestUsdc.vue](/Users/alejoamiras/Projects/nulo/nulo-4/packages/faucet/src/components/MintTestUsdc.vue:26)). Deploy-wise, stale bridges are safely bound to `chainId + portal + bridge` ([useBridgeJournal.ts](/Users/alejoamiras/Projects/nulo/nulo-4/packages/faucet/src/composables/useBridgeJournal.ts:271)); seal-trust survives redeploy by design ([seal-trust.ts](/Users/alejoamiras/Projects/nulo/nulo-4/packages/bridge-core/src/seal-trust.ts:40)); token registry/incoming-trust are contract-keyed, so redeploy correctly reads as unregistered/untrusted ([token/service.ts](/Users/alejoamiras/Projects/nulo/nulo-4/packages/extension/src/wallet/services/token/service.ts:510), [repository.ts](/Users/alejoamiras/Projects/nulo/nulo-4/packages/extension/src/wallet/services/incoming-transfer/repository.ts:23)). Primary redeploy beats alias; alias cannot satisfy 18-dec or honest on-chain identity. The deploy script currently hardcodes both sides to `6`, but does not assert symmetry ([deploy-bridge-testnet.ts](/Users/alejoamiras/Projects/nulo/nulo-4/packages/bridge-core/scripts/deploy-bridge-testnet.ts:98)).
