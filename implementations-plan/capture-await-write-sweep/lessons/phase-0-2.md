Pass-1's full-file reading was immune; the screen-based pass 3 caught the two missed fee files only because its sweep included a generic `ident(.prop)+ =` pattern. Future censuses: include property-chain assignment in the write signal from the start.
- **The fenced-restore/unfenced-create asymmetry is a pattern-hunt goldmine**: batch 7 fenced all nine `restore()` writers with entry-captured deletion epochs, and the CREATE paths in the same files (addNetwork/addContact/addFpc/addDappSession/persistToken) were left bare. When an audit fixes a family member, sweep the siblings by construction, not by finding.

All three CONFIRMED.
