Pass-1's full-file reading was immune; the screen-based pass 3 caught the two missed fee files only because its sweep included a generic `ident(.prop)+ =` pattern. When an audit fixes a family member, sweep the siblings by construction, not by finding.

The strict per-file coverage statement ("zero-candidate files still listed with a reason") is what makes absence claims auditable.

## Phase 3–4 (implementation + battery)

- **Widened dependency surface widens every stub — the FULL suite is the only census.** Per-file test runs during F1..F13 caught 3 stub-widening breaks; `audit:vue`'s full run caught a 4th (`cross-profile-isolation.test.ts` — its `FakeProfileService` class predates the fence). Any change that adds a method call on an injected service must expect one widening per HAND-ROLLED stub class, and only the whole-suite run enumerates them.

When a downstream write already carries an authority assert, "thread the fence" can collapse into "derive identity from the already-asserted row".
