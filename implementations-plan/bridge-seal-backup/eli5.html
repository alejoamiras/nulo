bridge-seal-backup

An in-flight bridge lives only in your browser's storage - wipe the site data mid-bridge and the claim is stranded. This adds a tiny escape hatch: every pending bridge card (and the live stepper) gets a small ⤓ icon that downloads that ONE bridge as an encrypted recovery file, and the PENDING BRIDGES header gets a quiet RESTORE button that loads such a file back - on any browser, as long as you hold the same Ethereum wallet. The file is always sealed: stolen or leaked, it's useless without your wallet's signature.

Why this tier was chosen

light, your call, rubric-consistent: one bounded feature, no new cryptography (it reuses the audited recovery-key scheme from the private seal), one package + a small bridge-core module. The single codex audit earned its keep anyway - it caught that a first-time export needed the same sign-twice determinism check the private seal does (otherwise a quirky wallet could export a file that can never be opened again), and that half-started withdraws have nothing restorable in them yet.

Phases

Phase 1: The file format (bridge-core)

A small module that seals a whole bridge record into a versioned JSON file and opens it again: encrypt-everything (public bridges' claim secret never touches disk readable), tamper = refuses, wrong wallet = refuses, unknown version = honest "newer app needed". Proven by round-trip and sabotage tests.

Phase 2: The two buttons (faucet)

The ⤓ on unfinished cards + the stepper (tooltip explains it; withdraws only once they have their exit transaction - before that there's nothing worth saving). RESTORE in the journal header opens a file picker, validates hard (right deployment, not already tracked, your wallet's signature opens it, the contents check out), then the bridge appears as a normal pending card - you press CLAIM like always; nothing fires automatically.

Human context

The trick making this cheap and safe: your Ethereum wallet always signs the same secret message for a given bridge, and that signature IS the encryption key. So the file needs no password, no server, no account - just the wallet that made it. Exports of bridges you sealed this session cost zero extra signatures (the key is still in memory); otherwise one signature to save, one to load. First-time wallets sign twice once (a determinism check the private seal already does) so we never produce a file that can't be reopened.
