token-prices

Today the wallet shows fake dollar signs: the home screen says "$0.00", the send screen says "~ $0.00 · no quotes available", and fee costs are computed from a made-up rate (0.02) hardcoded in the source. This plan makes all of those real. The wallet will ask CoinGecko (a free public price site) "what are USDC and AZTEC worth?" every few minutes while unlocked, remember the answer, and use it everywhere a dollar amount appears. Aztec-network tokens are too new to be listed anywhere, so we map them to their Ethereum twins: cUSD is priced as USDC, and Fee Juice (the gas token) is priced as AZTEC. Separately, the wallet will come with cUSD pre-added on Mainnet and Testnet, so a fresh install isn't an empty token list.

Why this tier was chosen

mid. Rubric: novelty LOW (the background-service pattern is well-established here), blast radius MODERATE (display across many screens; prices never move funds on their own), irreversibility LOW (no migrations), migration cost LOW, external coupling HIGH (third-party price API), security sensitivity MODERATE (the one risky spot — typing dollars in Send — got a dedicated safety policy). One HIGH → mid: plan + competing outline, dual audit, decision ledger, final fresh codex pass.

Your design picks (from the options artifact)

  • A1 — home header keeps the token amount big; a small "≈ $1,249.38" appears under it. "Account Value" finally shows a real total (labeled when some tokens have no price).
  • B1 — each token row shows what your holding is worth. No price → nothing shown, never a fake zero.
  • C3 — the send screen gets a flip switch: type dollars, the wallet converts to tokens — with a shimmer while it recalculates, and hard safety rules (below).
  • D2 — fees use the real AZTEC price instead of the made-up rate; the gas card shows what your Fee Juice is worth.

What the audits changed

Two independent reviewers (codex: reject; fable: conditional approve) attacked the draft. Their findings converged and were all adopted. The big ones, in plain language:

  • The draft had a stale Testnet id. The network hard-forked recently and the plan's Testnet identifier was the old one — tokens would silently never seed. Fixed and re-verified against the code; a live on-chain check of the cUSD address is now a blocking step before anything ships.
  • Typing dollars needed stricter rules. Prices move; the amount you saw must be the amount that sends. Now: the quote is frozen while you type, the send button is disabled while converting, you always confirm token units, and if the price moved more than 1% you're asked to re-confirm. The line also says "via USDC" so the proxy is explicit.
  • Pre-added tokens can't trust the network blindly. The wallet's RPC endpoint could lie about what a contract is. Seed entries now pin the expected contract fingerprint; mismatch → nothing is added.
  • No always-on beacon. Price fetching only runs while the wallet is unlocked (it was going to be every 3 minutes forever). This is one of the questions below.

A second fresh-eyes codex pass on the revised plan pushed further and won four more changes: the seeding check now validates and saves the exact same data in one pass (no window for a lying server to swap answers), fee screens never trigger a fetch at transaction time (that timing itself is a privacy leak — they use the cache or show nothing), a release build now fails if an API key is present (not just a scan), and two honest limitations were promoted to questions for you (#7 and #8 below).

Final verdicts: fable — conditional approve (all conditions adopted). Codex — conditional approve on the amended plan (its last two conditions: validate before registering / roll back so a rejected seed can't poison local state — adopted; and a deleted default token now stays deleted even across network remove/re-add — adopted). The remaining codex conditions are exactly the eight questions below being answered before their phases.

Phases

Phase 1: The price engine

A background worker that asks CoinGecko for all mapped prices in one request (every 3 minutes, only while unlocked), checks the answers look sane, remembers them, and tells the UI. Includes a real settings toggle ("Show fiat values") that turns all of it off. AZTEC ($0.0147) and USDC ($0.9999) listings verified live during planning. No new browser permissions needed (verified: CoinGecko allows extension fetches).

Proves itself by: unit tests (fetch/cache/off-switch/staleness/backoff/sanity-bands) + one opt-in real-API test run locally + lint + typecheck, all green.

Phase 2: Pre-added tokens

A short built-in list (cUSD on Mainnet + Testnet). After unlock, the wallet quietly adds missing listed tokens through the same machinery as a manual add — with the contract-fingerprint check. Delete one and it stays deleted; failures retry a few times then give up quietly.

Proves itself by: unit tests (seed/skip/retry-cap/deletion/purge cases) + a BLOCKING live check that cUSD actually exists at that address on today's Testnet and Mainnet, logged in lessons.

Phase 3: Home screen dollars (A1 + B1)

The header's fiat line, the real Account Value total, per-row values in the token list, and removal of every fake $0.00 (including two screens the draft missed — the balance-type popup and the Fee Juice card get theirs in phase 4).

Proves itself by: Vue component tests (priced / unpriced / stale / partial-total cases) + unit + lint + typecheck, all green.

Phase 4: Real fee prices (D2)

Fee estimates, transaction details, and the gas/Fee Juice cards switch from the made-up 0.02 rate to the live AZTEC price (~$0.015 today, so displayed fee dollars will visibly change). Done before the send-input phase on purpose — lower risk first.

Proves itself by: updated fee-estimation unit tests + component tests for both cards + lint + typecheck, all green.

Phase 5: Type dollars in Send (C3)

The flip switch, under the safety policy: frozen quote while typing, send disabled mid-conversion, token amount always confirmed, >1% price move forces re-confirmation, "via USDC" label, and math that never loses precision (rounds down, never invents dust).

Proves itself by: ≥10 new component tests on AmountCard (both directions, rounding at extremes, Max/Half, freeze + re-confirm rules, shimmer) + unit + lint + typecheck, all green.

Phase 6: End-to-end + docs

Browser tests confirm nothing fake shows when prices are unavailable; the full network suite confirms nothing broke; a release check guarantees no API key ever ships in a build; docs updated.

Proves itself by: full pre-PR gate (typecheck → tests → lint → build) + smoke e2e + network e2e, all green.

Human context

The old hardcoded fee rate carried a comment "hardcoded for privacy (no external API)" — a deliberate stance this plan consciously trades away, narrowly: the wallet always asks for the same fixed list of prices in one request (nobody can tell what you hold from the question), only while you're actually using it, and the settings toggle turns it off entirely. And prices are display-only by design everywhere except the dollar-input switch, which is why that one surface got the strict policy above.

Open questions (the plan's Asks — answer with your verdict)

  • 1. Seeding isn't covered by the live-network browser suite (the local sandbox chain has no cUSD by design). It's covered by unit tests + the blocking live preflight instead. OK?
  • 2. USD only — no currency picker. OK?
  • 3. 1 Fee Juice = 1 AZTEC for pricing. OK?
  • 4. Refresh only while unlocked, on by default (no always-on fetching; note the first fetch happens right after unlock, before a new user sees the settings toggle). OK, or require opt-in consent first?
  • 5. Testnet shows real prices (test tokens valued at real-market USD; Aztec's docs are explicit that Testnet Fee Juice is NOT AZTEC — so this is a knowing dev-convenience fiction). OK, or hide fiat on testnet?
  • 6. Seed trust = pin-on-first-probe: the expected contract fingerprint is captured once from the canonical public RPCs and pinned in code. OK?
  • 7. Dollar-input uses a single price source. If CoinGecko's quote were persistently wrong (depeg, poisoning), the 1%-movement check can't catch it — your protection is that the token amount is always shown and confirmed before sending. Accept that, or restrict dollar-typing to nothing (display-only prices, dropping the C3 flip switch)?
  • 8. CoinGecko's free keyless tier is aimed at non-commercial use. The plan ships "Prices by CoinGecko" attribution + a docs note either way. Accept keyless-with-attribution now and revisit the plan tier at release time, or resolve licensing before implementation?
