# Recon — self-pay-setup-fix

2026-09-05, against `origin/dev` (898a3b99). Two read-only explorers (one batched reuse sweep, one build-path mapper) plus the driver's own reads of the node and the frozen/installed Aztec sources.

## The failure, restated from evidence

Two bridge claims from the tools preview (`worktree-tools-console`, built on this same `dev`) failed inside the dApp-facing **`simulateTx`** (the bridge polls `claimCall(hub, p).simulate(claim)` in `packages/bridge-core/src/hub-l2.ts:236` before it sends):

| Attempt | Account | Fee path chosen by the bridge | Node error |
|---|---|---|---|
| 1 | `0x00f6…40a2` (first private bridge, "two signatures") | private credit at the PrivateFPC | `Nullifier read request at index 0 is reading an unknown nullifier` |
| 2 | `0x0e35…c659` | `own-gas source: public` — self-pay from 71.077 public FJ (`publicAllowed: true`) | `The simulated transaction is unable to be added to state and is invalid. Reason: Setup function not on allow list` |

Trace of attempt 2: `SimulatedSchnorrAccount:entrypoint → TokenBridgeHub:claim_private → Token:mint_to_private → HandshakeRegistry:non_interactive_handshake → validator error`. The public call the validator rejected is `Token._finalize_mint_to_private_unsafe`, enqueued by `mint_to_private` two frames inside the app payload (`contracts/bridge/aztec/token_bridge_hub/src/main.nr:253-273`). For it to be in setup, nothing in the transaction had ended setup by then.

## After the dual audit (rev 2)

- **H5 (added, code-verified):** `packages/wallet-bridge/src/dispatcher.ts:1299-1301` resolves every ACCOUNT_KIND (`aztec_simulateTx`, `aztec_profileTx`, `aztec_executeUtility`, `aztec_createAuthWit`) without the requested `from`, and `:1368-1376` overwrites `opts.from` with the session's first wallet-ordered account; only `handleSendTx` (`:834-838`) honours it (PR #110; `implementations-plan/network-e2e-required/FOLLOWUP-opts-from-clobber.md` names the remaining methods). A self-pay payload from account B simulated as A → `classifyFeePayer(B, A)` = `fpc` → `EXTERNAL` → no `end_setup` → the PXE's kernelless split (`contract_function_simulator.js:441-455`) files every public call as setup → the production error, on simulate only. Prime suspect.
- **H1 demoted:** the installed 5.2.0 stub's embedded source delegates to `AccountActions::entrypoint` (same fee branches); the kernelless split honours a nested `end_setup`.
- **H2 cannot explain a simulate failure:** `executeAztecSimulateTxStandard` never enters `buildAndEstimateTxRequest`.
- **H3 weakened:** the green `tx-sendTx-selfPay` is never-sent + `PREEXISTING` + a public enqueue after `end_setup`; the trace's root frame (account entrypoint, no multicall) suggests attempt 2's account was deployed.
- **H4 refuted** at the SDK (above).
