Card affordances — round 4

v0.15.4 QA surfaced 5 issues. Plan went through me + a Plan subagent in parallel, then two codex pre-implementation rounds. Each round caught a real bug. Plan v4 is ready to implement.

5 things you reported

1. Retry is misleading

The Retry button on Interrupted transfer cards looks like it'll retry the same tx, but it just opens the Send page fresh. Plus it only existed for transfers — never for dApp ops (we can't replay dApp requests) — which feels asymmetric.

Decision (you): drop retry entirely. Cleaner UX, ~9 fewer tests as a bonus.

2. Terminal transfer cards show no amount

Cancelled or Interrupted card for a transfer: shows the token symbol + "Cancelled" / "Transaction was interrupted". No amount.

Why: the journal record persists tokenId but never persisted amount (we explicitly punted on this in plan v3 — "don't bloat the schema").

Fix: add amountRaw (BigInt-as-string) + recipientAddress to the journal record. Display amount on terminal cards via the existing balanceFormatted path. Recipient persisted but not displayed yet — useful for a future tx-detail view.

3. Terminal cards disappear after 5 min

"What the hell, why did they disappear?" — fair. The 5-min auto-age was a row-budget compromise that didn't communicate well.

Fix: drop the 5-min window. Cancelled / Interrupted / Failed stay visible until browser exit (same as settled txs). Row cap bumps from 3 → 5 to make room (popup scrolls anyway if needed).

4. Duplicate card during cancel

Click Cancel → cancelled terminal card appears immediately, but the previous awaiting card also stays visible for a few seconds.

Why: the awaiting card has two data sources — TaskService (in-memory) and the journal (durable). Journal turns to cancelled fast; TaskService catches up slower. Brief gap = both render.

Fix: when a journal record transitions to terminal AND matches the current task, clear the task immediately. This took 4 audit iterations to get right (see "the audit cycle" below).

5. X icon clashes with amount column

On transfer cards (which have 5.00 USDC in the right column), the top-right X overlaps the amount text. "Almost impossible to see."

Fix: when the action slot is filled, add padding-right: 36px to the card wrapper. Amount column shifts left and gives the X dedicated space. No layout rewrite needed.

Context — two ways the popup knows about in-flight work

TaskService: in-memory task records the SW updates as the work progresses. Fast, ephemeral, lost on SW restart.

Journal: durable records in chrome.storage.session — Phase 2's whole reason for being. Survives SW restart + popup close/reopen.

The popup uses both; Phase 2 made the journal the primary source of truth for "is this in-flight?" The duplicate bug (#4) is fundamentally the two sources getting out of sync for a beat after cancel.

Known limitation we're accepting

Concurrent same-account dApp ops can cause a brief flicker. If two dApp ops are in flight at once (rare — approval popups serialize at the user level), a terminal event on op A could clear the executingTask while it's currently B. Visual: the awaiting card briefly disappears, then reappears within ~1 frame when TaskService re-syncs. No state corruption.

A future enhancement (plumb journalId onto task content for identity match) closes this if QA shows the flicker. Punting now because the surface change is larger and the consequence is purely cosmetic.
