The Untested Guard

Two jobs on the Ethereum side of the bridge: delete a copied contract file that no longer earns its keep, and write one proof for a safety check that — as it turns out — nothing tests. Planning it also uncovered a separate live bug, already fixed in its own PR.

The short version

You asked for two things. Along the way, two surprises showed up that changed what the work is worth.

Surprise 1 — a safety check nobody tests

The contract that holds your USDC has two guards on its setup function. One stops a stranger claiming it before you. The other stops anyone re-pointing it afterwards.

I deleted each guard in turn and ran all 62 tests. Deleting the first breaks a test — good. Deleting the second breaks nothing at all. The test named for it passes, because it checks a hand-written copy of the guard rather than the real contract.

So the plan isn't "add proofs to code that's already fine." It's closing a real gap and removing the test that was hiding it.

Surprise 2 — the deploy path was broken on dev

Unrelated to your request, and found by an auditor reading the same files: a hash pin had drifted, so verify-l1 and both deploy scripts died on startup. Your next deploy would have hit it.

Already fixed and out for review as PR #481, separate from this plan. It fails closed, so nothing unsafe could have shipped — the path was simply unusable.

What the pin bug was

Three things have to agree: the contract's source file, the pre-built artifact the deploy actually ships, and the hashes recorded in code that gate them. They're supposed to move together, as one deliberate act. A change last month moved only the third.

Nothing caught it because nothing in CI runs that path: no job installs the compiler toolchain, and the contracts workflow only watches the contracts folder. PR #481 re-pins to what the source actually compiles to and adds a fast test so the three can't drift apart silently again.

The plan itself

Job 1 — retire the copied file

There's a copy of Aztec's example portal in the repo. It exists because Aztec ships the compiled artifact but not the source, so verifying a canonically-deployed portal on Etherscan would have nothing to compile.

Every deployment now uses your forked portal instead, whose source you own — so that branch never runs. Deleting it is a genuine retirement, not dead-code removal: old pre-fork deployments were verified from this file and won't be re-verifiable afterwards. Those portals are superseded, and you've chosen deletion knowing that. Worth stating plainly rather than pretending nothing is lost.

Job 2 — prove the guard nothing tests

A normal test tries one attacker address you thought of. A proof checks every possible address at once, mathematically. We already have four such proofs on the router; this adds one to the contract that holds the money.

Phases

Phase 0 — baseline ✓ done

Set up the build, record what passes before anything changes, and run the experiments that found the untested guard.

Proves itself by: the build succeeding, 62 tests green, and the four existing proofs passing — all numbers written down so later claims have something to compare against.

Phase 1 — retire the copied file

Delete it and the code path that fed it. Every config now goes through the existing strict validator, which already refuses anything but the current format.

Proves itself by: unit tests including a new case for the rejection, lint and typecheck clean, and a real dry-run against the live testnet config still producing verification input for all four contracts.

Phase 2 — the proof, and repairing the broken test

Write the proof against the real contract. Delete the stand-in copy and rewrite the test that was checking it so it checks the actual thing.

Proves itself by: the proof passing — and then deliberately deleting the guard and watching it go red, restoring it, watching it go green. A proof nobody has seen fail is not evidence.

Phase 3 — make CI able to notice

Today the check would still pass if the proof file were deleted. Bind the expected count to the contract by name and remove that escape hatch.

Proves itself by: a real CI run, plus checking that hiding a proof file makes the step fail rather than quietly skip.

Context worth having

  • Why a copy exists at all. Aztec marks nothing in their portal as overridable, so a security fix couldn't be added by extending their contract — the file had to be copied and edited. That's a language constraint, not a style choice.
  • Why the contract file is now untouched. The compiler folds a hash of the source — comments included — into the bytecode. Editing even a stale comment would change the deployed bytes and invalidate the trust anchor for a live contract. Two comments stay out of date on purpose; that's the cheaper cost.
  • None of this blocks a merge yet. The contracts check is advisory, not required. Making it required is a separate decision you scoped out.
