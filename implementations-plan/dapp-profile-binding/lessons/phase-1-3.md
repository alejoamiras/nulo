- **The dispatch guard was extracted (`enforceSessionProfileBinding`) rather than inlined**: background.ts is untested by convention; the directory's extract-and-test pattern gave the guard its ordering pin (respond BEFORE terminate) and failure-path pin for free.
- **Fixture archaeology beat fixture-building**: the "never-driven" in-session profile switch turned out to be fully drivable with EXISTING testids (`header-lock` → `auth-profile` → `select-profile-new-btn` → `register-*` → creation auto-activates B = the switch). Phase 3's budgeted fixture-pioneering reduced to composing helpers that already existed (`waitForPopup`/`approveDiscover`/`approveVerify`).
- Marker-type migration touched exactly the 4+2 sites recon predicted; the session-established suite gained the five N-04 branch pins (fresh-match stamp, skew terminate, stale terminate, trusted-reconnect stamp, request-keyed isolation) and queued-journal gained the switch-race + belt + anchored-network pins.

## Battery-kill incident (2026-08-24 evening)

Three consecutive background-battery tasks were externally killed mid-run (first mid-audit:vue, then twice during/around the co-agent drain-wait). Not resource pressure (17-20 GiB free throughout); correlates with (a) the concurrent `vitest-on-bun` session's 50-worker load on the shared host and (b) the owner's interactive presence in this session (interrupts can reap background tasks). Response, per the 3-failures-reassess rule: stopped relaunching the monolithic 60-90 min chain and rebuilt it STAGE-RESUMABLE (per-stage marker files; every heavy stage gated on the co-agent's drain) — a kill now costs only the in-flight stage. Durable lesson for the remaining batches: long validation chains on a multi-agent host should be checkpointed by construction, not monolithic.
