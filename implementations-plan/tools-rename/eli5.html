Faucet to Tools Rename

The web app at tools.nulo.sh has been called "tools" since the domain moved, but the repo still calls it "faucet" everywhere that matters: the folder, the package, the build scripts, the CI jobs, the release job, the test harness, and the name the wallet shows when you connect. This plan finishes the rename, and turns the in-app "Faucet" tab into "Drip", the word the code and the contract already use.

Why "light"

One risk dimension is high: the two Cloudflare Pages projects build from a folder path set in their dashboard, which the repo cannot change, and a wrong or late change there silently stops new deploys. Everything else is mechanical and reversible.

Noveltylow — a rename with a precedent in this repo
Blast radiusmedium — ~160 files, one app, CI wiring
Irreversibilitylow — git history preserved, no data
Migration costlow — two browser storage keys
External couplinghigh — Pages dashboard root directory
Securitylow — no new credential or boundary

Codex rejected the first draft on four points (a leaky lockfile check, an internally contradictory phase order, an incomplete storage carry-over, and an untested assumption about the connect id), then conditionally approved the rewrite with eight smaller conditions (exact structural checks for the two generated files, a real proof for the Cloudflare step, branch-by-branch dashboard timing, two missed comment sites). All are folded in; details live in the plan's audit log.

Phases

Before anything

Phase 0 · wait, then rebase

Let faucet-cluster land first

A separate cleanup is already reshaping files inside this app. Doing the rename on top of it avoids a messy conflict. We wait for its two PRs, rebase, and record the exact commit the rename starts from.

PR 1 · the identity

Phase 1 · the rename itself

Move the folder and every name that points at it, in one go

Git keeps the file history. Then the package name, scripts, CI job names, harness variables, build-target names, the connect id (with a carry-over so returning users keep their remembered wallet), and the test prefix all change in seven small commits. Two generated files (the dependency lockfile and the complexity baseline) are regenerated and checked against an exact "old file with the path swapped" copy, so nothing else can slip in.

Proves itself by: both generated-file diffs are empty after the path swap; typecheck, lint, unit tests, the app's browser smoke test, the CI-graph guard test and the workflow linter all pass; searches for every old name return nothing.
Phase 2 · prove it in real builds and real CI

Build both network targets and run the real pipeline once

The app ships as two builds (testnet and mainnet). Both are built and checked. The extension's smoke tests run. Then the actual CI workflow is triggered by hand on this branch, which runs the renamed build jobs before any PR exists.

Proves itself by: both builds verify; smoke tests green; the CI run shows "Build Tools (testnet)" and "Build Tools (mainnet)" succeeded.
Phase 3 · docs

Update the living documents

CLAUDE.md, CI.md, the architecture notes, the app README, the package READMEs, the Aztec-update runbook, and comments in other packages that mention the app. Old plans and the changelog stay as they were: they are history.

Proves itself by: the full audit script passes; the dead domain appears nowhere; the remaining "faucet" mentions are reviewed one by one and match the keep list.

PR 2 · the Drip tab

Phase 4 · feature vocabulary

Rename the tab and everything that only exists because of it

The tab label, the view, the composables, the token list, the manifest builder, the deploy-script token config, and a validator in the bridge tooling all say "drip". A real connect / disconnect / reconnect with the Nulo extension confirms the wallet shows "nulo-tools", remembers you, and forgets you when asked.

Proves itself by: the audit script and the app's browser tests pass; no "faucet" remains outside the keep list; the manual wallet check is recorded with the extension build id.

After the merge reaches each site's branch · you

Phase 5 · Cloudflare dashboard

Point each Pages project at the new folder, one branch at a time

Each site builds from a branch. Flip a project only after the rename is on that branch: nulo-tools-testnet (tracks dev) right after PR 1 merges; nulo-tools-mainnet (tracks main) right after the next promote. In each project change Build → Root directory from apps/faucet to apps/tools and retry the last deployment. Flipping too early only makes new deploys fail; the live site stays on the previous build, so nothing goes dark.

Proves itself by: each site's /build.json build id ends in the short commit hash of the branch it tracks, and the build log shows apps/tools.

Human context

  • The domain already moved. faucet.nulo.sh no longer resolves. The 55 mentions of it in the repo are stale text, not a live dependency.
  • The deploy hook secret never existed. The release job's tools deploy step already skips itself. Renaming the secret's name in the workflow is a text change; the Pages projects deploy through their own Git integration.
  • Why "Drip" and not "Mint". "Mint" already means two other things in this app (the Bridge tab's test-USDC mint and the Fuel tab's asset mint) and one in the wallet (any minting transaction). "Drip" is the contract's own verb.
  • Why the connect id changes. The wallet can display that id to you during approval, so today Nulo may literally show "nulo-faucet". A third-party wallet might treat the new id as a new app and ask you to approve once more. Nothing you own is keyed by it.
  • Other branches. One open PR (#471) and any in-flight work touching the app will need a rebase across the folder move. Git detects the move, so this is usually painless.
