Faucet receipt — hero the bridged tokens

The faucet shows a little "receipt" after you bridge tokens. Right now it treats the Fee Juice (gas) as loudly as the tokens you actually bridged. A draft PR from two weeks ago (#99) fixed that — make the bridged tokens the star, push gas to quiet little rows — but dev has moved 52 commits since (including a big folder restructure and a brand-new "Fuel" receipt type), so the draft no longer applies cleanly. This plan re-does that good idea on today's dev and also gives the new "Fuel" receipt the same look. Two files change. Nothing else.

What the receipt will look like

▌ ETHEREUM → AZTEC · PRIVATE · 3M 42S ✓
▌
▌ Bridged 100.00 AZLO ← big, cream (the hero)
▌ Gas ready 84.82 Pvt FJ ← dim
▌ Gas used − 2.88 Pvt FJ ← dim

  deposit tx ↗ claim tx ↗
  [ NEW BRIDGE ]

The mint left-rule and the small ✓ are the only green — the single "done" signal. The bridged amount is the only thing that's big and bright. Gas drops to two quiet rows (the old gross "Gas bought" line and the boxed "available" panel go away). The Fuel receipt gets the same frame, with the Fee-Juice amount itself as the hero (because on a Fuel bridge, gas is the product).

Why this tier was chosen

light. The rubric scores zero HIGH dimensions: no novelty (the design already exists in #99), tiny blast radius (one faucet component), trivially reversible (it's CSS + template), no migration, no external service, no security surface. Bounded and single-package — the lightest tier fits.

Phases

Phase 1: Rework the component + its test

Rewrite BridgeReceipt.vue's layout to the picture above for all three receipt kinds (token bridge, withdraw, Fuel), and rewrite its test to check the new labels (Bridged / Released / Fueled, "Gas ready", the ✓) instead of the old ones.

Proves itself by: the BridgeReceipt unit tests pass for every variant + typecheck + lint, all green.

Phase 2: Build + eyeball + ship

Production-build the faucet, then run it locally and look at all three receipts with my own eyes (you asked for a visual smoke). Then open a fresh PR to dev and close the old #99 with a pointer.

Proves itself by: the faucet build succeeds, the three receipts render correctly on screen, and the new PR's required checks start firing.
