Why light

All six risk dimensions score low: nothing new for the team (Vite + TypeScript we already use), a marketing page that ships on its own, nothing to migrate, no external service beyond the release info and Cloudflare Pages that already work, and no security surface beyond the page's existing content-security policy. One codex audit is enough.

Phases

1 · Foundation

Point the landing at the wallet's design stylesheet, undo the few things that stylesheet does that a website shouldn't (blue links, unselectable text, hidden scrollbars), and stop shipping the landing's own copies of the fonts.

Proves itself by: install, typecheck, lint, unit tests and a production build all green, and the three fonts present in the built output.

2 · The renderer

The feed is a small pure function: given a size, a time and a seed it returns the frame as text. A thin layer puts that text on the page, keeps it to about 30 frames a second, pauses it when off-screen or in a hidden tab, and shows a single still frame for people who asked for reduced motion.

Proves itself by: unit tests on the pure function (right size, only the five glyphs, same input gives the same frame, the subject blob brightens where it should, zero gain gives blank) plus typecheck and lint.

3 · The page

The approved markup and styles go in (with the two copy corrections); the old sections, animations and stylesheets go out. The "Add to Chrome" links keep pointing at the latest release exactly as today. The public record is labelled illustrative, and a Pause button sits in the hero corner.

Proves itself by: the full check set, a production build with no leftover template tokens, then a browser pass on the built page under the real security policy: feed drawn at desktop and phone width, plate and buttons readable, keyboard focus visible, reduced motion gives a still frame, Pause stops it, the record never grows past 16 rows, and a throttled phone stays responsive.

4 · Docs and last read

Update the landing's README, add the plan to the index, and re-read every visible sentence against the copy rule: no wallet jargon above the fold.

Proves itself by: the full check set green and the README's file list matching the folder.

Human context

  • Why depend on the design package instead of copying colours? You chose it at the clarifying step so the palette can't drift. The price is a small override file (the package's stylesheet was written for the wallet popup, where links are blue and text isn't selectable) and about 180 kB of styles and fonts the page doesn't use. If that weight ever matters, the fix is a slimmer tokens-only export from the package, not a landing-side copy.
  • Why is the build only checked locally? The repo's CI lints, typechecks and unit-tests the landing on every PR, but nothing in CI builds it; Cloudflare builds it on deploy. Each phase gate runs the build locally. A CI build job is listed as a follow-up, not part of this PR.
  • What stays true on the page. Private by default, public by choice and labelled, password or passkey, testnet only, not audited yet. The old warning banner's facts live on in the preview-notice plate.
