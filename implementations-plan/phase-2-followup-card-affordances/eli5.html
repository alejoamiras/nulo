What broke in v0.15.3

🪲 Issue 1 — Empty icon box

When you saw the Interrupted card after a SW restart mid-prove, the badge area was empty. No glyph.

Why: I shipped icon names refresh-cw and circle-minus — those look like Material Icons but aren't in this project's icon set (only 104 specific names in icons.json). The Icon component silently renders empty SVG when the name is unknown — no console error.

Failed didn't have this bug only because close-circle happened to be a real name.

🪲 Issue 2 — No Retry button

The Interrupted card just sits there with no action. You wanted a way to retry without manually re-navigating to the Send page.

Why: I shipped the card as purely visual. Phase 2 Week 5 didn't budget for action affordances on terminal cards.

🪲 Issue 3 — No Cancel button

You can't even trigger the Cancelled state from the UI, so you couldn't test it. The "Cancelled" path exists in the SW (ExecutionService.cancelJob) but no popup button calls it.

Why: Same reason — Phase 2 W5 wired the journal as the in-flight source of truth but never added the cancel surface on the awaiting card.

The plan — three phases

Each phase is one commit. Smallest first. Each independently passes typecheck + tests + lint + build.

Phase 1 — fix the icon bug smallest

What: Switch the three terminal icons to actually-real names:

  • Cancelled: cancel (literal X — both auditors endorsed; semantically distinct from Failed)
  • Interrupted: refresh-circle (in the *-circle badge family; visually echoes the "try again" suggestion)
  • Failed: close-circle (was already correct, no change)

Also: extract these into a const ICONS = { ... } as const inside the util so the next person can't ship an invented name. Update the existing Storybook stories + the test assertions that pinned the old wrong strings.

Phase 2 — Cancel button on the awaiting card

Where: Right side of the secondary row on the in-flight card. Small text link, quiet styling — never competes with the title for attention.

What it does: Calls executionService.cancelJob(topJournalOp.id). The SW flips the journal from proving → cancelled. The popup observes the change and the card transitions from awaiting → Cancelled.

Smart bit (from codex audit): when the SW has already moved the job to submitting stage, the FSM forbids cancelling — so we hide the button at that point. No "click does nothing" frustration; the affordance simply disappears when it stops being useful.

Phase 3 — Retry button on the Interrupted card

Where: Same secondary-row right placement, mirrors the Cancel button visually.

What it does: Navigates to /popup/send?tokenId=X. The Send page is already wired to pre-select a token from this URL param (used by other "send this token" links throughout the wallet). User completes recipient + amount; the rest is the normal Send flow.

Why retry is limited:

  • Cancelled: You stopped it on purpose. Retry would be confusing — Send page is one tap away.
  • Interrupted (UI transfer): ✅ Retry navigates to Send with token preselected.
  • Interrupted (dApp): Wallet has no replay path — the dApp owns the request.
  • Failed: Some kinds (network, prover) might recover; others (simulation) won't. Needs per-kind logic — deferred to a follow-up.

Audit summary

Plan v1 went to codex + opus 4.7 in parallel. Both surfaced overlapping critique. Here's where they agreed, where they diverged, and which call wins.

What both audits caught (hard fixes)

H3
Cancel button never shows for UI transfers. v1 said "Cancel only on the journal-driven awaiting branch". But the template's v-if renders the executingTask card first, journal second. For UI transfers, both exist — executingTask wins — Cancel never appears for the most cancellable flow.
opus + codex both flagged Hard / High
v2 fix: re-architect. The journal record is canonical for "in-flight" (per the W5 docstring at L181-196 of the file). executingTask becomes pure subtitle enrichment. Render journal card whenever topJournalOp exists.
Late cancel
Cancel during submitting = silent no-op. User clicks Cancel right before submit completes, sees nothing happen, then a few seconds later card flips to Succeeded. Reads as "Cancel is broken."
opus + codex both flagged
v2 fix: codex's call — hide the button when stage is submitting. Structurally cleaner than a "couldn't cancel" toast. The popup already knows the stage; remove the affordance when it's not effective.
H1 / retry payload
Retry emit had no payload. Parent would have to re-lookup the op. Minor but inefficient.
opus Hard
v2 fix: emit("retry", op). Parent gets the OperationRecord directly.

v2: +3 (opus icon-name regression pin, retry-payload, race-pin) +2 (codex wire-tests for cancel + retry routing in RecentActivityView). Total 16 new + 3 modified.

Endorsed without change

Scope
Retry restricted to interrupted + transfer. dApp can't be replayed. Failed deferred.
Both audits agreed. Codex specifically said don't add a "Dismiss" button for dApp-interrupted — the 5-min age-out handles it.
Placement
Inline secondary-row vs. top-right of card.
Both audits picked inline. Top-right is "owned" by the badge + title-trailing slot (explorer link on settled cards).
Retry context
Token-only preselection vs. persisting recipient+amount on journal.
Both audits picked token-only. Don't bloat the journal for the rare Interrupted case; 5-min-old card means user already context-switched.

Where opus & codex disagreed (codex won)

Late cancel UX
opus: optimistic cancelling… state or a toast. codex: just hide the button when stage = submitting.
Codex's call wins — fewer lines, structurally honest, no temporary UI state to debug.
E2E
opus: one non-network e2e for SW-restart-mid-prove + retry button. codex: skip e2e, add 2 RecentActivityView wire-tests instead.
Codex's call — the wire-tests prove the same regression matrix at <1s vs. 30s per run, and avoid puppeteer fragility.

Decisions resolved

Your placement override (icon-only top-right) dissolved the remaining open question. All 9 decisions now resolved.

Why Q2 dissolved: with icon-only buttons, no visible text is shown on the card — the X glyph universally reads as "close/stop" without the "Cancel" word's overlap with the dApp-approval popup's "Cancel request" button. Opus's overloading concern goes away. The aria-label (screen-reader-only) uses the standard "Cancel transaction" / "Retry transaction".
