One shared balance cache for the wallet popup

APPROVED 2026-08-06 — full approve; deviation 4 and the cross-profile leak fix both approved. Seeds below are final.

Two parts of the wallet — the fee selector on the Send screen and the fee-juice card on the home screen — each grew their own private copy of the same plumbing: fetching your gas balances, retrying quietly when the network hiccups, showing last-known values instantly. It all works and it's all covered by tests, but the same logic living in two places is how bugs creep in later. This plan moves that plumbing into one shared place, turns both screens into simple readers of it, and fixes one long-standing dishonesty: today, when a balance check fails, the wallet shows a confident 0 — after this plan it shows an honest "unknown" (—) instead.

Why this tier (mid)

Rubric: novelty LOW (everything reuses patterns the codebase already has) · blast radius MEDIUM (Send screen, dApp-approval window, home card) · irreversibility LOW · no migrations · no external services · security MEDIUM but fully mapped. One medium-high dimension → mid: one plan + one competing alternative, audited in parallel by Codex and an independent Claude reviewer, then a final fresh Codex pass. Both auditors materially improved the design (details in plan.md at implementations-plan/balance-fpc-cache/).

The one thing changing for users

Nothing — except honesty when a balance check fails. Three approved changes, plus one that needs your explicit sign-off below:

  • A failed balance check shows — FJ instead of 0 FJ.
  • The fee dropdown marks fee-juice "couldn't check balance" instead of "no balance" when the check failed (a saved fee-juice preference temporarily falls back to the default method while unknown — same as today, now deliberate).
  • The "get fee juice" nudge still appears when your balance is genuinely zero.

Needs your sign-off: deviation 4

Today, when a balance check fails, the wallet wrongly tells you to go bridge gas — because a failed check looks identical to a zero balance. After this plan, that nudge only appears on a confirmed zero. Strictly more honest, but it is a visible change beyond the original three, so the auditors required it to be approved by you explicitly rather than slipped in.

Phases

Phase 1 — Make "unknown" representable, safely

Change the data shape so a failed check is "unknown" instead of a fake zero — together, in the same step, with the safety guard that keeps unknown balances from ever enabling a fee method they shouldn't. (The audits proved the type system cannot catch this mistake; tests written before the change are the only guard, so they come first.)

Proves itself by: the full check suite (types, all unit + component tests, lint, build) green.

Phase 2 — Build the shared cache, tests first

The one shared place: knows who's asking and what they need, never fires more network requests than the two screens do today (the auditors made this a hard, test-enforced requirement), survives profile switches without leaking one profile's data to another, and retries quietly exactly the way the Send screen does now.

Proves itself by: a dedicated test suite for the cache covering every audited edge case, plus the full check suite.

Phase 3 — Home-screen card reads from the cache

The fee-juice card keeps its look and feel (instant paint, dimmed-while-refreshing) but deletes its private plumbing.

Proves itself by: every existing test for that card still green, plus the full check suite.

Phase 4 — Fee selector reads from the cache

The Send screen's fee selector keeps ALL its careful behavior (when it locks, when it retries, how it protects your selection mid-load) and deletes its private plumbing — the largest deletion of the plan.

Proves itself by: every existing fee-selector test still green, plus the full check suite.

Phase 5 — Cleanup and end-to-end proof

Delete the now-dead code, deduplicate a copy-pasted formatter, update docs.

Proves itself by: full check suite + browser smoke tests + the real-network end-to-end suite (including the "reopened popup paints instantly" test) all green.

After the phases: an automated code review iterated until clean, a Codex audit of the diff iterated until it explicitly approves, then a PR babysat until every CI gate is green — and then it stops and waits for your go-ahead; the merge is yours. No extra hardening pass (your call, recorded).

Human context

This is the cleanup we parked after the two fee-juice fixes earlier this week (#342/#343): those PRs made the two screens correct under failure, at the cost of each carrying its own machinery. The audits caught real problems in the first draft of this plan — most importantly that a shared cache keyed the "obvious" way could leak one profile's fee-payment contracts to another profile, and that a naive rewrite would quietly lose a protection against runaway network requests. Both are designed out and pinned by tests now; the audit trail is in the plan folder.

Needs your sign-off: fix a live cross-profile leak (found by the final audit)

The final fresh-eyes audit found a bug that exists in the wallet today, unrelated to this refactor: after switching profiles, the background cache can show the NEW profile the OLD profile's private-gas balance for up to five minutes (the cache doesn't know profiles exist, but the private balance is profile-specific). The plan proposes fixing it at the source — one small, well-tested change: forget cached balances whenever the active profile changes. It's technically outside the original scope (it changes when re-fetches happen), so it needs your explicit yes. Recommended: yes. If you say no, the refactor still protects its own new cache, and the old leak is documented as accepted risk.
