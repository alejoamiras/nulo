# Phase 4 lessons — FeeSettingsCard onto the store

- **34/37 on first contact** — the suite already ran a real Pinia + client-layer mocks (hoisted `mocks.getGasBalances`/`getFpcs`), so the store consumed the same mocked clients with zero re-pointing. Two mocks had to be ADDED for the store's own constructions: `TransactionServiceClient` (settle subscription) and `@/stores/app.store` (the belt watcher — an inert stand-in, since this suite drives identity via PROPS).
- **A real gap the pins caught: entering embedded mode via the parent's v-model never runs `runInit`**, so the early-return release never fired and the store's retry loop survived into embedded mode — a retry tick would then recommit and CLOBBER the dApp's embedded settings with a reconciled sponsored method. Fix: a `[isCustomMethod, useOwnMethod]` watcher releases the subscription on entering the embedded-visible state (killing the armed backoff timer — today's chain death), plus the same entry-condition guard in `recommit`.
- **Debt-scoped retries changed two pins' traffic expectations, deliberately**: the store's backoff re-fetches ONLY indebted legs, so the old whole-init-retry artifact (`getFpcs > 1` after a gas-only failure) inverts — a healthy leg is never re-fetched (pinned as `toHaveBeenCalledTimes(1)`). The alternating-leg last-good-FPC arc can't occur via retry anymore; the card-level pin now runs it through a same-identity refresh (the retry-path retention stays pinned in balances.store.test.ts). Both follow from the approved retryDebt design (D11 / traffic matrix), not silent drift.
- **Recovery is commit-only, per plan flow item 4**: the retryVersion watch re-runs the COMMIT path (fresh storage read + baseline-guarded reconcile) against the live entry — never a second ensure, so a recovery costs zero extra RPCs (today's retry traffic came from the store's own retry fetch).
- **Reconcile ordering preserved verbatim**: refs commit BEFORE reconcile (on a first load the still-closed gate means `methods` resolves against undefined balances — the deviation-2 subtlety from Phase 1), gate opens after, degraded included.
- New plan-mandated pin: a profile-switch-superseded ensure (typed `EnsureSuperseded`) is a NO-OP — no degraded row, no settings emit, no retry armed.
