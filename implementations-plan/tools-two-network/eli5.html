Two versions of the tools site — one for real money, one for testnet

The plain-English companion to plan.md. This is the decision layer — no code jargon. Read it, then approve or push back at the gate.

Today tools.nulo.sh is one site pointed at Aztec testnet. We want it to be two sites built from the same code: one for the real Alpha/mainnet network (bridging real Ethereum USDC + real fee juice), and one that stays on testnet for safe play. Which one a build becomes is decided by one committed config file — not a dashboard toggle that can silently drift.

Why now

The extension release just shipped and it defaults Alpha's fees to Private Fee Juice. For the team to actually use Alpha, they need a real place to get fee juice — that's this tool. So this isn't a nice-to-have; the extension's "Get Fee Juice" nudge points here.

The money reality — read this twice

Real funds

The mainnet build moves real Ethereum USDC and real fee juice. The ~$5-per-user limit is something we tell people, not a rule the contract enforces — the guardrails are Cloudflare Access, a trusted team, and keeping wallet balances low.

Deploying the contracts will cost more than $5 in gas — that's expected and accepted. Only the last two phases spend real money, and each on-chain step needs your explicit go every time.

How a wrong build is stopped

The nightmare is a build that looks like mainnet but talks to the wrong chain, wrong token, or wrong decimals — that silently burns real money. Five independent checks make that fail loudly instead:

① The config file that picks the network is committed to git, never a dashboard setting.
② The manifest states its own chain, and the app refuses to load unless the build target, the manifest, and the live node all three agree.
③ The old ?chainId= URL trick that could repoint the app is switched off outside tests.
④ CI verifies each build's addresses on-chain before it can ship — it's no longer optional.
⑤ Each build knows which hostname it belongs at and refuses to run elsewhere — so a testnet build can't quietly sit at the mainnet address (this one was found in the final audit pass).

The two decisions you already made

1 · Private fee juice works on mainnet. Because the extension defaults Alpha to Private Fee Juice, we deploy/pin a real mainnet PrivateFPC so a private deposit can't strand. (An audit caught that leaving this out would trap funds.)

2 · Ship both networks now — token bridge + public & private fee juice on each — at production rigor on the money paths, sized to the <$5 exposure.

Nine steps, safest first

Everything real-money is pushed to the very end. Steps 1–7 are refactors and testnet/fake-money work you can drive autonomously.

  1. Withdrawals stop setting a fee safe
    The wallet pays its own way on withdraw — never the app. Isolated fix.
  2. One source of truth for "which network" safe
    Collapse ~9 scattered hard-coded Sepolia references into one file; ban the footgun import.
  3. Manifest + build integrity safe
    Teach the config file to name its chain and carry the fee-juice contracts; migrate everything at once so nothing half-breaks.
  4. Build & deploy twice safe
    Two build configs, two Cloudflare projects, CI verifies each. Rename faucet → tools finished.
  5. App: real-USDC + private fuel + per-network UI safe
    Add the Permit2 approve step real USDC needs; hide testnet-only buttons on mainnet; wire private fuel to the pinned mainnet FPC.
  6. Testnet rehearsal + real cutover safe
    Deploy a mint-able test USDC on Sepolia, move testnet onto it, and rehearse the exact mainnet path with fake money.
  7. Deploy tooling for mainnet safe
    Make the deploy script network-aware, use a stable recoverable deployer, budget the whole gas sequence, pin the real USDC identity.
  8. Deploy on mainnet real money
    Fund a fresh key, deploy the portal + token trio + router + PrivateFPC against real USDC, then renounce the router owner key.
  9. Ship & harden real money
    Point the live site at it, you smoke-test a real <$5 bridge + both fee-juice paths on Alpha, then revoke the Permit2 approval.

How the plan got here

This survived two full audit rounds (Codex + an independent Claude reviewer). The disagreements were the point — each round caught real money-loss paths before any code was written.

v2 split verdict

v3 both conditional-approve
final Codex pass confirmed both criticals closed; found 5 fixable items (missed migration files, the AZLO recovery risk, +3) — all folded in.
