Audit-fixes ELI5

Three independent codex audits read our onboarding+fees+history work and all said "reject — here's a list of real bugs." This plan fixes nine of them. (We're skipping the tenth because the strategy it'd protect is being deleted anyway.)

What's broken — in plain English

The home widget can't actually show incoming transfers (critical)

The History page works. The little "Recent Activity" widget on the home tab does not. The code that's supposed to load incoming receives there is wired up — but the connection to the backend was never opened, and the initial-load call was never made. So the listeners are sitting there waiting for events that can never reach them.

Fix: two lines added to the widget's mount handler. Phase 3

The "hide incoming transfers" setting only half-works (critical)

The toggle hides existing rows + blocks new ones from rendering. But the first-receive trust popup still pops up when a new contract sends you something, even if you've turned the whole feature off. A privacy promise that leaks.

Fix: the service checks the toggle before firing the prompt event. Plus symmetric: turning the toggle back on should re-prompt you for anything that piled up while it was off.Phase 4

Fake-link defense only protects one page

If a malicious app sets its name to https://evil.com, we bracket the value so it doesn't visually read as a link. We added that defense to the new "canceled-tx details" page. But the same dApp name shows up on the in-flight cards and the terminal cards on the main feed — unprotected.

Fix: apply the bracketing at the shared label-builder, not just the detail page. Also broaden the pattern to catch more URL-shaped strings (mailto:, javascript:, etc.).Phase 1

Internal error codes leak to end users

When a transaction interruption happens, the journal records an error kind like sw_restart_post_prove. We show that string directly on the detail page. It's not technically harmful, but it's gibberish to the user and reveals internal classifier names.

Fix: map each known kind to friendly copy. Unknown kinds show generic "Error" + log the raw kind for telemetry.Phase 2

New accounts don't get scanned for incoming transfers

The background service is told about new accounts via an event, but it never subscribes to that event. So if you add an account after the wallet started, the incoming-transfer poller doesn't pick it up until next restart.

Fix: subscribe to the event, rebuild the poller list on account add/delete.Phase 5

"Verify the contract" prompt is hard to actually verify

The first-receive popup shows the contract address as 0x1234..5678. That's not enough for a user trying to tell real-USDC from fake-USDC apart. Need expand-to-full + copy.

Fix: add a "show full address" toggle + a copy button in the popup.Phase 6

Multi-contract pending prompts overwrite each other

If two apps send you tokens from two unknown contracts at the same time, the prompt for contract B overwrites the prompt for contract A while it's still on screen. After you resolve B, A re-appears (the safety net catches it on the next pass). Not great UX.

Fix: a real queue in the popup manager. One prompt at a time, in deterministic order, drained after each resolution.Phase 7

Test coverage on the incoming-transfer service is thin

We shipped two pure-function unit tests (sorting + key composition) but didn't actually test the risky logic: dedupe, late-delete, trust transitions, queue, visibility gating, cleanup wiring. Production calibration wants those pinned.

Fix: backfill ~30-50 unit + component test cases.Phase 8

The onboarding skip route isn't pinned by a test

We split the "Skip intro" link on the Aztec page into its own handler (Continue → fees, Skip → accelerator). The e2e tests cover Continue. Skip isn't asserted anywhere.

Fix: one e2e assertion per skip route.Phase 9

What we're NOT fixing (and why)

  • claim_and_end_setup missing from FEE_METHODS — the FeeJuiceWithClaim strategy is being deprecated. Pinning a fee-method allowlist for a strategy we're removing is anti-investment.
  • StepIndicator <nav>> → <ol> for richer screen-reader semantics — low-value polish; the aria-current="step" we already have is the load-bearing a11y signal.
  • Stale "first call" JSDoc on OperationPlanner.extractPrimaryMethod — pure doc drift; fix opportunistically.
  • chrome.alarms refactor, symbol-collision badge, 5-minute ring buffer — already tracked as follow-ups in the parent arc's lessons.

Order we'll ship

Risk-ascending, but with the two criticals front-loaded near the top:

  1. Phase 1 — sanitize widening (pure helper)
  2. Phase 2 — error.kind humanizer (pure helper)
  3. Phase 3 — RecentActivityView wiring fix (3 lines, fixes critical)
  4. Phase 4 — visibility-toggle gate completion (2 guards + 1 subscription, fixes critical)
  5. Phase 5 — AccountService lifecycle (subscribe + handler)
  6. Phase 6 — IncomingTrustPopup contract verification redesign (UI)
  7. Phase 7 — pending-prompts queue refactor
  8. Phase 8 — test backfill
  9. Phase 9 — onboarding skip-route e2e

Open questions for the audit pass

  • Regex aggressiveness — broadening to scheme: (no //) catches more shapes but could false-positive timestamps (12:34), versioning (v1:), CSS values (color:red). Acceptable, or should the matcher require :/ OR a known scheme set?
  • Apply-at-builder vs apply-at-component — defense in depth?
  • Visibility-gate symmetry — when toggle flips back ON, re-emit Pending events for stranded pending records? Plan says yes; bundled into Phase 4.
  • Queue location — popup-side (proposed) or service-side?
  • Trust popup affordance — show full address + copy. Also link to a block explorer? Plan defers explorer link to a follow-up.
