audit-fixes-v2 (slim) — what we're shipping

After 4 codex Rejects on increasingly complex versions of this plan, scope was SPLIT. This PR ships the user-QA-flagged bugs + the audit findings that are independently safe + tactical (good-enough, non-bulletproof) fixes for C1 and C2. The full trust-state-machine concurrency surgery gets a separate planning session.

The 13 phases

P1 — Onboarding copy fixes (A1–A4)

Strip em-dashes in fees.vue. Reword private fee juice as a separate asset (not "fee juice held privately"). Add that fee juice is L2-only (only obtainable via burning $AZTEC on L1). Add a "not transferable today" note. copy only · zero risk

P2 — "Claim Fee Juice" label (D1)

Today the claim_and_end_setup method shows as "Claim And End Setup" — robotic. Add a friendly label. One-line allowlist addition. trivial

P3 — Trust-popup a11y fix

The expand-toggle on the incoming-trust popup advertises a control that points at a node that doesn't exist when collapsed. Fix: keep the controlled node in the DOM (hidden via v-show) AND only advertise the control when expanded. a11y

P4a — C2 failing repro test

You closed the extension popup window and the trust prompt never reopened. Before we write the fix, we capture a deterministic failing test that reproduces this. The test pre-seeds a pending contract, opens + closes + reopens the popup, asserts the prompt re-fires. P8 makes it pass. test-first · this fails on dev today

P5 — Account-filter the late-delete path

Two of your accounts (A and B) could receive notes for the same contract. If account A sends a transaction whose hash matches an incoming record for B, today's code would delete B's record by mistake. Adds a filter so only A's records get deleted. Also adds a per-hash guard against double-delete on concurrent events. codex Med #2

P6 — Popup visibility toggle race + listener leak

The Settings toggle has a race: if you flip OFF→ON in the first few ms after popup opens, the replay path silently drops pending prompts. Fix: register the listener inside onMounted after the setting reads from disk, AND deregister on unmount so listeners don't accumulate. codex Med #1

P7 — Tactical C1: auto-trust on manual token-add

When you manually add a token, the trust prompt shouldn't fire on the first incoming note — you implicitly trusted it by adding. Fix: after addToken succeeds in NewTokenPopup, immediately call setTrustAllow. Race window with the scheduler's 30s poll is small (~100ms vs 30s). dApp-driven register_token stays gated. tactical · ~100ms race window vs 30s poll

P8 — Tactical C2: one-shot replay on triple-ready

P4a told us the bug: when the popup mounts, the active profile/network/account triple isn't populated yet. The replay-on-connect listener fires too early and silently returns. Fix: install a watcher that fires replay when the triple becomes ready. Keyed on the triple itself, so a profile switch re-fires. tactical · stale-resolve risk under rapid switching

P9 — Failure-category helper for the detail page

Pure helper that maps JobError.kind to a user-friendly category ("Stopped before broadcast" / "Interrupted mid-flight" / "Network error" / etc.). Feeds P10. helper

P10 — Brutalist restyle of failed/cancelled detail page

The cancelled/failed detail page doesn't match the brutalist design of the rest of the app. You said the confirmed-transfer / confirmed-transaction detail pages look great — DO NOT touch those. We restructure only the failed/cancelled page to mirror the same hierarchy + brutalist tokens. The developer-mode raw error block stays verbatim — you said it's good. visual · largest LoC

P11 — Profile-switch token list (and more)

When you switch from Profile A to Profile B and press Send, you see "no available tokens" until you click into a token detail. Root cause: 10+ pages snapshot the token list once on mount and never re-fetch when the profile changes. Fix: a new useIdentityScopedFetch composable that watches the triple AND has a sequence counter to ignore stale resolves on rapid switches. Applied to all 10+ consumers. bug fix · multi-file refactor

P12 — Test pin backfill

Closes three test gaps codex flagged from the prior arc: onAccountAdded → hydrateSchedulers, RecentActivityView.connect() on mount, OFF→ON config replay (already added in P6).

P13 — Manual QA + lessons + rollback matrix

Walk through every F1–F4 surface to confirm no regression. Walk through every v2 phase to confirm fix. Document rollback units. Note residual risks for the deferred trust-state-machine work.

What we're NOT doing here (deferred to a separate arc)

  • The full reconcileTrust mutex with proper unlocked-helper split
  • The scanContract trustState caching race (reveal-on-Allow-mid-scan)
  • The scanContract end-of-scan orphan sweep
  • Reconciling self-notes on journal submitting.txHash (the codex post-impl High from prior arc)
  • Cross-profile address collision fix (same mnemonic in two profiles)
  • The full setUserAddTrustHandler architecture with startup-ordering guard
  • Proper popup-reopen fix with AbortController + cancellation on rapid profile switch
  • Perf optimization for the 8–10 storage reads per scan

These need a focused planning session with research subagents on the concurrency model, possibly an architectural rethink (event-sourced trust log vs. mutex-based). Not safe to retrofit here.

The non-obvious decisions

Why "tactical" C1 and C2 instead of full design

P7 puts setTrustAllow inside NewTokenPopup directly, racing with the scheduler. P8 uses a triple-keyed idempotency flag instead of AbortController. The full versions kept getting rejected by codex for subtle concurrency bugs. The tactical versions close the user-visible QA scenarios (popup-on-already-added-token, popup-never-reopens) with documented residual races.

Why useIdentityScopedFetch has a sequence counter

Without it, rapid profile switches (A→B→A) could let an old fetch resolve LAST and overwrite the latest profile's data. The counter rejects stale resolves.

Why P10 doesn't touch the confirmed tx detail page

You said it looks great. Don't fix what isn't broken. We mirror its structure for the failed/cancelled page without modifying the source.
