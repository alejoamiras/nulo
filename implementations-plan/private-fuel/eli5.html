private-fuel — private gas, end to end

Today you can bridge tokens privately, and you can "arrive with gas" — but only on public bridges, because the only way to get gas onto a fresh Aztec account currently writes your Aztec address onto Ethereum (a leak). This arc adds private Fee Juice: a private bridge arrives with gas through Wonderland's PrivateFPC, with nothing linking it to you on L2. Gas privacy follows the token — pick PRIVATE and your gas is private too — and we finally ship the private-by-default presets and delete the "fuel withheld on private" block.

Why this tier was chosen (deep)

Four HIGH-risk dimensions: novelty (first private-FJ integration), security/privacy (a wrong fee method leaks the user), irreversibility (gas deposited to a wrong FPC address, or with a wrong secret, is gone forever), external coupling (Wonderland's FPC, whose address is version-specific). The rubric leans mega-deep, but two reference implementations (Holonym + Wonderland) and pieces already shipped in our own extension de-risk the novelty — so deep. Three independent plans were drafted, merged, contradiction-checked, and double-audited; the double-audit caught a real privacy hole (below) that the rework fixes.

The shape (what we learned)

Good news: the arc is smaller than it looked. The Ethereum contract needs no change (it was built anticipating this). The secret math is already proven in our test suite. And the wallet needs no new "mode" — it already runs the dApp's pre-built fee transaction verbatim (two independent reviewers traced the code to confirm this). The real teeth are three irreversible edges: deriving the FPC address from the exact installed version (not a stale clone), turning a random secret into a derived one the recipient can reconstruct, and keeping two different "salts" from being confused.

Phases

P0 — Safety keystone (riskiest first, moves no funds)

Pin the FPC address from the installed package, prove our secret math matches the contract's, and check the live network runs the matching version. Nothing real happens until this is locked.

Proves itself by: bridge-core unit tests (secret parity + an address tripwire) + a read-only live node-version check.

P1 — bridge-core private-fuel plumbing

Make the fuel secret an injected, derived value (fixing a latent "random secret = lost funds" bug for private), route private fuel to the FPC, and persist the per-deposit salt safely.

Proves itself by: bridge-core typecheck + unit tests (the private secret/witness matches; the public path is byte-identical).

P2 — wallet: scope + prove the private payload (no new mode)

Let the wallet's permission manifest allow the two private fee calls, register the FPC, and prove — through the real extension — that a cold-start private claim goes through. (Requires teaching the test playground to emit the private payload first.)

Proves itself by: audit:vue + a network-e2e that drives a private cold-start claim through the actual extension.

P3 — faucet: private-default UI + the claim matrix

Ship the PUBLIC/PRIVATE preset cards (private default), remove the old guard, and wire the three fee paths: no-fuel (wallet's own FJ; a cold empty account is blocked with guidance — never Sponsored), public fuel (self-pay public), private fuel (self-pay private). Plus a fail-closed rule: only offer private fuel when the gas bought provably covers its own claim — and if it ever falls short, recover privately, never via the public/Sponsored path.

Proves itself by: audit:faucet + audit:vue + a network-e2e for the no-fuel cold-start, with pins for the private insufficient-fuel branch + a backup round-trip.

P4 — live private run on testnet (required gate)

A real-proofs headless run that bridges + self-pays a private claim, asserting your public balance does NOT move and no Sponsor touched it (the privacy proof). First slice is a tiny "dust canary" against a wrong address.

Proves itself by: the live fuel-testnet.ts private variant passing both privacies with real proofs.

P5 — /harden security close-out

A focused security pass over the whole bridge+fee surface, with fail-closed guards.

Proves itself by: a /harden security report with no unresolved high/critical + all suites green.

Human context

"Fee Juice" is Aztec's gas. A brand-new account has none — a chicken-and-egg problem this whole feature solves by bringing gas in with the bridge. The PrivateFPC is a shared "gas station" contract: your gas lands there (so no per-user address is exposed on L2), and only you can pull your share, because the deposit secret is cryptographically tied to your address. The catch the audits surfaced: the gas deposit on Ethereum is still a public transaction from your wallet, so it hides your Aztec identity and which user gets the gas, but not the fact that your Ethereum address funded the station — we'll say that plainly in the UI.

Open questions (the Asks)

Rather than a Sponsored fallback, the faucet now BLOCKS a no-fuel claim from an empty account with guidance ("enable fuel, or fund first") and never sends Sponsored — honoring the "never send Sponsored" rule.
  • FPC version reconciliation (blocking before the live run): confirm the testnet runs the Aztec version matching the installed Wonderland package, so the derived address is the one the network recognizes. Who owns that version pin?
  • Where does the verified FPC address live — deployment config, or a generated test snapshot only?
  • Dust canary on every release, or only when the Aztec version / Wonderland package changes?
