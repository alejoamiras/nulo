# Lessons — phases 1–5 (single implementation pass)

All five phases went green first-try against the integration suite (122 tests, no assertion changed); the only mid-flight failures were a formatter nit (line width on a new helper) and one TS narrowing error (`exportPasskeyCredential` needed `Extract<Profile, { type: "passkey" }>` — the extracted method loses the call site's control-flow narrowing). Log of the non-obvious bits:

- **Directives sit on inner arrows, not methods.** `unlockProfile`'s cognitive-19 directive annotated the phase-3 `runExclusive` arrow — extraction targets the arrow's body, and the method-level count in the manifest is per-file, so "which function was scored" needs the directive's line, not the method name.
- **Phase 2's mechanical families alone removed only 1 of 11 directives** (`exportPlain`, and only after also splitting its passkey branch: 25 → 24 → clean). The clone mass and the branching mass are correlated but not identical — the phase decompositions (3–5) did the heavy lifting.
- **The codex round-2 ownership rule bit immediately**: `unsealResealedVerifiedHoldingLock`'s fail-closed throw needed an explicit half-pair zeroize the original didn't visibly have (the outer `finally` covered it); same for `rekeyedDekForPasswordChangeHoldingLock`'s refusal throw. Every extracted helper that allocates secret material got the catch-zeroize-rethrow shape.
- **`restore`'s split used out-param scratch objects** (`PasswordRestoreScratch` / `PasskeyRestoreScratch`) so the branch's single post-lock-release `finally` keeps owning every wipe — byte-equivalent cleanup topology to the closure-captured `let`s, without moving zeroize inside the lock.
- **Scoped jscpd after: 13 clones/202 lines → 4 clones/56 lines.** The 4 survivors are adjudicated, not missed: create↔import row-literal (a 7-param row-builder would be worse than the 10-line literal), the unlock pair's phase-3 prologue (F3 deliberately per-method — ledger), and the export openers that are now parallel 3-line helper-call runs (merging them = the rejected `unsealForExport`). Gate said ≤3; actual 4 — accepted with rationale over forcing a worse abstraction.
- **Manifest: 230 → 219, zero directives left in `service.ts`** — the residue fallback went unused, as Inference 1 predicted.
