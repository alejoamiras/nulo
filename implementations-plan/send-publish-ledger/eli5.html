Blueprint · send-publish-ledger · approved 2026-09-21

Say what a send publishes, right at the button

Every Aztec transaction names who paid its fee, in public. Today the wallet warns about that inside the fee card — which is below the fold when you press Confirm. This plan puts a one-line readout above the button on every send, and makes the single send that names you against your intent go through a short review first.

Design already chosen by you: option B plus the fee-source tag, from Publish Ledger Options. This page is about how it gets built and proven.

Why this is a "mid" plan

Six risk questions; two or more "high" would make it a deep plan. Here: novelty low (same page, same fee logic), blast radius medium-high (the footer is on every send), irreversibility low (UI only, no stored data changes), migration none, outside services none, security medium (it is a privacy claim). One near-high, so: one plan, a competing outline, two independent audits, a final fresh audit.

Budget: 2 recon agents, codex at "high", /code-review off — your Phase 0 answers.

The one idea that matters

The old warning could only fail by being missed. The new strip makes a claim — "HIDDEN" — so it can fail by being wrong. Everything in the plan follows from that:

  • "FEE PAYER" is decided from the exact fee settings that are about to be submitted — not from what a dropdown displays.
  • "HIDDEN" is shown only when the fee is paid by a contract the wallet itself derived (the protocol's private-gas or sponsor contract). Anything else reads —.
  • A gated send goes out only if the tap came from the sheet's button, while the sheet is open, after a short arm delay. That rule lives in the send function, not in how a button looks.

Phases

1 · The facts

One small pure function: given where the money comes from, where it goes and who pays, what does the chain learn? Plus the little timer that arms "Send now".

a written-out table of all 16 combinations, the approved sentences pinned word for word, lint and typecheck.

2 · The strip, the sheet, and a popup fix

The two new pieces, built on the wallet's existing bottom sheet. That sheet has lifecycle gaps that were barely reachable until now (its focus trap is not released if it disappears while open, and the popup stack can hand two popups the same slot); they get fixed at the source.

component tests for every cell state and sheet row, a Storybook page you can flip through in both themes.

3 · The money path, then the gate

The send function is already at the repo's size limit, so first it is pinned by tests exactly as it behaves today, then split, and only then does the gate go in. The old warning is still there at this point — nothing is removed before its replacement works.

a test that mounts the real Send page with the real fee card and walks every funding shape, origin and destination, checking at each step that the tag, the button label and the strip agree — then clicks and checks what was actually sent. Plus a look at the built popup by hand.

4 · Warning row becomes the tag

The 118px block goes; the tag arrives on "Fee Source"; its sentences now live in the sheet.

the full local gate (typecheck, all unit and component tests, lint, build).

5 · Real chain, then trying to break it

On a local Aztec network: a one-tap shield, a private send through the review sheet to a confirmed transaction (both wordings), a sponsored private send that must not be gated, keyboard and Escape in a real browser with real, hit-tested clicks. Every other send test in the suite now states whether it expects a review, and fails if reality disagrees. A send made from the optional sheet must also work. Then twenty deliberate bugs are planted one at a time; each must turn specific tests red.

smoke + network e2e at zero retries, the bug-planting table fully red, screenshots in both themes.

6 · Docs

Architecture note, the e2e skill (its advice to "wait for the warning row" is now obsolete), the plan index.

the full local gate again.

What the audits changed

Codex rejected the first draft and, with fresh eyes, the second; the Claude-side auditor approved the first with conditions. Every claim was checked against the code and held. On the third draft codex returned conditional approve — "no architectural redesign is needed" — and its five conditions are in this, the fourth. The plan is different in ways worth knowing:

  • The first draft would have said HIDDEN for any sponsor contract, including one a user typed in by hand. The wallet cannot vouch for that code. Now it reads "—".
  • "Reviewed" was a flag a caller passed in. A flag is not consent; the check moved into the send function and is bound to the sheet actually being open and armed.
  • Several tests could not fail — one checked the strip on a screen where the strip never exists; the shared send helper would have followed whatever the button said, hiding a gate that appears when it should not.
  • The sheet could end up drawn on top of another popup that owned the keyboard. It now takes a normal place in the wallet's popup stack — and a second fresh audit caught that my first fix used the wrong number for it, plus a rule that would have made the optional sheet unable to send at all. Both fixed.
