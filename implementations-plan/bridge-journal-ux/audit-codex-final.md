REJECT — v2 still overclaims hostile-record integrity and at-most-once deposit safety; both affect on-chain spending.

1. **SEC—CRITICAL: the three-layer guard is not claim-latch equivalent.** Web Locks serialize live cooperating tabs, but neither the latch nor the pre-send read is atomic with wallet broadcast/hash persistence. A resumed plain-token/direct-Fuel send can broadcast, crash before `depositTxHash`, then be sent again. Claims have protocol nullification; these deposits do not. Make `resumeAttemptAt` a write-once attempt token set before prompting: ambiguous send errors/reloads become permanent unknown-outcome, never age out or clear without chain proof. Otherwise defer non-Permit2 RESUME. The original send path must use the same origin lock if crash-derived records become resumable.

2. **SEC—CRITICAL: `secretHash == id` does not authenticate the spending intent.** Public secrets are random independently of recipient and amount ([fuel.ts](packages/bridge-core/src/fuel.ts:39)); token calls take recipient/amount separately ([useDeposit.ts](apps/faucet/src/composables/useDeposit.ts:952)). An attacker can preserve secret/id while changing either. Private plain-token secrets are also random—not salt-derived; only direct private Fuel uses salt+claimer. Pre-envelope sealing deaths authenticate whatever mutated amount is re-sealed. The proposed hostile-fuzz gate therefore cannot satisfy its claim. Require authenticated full intent, or narrow eligible variants/threat claims; require connected-recipient equality for public too.

3. **ASSUME—HIGH: hashless recovery copy is false.** The engine explicitly cannot recover without `depositTxHash` ([useBridgeJournal.ts](apps/faucet/src/composables/useBridgeJournal.ts:567)). Build paste-hash/log discovery or remove “this card will recover it.” Also, a hard reload before `catch` persists no failure facts, so v2 crash, legacy, and still-active records are indistinguishable.

4. **CONTRADICTION—HIGH:** L5’s validator-rejection redo conflicts with L6 review-only; unknown/attempt-latched records must never offer redo. L9 conflicts with permitting a “new nonce”: for the same record, unused+expired can reuse the nonce; used means recover, never reauthorize. Re-quoting must not overwrite the authoritative floor while an older same-nonce signature might win.

5. **SEC—MEDIUM:** approval identity has no trusted expected owner. Persist `approveOwner` alongside the hash.

6. **PHASE—HIGH:** J2-before-UI is right; J3 must expose no clickable RESUME until each runner lands atomically. Gates need send-boundary fault injection plus mandatory rig tests for two tabs, kill-after-wallet-acceptance, lock absence, storage failure, and Permit2 used/expired states. Fueled-public smoke cannot be optional if J5 ships.
