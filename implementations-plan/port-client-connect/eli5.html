When the wallet's inner phone line is dead, say so at once

Every popup screen talks to the wallet's background process over a small private phone line (a "port"). If the extension gets updated or reloaded while a screen is open, that line can't be opened any more — and today the screen keeps redialling once a second, forever, writing an error into the log each time, while whatever the user asked for just hangs until it times out. This plan makes a dead line fail once, immediately, with a clear reason. It also tidies the three pretend phone lines our tests use into one honest one.

Human context

The redial loop was written to cover a case that doesn't exist: Chrome never refuses to open the line because the background process is asleep — it opens it and wakes the process. The only time opening fails is when the page itself has been orphaned by an extension update or reload, which is permanent for that page. Retrying can't help; it only hides the answer. If the background process dies after the line is open, a different mechanism already reconnects — that one stays exactly as it is.

Separately, our unit tests fake that phone line in three different ways (one per corner of the repo), and they disagree about basics such as "can two lines share a name" and "can a line be hung up". The fake written for the last plan (#613) is the honest one; it becomes the only one.

Phases

1 · A dead line fails once

Remove the redial loop and the "still connecting…" polling. When the line can't be opened, the request that needed it fails right away with a named error; calling "connect" on its own still never throws (many screens fire it and don't wait).

Proves itself by: three new unit tests (fails at once, nothing retries, recovers on a later success) plus the existing reconnect tests, lint and typecheck — all green.

2 · One shared fake phone line

Move the honest fake into the messaging package where the other test helpers live, and put the package's own test harness on it. The helper names tests already use keep working.

Proves itself by: three contract tests for the fake, every existing messaging test green, lint and typecheck.

3 · The extension's tests use it too

The extension's global test setup and the #613 port test switch to the shared fake; the old "throw if a second line opens" guard becomes an explicit count a test asks for.

Proves itself by: the whole extension unit + component suite green, lint and typecheck.

4 · Docs and a real browser

Fix the messaging README (it names an error class that doesn't exist) and record the new rule. Then run the popup smoke suite locally and the network suite locally in two shards; CI runs the full network partition on the PR.

Proves itself by: smoke exit 0, both local network shards exit 0, then every required CI check green including the real-proving canary.
