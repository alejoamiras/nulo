Q2 — Profile-flow dedup + passkey-UI relocation

Two screens create and import wallet profiles: the small toolbar popup and the full-tab onboarding page. They do almost the same work with copy-pasted code. A month ago the low-level helpers (name field, passkey ceremony, backup import) were already shared — what's left is the glue that strings them together, still duplicated. This plan pulls that glue into two shared composables (useProfileImportFlow, useProfileCreateFlow) and moves the shared passkey dialog out of the "popup-only" folder into a neutral home both screens can use. It changes no behavior except two small, deliberately-chosen fixes.

Why this tier was chosen

Deep. Rubric: 2 dimensions are HIGH — blast radius (onboarding/import is the wallet's fund-access critical path; a broken import locks users out of their funds) and security sensitivity (passkey/WebAuthn ceremony + raw secret material in memory). Two HIGH → deep regardless of it being one package. The plan went through 3 independent drafts (me + a Claude planner + Codex), a consolidation, a contradiction-check, a fresh hostile audit, and a final Codex pass. (Note: Fable 5 was unavailable, so the second planner + one audit slot used a Claude Plan subagent instead — cross-family rigor preserved via Codex.)

The one big design decision

The two screens "wake up" a freshly created/imported profile differently: the popup waits for a background service-worker signal to do the heavy setup; onboarding has no such signal so it does the setup itself. These aren't cosmetic differences — they're different sequences. So the shared composable owns everything up to activation, and each screen plugs in its own "finish" step (onComplete(profile)). This reuses a pattern the codebase already has, and it makes the first quirk-fix disappear for free.
