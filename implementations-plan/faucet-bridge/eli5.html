Faucet → Bridge

Turn Nulo's testnet faucet into a unified Faucet + Bridge app. Today the faucet hands you fake USDC/ETH on Aztec (L2). We're adding a real bridge: move those tokens between Ethereum (L1) and Aztec (L2) in both directions, and "fuel up" — swap a slice of your USDC into Aztec's gas token (Fee Juice) and land it on L2, all in one transaction. The whole thing stays a static website with no server, like the faucet. It reuses the work the author already did for the Holonym bridge — but strips out Holonym's identity/compliance checks and its database backend.

Why this got the heaviest planning ("mega-deep")

The plan scored HIGH on three of six risk dimensions: Novelty (first L1↔L2 bridge in this repo), External coupling (Ethereum + Uniswap + Permit2 + Aztec's portals all at once), and Security (it moves value across chains in one signed transaction). Three highs including novelty ⇒ the full ceremony: research agents mapped the code first, then three independent plans, then two rounds of hostile review by two different AI model families.

That review paid for itself. It caught two "facts" the plan had wrong: a contract we were about to hand-write already ships ready-made in Aztec's libraries (so we just deploy it), and a minting function we thought was locked-down is actually open to anyone. Both made the plan simpler and safer.

The plan, phase by phase

P0 — Shared design package.low Pull the faucet's buttons/cards/colors into a reusable @nulo/design package so faucet and bridge look identical. Pure refactor.
P0.5 — Plumbing spike.high Before building anything real, prove the tricky tech actually runs in a plain website: the Ethereum wallet library, the private-fee-juice library, and in-browser crypto. Fail fast here, not in month two.
P1 — Look before you leap.highest Ask the live network what addresses it actually uses, confirm it speaks our pinned version, and confirm we can mint test Fee Juice. A 20-line test pins the one thing that, if wrong, silently loses funds: that Ethereum and Aztec agree on the exact message format. Stop-the-line if the network doesn't match.
P2 — Deploy the portal.med The "portal" is the L1↔L2 lockbox. Aztec already ships a clean one — we deploy our own copy pointed at our tokens instead of writing risky bridge code from scratch.
P3 — L1 faucet token.med A fake USDC/ETH on Ethereum anyone can mint (capped per transaction) so people have something to bridge. Redeploy the L2 tokens so both the faucet and the bridge can mint the same token.
P4 — Bridge brain.med A framework-free TypeScript library with all the bridge logic (deposit, claim, withdraw, status-tracking, encrypted local recovery). Reuses Nulo's existing crypto.
P5 — App shell.med Turn the faucet into a two-tab app (Faucet / Bridge) and wire up the second wallet (Ethereum) next to the existing Aztec one.
P6 — First real round-trip.high Move a token L1→L2 for real, with public Fee Juice, and a live progress bar. Exit gate: you can export your recovery secret and re-import it after closing the tab.
P7 — Private fuel.high Pay your Aztec fees privately via Wonderland's Fee-Paying Contract. The fiddliest cryptography in the project (the author already fixed the key bug once).
P8 — Withdraw home.high Move tokens L2→L1. This is the long wait (proving takes 20–60 min) — and where the "N blocks remaining" bar really shines.
P9 — The headline trick.high The "spend USDC, get Fee Juice + your bridged tokens in one transaction" swap, via our own Uniswap pools. Supports private tokens too (your call — see below).
P10 — Polish + ship.low Activity list, retire the old package, two domains, docs.

Human context (the ideas behind the decisions)

  • Portal / Fee Juice. A portal locks a token on one side and mints it on the other via the chains' official message mailbox. Fee Juice is Aztec's gas token — you need a little to do anything on L2.
  • No server, on purpose. Keeps infrastructure trivial. The cost: your "claim secret" lives only in your browser. Lose it before the second step and your deposit is stuck. So a loud "export your secret" button is built into the core flow, not bolted on later.
  • Private secrets are like cash. For private transfers, the claim secret isn't tied to a recipient — whoever holds it can claim the funds. So an exported private secret is a bearer credential: treat the export file like cash, and the UI says so.
  • Why copy Holonym but drop half of it. Holonym's bridge carried identity/compliance checks and a database. We keep the clever cross-chain plumbing and throw away the compliance layer — which is exactly what lets us offer private bridging that Holonym had to disable.

Open questions (resolved in early phases, not blocking approval)

  • Does the live network run our pinned version, is the Fee-Juice minter wired, and how big is each mint packet? → answered by the Phase-1 look-before-you-leap, which can halt the project cheaply if the answer is bad.
  • Does the Ethereum wallet library work against Aztec's forked copy of its dependency? → answered by the Phase-0.5 spike, with a hand-rolled fallback ready.
