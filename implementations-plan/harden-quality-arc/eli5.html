Why mid (for the plan itself)

The rubric scores the driver, not the arc's reach: novelty low (this is the exact pattern that shipped the batch-2 arc), blast-radius low (it writes only to a throwaway branch; the one irreversible step — the dev merge — is yours), irreversibility/migration/coupling all low. 0–1 high → mid. The risk lives in individual findings, so each one gets its OWN tier inside the loop: light for the 7 cheap wins, mid for the dedup/typing, deep for the cross-cutting + concurrency + privacy ones, mega-deep for the two trust-boundary rewrites (Q-01 decode layer, Q-02 typed dispatch).

How each finding is handled (the loop's per-finding cycle)

Re-verify it's still real → blueprint at its tier (with a Codex + a second-model consult) → implement on its own branch → fast checks after every edit → /code-review + a Codex post-impl audit → full gate (units + smoke + full network) → squash-merge into dev-quality → mark done + log lessons → next. A failed CI job is re-run once; still red → root-caused and fixed, never skipped or weakened.

Human context

The two auditors (Codex + a top-tier Claude) agreed the single biggest danger isn't a typo — it's that the network test only exercises a friendly dApp, so a refactor that accidentally loosens a permission check at the dApp boundary would still go green and merge. The defense the plan builds in: a hand-frozen "authz oracle" test that the loop is forbidden to edit (editing it to pass = an instant halt-and-ask), plus a hostile-dApp test suite. That, not the network test, is what proves permissions didn't regress. The other recurring theme: "no production users" lets us skip data-migration, but it does not mean we can't break the wallet's own restore/backup tests — those are real contracts, so the secret-typing (Q-06) and decode-layer (Q-01) phases are gated on a restore round-trip.
