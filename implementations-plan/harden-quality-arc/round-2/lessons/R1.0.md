## The key decision (deviation from "one comprehensive suite upfront")
The plan spec'd R1.0 as the full 8-service suite written first. Reality: wiring all 8 (esp. network's nested `endpoints[]` + auth-registry's tx-building `revokeAuthwits`) upfront is a lot of cost for stores whose refactor is phases away. **Adopted: R1.0 lands the foundation + the 3 highest-risk guards; each remaining store's scoping is added TDD-with-its-fix** — fpc/network→R1.3, account→R1.4, **gap#3**→R1.5. Each store's guard still lands *before* its refactor touches it, so the "written-first" safety holds; it just grows the file per phase instead of front-loading. (Documented in the #229 PR body + plan R1.0.)

## Wiring recipe (reuse for R1.2–R1.5)
- Seed rows raw: `api.storage.local.set({ [`${root}@${id}`]: JSON.stringify(row) })` (roots in the Explore map) OR a typed repo/`EntityStorage` over the SAME `api`.
- Each service: `services.add(fakeProfile)` + `svc(X.name, {…})` stubs for every dep its `init` resolves (include the EventHandlers it `.add()`s — e.g. token-balance needs `onAccountAdded`/`onToken*`/`onTransactionUpdated` on the stubs) + `await services.start()`.
- Fire the cascade yourself: `fakeProfile.onProfileDeleted.invoke(p2)` + `await new Promise(r => setTimeout(r, 0))`.
- `svc()` returns `as never`, so stub method types don't need to match the real service.
