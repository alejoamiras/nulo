## Decision ledger (codex `019f1a37` + opus Plan, dual blueprint)

**Convergence (both, high-confidence):**
1. **`makeRemoteError` extraction is SAFE** — executable bodies byte-identical (only the comment differs); no `this`/closure/transport state. → standalone `remoteErrorFromResponseContent(content)` in `errors.ts` with a **structural param** (no new import → cycle-free). Both clients call it. The sibling `makeTimeoutError`/`makeSendFailureError` are **intentionally divergent wording** ("RPC '…' timed out after Nms" vs "Offscreen request timed out: …") — leave them.
2. **`getErrorMessage` ≠ `extractMessage` — do NOT collapse** (would change user/dApp-visible strings: `null`/`undefined`→`"Unknown error"` vs `"null"`/`"undefined"`; plain `{code,message}` PXE/JSON-RPC throw→duck-typed `.message` vs `"[object Object]"`; primitives→raw passthrough type-lie vs `String(x)`). The wire projection uses `getErrorMessage` (`core/error-response.ts:22`); `jobs/error.test.ts:71-76` pins the `extractMessage` semantics. → extract canonical `errorMessageFromUnknown` (= `extractMessage` exactly), route `jobs/error` through it, and keep `getErrorMessage`'s two quirks in a **thin wrapper** that now genuinely returns `string`. Add REGRESSION PINS so nobody collapses it later.
3. **`JobError.kind` open union = autocomplete, NOT exhaustiveness** — `(string & {})` defeats `never`-narrowing; consumers MUST keep `default` arms. Runtime schema stays `z.string().min(1)`. Drift caught by a `satisfies Record<KnownJobErrorKind,0>` table + a UI-iteration test, NOT the compiler.

**Divergence — the payload DU (RESOLVED):**
- codex: DEFER the payload-DU to Q-01 (a DU without a runtime parser "just moves casts around"; the wire boundary stays `errorPayload?: unknown`).
- Plan: do a LOW-RISK **closed-DU subset** now — keep `WalletErrorPayload` permissive (wire untouched), add an internal `KnownWalletErrorPayload` used ONLY inside `walletErrorFromPayload` after ONE documented boundary cast; this removes the 2 scattered per-case casts (`errors.ts:229,234`) + (4b) 2 instance-side casts (`error-envelope.ts:35,45`).
- **Verdict: adopt Plan's closed-DU subset (Phase 4), as the LAST/optional slice.** It is NOT the full public DU codex warned against (wire type stays `unknown`); it's confined to `errors.ts`, type-only, zero wire change, and *sets up* (not conflicts with) Q-01's future parser — which will later validate the `unknown` wire INTO this closed union. codex's caution applied to typing the wire, which we explicitly do not do.
