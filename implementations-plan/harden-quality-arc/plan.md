# Harden-Quality Arc — meta-plan (autonomous driver)

**Goal:** land all 22 quality findings from `audit/quality/2026-06-29-ext-ultra/` onto a fresh `dev-quality` branch off `dev`, each re-verified → tier-appropriately blueprinted → codex-consulted → implemented → squash-merged → validated (units + smoke + **full** network e2e per PR), with nothing broken along the way. End state: a `dev-quality` carrying the whole arc, green on a final full-network sweep, with a `dev-quality → dev` promote PR opened **for the owner to merge** (never merged autonomously).

**Owner decisions (Phase 0):** (1) all 22 in scope, including the 3 architectural seams Q-01/Q-02/Q-03 — fully autonomous; (2) full network e2e on **every** PR; (3) fully autonomous — never pause except hard limits.

This is the **meta-plan**: it defines the per-finding cycle, the tier per finding, the sequence, and the gates. Each finding's own micro-blueprint is produced *during* the loop (the tier is pre-assigned here).

---

## Why `mid` (Phase 0.5 rubric — for THIS meta-plan, not the findings)

Rubric over the meta-plan (the orchestration), not the arc's blast radius: Novelty **low** (this is the exact pattern of the just-completed batch-2 `quality-arc-deferred`), Blast radius **low** (the driver writes to a throwaway `dev-quality`; the owner gates the only irreversible step — the `dev` merge), Irreversibility **low**, Migration **none** (no production state; no backwards-compat required), External coupling **low**, Security sensitivity **low for the driver** (individual findings that touch the dApp trust boundary — Q-02/Q-04/Q-05 — get their own `deep`/`mega-deep` tier + adversarial audit *inside* the loop). 0–1 high → `mid`. The per-finding tiers below carry the real rigor.

## The per-finding cycle (every implementation phase runs this)

For each finding (or coupled pair):

1. **Re-verify** still valid vs current `dev-quality` HEAD — grep the cited `file:line` from `consolidated.md`; if the smell is gone (already fixed by an earlier phase) → mark `✓-moot` + evidence + advance. If shrunk → re-scope.
2. **Blueprint at the assigned tier** (`light`/`mid`/`deep`/`mega-deep`): clarifying-answers are already encoded here, so the loop drafts the micro-plan + (mid+) a competing outline + dual audit (codex `/codex xhigh` + an opus `Plan` subagent) + decision ledger. Persist to `implementations-plan/harden-quality-arc/findings/<Q-NN>/plan.md`.
3. **Codex consult** on the finding's open questions (xhigh); reconcile into the ledger. Disagreements are resolved by codex + judgment (fully autonomous per Phase 0) — EXCEPT a hard limit, which halts.
4. **Implement inline** on a branch `qa/<Q-NN>-<slug>` off latest `dev-quality`. Behavior-preserving by default; **no backwards-compat / no state migration required** (owner ruling) — but the app + ALL tests must keep working. BUG-PIN any surprising pre-existing behavior. Tests inline + deterministic.
5. **Per-edit fast gate**: `bun run lint` + `bun run typecheck:all` + touched-package `bun run test` after each meaningful edit.
6. **Per-arc tail**: `/code-review max --fix` → codex post-impl audit (`/codex xhigh`, net diff + adversarial/modularity ask) → fix loop.
7. **Full gate** (owner ruling — every PR): units (`bun run test`) + smoke (`pr-smoke-e2e.yml`) + **FULL** network (`pr-network-e2e.yml`: 5 shards + heavy/concurrent-confirm + heavy/fee-methods + canary/real-proving). dev-quality PRs do **not** auto-trigger CI (the `pull_request` filter is `[main,dev]`) → dispatch via `gh workflow run pr-network-e2e.yml|pr-smoke-e2e.yml|pr-quick.yml --ref <branch>`. **For trust-boundary phases (P15/P18/P19/P20 + any touching `dispatcher.ts`/`method-descriptors.ts`/`scope-enforcement.ts`/`capabilities.ts`/storage codecs) the network e2e is a SMOKE signal only — it drives the COOPERATIVE playground dApp and CANNOT prove authz didn't regress. The AUTHORITATIVE gate there is (a) the frozen authz oracle `method-descriptors.test.ts` FROZEN_* staying green UNEDITED, and (b) a new adversarial-bypass suite** (see "Trust-boundary safety").
8. **Green = merge**: squash-merge into `dev-quality` via **plain** `gh pr merge <n> --squash --delete-branch` (self-authored + signed commits → GitHub signs the squash and the required gates pass; **no `--admin`** — per CLAUDE.md `--admin` is emergency-only and bypasses BOTH the status checks and signatures; never use it to dodge a red gate). Mark the phase `✓` + SHA + run-id in this plan; file `lessons/<Q-NN>.md`; print `LESSONS_FILE=…`; advance.

**RED policy:** re-run a failed job ONCE; green → proceed; still red → root-cause + FIX (reproduce locally; codex if stuck). FORBIDDEN: retry-until-green, skip/`.skip`/quarantine/disable a test, weaken an assertion, merge over red, introduce a flake. **CARVE-OUT (hard limit):** "make it green" NEVER includes editing a frozen authz/crypto oracle — `method-descriptors.test.ts` `FROZEN_*`, `scope-enforcement.test.ts`, `dispatcher.test.ts` authz cases, `key-vectors.test.ts`. A diff that needs one of those to change = a behavior/trust-boundary change → **HALT + surface**, never self-resolve. (This is distinct from "update an expected value", legit for Q-22 docs.)

**Merge mechanics:** keep commits **signed** (a self-authored signed squash passes the required gates + signatures with NO `--admin`). If signing is unavailable, OR the protected squash-merge is refused for any reason → **HALT + surface**. Do NOT fall back to `git -c commit.gpgsign=false` or `--admin` in the autonomous path — that reopens the gate/signature bypass (codex final-pass condition 1); `--admin` is emergency-human-only, never the loop's path. Push via `git -c credential.helper='!gh auth git-credential' push https://github.com/alejoamiras/nulo.git <b>:<b>`; PR title ≤ 93 chars (`(#NN)` squash-suffix + commitlint `header-max-length=100`); sync via `git fetch --prune …; git checkout dev-quality; git reset --hard FETCH_HEAD`.

**`✓` is LOCALLY green, not permanently settled.** The registry cluster (P15/P18/P19/P20) all re-derive `method-descriptors.ts`/`dispatcher.ts`/the codecs, so a later phase can invalidate an earlier `✓`'s authz invariant WITHOUT the re-verify step (which checks the *smell*, not the invariant) noticing. After ANY registry-cluster phase merges, re-run P15's adversarial-bypass suite + the frozen oracle against the new HEAD. The final full sweep (P21) is the real settle.

## Trust-boundary safety (audit-mandated, cross-cutting)

Both audits' #1 finding: the network e2e drives the **cooperative** playground dApp = happy path only, so a fail-open ships **green**. For every trust-boundary phase, the authz-didn't-regress proof is NOT the network e2e but:

1. **The frozen authz oracle** — `method-descriptors.test.ts` `FROZEN_CAPABILITY_MAP`/`FROZEN_EXEMPT`/`FROZEN_SCOPE_CHECKER` (by-reference identity) + the batch/F-003/F-004 asserts. It **already exists on `dev`** (not "established" by P15) and must stay green AND **byte-UNCHANGED** through P15→P20. **Operational check (codex final-pass condition 2 — not just prose):** after each trust-boundary phase run `git diff --exit-code` on the oracle paths (the `FROZEN_*` ranges in `method-descriptors.test.ts`, the authz cases in `scope-enforcement.test.ts` + `dispatcher.test.ts`, and `key-vectors.test.ts`); a non-zero exit = the oracle changed = HARD-LIMIT halt (RED carve-out). An intentional boundary change = surface-and-stop, never self-resolve.
2. **An adversarial-bypass suite** (build in P15, EXTEND + re-run after P15/P18/P19/P20) — a HOSTILE protocol-client that ATTEMPTS each bypass and asserts DENIED:
   - *Dispatcher/scope:* scope-array widening, missing-grant call, batch-smuggling a forbidden method, unknown method, prototype-name method (`__proto__`/`constructor`), tuple/arg mismatch, a method whose scope checker was dropped.
   - *Capability negotiation (codex final-pass condition 3 — the biggest P19/P20 risk, OUTSIDE the metadata oracle):* a crafted/partial `CapabilityManifest` that should be DENIED or only-partially-granted is not over-granted; `covers`/`delta`/`merge`/`enrich` never default an unknown/missing field to "covered"/"no delta"/granted.
   - *Decoder fail-closed:* a malformed RPC / capability / session / storage payload is REJECTED, never defaulted-to-grant and never accepted LAXER than the cast it replaced.
   This is the regression proof network e2e cannot give. **It is MANDATORY (not optional) after every registry/decoder-cluster phase.**
3. **Per-phase adversarial codex ask (verbatim):** "Can any crafted method / prototype key / batch leg / hook path / tuple mismatch now reach a sink with FEWER grants than before? Did every method keep its scope checker + capability gate? Does any missing registry row default to grant / `AccessLevel.None`-as-grant / 'covered' / 'no delta'? Is any decoder LAXER than the cast it replaced? Does `registerContractClass` stay the fail-closed 'Neutralized' stub and `contractClasses.register` stay denied?"

## Security & Adversarial Considerations

- **Threat model:** TWO adversaries. (1) A **malicious dApp** — the arc touches the dApp trust boundary in Q-02 (dispatch), Q-04/Q-05 (operation/capability policy), Q-01 (decode); a refactor that *loosens* validation or whose registry default *grants* instead of *denies* is the danger. - **Concurrency:** Q-15 (execution slot/journal) + Q-17 (profile lock) sit on the money/cancel path the batch-2 arc hardened; the ordering invariants are load-bearing — preserve verbatim, gate on the race tests + concurrent-confirm shard.
