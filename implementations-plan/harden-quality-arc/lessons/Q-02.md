## The `satisfies`-vs-frozen-oracle friction + the fix (the real lesson)
To derive `MethodName = keyof typeof METHOD_REGISTRY` I needed literal keys, which the `: Record<string, MethodDescriptor>` annotation ERASES (keyof = string). Switching to `... satisfies Record<string, MethodDescriptor>` gave literal keys BUT narrowed the VALUE types to each row's exact shape — which broke the frozen oracle's `.exemptReason?`/`.scopeCheck?` optional-field access (TS2339), and I CAN'T edit the frozen oracle. Fix: a **private `satisfies` source (literal keys) + a wide-typed re-export** `export const METHOD_REGISTRY: Record<string, MethodDescriptor> = METHOD_REGISTRY_SOURCE` (same runtime object; wide values for the oracle's optional-field access). MethodName derives from the source, everything else consumes the wide re-export. Lesson: `satisfies` narrows value types — if a downstream (esp. a FROZEN, un-editable) consumer relies on the WIDE optional-field type, split into a private-`satisfies`-source + wide-annotated-re-export of the same object. And: caught the TS2339 only because I ran typecheck by EXIT-CODE + grep (the Q-01 lesson) — a `| tail -N` would have hidden it.
