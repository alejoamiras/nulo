## Key lessons
- **The renderers are genuinely divergent — unify the VOCABULARY (type), not the PALETTE.** Badge = colored backgrounds, Banner = colored icon-fills (surface-low bg), Toast = colored left-border, ToastManagerBase = raw red/green/orange. A single tone→color map would change visuals (codex). So: one broad `SeverityTone` type + per-renderer SCSS kept + each prop typed to its exact subset.
- **No widening / no narrowing.** Each `Extract` subset matches the renderer's SCSS classes exactly (codex post-impl verified). Widening would accept an unrenderable tone (blank render); narrowing would type-error a used tone. `typecheck:all` = 0 confirmed no call site passes an out-of-subset value (behavior-preserving).
- **Raw-color axis left deliberately.** `ToastManagerBase` (raw `red|green|orange` borders) + `composables/toast.ts` (`color?: string`) are a raw-color passthrough, not the semantic `Toast.kind` axis — unifying risks a visual change (codex: only migrate explicit `color:"red"`→`tone:"error"`, deferred). Documented in `severity.ts`.
- **Smoke flake re-run (RED policy):** `accounts > switch between accounts` (Client-disconnected, retry x2) is the known pre-existing SW-restart timing flake; Q-11 is type-only (can't cause it) → re-ran once → green.
