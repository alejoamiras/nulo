## The mega-deep finding SHRANK to a staged safe core (codex: "don't run as one mega-phase")
Q-01 spans 5 seams (persistence / RPC / dApp / backup / PXE). Research (codex `bg0v9z0zg` + 2 Explore maps) re-scoped it:
- **PXE-uniform SKIPPED** — the 2 "casts" are JUSTIFIED: `getNoteSchemas` returns plain data (no branded fields, no zod schema exists → lossless cast); `getBlockTimestamp` uses `Number()` coercion (strict `z.number()` = a behavior change). 13/15 pxe methods already `parseAsync`. The finding's "proves the pattern then skips it" was 2 justified casts, not a real gap.
- **STORAGE is the real seam** (14 EntityStorage consumers `JSON.parse … as T`; only operation-journal validates, via a hand-rolled layer-2).
- **RPC decode / dApp / backup DEFERRED** (RPC = big surface, malformed already rejects; dApp needs threading the discarded SW `type` onto the record + is a fail-closed behavior change; backup is v2-only + no schema + checksum key-order load-bearing + heterogeneous `restore` sigs → rejecting a restorable backup is worse than the casts).

## The central design rule: split JSON-SYNTAX failure from CODEC-VALIDATION failure
codex's #1 point + the mega-deep trap: `entity_storage.parseOrDelete` DROPS a row on parse-throw. A stricter codec rejecting a valid-but-drifted row would VANISH it as a silent empty read = worse than the `as T` cast. So `decodeRow` splits: JSON-syntax-fail → legacy policy (EntityStorage drops / ValueStorage throws); codec-validation-fail → NEVER delete (EntityStorage keeps + returns undefined "present but unreadable"; ValueStorage throws). Non-Error/NPE throws from the codec are ALSO caught as validation (kept), never as syntax (dropped). codex post-impl verified this airtight.

## wallet-core stays zod-free → INJECT the parser
wallet-core deliberately has zero zod ("no zod" comments). So the codec is an INJECTED `parse?: (raw:unknown)=>T` via the `(root, area, parse?)` ctor; zod schemas stay in apps/extension. Per-seam (serializers DIFFER: storage raw `JSON.stringify` vs RPC `jsonSanitize` — BigInt/Date/AztecAddress/Fr wire shapes differ; do NOT standardize).

## Policy-only FIRST PR (behavior-preserving) — codec is opt-in
The `parse` param is optional + NO consumer passes it yet → all 16 consumers unchanged. This is codex's staged "policy-only first, then codecs one at a time." The foundation is the never-delete-on-validation-fail GUARANTEE (tested) that consumer migrations require. Real codecs MUST THROW on invalid (not return undefined — codex's non-blocking note) + have a per-namespace write→read corpus.

## LESSON: verify typecheck by EXIT CODE + `grep error`, never `| tail -N`
CI pr-quick caught `TS7006: Parameter 'c' implicitly has an 'any' type` in a new test (`.mock.calls.some((c)=>…)`). It passed my local vitest run (esbuild strips types) but failed `tsc`. I MISSED it locally because I ran `typecheck:all | tail -3` — a `bun run --filter` failure in wallet-core scrolled off the tail while the last 3 packages showed green. **Two compounding traps:** (1) vitest/esbuild green ≠ tsc green (esbuild doesn't type-check); (2) `| tail -N` hides a mid-run per-package failure. Fix: `bun run typecheck:all >log 2>&1; echo EXIT=$?; grep -iE 'error TS|Exited with code [1-9]' log`. The gate did its job — RED policy applied (root-cause + fix `c1b69fb`, re-verified by exit-code, re-gated; never neutralized).

## P19b — operation-journal is the first consumer (delete→keep is the safety-improving behavior change)
Merged `f2d0e5b` (#218). Injected `OperationRecordSchema.parse` into operation-journal's `EntityStorage` ctor; collapsed the hand-rolled `_loadValidated`/`_loadAllValidated` to thin `storage.get`/`getAll` wrappers (validation now lives in the codec). The ONE behavior change: a schema-invalid row is now KEPT (read as undefined) instead of DELETED — the never-delete guarantee; DOWNSTREAM behavior preserved (FSM never sees it; getOperation→undefined, getOperations→skips, transitionOperation→'not found'). Updated the 3 schema-invalid tests delete→keep. Lesson: the safest first consumer is one that ALREADY validates (operation-journal's hand-rolled layer-2) — migrating it is downstream-behavior-preserving; only the storage-side delete→keep changes, which is the codex-mandated safety direction. The durable stores (which DON'T validate today) are riskier follow-ons (adding validation = fail-closed on drift).

## Trust boundary: storage is client-of-the-boundary, not the boundary
No `method-descriptors`/`dispatcher`/`rpcMethods`/`service.ts` touched; frozen authz oracle git-diff-UNEDITED; wallet-bridge adversarial-bypass unaffected. The codec is fail-CLOSED (validation-fail surfaces/keeps, never silently defaults) — the security-correct direction.
