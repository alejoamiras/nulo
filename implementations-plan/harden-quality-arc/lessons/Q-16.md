## Key lessons
- **`Client | null`, NOT `| undefined`** (codex strict-preservation). Runtime was already `null` (the `null as unknown as` IS null at runtime); `| undefined` would change observable bare-read + TypeError shape. `| null` keeps runtime byte-identical — only the static type tightens.
- **vue-tsc does NOT strict-null `.vue` `<script setup>`.** Typing the clients `| null` produced ONLY 6 errors (all `.ts`, app.store.ts); the ~30 `.vue` `managers.network.foo()` reads compile clean under `| null` (even with explicit imports). So the compile-safety win is `.ts`-only; the ~30 `.vue` sites are left raw (all unlock-guarded popups — codex post-impl confirmed no pre-unlock-reachable deref; behavior-identical). `require*/get*` is the convention for new code; closing the `.vue` gap is a separate infra task. (NOTE: this is the strict-NULL gap specifically — vue-tsc DOES check defineProps generic prop TYPES at call sites, relevant to Q-10.)
- **REGRESSION (the big lesson): run the FULL touched-package suite locally, not just the new test file.** Adding `require*` exports broke `useProfileBootstrap.test.ts`'s `vi.mock("@/utils/core")` (CI quality red: "No requireNetwork export"). I'd only run the new `core.test.ts` locally, so I missed it. The per-edit gate is `touched-package bun run test` = the WHOLE package.
- **The mock fix taught the real-vs-mock seam:** the first fix (`requireNetwork: () => networkMock`) was ALSO wrong — `initNetworks` REASSIGNS `managers.network = new NetworkServiceClient()` (a fully-mocked client with `getNodeStatus`), so the mock's accessor must read the CURRENT `managers.network` (close over the `managers` object), exactly like the real `requireNetwork`. This CONFIRMED app.store is behavior-preserving (`require*() === the live managers.X`).
- **RED policy in action:** the quality failure was a REAL regression (not a flake) → root-caused + FIXED (not re-run); the network e2e was unaffected (it uses the built extension, not vitest mocks).
