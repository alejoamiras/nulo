## The finding split cleanly: client half (done) vs PXE half (deferred)
Q-03 had two parts — 110+ client `return this.request(...)` forwards, and a 7-surface PXE descriptor sprawl. codex's blueprint verdict: do the CLIENT half (safe, client-side, no authz), DEFER the PXE half (SW-only methods like `clearChainState`/`getNoteSchemas` are excluded from `IPXE`; a naive one-table could expose chain-purge via the per-network facade; the service bodies encode validation/rehydration/locks that must stay hand-written). So P18a = client factory; P18b = PXE, separate + shape-only + explicit per-field flags. The bulk of the dedup (the 110 forwards) is the client half.

## definePassthroughs: explicit name-list + declaration-merge, NOT a Proxy
`definePassthroughs<M>(proto, names)` installs `function(...args){ return this.request(name, ...args) }` on the prototype from an EXPLICIT `as const` name list. NOT a Proxy (codex: a Proxy changes stack traces / identity / `function.length` / enumeration and hides holes behind casts). Each client: `const X_METHODS = [...] as const satisfies readonly (keyof Methods)[]` (blocks EXTRA names) + `type _E = Exclude<keyof Methods, (typeof X_METHODS)[number]> extends never ? true : Exclude<...>; const _e: _E = true` (errors on MISSING names) + `interface X extends MethodsSpec<Methods>` (declaration-merge for the types) + a justified `noUnsafeDeclarationMerging` ignore + the class (events + ctor only) + `definePassthroughs(...)`. The two-directional drift guard is what makes the runtime name-list provably match the `Methods` type — codex confirmed it's airtight for these specs (closed string-key literals, no optional/index/symbol keys).

## The base `restore`/`backup` collision LANDMINE
`ServiceClient` (extension-messaging/background/client.ts:159-165) hardcodes generic `backup()` + `restore()` convenience RPCs returning `Promise<unknown>`. Any client whose `Methods` has a `restore` or `backup` key COLLIDES: the declaration-merged `MethodsSpec["restore"]` (typed) conflicts with the base's `restore(): Promise<unknown>` → a TS2320 "cannot simultaneously extend" error. **profile** hit this (its `restore` RPC) — its original explicit `restore(profile, secret, ...): Promise<Restored<ProfileInfo>>` was silently OVERRIDING the base. So profile was left explicit (a factory carve-out excluding `restore` would be messier than the explicit form). The GREEN TYPECHECK proves none of the 16 migrated clients collide — the collision fails compilation, so it can't slip through. Lesson: a generic base class with hardcoded method-name conveniences is a hidden collision surface for any name-list/declaration-merge factory; the compiler catches it, but know it's there.

## The `noUnsafeDeclarationMerging` suppression is the pattern's real cost (16×)
The class+interface declaration-merge trips biome's `noUnsafeDeclarationMerging` (TS doesn't check the interface's methods are initialized in the class). Every migrated client needs the suppression (justified: the methods ARE installed by definePassthroughs + the exhaustiveness guard proves completeness). This is the honest tradeoff vs the simple explicit methods: 16 suppressions + name-arrays + merge machinery to remove ~110 boilerplate bodies. Defensible (codex + audit endorsed, it typechecks, the guard makes it safe), but not a slam-dunk clarity win — the clients aren't the trust boundary (just forwarders), which is what makes it low-risk enough to be worth it.

## Delegated the 15 mechanical migrations to a subagent — typecheck was the safety net
A general-purpose (sonnet) subagent migrated the 15 pure clients from the token template, self-classifying (skip anything not purely mechanical → it correctly skipped config/logger). I re-validated the aggregate myself: typecheck:all (the drift guard + `implements ServiceSpec` surface any bad name-list/missing-event as a COMPILE error) + full ext suite (2723) + wallet-bridge (159, frozen oracles UNEDITED). Lesson: a mechanical multi-file refactor with a strong compile-time invariant (here: exhaustiveness guard + implements) is a good subagent-delegation candidate — the type system catches the subagent's mistakes, and you validate the aggregate rather than every file.
