## Key lessons
- **"Observably identical at sinks" is FALSE at non-coercing sinks (codex post-impl HIGH).** My p2 `getErrorMessage` wrapper string-coerced non-string values (`{message:0}`→`"0"` etc.). codex traced that `getErrorMessage`'s result flows UN-coerced to the dApp **wire JSON** (`core/error-response.ts` `buildErrorResponseContent`) and **`LoggerStore`** (`logger/store.ts` keeps `trim(data)`). So `{"error":0}`→`{"error":"0"}`, `{"error":{nope:1}}`→`{"error":"[object Object]"}` — a real wire/log behavior change. **Fix:** revert `getErrorMessage` byte-identical; keep ONLY the `errorMessageFromUnknown` extraction + jobs routing. The pre-existing type-lie (typed `string`, can return non-string) is BUG-PINNED + deferred to Q-01 (boundary parser). Lesson: before "fixing" a type-lie, find EVERY sink — a value reaching a JSON-serialized field or a raw store is not coerced.
- **The finding's "merge both extractors" was wrong.** `getErrorMessage` (lenient, wire/popup) ≠ `extractMessage` (jobs). codex (blueprint AND post-impl) said keep them separate; the dedup is the SHARED core + jobs routing, not a merge.
- **`(string & {})` open union = autocomplete, NOT exhaustiveness.** A `switch` won't narrow to `never` (open arm); the drift guard is the `satisfies` table + a UI-iteration test, not the compiler.
- **`z.string().min(1)` stays assignable to `z.ZodType<JobError>`** after `kind` became the open union (`string` fits `KnownJobErrorKind | (string & {})`) — no schema change, behavior-preserving.
- **Frame-detached network flake** (`tokens.test.ts > import token by contract address`) cleared on one re-run (RED policy). Q-07's diff has no token path → confirmed unrelated before re-running.
