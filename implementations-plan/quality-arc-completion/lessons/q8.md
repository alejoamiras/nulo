## Implementation

Adopted in EditEndpointPopup (`fillFromEndpoint`→rebase, `isDirty`→`form.isDirty`) + EditNetworkPopup (`handleFillFieldsWithDefaultValues`→rebase, `isStartedEditingName`→`form.fields.name.isDirty` — the per-field API codex specifically wanted for warning-gating, NOT `form.isDirty`). 5 new tests (dirty/reset/cross-field/partial after rebase).

**Gap (b) drifts (verified real, not intentional):** `SelectTokenPopup` had no `onTokenUpdated` handler though `TokenServiceClient` emits it (client.ts:12) → stale on rename; added it. `BalanceView.onBalanceDeleted` never removed the row (unlike add/push + update/splice) → stale after delete; added the filter, preserving the display-option side-effect.

## Post-integration codex audit — regression in the Gap (b) drift fix (PR #136)
Two independent codex audits over the integrated `dev-quality` diff (behavior `019eebfa-df96-7db1-8379-1fa22af12688`, adversarial `019eebfa-e322-7281-becf-c1bfbfd2089d`) both flagged the SAME bug — and it was in this arc's own "drift fix": the `BalanceView.onBalanceDeleted` filter was added **before** the selected-token guard. `tokenToDisplay` is computed from `tokenBalances`, so filtering first made the guard read post-delete state (`tokenToDisplay` → `undefined`), and the `displayOption = "total_account_value"` reset never fired. Deleting the *currently displayed* token's balance stuck the home view on a stale $0.00 selection. The pre-Q8 handler read the guard against the unmutated list, so it was correct on this path — the reorder I added regressed it.

**Fix:** capture `wasDisplayed` BEFORE the filter (one-line reorder). Keeps the list-maintenance, restores the guard.

**Lesson:** a "drift fix" that adds a mutation next to a computed-dependent guard must respect read-before-mutate ordering. The network/smoke suites never delete the *displayed* balance, so e2e stayed green — the bug only surfaced under the post-impl audit + a targeted unit test. Added `BalanceView.test.ts` (mount + capture the deleted handler; 2 cases, both proven to fail against the old ordering). Both audits cleared every other arc, including the two I worried about most (Q15 purge lock/emit-order + authz; Q9 startup-dep no-cycle).
