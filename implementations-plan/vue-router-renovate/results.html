vue-router 5 + Renovate — plan ELI5

Consolidated plan · 2026-05-18 · two scopes, two PRs · Codex review folded · awaiting approval

The 30-second version

Scope A: drop a dependency that just got archived upstream (unplugin-vue-router) and move to vue-router 5, which absorbed its features. The work is much smaller than it sounds — the archived dep isn't actually wired into our build pipeline.

Scope B: turn on Renovate (a quieter, more controllable alternative to GitHub's Dependabot). Conservative defaults: 7-day age gate, weekly schedule, @aztec/* never touched, no auto-merge. Mend's hosted GitHub App is free for private repos.

Ship as two PRs, A first then B. Order matters: PR-A trims the Renovate routing group from 3 packages to 2, so PR-B can ship the accurate group from the start.

Codex review — folded corrections (4 rounds)

Both scopes went through two Codex xhigh review rounds each — plan-stage + impl-stage. All four rounds verdicted yellow-flag; all four sets of corrections folded:

Plan-stage corrections (both scopes)

  • Renovate packageRules precedence is later-wins, not earlier-wins. The Aztec disable rule moves to the bottom of packageRules (was top in earlier draft).
  • config:recommended does NOT bundle :prImmediately — corrected. Our schedule directive applies normally.
  • Existing CI does NOT catch packageManager ↔ setup-bun drift. Initially I claimed CI doesn't run with action-pinned Bun — wrong; CI does use setup-bun. The real issue is narrower: no CI step verifies the two pinned values match.

Impl-stage PR-A (vue-router) corrections

  • R17 (typed-route widening) was over-stated. Impl-stage Codex verified that the deleted RouteNamedMap only enumerated 5 static routes (/common/about, /popup/, /setup/, /setup/install, /setup/update) — NOT the popup auth/register/[id] routes I had called out. Typecheck stayed green across all 9 workspaces with no narrowing changes needed. R17 deprecated in §4.
  • auto-imports.d.ts regen is additive, not replacing. Running build:chrome against the stale file does NOT remove dead entries. Delete the file first for a clean regen. The actual regen dropped 251 lines (vs the "two dead lines" the plan originally promised) — all of them stale and unused.

Impl-stage PR-B (Renovate) corrections

  • baseBranchPatterns: ["dev"] added. Repo default branch is main; Renovate only reads config from the default branch. Without this, installing the App would onboard against empty config. Implies: PR-B must reach main (via the standard dev→main promotion) BEFORE installing the App.
  • Schedule converted to cron: "* 0-5 * * 1" instead of "before 6am on monday". Renovate's @breejs/later text syntax is deprecated.
  • Validator invocation corrected: --strict --no-global added. Without --no-global, passing a filename made the validator treat renovate.json as self-hosted/global config — wrong mode. --strict fails on warnings.
  • Validator version pinned to renovate@43.150.0. npx --yes -p renovate fetches latest on every PR — supply-chain exposure for a wallet repo. Renovate's own routing-group PR will bump this pin going forward.
  • SECURITY.md Bun-drift note corrected: the prior wording claimed CI doesn't run with action-pinned Bun (wrong — every job uses setup-bun). The real issue is narrower (no consistency check between the two pinned values).

Two operational refinements:

  • Better regen workflow: bun run --cwd packages/extension build:chrome is non-interactive and runs the same plugin chain as dev. (unplugin-auto-import has no CLI bin.)
  • Monday-only schedule delay: merging PR-B on Tue 2026-05-19 means first PR batch lands Mon 2026-05-25 (~6-day gap). Accept that or drop schedule for the first week.
  • Pre-create GitHub labels (dependencies, security) before the Mend App's first run; rely-on-first-run label creation is flaky.

Why now

  • Scope A unplugin-vue-router was archived upstream on 2026-02-24. Last release was 0.19.2 in late 2025. No more upstream patches. If a CVE lands, there's nobody to fix it. We're on ^0.15.0 today.
  • Scope A vue-router 5 ships native file-based routing — what unplugin-vue-router used to provide. Upstream frames it as a "boring release, no breaking changes." For us specifically: the feature was never used (we have zero typed-route consumers), so the migration is mostly deletion.
  • Scope B Renovate closes the loop on the dependency-hardening work from PR #95 (age gate, audit). Without automation, dep maintenance is human-driven and inconsistent. Renovate gives us one consolidated dashboard, weekly cadence, and explicit carve-outs for the things we want to bump manually (Aztec).
  • Scope B Dependabot was loud — that's why we held off. Renovate is the answer: prConcurrentLimit, prHourlyLimit, weekly schedule, no auto-merge, and a single Dependency Dashboard instead of N open PRs.

Recon — what's actually in the codebase

Both planners (this assistant + Opus 4.7) independently verified the same facts:

  • unplugin-vue-router is NOT wired into vite.config.ts. Only vite-plugin-pages' usePages is in the plugins array (line 128). The archived plugin sits as a devDep and never runs.
  • Its only surface in our tree: packages/extension/src/types/typed-router.d.ts (141 lines, // @ts-nocheck already) and two dead lines in auto-imports.d.ts (defineLoader, definePage).
  • Zero consumers: grep -r 'definePage\|defineLoader\|vue-router/auto' across src/ returns the generated files themselves. Nothing else.
  • All ~30 router.push(...) callsites use path strings (e.g., "/popup/auth"), not typed RouteRecordNamedMap objects.
  • vue-router 5.0.5 published 2026-04-22 (26 days old) → safe for our 7-day age gate. 5.0.6/5.0.7 are inside the window.
Bottom line: the "migration" is deletion + a one-version-bump of vue-router. No application code changes expected.

Scope A — the migration in three steps

Scope A PR: chore(deps): drop unplugin-vue-router and bump vue-router to 5

Commit 1 — remove the archived plugin

  1. Delete "unplugin-vue-router": "^0.15.0" from packages/extension/package.json devDeps.
  2. Delete the entire file packages/extension/src/types/typed-router.d.ts.
  3. Delete auto-imports.d.ts too, then run bun run --cwd packages/extension build:chrome. unplugin-auto-import's d.ts writer is additive — without deleting the file, stale entries linger.
  4. Commit the regenerated auto-imports.d.ts diff (251 lines of stale cruft removed alongside the two we cared about).

Commit 2 — bump vue-router

  1. "vue-router": "^4.5.1" → "vue-router": "^5.0.5" in packages/extension/package.json.
  2. bun install. Then bun run typecheck:all.
  3. If any type narrowing surfaces (most likely at the auth guard popup/index.ts:50-96), fix at the call site.
  4. Run bun run dev once → regenerates components.d.ts if RouterLink/View drift.
  5. Wipe storybook cache locally (rm -rf packages/extension/node_modules/.cache/storybook) — it pins the old version.

Validation

bun run audit:vue (typecheck + units + lint + build) → bun run test:e2e (smoke; the auth guard is the canary) → ~30s manual click-through (/popup/auth → /popup/general → /popup/send → /popup/settings/connected-apps/[id]). Network e2e skipped — vue-router doesn't touch the Aztec wire boundary.

Scope B — Renovate config

Scope B PR: chore(infra): add Renovate config with conservative defaults

Single file: renovate.json at repo root. Plus doc updates in CLAUDE.md and SECURITY.md.

The shape

  • 7-day age gate mirrors bunfig.toml. Renovate won't open a PR for anything younger than 7d.
  • CVE bypass: vulnerability alerts skip schedule + concurrency limits by default. vulnerabilityAlerts.minimumReleaseAge: "0 days" is explicit belt-and-suspenders.
  • Aztec disabled: @aztec/*, @alejoamiras/aztec-accelerator, @defi-wonderland/aztec-standards, @wonderland/aztec-fee-payment never get PR'd. Manual via the Aztec milestone (class-id stability required).
  • @types/node capped at <25: stays on the Node 24 lifecycle. 24.x patches still bump.
  • baseBranchPatterns: ["dev"]: Renovate reads its config from the default branch (main) but creates PRs against dev.
  • Throttled: prConcurrentLimit: 3 + prHourlyLimit: 2 + cron schedule "* 0-5 * * 1" (Mondays 0-5am Buenos Aires TZ).
  • Grouped clusters: routing, vite, test-runner, puppeteer, storybook, codemirror, commitlint, typescript, unplugin-*. Avoids the PR-storm pattern Dependabot is famous for.
  • No auto-merge anywhere. Wallet is security-sensitive.
  • Single Dependency Dashboard issue: one place to see everything pending; PRs throttled separately.
  • Validator pinned: CI runs renovate@43.150.0 so npx doesn't fetch arbitrary fresh code per-PR.

Five corrections vs the PR #95 draft

  • Regex fix: /^@aztec/ → /^@aztec\/ (escaped JSON "/^@aztec\\//"). The old form matches @aztec-fake/x. Still catches @aztec/viem empirically.
  • Rule ordering: Aztec disable rule goes LAST in packageRules. Renovate's later-rules-win precedence — plan-stage Codex caught my draft initially had this backwards.
  • @types/node: allowedVersions: "<25" rather than full disable. We still want 24.x patch bumps.
  • baseBranchPatterns: ["dev"] added (impl-stage Codex): repo default is main but Renovate must read config from there. PRs target dev.
  • Cron schedule (impl-stage Codex): "before 6am on monday" is deprecated; switched to "* 0-5 * * 1".

Validation

Local: npx --yes --package renovate@43.150.0 -- renovate-config-validator --strict --no-global renovate.json — "Validating renovate.json as repo config" + "Config validated successfully". (bunx doesn't work — bun 1.3.x segfaults on the re2 native binding pulled in by renovate.)

What happens AFTER Renovate is merged

  1. Merge PR-B into dev.
  2. Promote dev → main via the standard promotion PR. Renovate only reads its config from the default branch (main); without this, install would onboard against empty config.
  3. Pre-create GitHub labels dependencies and security (rely-on-first-run label creation is flaky).
  4. You install the Mend Renovate App at https://github.com/apps/renovate, scoped to this repo. (Free for private repos.)
  5. Renovate scans against main, creates PRs against dev per baseBranchPatterns. Mend job scheduling is 4-hourly/daily — not fixed. Vulnerability PRs skip schedule entirely.
  6. Each PR is reviewed and merged manually. Never auto-merged.
  7. First cycle estimate: 10-15 PRs, ~5-7 weekday merges to drain.
Trap to watch for: When Renovate bumps package.json#packageManager (the Bun version), it does NOT update .github/actions/setup-bun/action.yml. Existing CI does NOT auto-catch this — _lint-and-typecheck.yml only runs lint + typecheck + bun audit. Manual review on every Bun-version Renovate PR until we add a consistency check. PR body for Scope B documents this.

Open decisions for you

  1. Pin vue-router as ^5.0.5 or ^5?
    Concrete vs caret. Both behave the same in practice.
    → Recommend: ^5.0.5 (audit-trail signal).
  2. For Renovate's @types/node: allowedVersions: "<25" or full disable?
    The first lets 24.x patches still flow through.
    → Recommend: allowedVersions: "<25".
  3. Add a CI step bunx --bun renovate-config-validator renovate.json?
    Tiny one-line addition to _lint-and-typecheck.yml. Catches config typos.
    → Recommend: yes (or defer to follow-up).
  4. Land PR-2 today (with a temp puppeteer carve-out) or wait until 2026-05-19?
    Waiting avoids carrying a sunset-dated carve-out in the config.
    → Recommend: wait until 2026-05-19. Cleaner.
  5. Two PRs or one stacked?
    Different blast radii. PR-A touches the popup router (smoke-e2e canary). PR-B is config-only.
    → Recommend: two PRs.
  6. Install Mend App before or after PR-B merge?
    Installing first means an empty-config initial scan creates a noisy Dashboard.
    → Recommend: merge config first, install App second.
  7. Doc updates (CLAUDE.md + SECURITY.md) in PR-B or split?
    Reviewing config and docs together can slow config review; splitting adds PR overhead.
    → Recommend: bundle into PR-B.
