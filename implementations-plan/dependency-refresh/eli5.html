Dependency refresh (in-range, min-age-respected)

The thing that kicked this off — "bump zod to v5" — turns out to be a no-op: there is no zod v5 (latest is 4.4.3, and we're already on it). So this isn't a migration; it's a routine "pull the small updates" pass. A full scan shows the only big jump available is @types/node 24→26, which our policy caps at <25, so we skip it. Everything else is small (minor/patch) and already allowed by our version ranges — so two small bun update passes (libraries first, then tooling, kept separate so any breakage is attributable) refresh them, and our 7-day safety rule automatically holds back anything published this week.

Why this tier was chosen

light (downgraded from the requested mid). Once research showed no zod v5 and no real major upgrades, the risk is low: routine small bumps, fully reversible (revert the lockfile), no data/migration, our supply-chain rule stays on. The only "moderate" bit is that it touches dev-dependencies of every package — but they're small bumps validated by the full test/build/e2e suite.

Phases

Phase 1: Runtime/lib refresh + full safety audit

Update the app/runtime libraries (Vue, vue-router, pinia, viem, CodeMirror, etc.) within their ranges. Then audit the entire lockfile diff — every changed package, including indirect (transitive) ones — to confirm nothing newer than a week slipped in (a known Bun bug can let a too-new indirect dep survive, so we check them all, not just the direct ones), nothing jumped a major, and @types/node stayed at 24. Then typecheck + lint + all unit tests. Commit.

Proves itself by: frozen install passes; every changed entry (direct + indirect) is ≥7 days old; typecheck + lint + the whole unit suite green.

Phase 2: Tooling refresh + fix fallout (separate commit)

Update the build/test tooling (Biome the linter, vue-tsc the type-checker, Vitest, Vite plugins, Storybook, etc.) in a separate commit — so if a check breaks, we know it was the tooling, not the libraries. These can surface new lint rules or stricter type errors; fix anything new they flag. The same full-diff age audit applies.

Proves itself by: typecheck + lint + the whole unit suite (the 10 packages that have tests) green, with fallout fixed.

Phase 3: Builds + end-to-end + PR

The build-related bumps (Vite, Vue, CodeMirror, Sass, Storybook) affect bundling, so build all five surfaces and re-run the full checks explicitly (typecheck + lint + all unit tests — not the extension-only shortcut audit:vue takes), then open the PR; smoke + network end-to-end tests run in CI.

Proves itself by: typecheck + lint + test:all + all 5 builds pass; smoke + network e2e green in CI; final lockfile diff reviewed.

Human context

bun update moves each dependency to the newest version still allowed by the ^ range in package.json — so no manifest edits are needed. Our bunfig.toml blocks anything published in the last 7 days (supply-chain defense); this week's brand-new releases (Vite 8.1.0, Biome 2.5.1, viem 2.53.1) simply land a few days later, on their own. There's a known Bun bug (#25305) where a too-new indirect dependency can sneak through on a bulk re-resolve — so we audit the whole lockfile diff ourselves (and, if it's messy, fall back to the repo's documented "delete the lockfile and reinstall" which re-applies the rule to everything). @types/node is frozen below 25 by repo policy; @aztec/* are exact-pinned and handled separately — untouched here.
