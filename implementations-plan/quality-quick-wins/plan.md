## Q-05 scope decision (narrowed, verified.md-aligned) + owned follow-ups
The verified.md finding lists **four** duplicating sites and — critically — **overrides** consolidated.md's proposed full `AlarmBackedTask(name, period, tick, enabled)`: "extract only a thin `AlarmDispatcher(name)` wrapper (name const + create/clear + name-guard); leave scheduling semantics (periodic vs `when`, gating) per-caller … a period-bundling primitive does NOT fit session-manager's `when`-based reschedule-under-lock. Migrate GC first."

Confirmed against the source: `session-manager.ts:676` creates with `{ when: lockedAt }` (one-shot, rescheduled under lock); `reaper.ts`'s boot sweep calls `reap({ unconditional, bootCutoff })` — DIFFERENT args than its periodic `reap()`; `price/service.ts` is periodic but heavily gated (5 `clear` sites, 1 `create`) with an externally-centralized dispatch. So a boot-run/period-bundling primitive fits only GC (1 of 4); the thin `AlarmDispatcher` (create passthrough of the full `AlarmCreateOptions` + optional name-guarded `listen` + create/clear) fits all four — satisfying the "≥3 call sites benefit" bar. **Narrowed** = extract that thin primitive + a thorough unit test + migrate the ONE cleanest site (`gc.ts`, whose 8 tests isolate sweep from lifecycle, so the migration is provably behavior-neutral).

**Owned, dated follow-ups (2026-08-17)** — migrate the remaining three hand-rolled sites onto `AlarmDispatcher` (each behavior-preserving, each gated by its own existing tests; each keeps its own boot-run + gating, per the thin-wrapper contract):
- `apps/extension/src/wallet/services/operation-journal/reaper.ts` — `JOURNAL_REAPER_ALARM_NAME` / 1-min period; caller keeps its `reap({unconditional,bootCutoff})` boot sweep (distinct from the periodic tick).
- `apps/extension/src/wallet/services/price/service.ts` — periodic + gated; use `dispatcher.create/clear` for the gate logic; dispatch stays external (`wallet/index.ts`), so it may skip `listen()`.
- `apps/extension/src/wallet/services/profile/session-manager.ts` — `when`-based one-shot rescheduled under lock; caller keeps its reschedule; `dispatcher.create({when})` + name-guarded `listen`.

Each follow-up is a ≤1-file diff swapping local alarm plumbing for a `new AlarmDispatcher(...)`, mirroring the gc.ts migration. Split out (not dropped) to keep this arc [light] and each migration individually reviewable.
