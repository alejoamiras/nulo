Design system, round 2: the hard leftovers

Round 1 moved the easy shared UI bits (colors, fonts, plain little components like badges and toggles) out of the wallet extension and into one shared package, @nulo/design, so the wallet and the faucet both use the same source. Round 2 finishes the job: the 9 leftover components that round 1 skipped because each was "stuck" to something app-specific — the router, app state, or the page's HTML shell. We unstick each one cleanly, move it to the shared package, and tidy up the leftover tooling.

Why "deep" (the heaviest planning tier)

Scored against the rubric: blast radius is HIGH (these primitives — Button, Input, Spinner, Tooltip — render on basically every screen of a ~200-component wallet plus the faucet, so a mistake shows up everywhere). The other factors are moderate/low (it's reversible, no data migration, no new external services). One clear HIGH would normally be "mid", but the seams round 1 deliberately deferred (decoupling the router, the teleport roots, reconciling two different versions of Button + Spinner across two apps) are exactly the contested design forks where three independent plans + two audit rounds earn their cost. Three plans were drafted (this agent + codex + an Opus subagent), reconciled against the actual repo, then attacked by codex and a hostile fresh reviewer. They caught real defects — see "What the audits changed."

The faucet's look change is isolated to the LAST step (easy to roll back)

The locked rule is "the extension's components win; the faucet adopts them" — so the faucet's buttons will eventually change to the wallet's brutalist UPPERCASE accent style and its spinner from a 0.75-second spin to the wallet's 4-second spin. Per your call, all of that faucet visual change is packed into the single final step (PR7), and the faucet is held visually frozen until then. If anything looks wrong, reverting that one PR restores the faucet's current look completely, leaving all the shared-package work intact. The only cost is a small temporary "legacy spinner" kept around between steps 2 and 7.

The plan in 7 steps (each is one PR, each stays green on its own)

PR1 — Set up the safety nets first

Fix the (currently broken) Storybook build, add a lint rule so the new "ui" layer can't import upward, turn the package's boundary test into a tripwire (no router, no raw-HTML rendering), and add a guard that catches the exact kind of faucet styling regression that slipped through round 1.

Proves itself by: package tests + both app builds + Storybook build all green; the new guards actually fail when you break them.

PR2 — Merge the two Spinners into one (faucet kept frozen)

The wallet and the package each have a different spinner. Merge them into one (the wallet's look, keeping the package's accessibility labels). The wallet adopts it now; the faucet is pinned to a temporary "legacy spinner" copy so it doesn't change yet. Then move the two components that use it (Banner, LoadingState).

Proves itself by: all unit tests + both builds + smoke green; faucet build green + visually unchanged (no faucet sign-off needed yet).

PR3 — Move the toast (little popup messages) machinery

Move the toast logic into the package, but leave a one-line forwarder where it used to live so the ~55 places that use it don't change. Keep the wallet's toast region working as before.

Proves itself by: all ~55 toast users still compile + tests green.

PR4 — The Button + back-header (the router-coupled ones) — wallet only

Move Button so the shared package never needs the router: the package version is a plain button (or a safe link), and the wallet keeps a thin wrapper for router links. Same trick for the page back-header. The faucet is NOT touched here — it keeps its current buttons until the final step.

Proves itself by: all tests + both builds + smoke green; faucet unchanged.

PR5 — Tooltip + Popover (the ones glued to the page shell)

Move the "click-outside" helper into the package (it's shared with the dropdown too), then move Tooltip and Popover, letting each app say where they pop up instead of hard-coding it.

Proves itself by: package + extension tests + build + smoke green; the dropdown still works.

PR6 — Input — wallet only

Move Input (it uses Tooltip, now available) with its own copy of the small text-cleaning helper. Still no faucet visual change.

Proves itself by: package + extension + faucet tests + builds + smoke green; faucet still frozen.

PR7 — Faucet cutover + final sign-off (the only faucet-look change — fully revertible)

Now, in ONE PR, switch the faucet's 10 buttons to the shared Button, flip its spinner to the shared one, and delete the temporary legacy spinner. Update docs. Full gate: everything green, the network test suite, and a human check on both apps — wallet "looks identical", faucet "the intentional restyle looks right". If the faucet restyle is wrong, revert this one PR and the faucet is back to normal.

Proves itself by: full audit + network e2e green + human sign-off on both apps.

What the audits changed (proof the process worked)

  • Caught a self-contradiction in the Button design (a "plain button only" base can't also render links) → fixed to a safe closed button/link choice.
  • Caught that the toast/outside helpers are imported with an explicit .js ending in dozens of files → the forwarder must keep the .js filename or everything breaks.
  • Caught a potential infinite render loop in the Button wrapper (it must call the base by a different name).
  • Caught a made-up bug-pin one planner hallucinated → removed.
  • Caught that the faucet restyle was being undersold as a "rename" → now called out explicitly (the box above).
