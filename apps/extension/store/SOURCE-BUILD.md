# Rebuilding the Firefox add-on from this source archive

For the Mozilla add-on reviewer. This archive is `git archive` of the tagged release commit; the
add-on under review was built from exactly this tree by the release workflow
(`.github/workflows/release.yml` → `_build-extension.yml`, target `firefox`). Rebuilding it takes
one script and produces a tree that must match the submitted add-on byte for byte.

## What differs from the default reviewer machine

- **Package manager and script runner: Bun, not npm.** The exact Bun release is named by
  `package.json#packageManager` (`bun@1.4.2` for this line) and the script refuses any other
  version. **Node stays: Vite (the bundler) and `cross-env` are Node programs and run under the
  machine's Node** (the script prints the Node it found). The release builds run on GitHub's
  Ubuntu runners under their default Node 22; the output does not depend on the Node major: the
  runs recorded in `.github/workflows/source-rebuild.yml` (Node 22.23.2, x86_64 and ARM64) and a
  workstation on Node 24.18.0 produced identical trees, so the reviewer machine's Node 24 is fine.
- **Architecture:** the build is verified on Ubuntu 24.04 ARM64 and on x86_64 by
  `.github/workflows/source-rebuild.yml`, which does exactly what this document does.
- **Memory:** see § Resources below.

## Steps

1. Install the pinned Bun from the official release. Both Linux archives, with the SHA-256 that
   Bun publishes in `SHASUMS256.txt` for `bun-v1.4.2`:

   | Archive | URL | SHA-256 |
   |---|---|---|
   | Linux ARM64 | `https://github.com/oven-sh/bun/releases/download/bun-v1.4.2/bun-linux-aarch64.zip` | `54328bbc2d9c8e0c9f892c544d66c57a83b84139e34909e5ee81758f1ac8fda7` |
   | Linux x86_64 | `https://github.com/oven-sh/bun/releases/download/bun-v1.4.2/bun-linux-x64.zip` | `36368faef7527875d5ffa52e53cd48021741f2a83eb6208a8dd64068d422a913` |

   ```sh
   curl -LO https://github.com/oven-sh/bun/releases/download/bun-v1.4.2/bun-linux-aarch64.zip
   echo "54328bbc2d9c8e0c9f892c544d66c57a83b84139e34909e5ee81758f1ac8fda7  bun-linux-aarch64.zip" | sha256sum -c -
   unzip bun-linux-aarch64.zip && export PATH="$PWD/bun-linux-aarch64:$PATH"
   bun --version   # 1.4.2
   ```

2. Unpack this archive anywhere **outside** a git repository and run, from inside it:

   ```sh
   apps/extension/scripts/source-rebuild.sh 0.27.0
   ```

   The argument is the add-on's `version_name` (the semver; the manifest's four-part `version`
   is derived from it). The script checks that the tree is at that version, checks the Bun
   version, runs `bun install --frozen-lockfile` (dependencies from the npm registry exactly as
   `bun.lock` pins them; Puppeteer's browser download is skipped, nothing here needs a browser),
   then `bun run --cwd apps/extension build:firefox`.

3. Compare `apps/extension/dist/firefox` with the unpacked add-on:

   ```sh
   diff -r apps/extension/dist/firefox /path/to/unpacked-xpi
   ```

   Empty output is the expected result.

## What the build does

- Vite (Rolldown) bundles the TypeScript and Vue sources; the manifest comes from
  `apps/extension/manifest/manifest.firefox.config.ts`. No minified or generated code is checked
  in; everything under `dist/` is produced by this step.
- The build makes **no network request**. All inputs are the archive plus the installed
  dependencies.
- Third-party code is used as published, with the modifications listed in the reviewer notes
  (`store/listing.md` § Reviewer notes): four `patches/*.patch` files (`@aztec/noir-noirc_abi`
  and `@aztec/noir-acvm_js`, at two versions each, applied by `package.json#patchedDependencies`)
  that change package resolution metadata only, three module aliases in
  `apps/extension/vite.config.ts`, and debug symbols blanked in bundled contract artifacts.
- `THIRD-PARTY-NOTICES.txt` in the output is generated by the build from the installed packages.

## Resources

- Peak resident memory of `source-rebuild.sh` (install + build), `/usr/bin/time -v` Maximum
  resident set size: **2.1 GB on Ubuntu 24.04 ARM64**, 1.8 GB on x86_64 (GitHub-hosted runners,
  2026-09-21; 2.3 GB on a 12-core x86_64 workstation). Well under the reviewer machine's 10 GB.
- Wall time: 22 s on the ARM64 runner and 17 s on x86_64 with a cold package cache and a fast
  registry link; the install dominates, the build itself takes under ten seconds.
- Disk: the archive is about 80 MB unpacked; dependencies add about 2.1 GB.
