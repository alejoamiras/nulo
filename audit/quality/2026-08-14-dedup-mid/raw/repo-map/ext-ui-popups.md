## 2. Shared primitives in use

`FormPopup` (composite) — 11 popups build on it (all Edit*/New* form popups). `ItemsContainer`/`SettingItem`/`SettingField`/`SettingValue` (ui/Settings) — 10–11 consumers across settings modules + popups. `usePopupEntity` composable — 5 popups (submit/onHide wiring). `useFormState` composable (`src/composables/useFormState.ts`) — 9 popups. `@nulo/design` direct imports — 9 files in scope (rest get L1/L2 via auto-import resolver). `DropdownRoot`/`Dropdown*` — used by Header, several settings rows. No shared "already-exists" validator, no shared clipboard helper beyond the one described below, no shared identity-strip component despite two near-identical implementations (see §3).

## 3. Duplication candidates (audit focus)

1. **New\*/Edit\* near-copy popup pairs.** 5 pairs share structure (imports → `useFormState` → `FormPopup` wrapper → same `<Input>` fields → "already exists" hint): `NewAccountPopup.vue`/`EditAccountPopup.vue`, `NewContactPopup.vue`/`EditContactPopup.vue`, `NewEndpointPopup.vue`/`EditEndpointPopup.vue`, `NewFpcPopup.vue`/`EditFpcPopup.vue`, `NewNetworkPopup.vue`/`EditNetworkPopup.vue` (all in `apps/extension/src/popup/components/popups/`). Edit variants add "started editing" gating on top of the same field set — a diffable/extractable shape, not just superficial naming.

2. **Byte-identical dead `<style module>` block, copy-pasted 5×.** The exact same 58-line block (`.network`, `.icons`, `.item` — hover/active states for a network-list row that no longer exists in these templates) appears verbatim (md5-identical) in `NewAccountPopup.vue`, `EditAccountPopup.vue`, `NewNetworkPopup.vue`, `EditNetworkPopup.vue`, and (with 2 extra live classes appended) `NewSenderPopup.vue` — none of the 3 classes are referenced via `$style.*` anywhere in any of the 5 templates (verified: no `$style[` dynamic access either). ~290 lines of pure dead CSS. Related smaller dead-class findings (single components, not cross-file dupes but same copy-paste-and-drift smell): `EditContactPopup.vue` `.shake` + `@keyframes shake` defined but never applied (looks like the shake-on-error wiring from `NewSenderPopup.vue`'s `.shake` — which IS wired — got dropped on copy); `EditProfilePopup.vue` `.icon_btn`; `AccountsPopup.vue` `.account`/`.account_name`/`.icons`/`.txt_button`; `RevokeAuthwitsPopup.vue` `.row`; `SelectProfilePopup.vue` and `SelectTokenPopup.vue` both dead `.token`; `BalanceView.vue` `.hover_red`; `SelectNetworksPopup.vue` `.icons`.

3. **Repeated "already exists" form-validation wiring, 9 sites.** Same three-part shape — a `useFormState` field `validate` returning the literal `"Already exist"`/`"Already exists"`, a `computed` re-checking `form.fields.X.error.value === "Already exist..."`, and an inline `<Text>...Already exist...</Text>` warning row — duplicated in `NewAccountPopup.vue`, `NewContactPopup.vue` (×2, name+address), `NewFpcPopup.vue`, `NewNetworkPopup.vue` (×2, name+url), `NewTokenPopup.vue`, `EditContactPopup.vue` (×2), `EditNetworkPopup.vue`, `EditFpcPopup.vue` (all `popups/`). No shared uniqueness-validator helper or hint component exists; each site hand-rolls the same three parts with a slightly different string literal ("exist" vs "exists").

4. **Copy-to-clipboard reimplemented inline, ~9×.** `window.navigator.clipboard.writeText(...)` immediately followed by `openToast({ label: "... copied", icon: "copy" })` is hand-rolled separately in: `components/ScopeAddress.vue`, `components/ScopeClassId.vue`, `popup/components/modules/general/BalanceView.vue` (`handleCopy`), `popup/components/popups/AccountsPopup.vue`, `popup/components/popups/EditFpcPopup.vue`, `popup/components/popups/ReceivePopup.vue`, `popup/components/popups/IncomingTrustPopup.vue`, `popup/components/popups/TokenMetadataPopup.vue`, `components/JsonViewer/JsonViewer.vue`. Exactly one site was ever extracted — `components/header-copy-address.ts` (`copyAddressToClipboard`, used only by `Header.vue`) — and it isn't reused by the address-copying sites above even though `ScopeAddress.vue`'s inline version does the identical strip-then-write. `CapabilityDetailPanel.vue`'s own header comment already flags the sharing gap ("shared with `<ScopeAddress>`/`<ScopeClassId>` (clipboard wiring...)").

5. **Near-duplicate "identity strip" component, 2 independent implementations.** `components/composite/DappStatusStrip.vue` and `popup/windows/execute/SignerIdentityStrip.vue` both render: status-dot (dynamic `$style[`status_${status}`]`) + account name + `·` separator + network name + trailing "NULO" brand mark, with matching `identity_strip`/`identity_account`/`identity_sep`/`identity_network`/`identity_brand` class names in each one's own `<style module>` block. One was very likely copy-pasted from the other and re-themed rather than shared.

6. **Confirm-dialog invocation shape — not duplicated in this scope.** `cacheStore.confirm.{title,description,confirm_text,callback}` + `popupStore.open("confirm")` is defined once (`ConfirmPopup.vue`) and not re-invoked by any other file under the audited directories; its callers live in `popup/pages/**` (out of scope for this map). No candidate here — noted so the audit doesn't re-search for it.
