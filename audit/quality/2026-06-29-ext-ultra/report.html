Findings

ArchitecturalQ-01No uniform decode layer at the storage / RPC / dApp / backup seams
both modelsconfidence: highhot · 8 files · 30+ casts · typing

What it is. Whenever data crosses a boundary — read from storage, returned from an RPC, sent by a dApp, or imported from a backup — the wallet asserts it is the right type (JSON.parse(...) as T) instead of checking it. The right pattern already exists in one corner (aztec-runtime validates 16 PXE methods with a schema) but isn't used everywhere.

What gets harder to change. A storage migration, an RPC result change, or a backup-format bump can compile perfectly while feeding stale or malformed data into the app as if it were trustworthy. The failure then shows up somewhere far away and confusing, not at the boundary where it entered.

The fix. Give the boundaries a real "codec": storage constructors take a parser/schema, and the RPC/dApp/backup seams decode by method or payload kind. Copy the pattern aztec-runtime already proves — you're not inventing it, just applying it uniformly. Biggest item here; do it one seam at a time.

Technical trace

Instances: wallet-core/storage/entity_storage.ts:49, value-storage.ts:21; extension-messaging/core/decode.ts:15, utils.ts:22,28; aztec-runtime/pxe/client.ts:90-93,144,191-195; extension/composables/useFullBackupImport.ts:165,201-214,…, useDappInteractionPayload.ts:16,86 (full list in consolidated.md).

Refactoring: Introduce Codec / Replace Cast With Schema. Effort: weeks.

ArchitecturalQ-02RPC dispatch is stringly-typed end-to-end
both modelsconfidence: highhot · 6 files · 100+ casts · typing

What it is. Messages between the dApp, the popup, and the service worker are routed by a plain string method name and an untyped args: unknown[] bag; the receiver then hand-casts args[0] as X. (The low-level MethodsMap generic that looks suspicious is actually fine — the real looseness is downstream at the dispatch + dApp boundary.)

What gets harder to change. Renaming an RPC or reordering its arguments isn't caught by the compiler at the dApp trust boundary — the place you most want it caught. The request builders, the scope/permission checkers, and the enforcement code can quietly drift out of sync.

The fix. Derive a typed RpcRequest discriminated union from the method descriptors, narrow it once at dispatch, then pass typed tuples downstream. Biggest typing item; schedule deliberately.

Technical trace

Instances: wallet-core/base/index.ts:11; extension-messaging/core/base-service.ts:111,125,130; wallet-bridge/dispatcher.ts:275,328,503,…,1078-1162; method-scope-checkers.ts:58-190.

Refactoring: Introduce Parameter Object / method-descriptor-derived union. Effort: weeks.

ArchitecturalQ-03RPC/PXE method surfaces are hand-restated as passthroughs
both modelsconfidence: highhot · 30 files · dedup

What it is. 21 service client files each hand-write return this.request("methodName", ...args) for every method, even though the method list is already declared once in the spec. The PXE interface is worse — the same method list is restated in seven places (interface, subset, proxy, client, registry, impl, names).

What gets harder to change. Adding or renaming one method is a multi-file edit held together only by matching string literals — easy to typo, impossible for the compiler to verify. PXE is the most expensive because each method's validation body is hand-written too.

The fix. A typed ServiceClient proxy/factory generates the passthroughs from the spec; one PXE descriptor table generates the interface, proxy forwarding, RPC names, and schemas. Effort: days.

Technical trace

Instances: the 21 extension/src/wallet/services/*/client.ts; aztec-runtime/pxe/{spec,ipxe,subset,proxy,client,service}.ts.

Refactoring: Replace Boilerplate With Typed Proxy / Extract Method Table.

ArchitecturalQ-04OperationKind policy + Draft/Executable models are split
both modelsconfidence: highhot · 9 files · typing + dedup

What it is. An "operation" is a proper tagged union, but the dApp materializer turns it back into a loose blob and re-casts it (as unknown as Operation), and there's a parallel DraftOperation type in the popup. Five different places each switch over the same operation-kind strings.

What gets harder to change. Adding a new operation kind means finding and editing all five switches (materialization, authorization, fee-readiness, execution, UI). Miss the authorization one and the new kind silently falls back to "no access".

The fix. One OperationPolicy table keyed by kind, plus a single shared DraftOperation + assertExecutableOperation at the model seam. Pairs with Q-05. Effort: days.

ArchitecturalQ-12Token-function ABI matchers are copy-paste catalogs (~1.3k LOC)
both modelsconfidence: highhot · 12 files · dedup

What it is. Nine token-function modules (get-name, get-symbol, the balance + transfer variants) are near-identical — get-name.ts and get-symbol.ts are byte-for-byte the same except one word, and the same ABI struct literal is copied verbatim 12 times.

What gets harder to change. An Aztec ABI change or a new token capability means synchronized edits across all nine modules plus the service assembly, specs, and utils — ~1.3k lines that rot independently.

The fix. One TokenFnDescriptor table with shared ABI builders + scoring. The repo already does exactly this next door in fpc/handlers/. Effort: days.

ArchitecturalQ-15Execution send-paths duplicate slot/journal scaffolding
both modelsconfidence: highhot · 5 files · dedup

What it is. The send pipelines repeat the same acquire-slot → claim-journal → cancellation-check → catch/finally-release → record-transaction sequence, and a 10-argument recordTransaction closure appears byte-identical in two places.

What gets harder to change. This is the concurrency/cancel path you just hardened in the quality arc — the slot/journal/finally ordering is load-bearing. A copy that drifts can leak a mutex slot (wedged lane) or mis-record a transaction.

The fix. A lane.withExecutionSlot(...) template that owns journal/cancel/finally; a shared recordTransaction builder and payload parser. Refactor with extra care to preserve the verbatim ordering invariants. Effort: days.

Technical trace

StructuralQ-05Capability flow erases the union + mirrors enforcement (already drifted)
both modelsconfidence: highhot · 4 files · typing + dedup

What it is. dApp capabilities are carried as unknown[] and cast back to concrete types; separately, "what does this request cover" logic in the dispatcher hand-mirrors the "is this allowed" checks elsewhere.

What gets harder to change. A new capability field has to be added to delta-detection, coverage, enrichment, and enforcement — and it's already gone wrong: contractClasses is missing from the dispatcher's delta branches (4 of 6 capability types handled).

The fix. Parse once to Capability[]; one table keyed by capability type for parse/covers/delta/merge/enrich/check. Pairs with Q-04. Effort: days.

StructuralQ-06Secret bytes + wire encodings are primitive-typed
both modelsconfidence: highwarm · 8 files · typing

What it is. Passhash, salt, master secret, ciphertext, credential-id, PRF output — all carried as bare ArrayBuffer/Uint8Array/string, so they're freely assignable to each other. Worst case: one masterKey: string parameter holds a base64 master key for password restore but a credential-id for passkey restore.

What gets harder to change. A backup/import/profile refactor can swap two encodings or byte-roles and still type-check; the mistake only surfaces at decrypt/restore time. (This is the branded-types ask.)

The fix. Branded types — Passhash, MasterSecretBytes, Salt, Base64Ciphertext, … — and split the restore payload by profile type. Type-only; the KDF test vectors stay green. Pairs with Q-09. Effort: days.

Technical trace

Instances: wallet-crypto/{encryption-key,password-secret-box,passkey-credential,zeroize}.ts; extension/.../profile/{spec.ts:22-35,250-262,service.ts,session-manager.ts}. The dual-role masterKey is documented verbatim at spec.ts:250-262.

Refactoring: Replace Primitive With Branded Types.

StructuralQ-07Error taxonomies + projection are split and stringly-typed (already drifted)
both modelsconfidence: highwarm · 9 files · typing + dedup

What it is. JobError.kind is a bare string whose "known values" live only in a comment — and producers already emit kinds not in that comment. Separately, two functions duplicate hostile-input error-message handling, and makeRemoteError is byte-identical across both messaging clients.

What gets harder to change. It's already broken: token-import error kinds match none of the three hand-maintained UI switches, so they silently render the generic "Error" label. Adding an error category means manual edits across producers, schemas, and UI copy with no exhaustiveness signal.

The fix. An open union KnownJobErrorKind | (string & {}); a code-keyed discriminated WalletErrorPayload; extract the shared error helpers (the extractions alone are hours — a cheap win). Effort: days.

StructuralQ-10Design props bypass token unions; extension wrappers re-copy them
both modelsconfidence: highwarm · 16 files · 600+ call sites · typing + dedup

What it is. The design system already generates token unions (ColorToken, FontSize, …), but the older primitives still type their variant/size/color props as bare string (and Checkbox uses the array form, making every prop any). The extension then re-declares those prop contracts in untyped JS wrappers.

What gets harder to change. 542 color= + 59 variant= call sites get zero autocomplete or typo protection, and a typo'd Button variant silently renders an unstyled button. New base props can be silently dropped by the wrappers.

The fix. Migrate the old primitives to typed defineProps<{}>() over the token unions; export the base prop types so wrappers forward them typed. Start with Checkbox + ButtonVariant/Size (hours). Pairs with Q-11. Effort: days.

StructuralQ-17profile/service.ts defines runExclusive but bypasses it 21×
claude · codex-verifiedconfidence: highwarm · 21 lock pairs · dedup

What it is. The profile facade already has a runExclusive(fn) helper that does lock.enter() / try / finally lock.leave() — but 21 other methods paste that same try/finally structure inline instead of using it.

Cross-cutting observations

The wallet trusts its own wire

Q-01, Q-02, Q-06, and Q-07 are one theme at four seams: data crossing a boundary (storage, RPC, dApp, crypto/backup) is cast to a domain type instead of decoded into one. The antidote already exists in the codebase (aztec-runtime's schema rehydration; operation-journal's hand-rolled safeParse) — the work is making it uniform, not inventing it. This is the single highest-leverage architectural investment.

Describe the surface once

Q-02, Q-03, Q-04, Q-05, Q-12, Q-13, and Q-19 are all one list maintained in N places — RPC methods, PXE methods, operation kinds, capability types, token functions, entity CRUD, factory modes. The repo already demonstrates the descriptor/registry pattern (fpc/handlers, the two repository classes, defineRpcMethods); these findings extend it to the surfaces that still hand-restate.

Drift is not hypothetical here

Three findings have already drifted on dev: the missing contractClasses capability branch (Q-05), the JobError.kind values vs their consumers (Q-07), and design wrapper props (Q-10). These are the strongest candidates — the change-amplification cost is being paid right now.

The typing axis is any-clean but cast-heavy

Several packages (wallet-crypto, token/assets, execution) have zero any. The debt is as / as unknown as narrowing at boundaries plus primitive obsession — which a decode layer (Q-01) and branded types (Q-06) remove at the root rather than site-by-site.
