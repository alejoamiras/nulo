# Harden-Quality Report
**Repo:** nulo (Aztec wallet monorepo) · **Date:** 2026-06-11 · **Effort:** ultra · **Run ID:** 2026-06-11-ultra-50b45d
**Models:** Fable 5 (mapping, cluster ×2/cluster, rebuttals, verification, merge) + Codex xhigh (cluster ×2/cluster, rebuttals, coordinator, verification)
**Scope:** packages/extension, wallet-bridge, wallet-core, wallet-crypto, aztec-runtime, extension-messaging. Excluded: bridge-core, faucet, playground (user), design (no extension imports — verified), generated types, vendored JsonViewer files, node_modules/dist.

## Executive summary

Six clusters covering the extension, the wallet-sdk bridge, the service fleet, the messaging/PXE transport stack, the shared core packages, and the build/e2e tooling were audited by 24 independent cluster agents (2 Fable + 2 Codex per cluster), producing 178 raw findings. After full cross-model rebuttal, a two-round push-back cycle, coordinator consolidation, and dual-family verification of every surviving claim, 23 verified root-cause findings remain — 4 confirmed clean, 19 adjusted, 0 refuted. Every finding carries source-verified instances, a smallest-safe refactoring, and any behavior-preservation constraints the fix must honor.

The dominant repo-level pattern is the half-done migration: an abstraction was started, partially adopted, and then frozen, leaving the codebase paying dual maintenance on both the old and new shapes. This shows up as the composition-root/ports migration (Q10), the execution-pipeline extraction that never landed (`execution-coordinator.ts` documents a `proveAndSend` method that was never created — Q4/Q5), the popup form abstractions that don't cover the async edit lifecycle (Q8), config sharing under "keep in sync" comments with already-shipped drift (Q7), and the hand-maintained PXE subset projection (Q13). Four files concentrate the cost — `packages/extension/src/wallet/services/execution/service.ts` (2,302 lines, 4 duplicated send pipelines), `packages/wallet-bridge/src/dispatcher.ts` (1,011-line hub), `packages/extension/src/popup/components/modules/general/RecentActivityView.vue` (re-implements the already-extracted feed merge), and `packages/extension/tests/e2e/fixtures/extension.ts` (1,249-line harness with 4 copied setup ladders). Each combines size with duplicated subflows precisely because extraction stopped halfway.

Recommended order of attack, by computed priority: **Q1** (bridge method-metadata registry — small surface, hot files, eliminates a whole class of silent-omission edits), then **Q5 followed by Q4** (the shared prove→submit→persist lifecycle tail is the first concrete, test-backed slice of decomposing the hottest file in the repo — fixing Q5 makes every subsequent Q4 extraction cheaper), then **Q2** (popup/onboarding profile-flow duplication — hot UI surface where every profile change is currently paid twice), **Q3** (the forked background/offscreen transport stacks — every RPC-layer fix is paid twice and error contracts diverge), and **Q7** (config sprawl — roughly a day of work and the only finding with already-shipped, user-visible drift: the `e2e:all` config silently lost its noir aliases and retry policy). Before any fix work begins, treat the **Refactoring constraints registry** at the end of `findings/verified.md` (19 entries: wire-format parity pins, upstream mirrors, load-bearing error strings, lock-discipline and emit-order preservation) as a hard gate — several smallest-safe refactorings are only safe because they respect those constraints.

## Methodology

- **Phase 1 — hierarchical map.** 6 Fable Explore mappers produced per-cluster repo maps (hotspot ranking via git churn, dependency edges, exclusion verification). Maps were persisted by the orchestrator because Explore agents are read-only.
- **Phase 2 — parallel cluster audits.** 6 clusters × (2 Claude Fable + 2 Codex xhigh) = 24 fully independent agents, each with the same quality-only prompt (named Fowler-catalog smells, behavior-preserving findings only). Inter-procedural reasoning capped at ~4 functions, +1 across handoff edges.
- **Phase 2.5 — adversarial rebuttal, two rounds.** Round 1: full cross-model rebuttal — each Codex session resumed to attack the Claude findings for its cluster, and dedicated Claude rebuttal agents attacked the Codex findings. Round 2 push-back: Codex via session resumes; Claude via FRESH Fable self-critique agents (deviation from spec: async-agent session continuation was unavailable, so Claude Round 2 used fresh instances reading the full document trail instead of resumed sessions).
- **Phase 3 — consolidation.** A fresh Codex xhigh coordinator merged 178 raw findings into 23 consolidated findings, deduplicating by root cause and excluding every rebuttal-refuted claim.
- **Phase 4 — dual-family verification of ALL findings.** 3 Fable + 3 Codex verifiers, each finding checked by one verifier from each family under an anti-anchoring protocol: the verifier forms an independent judgment from the Instances source BEFORE reading the claim text. Result: 23/23 survive (4 confirmed, 19 adjusted, 0 refuted). One cross-family conflict (Q16: Codex REFUTED-as-written vs Fable CONFIRMED-at-symbol-level) was resolved by a convergence ruling narrowing the finding to the symbol set both verifiers accept.
- **Density note.** 178 raw ≈ 1.85 findings/agent/cluster; 23 consolidated ≈ 3.8/cluster — above the ~1.2 map-phase target, expected at ultra's 4-agent fan-out with high cross-model convergence.
- Scope confirmation was interactive (not unattended).

## Cross-cutting observations

- **Half-done migration is the dominant repo-level pattern.** Declarative startup deps (Q9), browserApi/storage/PXE ports (Q10), the execution-pipeline extraction (Q4/Q5), the activity-feed extraction (Q6), popup form abstractions (Q8), config sharing (Q7), and the PXE composition surface (Q13) all show migrations that stopped midstream and now force dual maintenance of the old and new shapes. The cheapest leverage is usually finishing (or explicitly abandoning) the existing migration, not inventing a new abstraction.
- **Manual parallel registries recur across layers.** Bridge method tables (Q1), execution tuples/clumps (Q18), PXE subset surfaces (Q13), config aliases/defines (Q7), and wallet-core serializers (Q22) all repeat "same fact, many places" with no mechanical derivation or drift pin.
- **Sync-by-comment is a recurring failure mode.** "Keep in sync" config comments (Q7), the scope-enforcement sync note (Q1), the affirmatively false `proveAndSend` extraction claim (Q5), the false activity-rows extraction claim (Q6), the wrong CAIP ownership header (Q20), and the stale PasskeyCeremonyDialog "Used by" header (Q2) all use comments as the synchronization mechanism. Two of those comments are outright false, not merely stale — comments do not pin anything; tests and types do.
- **Dead/public surface bloat is not isolated** (Q16): unused library subpaths, dead core exports, and an unused dependency all survived without consumers; the convergence ruling shows bulk dead-code claims need per-symbol proof.
- **The hottest files are the ones where extraction stopped halfway:** `execution/service.ts`, `dispatcher.ts`, `RecentActivityView.vue`, and `tests/e2e/fixtures/extension.ts` each combine size with duplicated subflows rather than one coherent abstraction.
- **Map-anchoring lesson.** The only fabrications among the 178 raw findings were claims transcribed from the Phase-1 repo maps rather than read from source — the phantom `isTerminalStage` export, the false `walletErrorFromPayload` deadness story, the overstated "no facade test" claim. Source-anchored claims survived rebuttal and verification at far higher rates. Treat map content as navigation, never as evidence.
- **Milestone-comment policy violations** were flagged broadly by C1/C3 agents (banned milestone vocabulary per the repo's comment policy) and dropped as standalone findings; only concrete false/stale docs were retained as evidence. The policy drift is real and cheap to fix opportunistically inside the Q4/Q5/Q6 work.
- **The verification round materially changed the set rather than rubber-stamping it:** 19/23 findings adjusted. Codex verifiers systematically *widened* instance families (~30 additional sites across Q9/Q10/Q14/Q15/Q18/Q19/Q21/Q23) while Fable verifiers reproduced exact counts and surfaced behavior-preservation constraints. The 19-entry Refactoring constraints registry in `findings/verified.md` is the distilled product of that asymmetry — it is the gate any fix PR must clear.
- **Round-2 rebuttals already paid for themselves before verification:** phantom dead exports, false "tests-only" consumers, over-broad fee-strategy twins, and the sentinel/activation coupling were removed rather than softened.
