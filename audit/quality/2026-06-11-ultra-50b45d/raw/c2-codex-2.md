## F1: Restore pipelines are copy-pasted across eight services
1. Title: Restore pipelines are copy-pasted across eight services.
2. Smell name: Duplicate Code. Each `restore()` rebuilds the same `Restored<T>[]` accumulator, per-record `try/catch`, and `restoreError` envelope; any contract change becomes Shotgun Surgery across the fleet.
3. Maintenance impact bucket: structural. Blast radius: 8 service modules. Change frequency: this family was touched in 4 commits over the last 3 months.
4. Concrete evidence: [packages/extension/src/wallet/services/account/service.ts:213](packages/extension/src/wallet/services/account/service.ts:213), [contact/service.ts:290](packages/extension/src/wallet/services/contact/service.ts:290), [config/service.ts:43](packages/extension/src/wallet/services/config/service.ts:43), [token/service.ts:532](packages/extension/src/wallet/services/token/service.ts:532), [transaction/service.ts:302](packages/extension/src/wallet/services/transaction/service.ts:302), [auth-registry/service.ts:285](packages/extension/src/wallet/services/auth-registry/service.ts:285), [fpc/service.ts:470](packages/extension/src/wallet/services/fpc/service.ts:470), and [network/service.ts:614](packages/extension/src/wallet/services/network/service.ts:614) all declare `const result: Restored<...>[] = []`, iterate imported rows, push the restored row on success, and push `{ ...row, restoreError: ... }` on failure, with only the inner persistence step varying.
5. Why it harms future change: if restore needs typed import errors, telemetry, rollback behavior, or a new dedupe policy, eight services have to be edited and re-synchronized by hand; the current variants already drift on error normalization (`err` vs `err.message`) and ID-remapping details.
6. Smallest safe refactoring: Extract Function / Template Method analog. Introduce a shared `restoreMany` helper that owns the accumulator and error wrapping while each service supplies `validate`, `persist`, and `mapSuccess` callbacks.
7. What disappears: the repeated accumulator, per-item `try/catch`, and ad hoc `restoreError` shaping disappear from eight files.
8. Instances: `account/service.ts:213`, `contact/service.ts:290`, `config/service.ts:43`, `token/service.ts:532`, `transaction/service.ts:302`, `auth-registry/service.ts:285`, `fpc/service.ts:470`, `network/service.ts:614`.

1. Title: Storage-backed services expose incompatible construction patterns.
2. Smell name: Alternative Classes with Different Interfaces. These classes all serve the same “storage-backed wallet service” role, but some accept injected `browserApi` ports while peers hard-code `chrome.storage.*`; the runtime must know each special case. This also behaves like config sprawl because storage binding is duplicated across constructors and the composition root.
3. Maintenance impact bucket: architectural. Blast radius: 11 files/modules. Change frequency: this family was touched in 6 commits over the last 3 months.
4. Concrete evidence: [packages/extension/src/wallet/runtime.ts:105](packages/extension/src/wallet/runtime.ts:105) explicitly documents the mixed world, then special-cases construction at `runtime.ts:110-125`; [contact/service.ts:35](packages/extension/src/wallet/services/contact/service.ts:35) and [profile/service.ts:62](packages/extension/src/wallet/services/profile/service.ts:62) accept optional `browserApi`; [profile/repository.ts:42](packages/extension/src/wallet/services/profile/repository.ts:42) and [profile/session-manager.ts:120](packages/extension/src/wallet/services/profile/session-manager.ts:120) each duplicate fallback ternaries; meanwhile [account/service.ts:23](packages/extension/src/wallet/services/account/service.ts:23), [dapp-session/service.ts:29](packages/extension/src/wallet/services/dapp-session/service.ts:29), [token/service.ts:42](packages/extension/src/wallet/services/token/service.ts:42), [transaction/service.ts:36](packages/extension/src/wallet/services/transaction/service.ts:36), [fpc/service.ts:43](packages/extension/src/wallet/services/fpc/service.ts:43), [network/service.ts:143](packages/extension/src/wallet/services/network/service.ts:143), and [auth-registry/service.ts:29](packages/extension/src/wallet/services/auth-registry/service.ts:29) hard-code `chrome.storage`.

Instances: `runtime.ts:105-125`; `contact/service.ts:35-39`; `profile/service.ts:62-66`; `profile/repository.ts:42-45`; `profile/session-manager.ts:120-132`; `account/service.ts:23-27`; `dapp-session/service.ts:29-34`; `token/service.ts:42-52`; `transaction/service.ts:36-44`; `fpc/service.ts:43-55`; `network/service.ts:143-153`; `auth-registry/service.ts:29-40`.
