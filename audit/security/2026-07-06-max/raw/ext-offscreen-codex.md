CLUSTER: ext-offscreen

## Findings

### [1] Firefox offscreen fallback can leave multiple PXE listeners handling the same secret-bearing RPC

1. **Title** — Firefox offscreen fallback can leave multiple PXE listeners handling the same secret-bearing RPC.

2. **Impact factors** — Violates confidentiality, integrity, and availability for a single Firefox-extension user/profile. Secret material and private wallet state sensitivity is high: account `secretKey` is sent over the SW→PXE RPC during account registration, and PXE state/IndexedDB can be mutated or deleted. Exploitability factors: attack vector network if a malicious dApp can drive approved wallet activity and wait for/nudge normal SW restart timing, otherwise local/environmental; attack complexity high because it depends on Firefox fallback plus SW restart while the hidden window survives; privileges required none from the web page after normal wallet permissions/approval flows; user interaction required for wallet/dApp use.

3. **Evidence confidence** — High.

4. **OWASP / CWE mapping** — OWASP A01 Broken Access Control; CWE-863 Incorrect Authorization; CWE-664 Improper Control of a Resource Through its Lifetime.

5. **Trace** — Firefox builds intentionally remove the `offscreen` permission and rely on the hidden-window fallback: `apps/extension/manifest/manifest.firefox.config.ts:7`. The fallback stores the hidden window id only in module memory: `apps/extension/src/wallet/utils/offscreen.ts:41`. The code documents that after SW restart the tracker resets and the old hidden window cannot be closed/discovered without extra permission: `apps/extension/src/wallet/utils/offscreen.ts:183`. Because `isOffscreenAlreadyRunning()` returns only `firefoxOffscreenWindowId !== null` on Firefox, a restarted SW sees no running offscreen even if the old hidden window still exists: `apps/extension/src/wallet/utils/offscreen.ts:201`. `ensureOffscreenRunning()` then creates another hidden window: `apps/extension/src/wallet/utils/offscreen.ts:215` → `apps/extension/src/wallet/utils/offscreen.ts:167` → `apps/extension/src/wallet/utils/offscreen.ts:175`. Each hidden window loads the offscreen entry: `apps/extension/src/offscreen/index.html:9`, starts PXE: `apps/extension/src/offscreen/index.ts:81`, and constructs `PxeService`: `packages/aztec-runtime/src/offscreen/entry.ts:43` → `packages/aztec-runtime/src/offscreen/entry.ts:45`. Each `PxeService` subscribes a `chrome.runtime.onMessage` listener: `packages/extension-messaging/src/offscreen/service.ts:32` → `packages/extension-messaging/src/offscreen/service.ts:33`. The listener accepts any object whose `to` equals the service name, without checking sender or instance identity: `packages/extension-messaging/src/offscreen/service.ts:36` → `packages/extension-messaging/src/offscreen/service.ts:38`, then dispatches request content: `packages/extension-messaging/src/offscreen/service.ts:43` → `packages/extension-messaging/src/offscreen/service.ts:48`. The SW client broadcasts each offscreen RPC with only `{ from: uid, to: "pxe" }`: `packages/extension-messaging/src/offscreen/client.ts:103` → `packages/extension-messaging/src/offscreen/client.ts:104`. With two hidden windows, both listeners execute the same RPC. A secret-bearing path is account registration: `apps/extension/src/wallet/services/execution/service.ts:634` → `apps/extension/src/wallet/services/execution/service.ts:635` sends `op.secretKey`; the offscreen service writes it into PXE: `packages/aztec-runtime/src/pxe/service.ts:236` → `packages/aztec-runtime/src/pxe/service.ts:239`. A destructive path is chain purge: `apps/extension/src/wallet/services/network/service.ts:604` → `apps/extension/src/wallet/services/network/service.ts:605`; the offscreen handler disposes runtime and deletes `pxe/${profileId}/${chainId}`: `packages/aztec-runtime/src/pxe/service.ts:460` → `packages/aztec-runtime/src/pxe/service.ts:468`. Duplicate responses are only dropped client-side after the first one settles: `packages/extension-messaging/src/core/base-client.ts:163` → `packages/extension-messaging/src/core/base-client.ts:171`, so that does not prevent duplicate side effects.

6. **Missing control** — The offscreen RPC channel has no current-instance authorization or sender/context check. The Firefox fallback has no durable singleton lease, no rediscovery/cleanup of pre-existing hidden windows after SW restart, and no per-instance token/document id binding in the SW→offscreen request envelope.

7. **Exploit story / violation scenario** — A Firefox user unlocks the wallet and uses a dApp, causing the wallet to create the hidden PXE window. The service worker later restarts while that hidden window remains alive. On the next wallet operation, `ensureOffscreenRunning()` has lost `firefoxOffscreenWindowId`, assumes no offscreen is running, and creates a second hidden PXE window. When the wallet later registers an account, proves/simulates a transaction, or purges a chain, the SW broadcasts one `{ to: "pxe" }` request. Both hidden windows accept it. The old window receives the new account `secretKey` and mutates its own PXE state; both windows may run expensive proving/simulation work; destructive cleanup can run against multiple PXE runtimes. The SW accepts whichever response settles first and drops later responses, leaving the duplicate secret/state mutation invisible to the caller.

8. **Preconditions** — Firefox build/runtime path; the wallet has already created the hidden offscreen fallback window; the service worker restarts while that window survives; a later PXE RPC is sent. For secret exposure to a zombie PXE, the later RPC must be `registerAccount` or another secret-bearing operation.

9. **Why mitigations fail** — `chrome.runtime.getContexts()` is only used on Chromium and does not protect the Firefox branch: `apps/extension/src/wallet/utils/offscreen.ts:193` → `apps/extension/src/wallet/utils/offscreen.ts:202`. The health check only waits for any `OFFSCREEN_PONG` and does not prove singleton ownership or current instance identity: `apps/extension/src/wallet/utils/offscreen.ts:73` → `apps/extension/src/wallet/utils/offscreen.ts:96`; the offscreen responds to pings without sender/instance validation: `apps/extension/src/offscreen/index.ts:14` → `apps/extension/src/offscreen/index.ts:17`. RPC method allowlisting and Zod parsing restrict method names and parameter shapes, but they do not bind requests to the intended offscreen instance: `packages/aztec-runtime/src/pxe/service.ts:60` → `packages/aztec-runtime/src/pxe/service.ts:82`; `packages/extension-messaging/src/core/base-service.ts:90` → `packages/extension-messaging/src/core/base-service.ts:105`. Client-side duplicate-response dropping prevents promise confusion, not duplicate execution: `packages/extension-messaging/src/core/base-client.ts:163` → `packages/extension-messaging/src/core/base-client.ts:171`.

10. **Instances** — Root cause instances are the Firefox hidden-window singleton tracked only in memory: `apps/extension/src/wallet/utils/offscreen.ts:45`, `apps/extension/src/wallet/utils/offscreen.ts:183`, `apps/extension/src/wallet/utils/offscreen.ts:201`, `apps/extension/src/wallet/utils/offscreen.ts:215`; the unauthenticated/offscreen-instance-agnostic message listener: `packages/extension-messaging/src/offscreen/service.ts:36`, `packages/extension-messaging/src/offscreen/service.ts:43`; and all PXE RPCs exposed through that listener, especially mutating or secret-bearing methods: `packages/aztec-runtime/src/pxe/service.ts:60`, `packages/aztec-runtime/src/pxe/service.ts:236`, `packages/aztec-runtime/src/pxe/service.ts:242`, `packages/aztec-runtime/src/pxe/service.ts:258`, `packages/aztec-runtime/src/pxe/service.ts:268`, `packages/aztec-runtime/src/pxe/service.ts:274`, `packages/aztec-runtime/src/pxe/service.ts:286`, `packages/aztec-runtime/src/pxe/service.ts:300`, `packages/aztec-runtime/src/pxe/service.ts:330`, `packages/aztec-runtime/src/pxe/service.ts:391`, `packages/aztec-runtime/src/pxe/service.ts:400`, `packages/aztec-runtime/src/pxe/service.ts:410`, `packages/aztec-runtime/src/pxe/service.ts:460`.
