CLUSTER: ext-content-script

## Findings

### [1] Build-time iframe support re-enables top-frame origin impersonation

1. **Title** — Build-time iframe support re-enables top-frame origin impersonation.

2. **Impact factors** — Authorization and confidentiality are violated for a single wallet user/session: a malicious iframe can be treated as the trusted top-frame dApp origin and inherit that origin’s remembered session/capability grants. Sensitive data includes granted account identifiers and any wallet data/methods covered by the trusted origin’s existing grants; integrity impact is possible for granted wallet methods, with transaction execution still subject to downstream confirmation flows. Exploitability: attack vector network, attack complexity low once the build flag is enabled, privileges required none, user interaction required to visit a trusted/previously-approved dApp page embedding attacker-controlled iframe content.

3. **Evidence confidence** — High.

4. **OWASP / CWE mapping** — OWASP A01: Broken Access Control; CWE-346: Origin Validation Error; CWE-863: Incorrect Authorization.

5. **Trace** — The extension injects the content script into all frames on all HTTP(S) pages via `all_frames: true` and `matches: ["*://*/*"]` (`apps/extension/manifest/manifest.config.ts:31`, `apps/extension/manifest/manifest.config.ts:33`, `apps/extension/manifest/manifest.config.ts:35`). The scoped content script starts the upstream `ContentScriptConnectionHandler`, which relays page messages to `chrome.runtime.sendMessage` (`apps/extension/src/content-script/content.ts:11`, `apps/extension/src/content-script/content.ts:12`, `apps/extension/src/content-script/content.ts:22`). The SW wrapper documents that upstream origin attribution uses `sender.tab?.url`, i.e. the top-frame URL, so an iframe at `https://evil.com` embedded in `https://app.example.com` is credited to `https://app.example.com` (`apps/extension/src/wallet/services/wallet-sdk/background.ts:150`, `apps/extension/src/wallet/services/wallet-sdk/background.ts:151`, `apps/extension/src/wallet/services/wallet-sdk/background.ts:152`, `apps/extension/src/wallet/services/wallet-sdk/background.ts:153`, `apps/extension/src/wallet/services/wallet-sdk/background.ts:154`). The only local control is build-flagged: `VITE_NULO_ALLOW_IFRAME_DAPPS=1` sets `NULO_ALLOW_IFRAME_DAPPS` true (`apps/extension/src/wallet/services/wallet-sdk/background.ts:57`, `apps/extension/src/wallet/services/wallet-sdk/background.ts:61`, `apps/extension/src/wallet/services/wallet-sdk/background.ts:68`), and the subframe reject branch is skipped when that flag is true (`apps/extension/src/wallet/services/wallet-sdk/background.ts:172`). The message is then envelope-validated only for shape and forwarded to the upstream listener (`apps/extension/src/wallet/services/wallet-sdk/background.ts:187`, `apps/extension/src/wallet/services/wallet-sdk/background.ts:188`, `apps/extension/src/wallet/services/wallet-sdk/background.ts:192`). Discovery auto-approval keys off the misattributed `discovery.origin` plus chain ID and approves without a popup when a remembered session exists (`apps/extension/src/wallet/services/wallet-sdk/background.ts:483`, `apps/extension/src/wallet/services/wallet-sdk/background.ts:486`, `apps/extension/src/wallet/services/wallet-sdk/background.ts:488`). Later wallet messages are dispatched with `ctx.origin = session.origin` (`apps/extension/src/wallet/services/wallet-sdk/background.ts:626`, `apps/extension/src/wallet/services/wallet-sdk/background.ts:629`, `apps/extension/src/wallet/services/wallet-sdk/background.ts:637`), and the dispatcher authorizes against the stored dApp session for that origin/chain (`packages/wallet-bridge/src/dispatcher.ts:281`, `packages/wallet-bridge/src/dispatcher.ts:297`, `packages/wallet-bridge/src/dispatcher.ts:320`). For an existing accounts grant, `getAccounts` returns the session accounts (`packages/wallet-bridge/src/dispatcher.ts:399`, `packages/wallet-bridge/src/dispatcher.ts:400`, `packages/wallet-bridge/src/dispatcher.ts:401`).

6. **Missing control** — When iframe dApps are enabled, there is no binding between the actual sender frame origin (`sender.url` / frame origin) and the origin used for discovery/session/capability authorization. The bridge needs either unconditional subframe rejection, frame-scoped session attribution and replies, or a check that the sender frame origin is the authorization principal.

7. **Exploit story / violation scenario** — A release is built with `VITE_NULO_ALLOW_IFRAME_DAPPS=1`. The victim previously connected and granted accounts access to `https://trusted.example` on chain `C`. `https://trusted.example` embeds attacker content in an iframe from `https://evil.example`. The iframe sends the wallet discovery postMessage from its own frame. Because the content script runs in all frames, the iframe’s content script relays it to the SW. With the flag enabled, the SW does not reject the subframe; upstream origin attribution credits the request to the top-frame origin `https://trusted.example`. `handleDiscovery` finds the remembered `(https://trusted.example, C)` session and auto-approves. The iframe completes the channel and sends `getAccounts`; the dispatcher looks up grants for `https://trusted.example` and returns the trusted origin’s granted accounts to the attacker-controlled iframe.

8. **Preconditions** — The extension must be built with `VITE_NULO_ALLOW_IFRAME_DAPPS=1`; the victim must browse a page whose top-frame origin already has a remembered dApp session/grants for the requested chain; attacker content must run in a subframe on that page.

9. **Why mitigations fail** — The default subframe rejection prevents this only while `NULO_ALLOW_IFRAME_DAPPS !== true`; the build flag disables that branch (`apps/extension/src/wallet/services/wallet-sdk/background.ts:172`). `validateContentScriptMessage` checks only the internal envelope origin/type and leaves `content` opaque, so it does not validate the browser sender origin or frame principal (`apps/extension/src/wallet/services/wallet-sdk/content-script-validator.ts:46`, `apps/extension/src/wallet/services/wallet-sdk/content-script-validator.ts:50`, `apps/extension/src/wallet/services/wallet-sdk/content-script-validator.ts:100`). Capability enforcement is downstream of the misattributed session origin and therefore enforces the trusted parent origin’s grants, not the iframe’s real origin (`packages/wallet-bridge/src/dispatcher.ts:281`, `packages/wallet-bridge/src/dispatcher.ts:299`).
