## Entrypoints (CRITICAL — attack surfaces)

### Service Worker (`src/wallet/index.ts`)
- **Entry:** Static chrome-runtime setup hooks (onInstalled, onMessage) + async `createWalletRuntime().start()`
- **Messages accepted:**
  - `nulo:open-toolbar-popup` (from onboarding done page) → calls `chrome.action.openPopup()`
  - Content-script-relayed wallet-SDK messages (via `BackgroundConnectionHandler` in `wallet-sdk/background.ts`)
  - Service-client RPC calls from popup (via chrome.runtime.connect + message ports in `extension-messaging`)
- **Ports/handlers exposed:**
  - Chrome message port per service (defined in `extension-messaging/background/service.ts`)
  - `initWalletSdkHandler` wires wallet-SDK encrypted channel (ECDH P-256 → AES-256-GCM)
  - Heartbeat alarm (`chrome.alarms`) on 10s interval for MV3 keep-alive
  - `chrome.storage.local` (profiles, networks, FPCs, dApp sessions, contacts, tokens) + `chrome.storage.session` (active session, operation journal)

### Content Script (`src/content-script/content.ts`)
- **Path:** Single 22-line relay (no custom logic)
- **Injected into:** Every frame matching manifest `content_scripts.matches`
- **What it injects:** Delegated entirely to `@aztec/wallet-sdk/extension/handlers/ContentScriptConnectionHandler`:
  - Sets up in-page `window` postMessage channel for dApp discovery
  - Relays discovery + encrypted wallet messages bidirectionally between page and background
  - No secrets, keys, or session data ever enter content script
- **Validation:** `validateContentScriptMessage()` in `wallet-sdk/content-script-validator.ts` filters messages with `origin: "content-script"` flag (lines 72–85); non-matching messages are passthrough

### Popup UI (`src/popup/index.ts` + routes)
- **Entry:** `createApp(App).use(router).use(createPinia()).mount("#app")`
- **Auth-required routes** (guarded at `/popup/index.ts:50–76`):
  - Line 68–69: `meta.isAuthRequired && !appStore.isLogined` → redirects to `popup-auth`
  - Routes checked: `/popup/*` (general, send, activity, settings, etc.)
  - Exception: `popup-auth`, `popup-register`, `popup-import`, `popup-profile-new` are public
  - Passkey-interaction routes bypass auth check (line 53–55, `meta.isPasskeyInteraction`)
- **Route guards also enforce:**
  - Profile selection (line 78–87): redirects unprovisioned users to registration
  - Profile type checks (line 90–93): password-only routes reject passkey profiles
  - Session state tracking (line 73: `appStore.isSessionChecked`)

### Offscreen Document (`src/offscreen/index.ts`)
- **Entry:** Runs `createPxeOffscreen()` from `@nulo/aztec-runtime/offscreen/entry`
- **What runs inside:**
  - Full Aztec PXE (private execution engine): note creation, proof generation, account setup
  - Protocol-contract artifacts (simulation, proof generation)
  - Key derivation via WebCrypto (never persisted to chrome.storage)
  - ProductionPxeFactory + optional Aztec Accelerator integration (if `VITE_NULO_ACCELERATOR_REQUIRED=1`)
- **How SW reaches it:**
  - Service-worker calls `ensureOffscreenRunning()` (in `wallet/utils/offscreen.ts`) → creates hidden window or document
  - RPC via `chrome.runtime.sendMessage` + response callbacks
  - Health-check ping (`OFFSCREEN_PING` constant) every ~30s; zombie offscreen is torn down + recreated
  - Firefox fallback: uses hidden `chrome.windows` window instead of offscreen API (Chromium MV3 only)

### Storage handlers
- **`chrome.storage.local` key prefixes:**
  - `nulo:core:profiles@<id>` — encrypted profile record (password or passkey)
  - `nulo:core:networks@<profileId>` — per-profile networks
  - `nulo:core:accounts@<profileId>` — per-profile accounts
  - `nulo:core:dappSessions@<id>` — per-session dApp metadata + granted capabilities
  - `nulo:core:tokens@<profileId>` — registered tokens
  - `nulo:core:contacts@<profileId>` — address book
  - `nulo:core:fpcs@<profileId>` — fee-paying contracts
  - `nulo:ui:*` — UI state (active network, display options)
- **`chrome.storage.session` key prefixes:**
  - `nulo:core:session` — active session mirror (passhash if strict-mode OFF; never raw secret)
  - `nulo:journal@<id>` — operation journal records (transfer, dapp_execute, token_import with FSM state)

### Background jobs / alarms
- **Heartbeat:** `chrome.alarms.create("heartbeat", { periodInMinutes: 1/6 })` — 10s interval in `runtime.ts:68`
- **JournalGC:** 60-min alarm caps terminal operation journal records at 50 per (profileId, accountAddress)
- **JournalReaper:** Marks stuck non-terminal records as failed on alarm trigger

## Trust boundaries (security-critical — extra detail)

| Boundary | Location | What crosses | Validation |
|----------|----------|--------------|-----------|
| **dApp page → content script** | `src/content-script/content.ts:11–22` | postMessage (discovery request, encrypted wallet messages) | SDK's `ContentScriptConnectionHandler` validates origin via `message.origin` frame check (implicit in SDK); content script is 22-line relay only |
| **Content script → SW (via chrome.runtime)** | `wallet-sdk/background.ts:60–150` | encrypted wallet messages forwarded by SDK + discovery pendants | `validateContentScriptMessage()` (`wallet-sdk/content-script-validator.ts:72–85`) rejects any message without `origin: "content-script"` flag |
| **dApp session auto-approval boundary** | `dapp-session/service.ts:85–100` | `tryGetDappSessionByOriginAndChain(origin, chainId)` — cached session lookup | **CRITICAL (AUDIT A12):** chainId is REQUIRED; old pre-v5 sessions without chainId were wiped (migrate.ts:18–24). Cross-network session bleed is prevented by session per-`(origin, chainId, profileId)` tuple. |
| **Popup → SW (RPC via ports)** | `popup/index.ts:35 + extension-messaging/background/service.ts` | Typed RPC calls (getProfiles, getAccounts, approveInteraction, etc.) | Service-client base class enforces typed methods; no raw message accept. Error reconstruction via message equality (`err.message === "..."`) — biome ignores explicit-any at boundary (wallet-core/base). |
| **SW → offscreen (via chrome.runtime.sendMessage)** | `wallet/utils/offscreen.ts:60–150` + `offscreen/index.ts:11–18` | PXE method calls (prove, simulate, createNote) + session secrets for key derivation | Health-check ping validates offscreen responsiveness; stale offscreen is torn down. Secrets never sent over the bridge — only per-call request/response pairs for stateless operations. |
| **SW ↔ external (Aztec node RPC)** | `wallet/services/network/service.ts` (RPC_URL env per network) | CAIP-2 chain ID resolution, account state queries, transaction submission | Network chain ID validated against stored network record; no cross-network request replay. |
| **SW → chrome.storage.local/session (persistence)** | `wallet/storage/migrate.ts:81–103` + service entity-storage writes | Serialized profiles, sessions, journal records, dApp sessions | Migration wipe on version bump (destructive for pre-v0.11.0 wallets; no production users). Per-row resilience: `EntityStorage` wraps `JSON.parse` in try/catch (`wallet-core/storage/entity_storage.ts`); malformed rows logged + deleted. OperationRecord schema validated via `OperationRecordSchema.safeParse()` — invalid records dropped before FSM touches them. |
| **Backup restore flow** | `profile/service.ts:44–55` (late-activation pattern) | Recovered secrets stashed in `pendingRestoreSecrets` map (in-memory, SW-lifetime) | `restore()` defers session open until `finalizeRestore()` called by importer. Prevents `onActiveProfileChanged` race against backup data import. Passkey recovery secrets never persisted (WebAuthn PRF non-portability). |
| **dApp origin validation** | `dapp-session/service.ts:85–100` + `wallet-sdk/background.ts:200–250` | dApp metadata (origin, title, icon) from discovery frame | `BackgroundConnectionHandler` validates frame origin via postMessage channel setup (origin-mismatch postMessage fails). Metadata stored in `DappSession.dappMetadata.url` per session. |
| **Wallet lock state enforcement** | `profile/session-manager.ts:100–180` + `dapp-session/service.ts:44–50` | Session TTL expiry check, re-derivation guard | `SessionManager.restore()` silently closes expired or corrupted sessions. `DappSession.getDappSessions()` checks `profileService.getActiveProfile()` — returns error if locked (line 45–48). No method runs without an active profile. |

## Dependency graph (one level deep)

**Imported workspace packages:**
- **`@nulo/wallet-core`** → heavily by wallet services (profile, network, account, execution, transaction). Provides ports, base types, entity storage, job queue, KV abstractions, utilities (error handling, entropy, mnemonic).
- **`@nulo/wallet-crypto`** → profile service (session derivation), passkey service. Provides `EncryptionKey`, `PasswordSecretBox`, `PasskeyCredential`, key-derivation vectors (`key-vectors.test.ts`).
- **`@nulo/extension-messaging`** → entire service layer + popup service-clients. Provides `Service` base class, `ServiceClient` base, RPC message schemas, error envelopes.
- **`@nulo/aztec-runtime`** → offscreen entry (`createPxeOffscreen`), PXE factory, account adapter (`NuloAccount`).
- **`@nulo/wallet-bridge`** → wallet-SDK dispatcher, capability map, scope enforcement (`WalletSdkDispatcher`, `DiscoveryQueue`).

**External Aztec packages (all pinned @ 4.2.0):**
- `@aztec/wallet-sdk` — dApp discovery + encrypted-channel handlers (`BackgroundConnectionHandler`, `ContentScriptConnectionHandler`)
- `@aztec/pxe` — PXE interface
- `@aztec/accounts` — Schnorr account contract artifact + entrypoint
- `@aztec/bb.js` — Barretenberg proof system (initialized at startup)
- `@aztec/aztec.js`, `@aztec/foundation`, `@aztec/protocol-contracts`, etc. — core protocol types

**UI/build stack:**

**Utility deps:**

- **@codemirror/*** — JSON editor in log viewer
- **@defi-wonderland/aztec-standards** — token standards

## Test surfaces

- **Unit + component tests:** 231 `.test.ts` files colocated next to source (`src/**/*.test.ts`). Entry: `vitest.config.ts`. Chrome API stubbed via `@webext-core/fake-browser` + `FakeBrowserApi`. Component tests via `@vue/test-utils` mount.
- **Smoke e2e:** `tests/e2e/*.test.ts` (71 files). Entry: `vitest.e2e.config.ts`. Popup UI flows (auth, send, settings, etc.) with no Aztec sandbox. Runs against in-memory storage + mocked network calls.
- **Network e2e:** `tests/e2e/network/**` (subdirectory). Entry: `vitest.e2e.network.config.ts`. Drives playground dApp against per-worktree anvil + Aztec sandbox. Agent runner (`bun run e2e:agent`) handles port allocation + parallel safety.
- **Crypto vector tests:** `src/wallet/crypto/key-vectors.test.ts` — byte-identical derivation checks for KDF, encryption, Schnorr signing.
